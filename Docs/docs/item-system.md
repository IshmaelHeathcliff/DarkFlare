# 统一物品系统

## alpha 0.4 范围

金币、锻造矿石和装备共同使用 `ItemBaseDefinition`、`ItemInstance` 与 `InventoryModel`。金币不再拥有独立钱包状态；`Gold` 是背包金币数量的统计，HUD、交易、打造继续读取该属性。穿戴后的装备仍归属装备槽，世界掉落与商人库存仍保持各自所有权。

物品分类为通货、材料、装备、消耗品、交易物、任务道具。保留原 `ItemType` 的武器、护甲、饰品编号作为装备子类型，`ItemCategory` 统一上层分类，避免破坏旧配置。后三类仅预留，无药水使用、贸易路线或任务逻辑。

## 数量与消耗

- `IsStackable` 和 `IsConsumable` 独立配置；可堆叠不代表能消耗，物品分类也不替代消耗资格。
- 装备有效堆叠上限始终为 1。金币为 1×1、上限 100，锻造矿石为 1×1、上限 50；两者均可消耗。
- 普通拾取先填充兼容堆叠，再放置剩余物品；空间不足整次失败，原有与传入数量保持不变。
- 指定格拾取 / 购买只接受指定格或该格的兼容堆叠，不回退到另一格。拖动到兼容堆叠会合并，达到上限后剩余数量保留原格。
- 合并要求同一基底、稀有度、品质和耐久，且两者没有词条或隐式属性；防止吞掉不同掷值。
- 当前操作以整堆为单位，尚无手动拆分数量窗口；原键鼠 / 手柄拿起放置与快捷动作继续使用同一事务入口；背包支持纵向滚动，手柄拖动会滚动到目标格，滚动条不参与物品焦点导航。

## 交易与打造

交易价格计算包含整堆数量。金币不能出售或购买自身；出售若无法放入所得金币则恢复原物品位置。余额溢出会拒绝操作。金币发放先填充已有堆叠，再按上限分成新堆；空间不足时整次失败。金币数量变化同时刷新物品栏与余额消费者。

打造只接受背包内装备。现有操作与金币价格保留，每次额外消耗 1 个锻造矿石；精准前缀 / 后缀范围消耗 3 个。材料不足在随机生成前拒绝，成功后统一扣除资源并通知 UI。失败不扣金币或材料。

锻造矿石目前通过怪物掉落获得，新游戏不额外发放材料。商人继续销售装备，玩家可出售材料。

## 掉落与显示

三张正式怪物掉落表沿用当前掉落概率（基础 50%、迅捷 60%、重装 80%），每条装备权重 100、金币权重 2000、锻造矿石权重 500。当前每表 20 条装备，合计权重 4500，成功掉落时装备合计约 44.44%、金币约 44.44%、矿石约 11.11%。装备仍从完整装备池生成对应稀有度与词条；金币数量 8–24，材料数量 1–3，均使用原掉落随机通道。

物品栏右下角、候选列表及地面标签显示堆叠数量；详情显示数量上限及消耗属性。打造按钮显示材料持有 / 所需数量，材料不足有本地化反馈。商店出售候选和打造候选分别排除金币与非装备。

## 存档

Save Schema 2 保存 `ItemInstanceDto.Quantity`，历史 Schema 1 经迁移为数量 1。core 内容目录提升至 v3，已发布 v1 / v2 内容先保留已有装备兼容规则，再把独立金币迁移为实际金币物品。原物品身份、位置与词条不改变；金币按配置上限分堆，空间不足时按需扩展背包行数保存金币，源存档不被预检修改。

新档 `Profile.Gold` 保留为余额摘要，恢复预检要求与实际背包金币一致；它不再是第二份运行时钱包。非法数量、未知未来内容或所有权冲突仍拒绝恢复。

配置字段见[物品与掉落](./config-reference/items-and-loot.md)和[交易与打造](./config-reference/trade-and-crafting.md)。
