# 刷怪地图手动重置

Alpha 0.6.4 在城镇通往刷怪地图的传送门提供“进入”和“重置并进入”。选择重置后须再次确认：目标地图未拾取掉落会清除。普通进入、离开地图和继续游戏保留原怪物、Boss、触发批次、掉落与随机进度；城镇、无刷怪图、当前活动图和切图中地图不能重置。首版没有费用、次数限制或自动刷新。

## 地图实例与存档

`InstanceEpoch` 是每张地图的持久实例代次。新图和 Schema 8 以前的历史档从 0 开始，只有成功的显式重置才递增；地图布局 `Revision` 与 MapScope `Generation` 仍分别表示内容版本和内存装配，不承担代次语义。活动图保存到 `Run.ActiveMapEpoch`，冻结图保存到 `MapStateDto.InstanceEpoch`。Schema 8→9 迁移只补 0，不重新生成已访问图；旧 `LegacyPreserved` 怪物和 Boss 进度继续保留，首次成功重置后才采用当前有限计划。

新实例的地图随机根由运行种子、MapId 和新代次确定性派生；代次 0 沿用历史算法。正式野外图每次重置恢复 20 个入图普通名额、10 个各 8 个范围触发名额，以及独立守卫 Boss。触发点、区域与布局保持地图 V4 原配置。怪物与 Boss 使用新的全局实例身份；已发布身份不回收。玩家背包、装备、金币和状态、商人库存、其他地图及全局身份分配器不重置。

## 提交与失败恢复

重置从非活动图发起。`SaveCoordinator` 在准备前取得排他保存租约，阻止自动保存、退出刷新或第二次重置穿过事务。`WorldMapRuntime` 保留旧冻结数据，准备并装配候选新图，保存前把源图暂存为冻结态。`SessionSnapshotSource` 在旧图尚未释放时只捕获新活动图的地图对象和 Session 玩家，再把源图与其他冻结图纳入同一快照；目标图旧掉落及其独占物品不进入新快照。存档继续走现有协调器和原子代际文件。

落盘前的准备失败、取消或明确保存失败会恢复源图、原目标冻结状态、玩家位置与资源、Boss、状态和随机流，并释放候选。落盘成功才释放旧图并反馈成功；落盘后清理失败进入 Fatal，不把磁盘新代次伪装成已回滚。写盘结果不明确时核对最新有效代际及活动图代次，无法判定则停止当前 Session 的继续操作。普通切图仍采用原先的非持久化提交路径，成功后安排自动保存。

## 玩家反馈与诊断

传送门选项复用 Application Shell Modal，默认焦点为“进入”；“重置并进入”打开二次确认，取消不修改地图。Busy、失败与成功反馈由 Scene Flow 和 Shell 管理，键盘、手柄导航提交及鼠标共用按钮。文本使用 Unity Localization 的 `ui` 表；伪本地化沿用现有运行时模式。运行时可通过 `WorldMapRuntime.ActiveMapEpoch`、`LastResetMapId`、`LastResetPhase`（准备、保存、已落盘、完成、已回退或 Fatal）、刷怪器的计划 / 批次 / 名额计数和存档提交序号定位重置进度。

长期回归放在现有 `WorldMapStateTests`、`SaveSerializerTests` 和 `WorldMapPlayModeTests`，覆盖代次迁移、确定性随机、成功重置、失败回退、继续游戏、传送门确认及重复重置生命周期。阶段实际执行结果见[0.6.4 验收](../plan/archive/0.6.4/acceptance/behavior/README.md)。
