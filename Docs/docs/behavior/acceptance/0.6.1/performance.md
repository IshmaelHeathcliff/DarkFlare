# 普通怪物 Player 性能

Unity 6000.6.0f1，Windows Development Player，1920×1080；AMD Ryzen 7 PRO 8845HS / Radeon 780M。关闭垂直同步、不限帧，测量时关闭 Editor 自动 Tick。原始结果见 [performance.json](performance.json)。

## 测量方法

本阶段的验收目标已按用户最新要求调整为常规 300、压力 600 单位；总帧 P95 目标分别为 16.7 / 33.3 ms，导航子预算为 2 / 3 ms。本次已完成的实测使用更高的 500 / 1000 单位规模，保留原始计数和原定预算来证明它覆盖新目标，不伪称执行了 300 / 600 单位采样。

500 / 1000 个正式怪物各测诊断关闭、开启两组，每组三轮；每轮预热 10 秒、采样 60 秒。60 秒按顺序拆成休眠、集中唤醒、密集闲逛、追逐、攻击中断五个 12 秒片段，分别计算 P50 / P95 / P99 / 最大值，并非每种状态各采样 60 秒。活动数量排除片段转换的前 0.5 秒，以实际 HFSM 状态检查。

使用正式三种怪物、HFSM / BT、Animator 桥、物理与导航。导航模式由各怪物正式配置决定。为让整个种群持续参与，临时内存配置扩大激活范围至 100 / 110 米、视距 100 米、视角 360°；闲逛片段缩短视距至 0.1 米并清除目标记忆，攻击中断片段将攻击半径扩大至 60 米，周期性中断已进入前摇的动作。玩家关闭操作与物理模拟并提高生命，按固定轨迹移动。以上仅用于受控压力，未写入正式配置，不能代表默认平衡下的玩家战斗体验。

开启诊断组对每个实例持有 Core 诊断租约，同时打开实际 Player 只读面板；关闭组不持有这些租约。保存、截图与构建不在采样区间执行。

MapTick、Perception、Decision、Presentation 使用 ProfilerRecorder；导航使用既有独立计时。表现标记只包含有效事件的 Animator 参数应用，不包含 Animator 系统全部成本。计时范围存在包含关系，各项分位数不能相加。全帧值包含实际场景、UI、战斗日志和采集开销。

## 发现与修正

[修正前记录](performance-before-routing.json)显示 1000 实例开启诊断时，集中攻击中断片段 P95 41.52 ms，超过 33.3 ms 目标。原动画桥全体订阅表现事件，且每次发布 / 控制线性查找句柄；大量同时动作产生平方级分发。

改为按 BehaviorHandle 索引注册项、按实例订阅 QFramework EasyEvent。少量全局观察者接口继续保留。新增长期回归验证订阅隔离、停止通知、注销后旧句柄及替代实例隔离，完整回归后重建 Player，再重跑全部矩阵。

[分发修正后的首轮矩阵](performance-before-navigation-burst.json)总帧通过，但 1000 单位导航最高 P95 为 3.37 ms，未满足 3 ms 子预算，不能据此封板。继续调整正式运行逻辑：登记行为实例时准备路径缓冲，模式切换保留缓冲；无目标时不采样移动属性；普通通行格直接返回节点，受阻邻域查询和近目标线段检查通过 Burst 执行；路径未就绪时不查询移动许可；转向完成后再提交下批搜索，避免争用工作线程。移动时仍按当前真实形状、行动许可与同源几何检查。中间未通过轮次保留为 `performance-before-*.json`，不替换为成功数据。

## 分配与容量边界

GC.Alloc 记录的是分配事件次数，不是字节。导航采样有 512 B 正向探针；路径缓冲在登记时分配并复用，登记与搜索池首次准备不属于稳态零分配承诺。本次不宣称正式场景或导航动态全过程零分配。采集器读取最后一个导航 Tick，单帧多次 FixedUpdate 时可能漏计，事件总数是观察值。

原生容量使用导航实际计数，不是进程总内存。搜索池峰值、实际活动数、前摇中断次数和标记有效性均随每轮记录，不能用休眠数量代替活动压力。生命周期释放和跨进程继续另见 [综合验收](README.md)。
