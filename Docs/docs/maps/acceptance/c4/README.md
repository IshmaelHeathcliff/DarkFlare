## 256×256 压力

Unity 6000.6.0f1 Editor，AMD Ryzen 7 PRO 8845HS / 16 逻辑线程、Radeon 780M、30503 MiB 内存。固定 seed=19260817，规范源 725512 字节、66049 个显示格。源编译 293.80 ms，单格修改后的源编译 236.32 ms，均不计入下表。

每轮新建 Session，依次冷构建、相同不可变快照热构建、修改 (31,31) 后构建；三轮完整记录见 [performance.json](./performance.json)，汇总见 [performance-summary.json](./performance-summary.json)。冷指新预览会话，持久地表资产在计时前已经加载。

| 操作 | 构建中位数 ms（最小–最大） | 比较中位数 ms | 求解中位数 ms | 重算显示格 |
| --- | --- | --- | --- | --- |
| 冷 | 972.68（796.97–985.29） | 0.711 | 206.314 | 66049 |
| 热，相同快照 | 785.14（737.23–876.97） | 0.006 | 0.0003 | 0 |
| 单格修改 | 937.70（846.91–966.05） | 133.654 | 1.235 | 4 |

构建耗时包括正式源 / 产物修订校验、异步调度、规则解析和完整 Tilemap 填充发布。热构建仍校验产物并完整提交新帧；单格修改仍比较地图数据。未将重算 4 格描述为整个显示链路 O(1)，也不直接与 B4 的诊断资源路径作性能等价比较。

恢复后首次 Render 调用 215.94 ms，后八次 1.80–5.35 ms；这是 Editor CPU 调用用时，不是 GPU 帧时或玩家帧率。[压力全图](./stress-1920.png)在最终回归完成后重新采集；上表全部采用恢复后的三轮完整测量。采集器的内存采样和异步轮询也有开销，不能当作无采集器的性能预算。

已加载 Tile / Sprite / Texture 的 Unity 内存合计 **8,569,040 字节（8.17 MiB）**，不含 Editor 源纹理、目录、RT 和托管快照。构建期间按异步 continuation 采样整个 Editor 已分配内存，相对起点峰值增量 0–70,446,123 字节；它包含其他 Editor 工作、受 GC 影响且遗漏瞬时峰值，0 不表示没有分配。原始记录同时保留绝对值和托管前后值。

每轮关闭后，自建 `Map diagnostic` 对象从 0 回到 0，Preview Scene 从既有基线 1 回到 1；持久材质不销毁。首次采集发生过原生崩溃，根因未确认，见[故障与恢复记录](./collection-incident.md)；恢复后的采集增加主线程检查，全部步骤记录 thread=1，三轮完成无再次崩溃。

## 取消、测试与边界

两次均在新 Tilemap 已填充 `(-1,-1)+(257,4)` 后操作。取消调用 **0.171 ms**，旧帧保留且标记过期；Dispose 调用 **0.234 ms**，旧帧与构建帧均释放。等待完成并额外观察 100 ms 后无迟到发布，诊断资源数 0，全部持久 Tile / Sprite / Texture 存活。见 [cancel.json](./cancel.json)。数字不包含点击输入延迟。

长期补充 `TerrainTextureBuildTests.FormalPopulation_CancelAndDisposeReleaseFramesButKeepPersistentTiles`，保护正式资源在构建中取消 / 关闭的生命周期；使用本会话构建帧而非全局窗口数量，并以真实时间等待异步线程结果，避免 Editor 快速测试 tick 带来的误判。已有地图、分区、编译、发布失败回退与资源共享测试保留。一次性截图、压力和审计脚本在采集后删除，不把历史证据变成运行测试。
