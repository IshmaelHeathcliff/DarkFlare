## 256×256 测量

Unity 6000.6.0f1 Editor；AMD Ryzen 7 PRO 8845HS，16 逻辑处理器，AMD Radeon 780M，系统内存 30503 MiB。相同 seed=19260817、规范源 725558 字节、66049 个显示格。第一次源编译 205.58 ms，修改后源编译 166.46 ms；下表不含这两次编译。

每轮新建预览 Session，依次冷构建、相同不可变快照热构建、修改逻辑格 (31,31) 后构建；三轮。冷指预览缓存为空，非 Editor 进程冷启动。构建计时包括异步调度、求解、资源生成与完整 Tilemap 发布，首次 1920×1080 渲染另计。[全部原始记录](./performance.json)。

| --- | --- | --- | --- | --- |
| 冷 | 942.10（931.71–948.56） | 0.653 | 74.016 | 66049 |

首次渲染 1.11–4.23 ms。稳定帧共享 260 份 Texture / Sprite / Tile 资源组合；按 `Map diagnostic` 名称汇总的 Unity 自有对象内存为 40171060 字节（38.31 MiB），不含未采用该名称的 PreviewRenderUtility 目标 RT、托管 DTO / 数组。

内存峰值通过每次异步 Editor continuation 采样 `Profiler.GetTotalAllocatedMemoryLong`；相对操作起点的最大增量范围 57.51–524.04 MiB，包含整个 Editor 的分配，不能全部归因于预览，且遗漏采样间瞬时峰值。原始记录同时保留绝对采样峰值和托管前后值；源编译不在该区间。每轮会话销毁后，自有诊断对象最终计数为 0。

热点边界：热构建和局部修改仍完整创建并填充新的 Tilemap，只有规则求解与 Tile 资源复用是增量；不将 4 格重算描述为整个渲染链路 O(1)。这些是本机 Editor 观测，不代表 Player 帧率或后续怪物导航性能预算。

## 取消与回归

从拓扑旧帧切换压力图，在新 Tilemap 已填充范围 `(-1,-1)+(257,62)` 时调用窗口“取消构建”的实际处理方法。同步取消调用耗时 1.79 ms；100 ms 后检查旧帧仍为同一对象、IsValid=false、IsBuilding=false，资源数从 63 回到 63，无迟到替换；关闭窗口后自有诊断对象为 0。该数字不包含物理点击输入延迟。见[取消记录](./cancel.json)和[过期画面截图](./stress-cancel-window.png)。

最终项目完整 EditMode 650/650、PlayMode 75/75 通过；工具附带运行包测试后总结果为 EditMode 651 通过（含 Addressables 文档示例 1 项），PlayMode 77 通过、2 跳过（含 Input System 2 通过，另 2 项包内按问题 1252825 标记不稳定而跳过），失败为 0。内容校验 0 问题、配置文档覆盖通过。保留既有取消、关闭、失败恢复、真实源导入刷新等行为测试，不保留一次性截图 / 性能采集脚本。未构建 Windows Player；运行版本保持 `0.4.2-alpha`，core v5、SaveSchema 3。
