# alpha 0.3：统一物品操作与菜单交接合同

> 状态：待实施、待运行时验证；本文不代表问题已经修复
> 更新日期：2026-09-07
> 上位计划：[alpha 0.3](./alpha-0.3-plan.md)、[首阶段](./alpha-0.3.0-independent-ui-windows-plan.md)

## 首先修复菜单交接

用户反馈：打开设置或返回主菜单确认时背包没有关闭；手动关闭背包后，上层界面无法交互。

静态检查发现 `GameMenuController.OnSettingsClicked` / `OnReturnFrontEndClicked` 直接调用 Application Shell，没有隐藏背包或明确移交输入；`OnCloseClicked` 直接调用 `SwitchToGameplay`。Shell 的设置 / 确认显示路径没有在这些入口取得独立的 UI 输入所有权。这条链路与反馈吻合，但仍需运行时核对 UIDocument 层级、命中阻挡和实际 Action Map，不能把静态分析当作已复现。

修复合同：

- 应用上层先接管 UI 输入与暂停，再取消拖动、释放 Pointer Capture、隐藏物品详情及全部玩法窗口；设置 / 确认显示时背包不可见、不可命中、不可被导航。
- 玩法窗口记录可恢复的组合、物品 ID 与有效焦点；设置返回或确认取消后恢复。确认返回主菜单成功则丢弃旧记录，保存 / 场景流失败时错误界面继续可操作，Session 保持现有事务语义。
- 关闭底层窗口只释放自己的所有权；只要 Settings / Modal 仍存在，就不能切换为 Gameplay 或恢复战斗。
- 一次 Esc / 手柄返回只处理最上层；打开和关闭按钮、导航提交都遵循相同路由，避免同帧级联关闭。
- 现有 `ApplicationInputService` 有 `SwitchContext` 与 suspension，但 suspension 禁用输入，不能替代可交互上层的上下文所有权。实现时复用唯一服务入口，按实际需要补充所有权协调，不另建 Input Actions / EventSystem。

首个回归必须覆盖“背包 → 设置 → 修改设置 → 返回”和“背包 → 返回主菜单确认 → 取消 / 确认”，并检查强制关闭底层窗口、连续点击、手柄返回、失败 Modal 及恢复后的移动与暂停状态。

## 操作矩阵

各输入入口提交同一语义意图，使用同一预检、Command 和反馈。落点在释放前显示动作名称、有效性及必要价格；悬停本身不移动物品、不扣费。

| 操作 | 鼠标拖动 | 右键快捷入口 | 手柄等价操作 |
| --- | --- | --- | --- |
| 背包移动 / 交换 | 拖到指定格；保留真实占格和已有单目标交换规则 | 不改变物品通常的上下文动作 | 拿起、导航到指定格、放置；返回取消 |
| 装备 | 背包物品拖到兼容装备槽 | 普通背包右键装备；戒指无明确目标时先选择左 / 右槽 | 快捷装备或拿起后选择兼容槽；戒指明确选槽 |
| 卸下 | 装备槽拖到背包指定格 | 装备物品右键卸下，自动寻找合法空位 | 快捷卸下，或拿起后指定背包格 |
| 丢弃 | 背包物品拖到明确标注的丢弃区，释放后生成世界拾取物 | 物品快捷菜单中的明确“丢弃”动作 | 物品动作菜单选择丢弃，或拿起后导航到丢弃区 |
| 买入 | 商人物品拖入背包指定格；商店单窗提供明确买入区以自动放置 | 商人物品右键买入，自动寻找合法空位 | 快捷买入，或拿起后指定背包格 / 买入区 |
| 卖出 | 玩家物品拖入商店明确出售区，显示售价 | 商店有效上下文中的玩家物品右键卖出 | 快捷卖出，或拿起后导航到出售区 |
| 放入打造台 | 背包物品拖入目标槽；单窗候选视图同样支持 | 打造上下文的可用候选右键放入 | 快捷放入，或拿起后导航到打造槽 |
| 取出打造台 | 打造槽拖回背包指定格，或单窗明确取回区 | 打造槽物品右键取回原格 | 快捷取回，或拿起后选择背包位置 / 取回区 |

- 丢弃区是明确 UI 目标；任意窗口背景、HUD、屏幕外及非法落点均取消，不把“拖出背包”一律解释为丢弃。丢弃后可重新拾取，不等同于永久删除。
- 右键默认动作由来源与当前有效上下文决定：商人库存买入、装备槽卸下、打造槽取回、商店玩家来源卖出、打造候选放入、普通背包装备。动作名和可用性持续可见；有歧义时显示动作菜单，不靠隐藏窗口推断。
- 手柄使用焦点导航、拿起 / 放置及动作菜单，不要求模拟鼠标。沿用现有 Submit、Cancel、Item Move 与 Glyph；新增快捷动作前检查绑定、重绑定及输入冲突。
- 装备中或打造槽中的物品先卸下 / 取回再出售或丢弃，避免隐藏跨归属动作。非法快捷操作显示本地化原因，不静默换成另一种操作。

## 手柄空间导航

本项在首阶段实现，收尾十槽扩展时完整回归。当前 `InventoryPanelController.RequestBoundaryNavigation` 只补充部分向右越界路径，不能作为完整四向导航合同。

- 用已完成布局的屏幕坐标矩形选择目标，不按资产顺序、列表索引、UXML 子节点顺序或固定四槽数组跳转。上下左右分别限定对应方向候选。
- 优先选择与当前物品横向 / 纵向投影重叠、方向距离较近的目标；无同行 / 同列候选时，再选方向偏差较小的邻近目标。按边界计算距离，兼顾 1×1、2×2、2×3 物品，不能只比较中心点而跳过贴邻物品；同分用稳定规则打破，不随刷新抖动。
- 浏览时一件多格物品是一个导航目标，连续方向输入不会在同件物品的内部格上空转。空装备槽、空打造槽和必要动作区仍可聚焦；普通背包空格不冒充可选物品。
- 拿起 / 放置时背包按格导航，允许精确落到空位；跨面板进入装备槽、买入 / 出售区、打造槽及丢弃区时沿用视觉方向。目标无效显示原因而不提交，不把浏览的“跳过空格”规则套到放置模式。
- 当该方向没有更近的本面板目标、已到达边缘时，将相邻可见窗口纳入候选，保持原行 / 列的空间接近关系。背包向右到商店后向左应能自然回到邻近背包物品，不能每次回到第一个物品或标题按钮。
- 同时只对可见、授权、未被应用上层阻断的窗口建立导航关系；方向移动不打开隐藏商店 / 打造窗口。无该方向目标时保留当前位置，不自动绕到相反边。
- 空背包、售空商店和空打造台也有明确的区域入口 / 有效控件，能够继续跨区移动；同方向的跨面板移动不能被无操作价值的装饰或隐藏按钮截走。
- 普通手柄导航同时更新活动窗口、当前物品和唯一高亮 / 详情；每窗记忆的旧选择不得抵消按空间选中的入口。拿起状态则以唯一搬运物品和落点提示区分，不新增第二件物品高亮。
- 一次方向输入只交给一个导航处理者；主动接管后阻止 UI Toolkit 默认导航再次移动。按住方向沿用统一重复节奏，摇杆斜向输入确定主轴并防止抖动，不用多个 Controller 叠加重复计时。
- 窗口开关、语言切换、交易 / 打造刷新、装备变化和布局完成后更新导航关系；焦点物品消失时优先保留同实例，否则按原视觉位置选择有效邻居。布局尚未有效时不读取零矩形，不允许旧异步回调覆盖新 Session 焦点。

验收用实际物品排列标记起点与四向预期终点，覆盖同列邻居、斜向备选、不等高窗口、不同物品尺寸、稀疏 / 满 / 空网格、十装备槽及双向跨窗口。D-pad 与摇杆均测试单步和长按，记录真实焦点、唯一高亮与屏幕位置；不能仅以“所有控件都能访问”代替方向正确。

## 原子性与生命周期

- 一次操作绑定 Session 代次、物品实例 ID、精确来源、动作和目标。释放 / 提交时重新验证所有权、窗口权限、库存、金币、容量及目标槽兼容性。
- 背包移动、装备和交换沿用已验证事务。当前购买调用 `TryAddItem` 自动找位，指定格购买必须补齐事务入口，不能先付款购买再尝试移动；精确格无效时不能擅自改为其他格。
- 出售仅在明确落点或快捷提交后执行；禁止拖动开始即移除来源。快速点击、拖动释放与同帧右键 / Submit 不能对同一意图重复结算。
- 打造目标仍属于背包并占原格；取回原格只解除表现占用。取到新格时先验证移动成功再解除占用，失败保留原槽；放入新目标时旧目标在成功提交后恢复显示。
- 丢弃新增背包到世界的转移事务，保留原 ItemInstance ID、词缀和种子，为世界拾取物分配 WorldDropId；不重新生成装备、不推进怪物掉落随机序列。
- 世界拾取物准备失败、位置非法或 Session 已结束时，背包必须保持原样；提交后存档快照中该物品只能归属于世界或背包之一。世界对象纳入现有 SessionObjectRegistry 和资源生命周期。
- 当前拾取依靠 `OnTriggerEnter2D`；丢弃必须防止玩家原地立即自动拾回。优先放到可达且不与玩家拾取范围重叠的位置；无法满足时需要明确的离开范围后重新进入拾取规则，并覆盖保存 / 继续，不能仅靠短计时掩盖。
- 来源 / 目标关闭、失去权限、焦点离开应用、设备断开或 Session 切换时取消未提交操作，清理图标、捕获和待执行回调。失败恢复来源和有效焦点，金币、物品和打造结果不变。

## 唯一高亮与详情排版

- 全部物品窗口共用一个活动物品来源；各窗可以记忆选择，但非活动窗口不得保留同级选中描边。稀有度装饰与操作高亮使用不同语义。
- 鼠标实际移动 / 点击和手柄实际导航切换预览所有者；静止鼠标不能在手柄导航后重新抢走高亮。显示设备 Glyph 与当前操作相符。
- 拖动中只强调当前搬运物品，来源使用弱化占位，合法目标使用区域 / 槽位边界提示；不能把待交换的另一件物品也画成选中。取消、成交及刷新后一次性切换来源。
- 同一物品可能在背包和商店玩家视图出现，但只有一个视图实例可以高亮。商人、装备、打造目标及候选列表也纳入同一规则。
- 共享详情只有一个实例，按活动来源定位，拖动时隐藏；完成 / 取消后遵循重新主动预览规则，旧异步回调不能复活失效物品提示。
- 详情按名称、类型 / 稀有度、基础属性、隐式 / 前后缀、价格 / 操作提示分组；统一标签与数值对齐、内边距和段落间隔。名称和长效果文本允许换行，不靠裁切或省略号隐藏关键信息。
- 先在 1920×1080 线框中为最高词条容量和三种 Locale 预留实际文字空间，再确定最终尺寸；不继续假设固定 360×680 足够，不以极小字号解决溢出。
- 单窗和组合窗口共用标题、内容起点及操作栏对齐规则；详情与来源窗口合理对齐且留在安全区，边框不侵入文字。数据、语言和焦点刷新不造成面板跳位或重叠。
- 物品详情与拖动图标输入穿透，不能覆盖关闭按钮、操作目标或应用上层。交互正确和排版通过后再应用最终边框 / 背景皮肤。

## 必须留下的验收证据

| 范围 | 必测场景 | 成功判据 |
| --- | --- | --- |
| 菜单交接 | 设置修改与返回、返回主菜单取消与确认、底层关闭、同帧返回、失败提示 | 背包按合同隐藏；上层可点击 / 导航 / 提交；输入和暂停由有效所有者决定 |
| 操作完整性 | 矩阵全部动作的拖动、适用右键和手柄路径；单窗及背包组合 | 相同意图结果一致；精确落格准确，反馈明确 |
| 失败 / 取消 | 满包、缺金币、售空、不兼容槽、多物品重叠、目标失效、切窗及拖动中断 | 不丢物、不重复、不扣错钱；可立即继续操作 |
| 世界丢弃 | 生成失败、成功丢弃、重新拾取、保存继续、返回前台再进入 | 实例与词缀保持，归属唯一，不原地自动拾回 |
| 高亮与焦点 | 跨商人 / 玩家 / 装备 / 打造切换，鼠标与手柄交替、交易刷新、重开窗口 | 渲染上最多一个物品高亮；无隐藏焦点及失效详情 |
| 空间导航 | 四向邻居、不规则物品、十槽、空面板、边缘双向跨窗、拿起放置、D-pad / 摇杆单步与长按 | 目标与屏幕方向一致，无索引跳转、双步、循环陷阱；跨窗后可沿相反方向自然返回 |
| 详情与对齐 | 中文、英文、Pseudo Locale；最长物品名、六条显式词缀、长数值、屏幕边缘及组合窗口 | 真实文字测量与截图均无超框、截字、遮挡、错位 |
| 生命周期 | 三轮 Session 往返、暂停菜单反复开关、设备切换 | 无事件 / 任务 / 资源累积，正常路径 Console 零新增错误或警告 |

领域核心写原子性与唯一归属测试；PlayMode 使用真实输入事件验证交接和操作，布局结合边界测量与截图检查，不能只验证 UXML 类名或源码字符串。测试使用隔离存储，不读写玩家正式存档。完成后将实际行为同步到模块文档，并随首阶段归档本合同。
