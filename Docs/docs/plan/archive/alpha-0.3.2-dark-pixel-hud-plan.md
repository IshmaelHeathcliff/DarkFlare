## 目标与边界

将顶部资源卡改为底部战斗仪表：生命偏左、法力偏右，中间显示已有自动攻击技能状态和常用窗口入口。玩家无需打开属性窗口即可了解资源、冷却和无法施放的原因；打开功能窗口后保持既有独立窗口、暂停和物品交互合同。

本阶段交付正式 HUD 组件，不以线框作为最终美术。沿用暗石 / 炭黑内底、旧铁框、少量金铜装饰，生命红、法力蓝、暖色正文。全套按钮 / 物品槽 / 浮窗 / Shell 皮肤仍属 0.3.3；十槽装备及配套内容属 0.3.4。不新增技能切换、药水、经验、地图、模拟 DPS 或伤害公式，不修改经济与存档结构。

## 已核对的实现基线

| 入口 | 当前行为 | 本阶段处理 |
| --- | --- | --- |
| `HUD.uxml` / `HUD.uss` | 顶部生命 / 法力 ProgressBar、金币卡，底部交互提示 | 改为底部双仪表、技能区和入口；保持数值文本独立于图片 |
| `HudController` | 资源 / 金币 / 装备事件刷新；技能提示仅记忆最近一次法力不足，成功攻击后清除 | 用当前只读状态驱动持续显示，解决资源恢复后提示仍滞留等问题 |
| `GetHudSnapshotQuery` | 每次构造资源、金币及完整属性数组，背包也使用该快照 | 冷却刷新不反复生成完整属性数组；保留既有调用兼容，只抽取必要公共状态 |
| `GetAttributeRuntimeQuery` / `PlayerSkillStateRegistry` | 已有资源、恢复、暂停 / 死亡 / 无来源 / 法力不足 / 冷却状态；技能读取器归属 Session | 复用技能读取与状态判定，必要时提取按玩法语义命名的共享 Query / 值对象，不复制条件链 |
| `GameMenuController` | 持有 HUD 暂停 / 属性入口；窗口或 Shell 阻挡时隐藏这两个按钮 | 迁移到 HUD 入口区并补齐背包入口，沿用同一菜单状态与所有权 |
| `InteractionPromptController` | 世界目标、输入模式、绑定 / 设备和 Locale 变化刷新 | 调整提示位置与底板，保留真实交互目标与 Glyph 来源 |
| `AccessibilityService` | ReduceMotion 通过 MotionProfile 即时广播 | 新 HUD 动效接入同一 Profile，解绑时取消并复位 |

当前完整回归为 EditMode 432/432、PlayMode 62/62，是 0.3.1 历史证据；本次规划不运行 Unity 测试，也不据此宣称 0.3.2 已通过。

## 信息与状态合同

| 区域 | 必须呈现 | 边界 |
| --- | --- | --- |
| 生命 | 当前 / 最大值、准确填充比例、低生命与死亡状态 | 空角色显示等待；零上限不除零；生命变化即时提交真实值 |
| 法力 | 当前 / 最大值、准确填充比例、恢复与不足状态 | 耗蓝与资源值取正式消费者；暂停不假装继续恢复 |
| 自动攻击 | 技能名称、耗蓝、施放间隔、剩余间隔及冷却比例 | 使用现有技能与时钟，不推进攻击、不消费随机数；间隔为零时明确视为无冷却 |
| 受阻原因 | 无有效来源、法力不足、死亡 / 禁用、暂停、等待角色 | 复用共享状态优先级；“就绪”只表示资源 / 冷却条件满足，不声称存在目标或必定施放 |
| 金币 | 当前数量与清晰图标 | 轻量显示，长数字可容纳，不重复占用大型顶部卡片 |
| 窗口入口 | 背包、属性、暂停 | 真实打开对应窗口，不增加无消费者的装饰按钮 |
| 世界交互 | 当前对象、操作和真实绑定提示 | 位于仪表上方；目标无效、UI 模式或上层接管时隐藏 |

低生命默认以有效最大生命的 25% 为表现阈值，集中定义并覆盖跨阈值恢复；只影响样式，不影响玩法。低资源和受阻提示同时使用文字 / 形状，不能只靠颜色区分。持续原因随当前资源和装备状态消失，不依赖再次成功攻击来清除；历史拒绝事件不得覆盖已经恢复的实时状态。

## 布局与双输入

1. 正式验收画布沿用 1920×1080。优先在现有底部约 160 px 安全区内安排仪表，世界交互提示置于其上方。先用真实三语言文本验证线框，再冻结仪表形状、内容矩形和图片规格；圆形或切角容器由实际可读性与填充验证决定。
2. 保持背包 560、商店 / 打造 760、属性 440 px 与现有网格尺寸。验证单窗、双窗及背包 + 商店 / 打造 + 属性三窗；长操作栏、六词条浮窗不能与 HUD 的可交互入口重叠。不能靠压缩网格或文字来腾出空间。
3. Gameplay 显示完整战斗 HUD。功能窗口打开时资源 / 技能摘要可保留在安全区，但 HUD 入口与世界提示退出点击和导航；暂停及 Shell 接管时 HUD 不抢焦点。返回 Gameplay 后立即恢复最新值与可用入口。
4. 鼠标入口直接调用既有菜单路由；键盘 / 手柄沿用背包与暂停 Input Actions，属性经现有菜单页签或背包标题栏到达。绑定提示使用 ApplicationInputService 实际绑定与设备 Glyph，不虚构属性快捷键；不新增会抢占移动方向输入的 Gameplay HUD 导航模式。
5. 进入 UI 后仍按视觉矩形导航，Esc / 返回一次只消费一层。HUD 装饰、资源填充、数字与技能读数不参与物品选择、拖放目标和焦点遍历；根容器不因底板扩大而吞掉世界输入。
6. 中英与伪本地化检查名称、数值、受阻说明、绑定提示、交互对象名称。优先调整分区宽度与换行，不将关键信息压成省略号或覆盖条内数字。

## 刷新、动画与生命周期

- Controller 只通过 Query 读取、通过已有菜单入口提交意图并订阅事件。资源、金币、装备、Actor 身份 / 生死变化立即更新对应区域；Locale / 设备变化只更新文本和 Glyph。
- 技能动态区使用有 Scene / Session 所有者的低频 UniTask（初始目标 100 ms）；不每帧重建 VisualTree、不轮询 PlayerController、不反复执行完整属性解释。纯显示插值不修改真实冷却或资源。
- 真实数字和主填充及时反映最新值；若添加受击余量或过渡，作为独立的次级表现，不能让玩家误读当前生命。PrimeTween 句柄与刷新任务均在隐藏 / 解绑 / Session 结束时终止，重新进入不残留旧角色状态。
- Reduce Motion 开启后立即停止非必要脉冲、晃动、延迟填充并回到真实值，保留静态轮廓和文本反馈；关闭设置后按当前状态恢复表现。游戏暂停 / 平台挂起时冷却与游戏资源冻结，不使用现实时间伪造推进。
- NewGame / Continue、返回前台后重新进入、禁用再启用覆盖事件解绑、计时取消和动画清理；不新增裸 CancellationTokenSource 或无归属 Forget。

## 美术生产与接入

按[美术资产规范](../../visual-asset-generation.md)及项目 `unity-2d-sprite-workflow` 执行。正式生成前阅读该 Skill 的资产合同说明，记录参考、固定画布、可见边界 / 留白、视觉中心、PPU / Pivot、运行尺寸、Border 和受保护装饰区域。

- 先审查已有正式底板、图标与保留的风格参考，只补 HUD 实际缺少的仪表框 / 内底 / 填充或提示组件，不顺带生成整套 UI 皮肤。
- 先制作并验证一个资源仪表 Pilot，再派生另一资源及必要状态。每个 PNG 只包含一个组件或状态，文字、数值、技能名和 Glyph 由 UI 绘制；不制作生产组件拼图，不手工切图。
- 分别验证 0%、低值、50%、100% 的填充和边框。圆形方案必须证明填充裁切不越界，不能用非等比拉伸模拟比例；九宫格不能切入独特角件。无法满足合同的图片重新生成，不逐图裁切或调整 Transform 补救。
- 每张图先运行自动审计，再导入 Sprite Single；按家族合同使用 Point、无压缩 / Mipmap、正确 Alpha 与 Pivot。保留不可变 Pilot、manifest、生成记录和运行时截图，核对引用无缺失。
- UI 创建、布局与绑定通过 Unity MCP / Editor API 完成；需要时先尝试启动 MCP。不得直接编辑 Editor 已打开的场景文件。现有 UIDocument、EventSystem 与资源所有权保持一致，动态加载沿用 Addressables。
