# Alpha 0.6.4：刷怪地图手动重置执行计划

状态：2026-09-23，**R1–R6 已完成并归档**。交付 `0.6.4-alpha`、地图 V4、core v10、Schema 9；正式野外图每实例有 100 个普通怪物名额（入图 20 个、10 个分散触发点各 8 个），守卫 Boss 独立。上位[总计划](alpha-0.6-plan.md)、[刷怪与重置合同](alpha-0.6/spawning-and-reset.md)、[手动重置模块](../../behavior/map-reset.md)。

## 目标与边界

玩家正常离开刷怪地图或继续游戏时，怪物、Boss、掉落和触发进度原样保留。玩家显式重置后，目标地图开启一个新实例：固定名额、入图批次、范围触发批次和 Boss 均按新代次重新准备；不自动重置，不击杀补怪。首版仅处理**非活动中的刷怪地图**，不增加费用、次数限制或定时刷新；城镇、无刷怪图和正在切换的地图不可重置。玩家背包、装备、金币、状态、商人、其他地图及全局身份序号保持原有语义。

城镇传送门提供“进入”和“重置并进入”，后者须二次确认，说明目标图未拾取掉落会清除。玩家已明确“离开保留状态、手动重置后刷新”。

成功标准：一次确认最多推进一个地图实例代次；成功反馈出现时新状态已持久化；准备、取消或明确的保存失败后旧图及其存档仍可进入；崩溃或退出按持久化提交点只恢复旧代次或新代次，不产生混合状态。

## 当前实现与必须补齐的接缝

- `WorldMapRuntime.ChangeAsync` 目前能在切图提交前回滚，却在提交后释放旧图；它从 `_frozen` 选择目标状态，不支持外部候选新实例及“先装配、持久化、再最终释放”的重置事务。
- `SceneFlowService.ChangeMapAsync` 与 `SessionSaveFacade.SaveAutoAsync` 是独立入口；保存协调器从当前 Session 捕获快照，当前没有排他候选提交接口。不能把现有的普通切图加一次自动保存就称作原子重置。
- 活动图由 `RunSaveData` 保存，冻结图由 `MapStateDto` 保存；两处均无实例代次。布局 `Revision` 和 MapScope `Generation` 分别表示地图内容与内存装配，不能代替代次。
- 传送门交互由 `OpenGameMenuCommand` 直接发起切图；Application Shell 已有确认、Busy 和结果反馈能力，但尚无传送门双操作入口。

## 执行切片

| 切片 | 工作与完成条件 |
| --- | --- |
| R1 合同与入口 | 冻结可重置地图资格、掉落清理、确认文案和失败反馈；明确传送门的普通进入与重置进入两条操作，键鼠和手柄均可选中、确认、取消；梳理暂停、输入、拖放和打造事务的门禁。完成条件：取消不触发切图或存档变化，普通进入仍沿用现有保留规则。 |
| R2 代次与迁移 | 为活动图及冻结图增加持久化 `InstanceEpoch`，与布局修订和作用域 generation 分离；新图为 0，成功重置才递增。新随机流从运行种子、MapId、代次确定性派生，同一失败重试不重新掷候选；新实例仍严格采用 20＋80 名额和独立 Boss。更新快照、恢复、验证、旧 Schema 迁移及地图随机状态。完成条件：旧 Schema 8 与更早存档默认代次 0，读档不刷新已访问图；`LegacyPreserved` 仅在成功重置后转为有限计划。 |
| R3 候选与事务 | 在旧冻结状态仍完整存在时，预检新实例名额、Boss 点位、出生区域、资源、容量与入口，创建候选；用地图作用域和存档协调器的排他门禁阻止并发切图、自动保存、退出刷新与重复重置。扩展既有地图切换链为可暂存、可回退、可最终提交的路径，不另建存档文件。完成条件：仅目标图的状态和独占掉落物品引用被替换，其他图与玩家资产不变。 |
| R4 持久化提交 | 在新图暂存、旧图尚可回退时捕获**完整世界快照**并经既有 SaveCoordinator 写入；收到可确认的落盘成功回执后才发布成功并释放旧图。落盘前失败或取消恢复旧图、旧冻结状态和输入；落盘后清理异常进入现有 Fatal 路径，不能谎报取消或回滚。若写入结果不确定，先核实提交序号或最新存档，无法判定则停止继续操作并报 Fatal，不盲目回滚。完成条件：进程在提交前后中断分别恢复旧、新完整世界，绝无新名额搭配旧掉落。 |
| R5 交互与诊断 | 传送门显示两个操作，重置确认明确怪物、Boss、触发进度和掉落清理；Busy 阶段阻断重复输入，错误反馈区分准备失败、存档失败与已提交后的故障。调试信息可查看目标图代次、名额、触发批次和重置事务阶段；本地化中文、英文与伪本地化。完成条件：鼠标、键盘、手柄路径都能到达并返回游戏焦点，不产生额外切图请求。 |
| R6 验收与文档 | 扩展地图、存档及交互已有测试，验证提交边界、历史档、玩家数据隔离和资源生命周期；更新模块文档、存档合同及验收记录，审查并清理一次性测试，最后归档本计划。完成条件见下方矩阵；未实测项如实记录。 |

R2–R4 先完成纯数据和事务合同，再接 R5 的可见入口。`InstanceEpoch` 溢出、配置不兼容或容量超限时明确拒绝，不截断计划；身份分配器不得回退已发布身份，失败准备中未发布的身份可留下序号空洞。重置清理的物品仅限目标图未拾取掉落独占引用，全档物品去重与归属校验继续作为提交前门禁。新代次发布后，旧地图 generation、旧触发任务与旧 Boss 回调不得再提交结果。

## 事务判定与故障矩阵

| 场景 | 预期 |
| --- | --- |
| 取消确认、非法目标、同图、重复请求或忙碌状态 | 不创建新代次、不改目标图和存档；显示可理解的结果。 |
| 资源、几何、容量或入口预检失败 | 旧图与旧掉落保留，候选释放；可正常选择普通进入。 |
| 目标装配、切换或写盘前取消 / 失败 | 回滚到原活动图、原冻结图和旧代次；没有孤立怪物、状态、任务或资源 lease。 |
| 持久化明确失败 | 不发布“重置成功”，恢复旧状态；退出再继续仍是旧代次。 |
| 持久化成功，后续清理失败 | 不回滚已经落盘的新代次；走 Fatal 恢复，重新启动后是完整新实例。 |
| 写盘回执不确定或提交边界进程退出 | 以存档提交序号 / 最新可验证快照判定，不能同时运行旧世界并保留新存档；恢复后只有旧或新完整实例。 |

## 验收范围

1. 新游戏与旧档：正常进入、离开、跨进程继续均不改变代次或补怪；旧 Schema 7 `LegacyPreserved`、Schema 8 有限计划和已有 Boss 进度保持，手动重置后才统一变为新有限实例。
2. 成功重置：目标图重新具有 20 个入图普通名额、10 处各 8 个范围触发名额及独立 Boss；触发点标识保留；击败与未触发状态清零，代次恰好加一，其他图与玩家资产不变。
3. 故障注入：覆盖候选准备、目标装配、存档前、存档失败、提交成功后清理、重复请求和进程恢复；验证活动图、冻结图、掉落与物品引用、身份及随机状态一致。
4. 交互：中文、英文、伪本地化与 1920×1080 基线下的键鼠 / 手柄焦点、确认、取消、Busy 与反馈；连续至少 20 轮切图和重置，检查怪物、状态、导航、任务、事件、Addressables lease 和原生容量收敛。
5. 运行与交付：相关 EditMode / PlayMode 及项目完整回归通过；Windows Player 和 300 常规 / 600 压力规模本阶段未执行，不计作通过，留到 0.6.5 综合交付记录。仅保留有长期价值的事务、迁移、输入和隔离测试，遵守[测试维护规范](../../testing/test-maintenance.md)。
