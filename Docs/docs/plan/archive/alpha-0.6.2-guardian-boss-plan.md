# Alpha 0.6.2：守卫 Boss 执行计划

状态：2026-09-23，**按用户调整的验收门槛结束并归档**。B1–B4 已实现，B5–B6 中可自动验证的内容与两种 Windows 构建完成；用户跳过本阶段 Windows 构建验收，独立 Player、跨进程继续及 300 / 600 性能矩阵未执行，不能视作通过。地图 V3、core v8、Schema 7、正式守卫 Boss 和 `0.6.2-alpha` 已接入。上位[总计划](../alpha-0.6-plan.md)、[行为合同](../alpha-0.6/monster-and-boss.md)、[有限刷怪与重置合同](../alpha-0.6/spawning-and-reset.md)；当前实现见[Boss 模块](../../behavior/boss.md)、[地图生命周期](../../maps/world-map-lifecycle.md)，[验收记录](../../behavior/acceptance/0.6.2/README.md)。

## 目标和完成定义

交付一只正式可遭遇的守卫型 Boss：近距离挥击、可预判并躲避的直线冲锋、低血量时一次性强化。它使用独立地图出生点，复用现有怪物属性、状态、伤害、掉落、导航、行为诊断和 Animator 桥。切图和跨进程继续保留战斗进度；已击杀 Boss 不因返回地图复活。Windows Player 中能完成完整遭遇，验证键鼠和手柄操作。

本阶段**不**改变普通怪物的间隔补满规则。固定普通怪物总量与触发批次属于 0.6.3，显式手动重置属于 0.6.4；0.6.2 先为 Boss 保留独立固定名额及状态。初始平衡值由配置提供，经实际 Player 体验调整，不把建议的 50% 阈值等数值当成已确认设计。

## 已核对的接入边界

- Core 内的 HFSM 与行为树已独立，可复用 `BehaviorSystem` 和 `IBehaviorRuntime`。当前 `MonsterBehaviorMap`、`MonsterController`、攻击 Command 仍具体依赖 `MonsterBehaviorRuntime`，必须加一层狭窄的怪物行为会话合同，才能让 Boss Runtime 接入；不改 Core 为 Boss 专用逻辑。
- `MapScope` 统一驱动行为后再驱动导航。冲锋不能另起速度写入器或直接移动 Transform；由导航持有唯一运动提交，并沿用地图足迹、动态障碍及扫掠许可。普通追逐的 Flow Field / A* 仍按原合同运行。
- 地图 V2 只有玩家入口和普通 Spawn 区域。Boss 点不能借用 `MapEntryKind`，否则可能被传送 API 当成玩家落点；也不能从普通刷怪池随机挑选。
- 当前 Schema 6 的活动图与冻结图均只记录普通怪物列表和间隔刷怪器。Boss 死后从怪物列表消失，必须另有持久化遭遇名额，不能用“列表中没有 Boss”推断它尚未生成。

## 运行合同

| 领域 | 本阶段定案 |
| --- | --- |
| 结构 | `MonsterDefinition` 保留已有普通行为配置供共用感知，并可另引 Boss 行为配置；普通怪物沿用现有配置。Boss Runtime 位于 Runtime 层，以已有 Core HFSM 管生命阶段、行为树编排动作，单实例持有计时、目标与随机序列。地图最多一个正式 Boss 点，城镇可为零。 |
| 决策 | 死亡 / 失活优先级最高；其次为一次性阶段转换、合法冲锋、合法挥击、接敌或等待。视野、失去目标与受控状态复用普通怪物的同源规则和地图时钟；不能透墙跟踪或攻击。 |
| 挥击 | 接纳时锁定方向并启动冷却；预警 → 前摇 → 单次命中窗口 → 后摇。预警扇区与实际角度、半径一致。命中时再次确认目标存活、许可、当前范围 / 遮挡和地图代次；落空也进入后摇。 |
| 冲锋 | 满足距离、视野、冷却和通行条件后锁定方向 / 最大距离；预警后直线推进，玩家移动不改变方向。每步由导航扫掠，撞墙、水域、动态障碍或边界即停并进入恢复；沿轨迹对同一玩家至多结算一次，不因低帧率跳过命中。 |
| 强化 | 配置阈值首轮建议 50%；阈值满足时安全中断或完成当前动作，再进入可见转换动作。转换只发生一次，调整已配置的技能参数 / 选择权重；不隐式无敌、不抹掉现有控制状态。死亡可立即打断转换。 |
| 伤害 | 复用现有 `CombatSystem`、伤害快照、阵营 / 状态许可和 MonsterAttack 随机流；为挥击与冲锋提供动作专属几何。动作 ID 与已命中标记是同一个结算门禁；动画回调只驱动表现，不能成为第二伤害入口。取消或非法命中不消费伤害随机数。 |
| 表现 | 独立名称、Prefab 和可辨识外观；中文 / 英文 / Pseudo Locale；挥击与冲锋均有非纯颜色预警、恢复空档及降低动态效果兼容。已有血条可表达阶段则不另造界面。开发诊断显示 Phase、树节点、动作 ID / 阶段、预警几何、冷却与中断原因。 |

伤害结算和移动权只由地图当前代次的有效 Boss 实例持有。暂停、控制禁止攻击、死亡、候选地图取消、切图及 Session 退出均撤销预警 / 移动 / 命中授权；后续旧回调不得补发伤害。接纳时开始冷却，前摇取消不退还。阶段转换不会重置技能冷却或复掷伤害随机流。

## 地图、名额和存档

地图格式升为 V3：增加独立 `bossSpawns` 记录（稳定点位 ID、Monster 内容 ID、局部世界位置与朝向），首版每地图 0 或 1 个。V1 / V2 读取时在内存升级为空点位，规范导出 V3；正式野外地图加入 Boss 点并增加修订，城镇保持无 Boss。结构 Schema、编译器、几何 / 内容引用校验、地图工作台与 AI Patch 的增删、Undo / Redo、预览、导入导出、差异与发布流程同步支持。点位须按 Boss 实际圆足迹验证地表、障碍、玩家安全区及容量，不合法则在候选装配前报出具体路径。增加复用 `SpawnSystem` 的定点 Monster 生成入口，不经过普通刷怪定义与加权池；Boss Prefab 在候选图预热，候选失败不得污染源图。

Boss 名额状态采用 `Ready / Alive / Defeated / LegacyAbsent`，绑定稳定点位 ID、Boss 实例 ID 和地图身份。`Ready` 仅在首次进入尚未访问的地图时转为 `Alive`；`Alive` 恢复同一实例、生命、状态、阶段、位置和掉落归属；`Defeated` 永不自动生成；`LegacyAbsent` 保留旧版已访问图的现状，待 0.6.4 手动重置才进入新规则。名额、当前怪物 DTO 与对象注册必须一一对应；Boss 单独于普通刷怪器，仍计入地图和全档怪物容量。

Schema 6→7 迁移同时处理活动图与全部冻结图：旧档中已访问的地图标记 `LegacyAbsent`，保留原有怪物、掉落、生命及随机状态；尚未访问的地图在首次新建状态时按新版点位生成。地图 V2→V3 的修订变化只允许对明确登记、验证“旧布局除新增 Boss 点外语义不变”的映射迁移；其它修订不匹配仍拒绝，不能通用地覆写存档修订。迁移链从真实旧档验证，不把迁移误当一次新地图生成。

新 Boss DTO 保存阶段、阶段转换完成标记、各技能剩余冷却、当前动作 ID / 子阶段、前摇 / 恢复剩余时间、锁定方向、冲锋剩余距离及已命中标记；不保存行为树对象、Animator 状态或路径缓存。前摇恢复只剩余前摇；已命中的动作只恢复后摇；冲锋从保存位置和剩余距离继续沿锁定方向，不再命中同一目标。恢复顺序为内容 / 名额 / 地图校验 → Actor 与状态 → 行为 → 安全导航授权 → 表现重建。活动图、冻结图、保存预检、失败切图回滚、实例身份去重和资源释放执行同一合同。

## 验收矩阵与维护

- **规则与回归**：扩充现有行为、导航、战斗、地图文档、编辑器、存档及迁移测试。长期保留命中去重、行动禁止、地图 / Session 隔离、旧档不补 Boss、死亡持久化与修订映射；不增加仅核验版本字符串或文件数量的测试。
- **真实流程**：Windows Player 完成“发现 → 挥击预警与躲避 → 冲锋锁向 / 撞墙 → 低血量转换一次 → 击杀 → 离场返回”，并从前摇、冲锋中段、命中后、转换前后和已击杀状态跨进程继续；键鼠及手柄输入均验证。命中几何与视觉预警对齐，调试显示对应实际 Phase / 节点。
- **性能**：沿用同一 Windows 基线，10 秒预热、60 秒采样、三轮，诊断关闭 / 开启分别记录。300 常规单位总帧 P95 ≤16.7ms、600 压力单位 ≤33.3ms；导航子预算分别 ≤2 / 3ms。两档都包含活动怪群与 Boss，不以休眠怪代替；分开记录行为、感知、导航、战斗、表现和分配。
- **生命周期**：至少 20 轮 Boss 遭遇中的切图 / 恢复，检查行为注册、旧回调、Addressables、任务和原生导航容量收敛；手动重置尚未实现，不计入本阶段循环。完整回归和正式构建通过后清理一次性验收工具，证据放在 `Docs/docs/behavior/acceptance/0.6.2/`。

遵守[测试维护规范](../../testing/test-maintenance.md)。本计划归档后的现行行为与验证状态以模块文档及阶段验收记录为准。
