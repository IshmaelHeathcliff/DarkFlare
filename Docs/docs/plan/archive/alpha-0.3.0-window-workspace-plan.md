## 交付边界

本切片交付可操作的独立背包、商店、打造窗口，以及独立暂停入口。三种功能分别单独可用，背包可以与商店或打造同时显示，关闭一个不影响另一个。共享选择、详情、现有拖放和四向导航随窗口拆分一起迁移。

本切片沿用现有移动、穿脱、买卖和打造领域事务。商品拖入指定格购买、世界丢弃、打造槽拖回新格及完整快捷动作矩阵，由紧接其后的“统一操作与事务”切片补齐；本切片不得显示尚无真实行为的这些新落点或按钮。这些工作仍属于 0.3.0，不延期到属性或皮肤阶段。

交付组合线框并验证详情文字和十槽扩展空间；正式代表组件在组合布局通过后制作。属性解释、正式 HUD、全套皮肤和十槽领域内容继续按 0.3.1–0.3.4 实施。本切片完成不升级版本，也不宣称 0.3.0 已完成。

## 已核对的代码边界

| 当前实现 | 本切片处理 |
| --- | --- |
| `GameMenuController.CurrentPage` 单选，`ApplyPage` 互斥显隐，关闭直接切 Gameplay | 分开记录打开集合、活动窗口、应用层阻挡和交互授权；关闭当前窗口后计算本组是否仍需 UI / 暂停 |
| `GameRoot.uxml` 永久共享玩家列，三个右侧模板切换 | 改为各自有标题、关闭和操作区的窗口根；详情与拖放层仍由同一宿主管理 |
| 商店 / 打造 `RequireComponent(InventoryPanelController)`，通过背包转接选择、浮窗和焦点 | 提取由宿主持有的共享物品表现能力；窗口控制器通过明确来源注册和注销，不调用隐藏背包执行 UI 工作 |
| `GameMenuOpenRequestedEvent` 只有页面和权限标志，没有来源目标 | 从已验证的世界交互保留具体目标与 Session 代次；目标失效和提交操作时都核对，不能用旧权限位继续操作 |
| `GameInput` 在任意 `HasUiContextOverride` 下阻断导航 / 拿起 | 保留当前 Gameplay / UI 请求作为玩法窗口组的所有权表达；Shell lease 继续代表上层覆盖，避免玩法窗口自己申请同类覆盖后禁掉自身导航 |
| 导航由背包和商店分别补方向边界 | 一个入口处理物品方向导航，使用实际布局矩形；窗口开关和列表刷新后重建有效候选 |

不复制 `InventoryModel`，不增加 Input Actions 实例或 EventSystem；不把现有庞大背包控制器整体改名后继续让它兼管所有窗口。优先提取现有实际复用的能力，保持 Query / Command / Event 边界。

## 窗口状态与生命周期

窗口宿主继续以 `GameMenuController` 为入口，维护仅在当前 Session 有效的打开集合、活动窗口和每窗有效焦点。共享物品状态至少携带来源窗口、来源区域、物品实例 ID 和刷新代次；不进入存档。

| 触发 | 预期结果 |
| --- | --- |
| 打开背包 | 只改变背包状态；已打开的功能窗口保持 |
| 与商人 / 打造台交互 | 打开并激活对应窗口，保留已打开背包；重复请求不创建第二个窗口 |
| 单窗点击“打开背包” | 在固定位置加入背包，不重建交易库存或打造目标 |
| 关闭活动窗口 | 清理它的拖动、详情来源和待执行焦点回调；焦点交给仍打开的有效窗口 |
| 关闭最后一个玩法窗口 / 暂停页 | 释放本组暂停并请求 Gameplay；不得释放 Shell / 平台所有权 |
| 打开独立暂停页 | 暂时隐藏物品窗口、取消拖动并保存组合；返回恢复仍有效组合，来源可为无物品窗口的 Gameplay |
| Shell Settings / Modal / Busy 接管 | 复用已提交的阻挡与 Cancel 分发，隐藏底层；取消后恢复组合，确认离开后清空 |
| 世界目标禁用、销毁、玩家失去交互资格或 Session 结束 | 撤销相关授权并关闭对应功能，取消未提交操作；不擅自开启另一商人或工作台 |

区分“关闭窗口”和“被上层暂时遮蔽”：关闭打造释放槽位的表现占用，遮蔽保留槽内目标；两者都不改变物品的背包归属。暂停导致物理更新停止时，不能仅依赖新的 Trigger 回调发现目标失效；通过生命周期通知与提交前校验收敛，不在 UI 每帧扫描世界。

## 共享表现与单窗操作

- **共享协调**：宿主拥有唯一高亮 / 预览仲裁、`ItemTooltipView` 和拖放会话。各窗可记忆选择，但只允许当前活动视图显示选中物品；同一实例出现在不同投影中也不能同时高亮。拖动期间只保留搬运来源和目标区域提示。
- **背包**：保留真实 10×6 网格、四槽装备、已有移动 / 交换 / 穿脱和当前属性摘要。装备呈现与导航按槽位集合生成，为十槽扩展留接口，不增加假的可装备槽。
- **商店**：商人库存保持完整 10×6 布局；单窗提供本窗口的玩家出售来源选择器，读取现有只读快照。背包同时打开时可直接从背包选出售来源；单窗选择器可以收起，切换前后按实例 ID 校验选择。
- **打造**：单窗提供可打造物品选择器，放入后只对槽内目标执行既有操作。背包同时打开时继续支持已有拖入；关闭背包保留打造槽，关闭打造解除表现占用，取回原格保持已有无损语义。
- **详情**：来源明确指向当前可见窗口；共享浮窗跟随来源和安全区定位，不再依赖唯一大面板。拖动 / 取消后的防闪现与重新主动预览规则继续保留。
- **既有快捷行为**：旧商店右键出售只在可见且有效的商店玩家来源上下文执行；其他来源不得被隐藏商店截获。输入动作提交前统一验证来源、目标及窗口代次；新快捷矩阵在下一切片补齐。

来源选择器是独立视图，复用图标、只读投影和详情组件，不挂靠隐藏背包控制器。允许候选列表滚动；商人库存和真实背包仍保留原占格规则，不通过裁掉物品或扩大背包来适配窗口。

## 输入与空间导航

先核对唯一 Actions 资产、可重绑定清单、UI Module 默认导航和 Glyph，再接线。现有 Tab / Start 打开背包、Escape / 东键返回、Space / 西键拿起放置的默认语义保留；新增暂停入口和窗口循环动作必须可重绑定。

默认键位候选为 Gameplay 下 Escape / 手柄 Select 打开暂停页，UI 下 Select 打开暂停页，UI 左右肩键循环窗口。Escape 在 UI 中只承担当前层返回，不能同时打开暂停页。键鼠另有可聚焦的暂停、窗口入口和关闭按钮。最终绑定须在实施第一步完成冲突表核对后写入资产；迁移已有动作时保留 Action / Binding ID 与有效玩家 overrides，不能悄悄重置已保存绑定。

- 背包开关在物品 UI 上下文也可执行；上层 Settings / Modal 存在、重绑定或平台挂起时不得穿透操作底层。
- 窗口循环只补充可达性；浏览和现有拿起状态都必须支持自然四向跨窗，不能用肩键代替边缘方向移动。
- 浏览候选是一件物品或一个有效槽 / 控件；按屏幕矩形的方向、投影重叠和边缘距离选择邻居，无候选保持位置。相同分数使用稳定次序，关闭窗口和移除物品后按原视觉位置恢复有效邻居。
- 拿起时保留背包按格定位、装备槽及已有打造槽落点；新交易 / 丢弃落点尚未实现时不进入导航候选。
- 同次方向事件只由一个处理者消费，主动接管后阻止 UI Toolkit 默认导航再次移动。D-pad 与摇杆采用同一重复节奏；被裁剪的列表候选通过滚动显露后聚焦，不把零矩形或隐藏元素当邻居。
- `Cancel` 继续一层一消费：Shell → 本组暂停页 → 拖动 / 来源选择器 → 活动功能窗口。输入回调内释放最后一个 UI 所有者仍延后实际 Map 切换，保留失效 control 索引回归。

## 线框与布局预算

以 1920×1080 为正式画布，先为底部 HUD 预留约 160 px，窗口上沿和外边距约 24 px。初始横向预算为背包约 560 px、功能窗口约 760 px、共享详情约 400 px、间隔约 16 px；这是线框起点，不能成为锁死旧尺寸的测试断言。

先量测现有 10 列网格及最高词条详情，再调整内容分区；不靠缩小到难以阅读的字号或遮掉商品解决空间不足。单窗布局保持相同内容基准，组合时按确定位置排列，动态刷新不跳位。

需要留下六种组合：背包、商店、打造、背包 + 商店、背包 + 打造、背包 + 属性位置预留。每种验证标题、关闭按钮、操作区及详情位于安全区；静态线框另验证十槽完整排布空间，不提前写入装备枚举、资产或存档结构。

实际 UXML / USS 通过 Unity MCP 创建和验证；正常语言、英文、Pseudo Locale 检查长名称、六条显式词缀和长数值。十槽 / 属性预留线框与截图工具属于临时验证，结论归档后清理，不保留无实际消费者的占位控件或运行测试。

| 4. 四向导航与线框 | 统一方向路由、可见目标注册、焦点恢复及组合布局 | 真实方向符合视觉；双向跨窗、稀疏 / 空列表、D-pad / 摇杆长按不双步、不失焦 |
| 5. 收尾 | 本地化、生命周期和现有套件回归，更新模块文档与证据 | 达成本切片验收，删除临时工具，列清下一切片新增事务；0.3.0 仍保持实施中 |
