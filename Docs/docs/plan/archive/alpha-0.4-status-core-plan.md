## 阶段目标

交付一个可脱离场景执行的状态核心：接受统一请求，正确维护来源、逐层数值、持有 / 生效层数、计时和移除原因；失败不改变原数据，查询不暴露可变集合。通过 QFramework 提供薄的 Command / Query 入口，供下一阶段角色接入复用。

本阶段落实规则配置、状态数据、显式时间推进、事务和测试。属性真正生效、周期扣血与行动门禁在阶段 2 接入；七种异常及抗性正式配置在阶段 3；Session 自动推进、存档和图标 UI 在阶段 4。阶段 1 完成后仍保持总计划进行中，完整状态验收时再升级版本。

## 数据与规则合同

建议将配置放在 `Data/Statuses/`，运行时规则、Model / System 与请求快照放在 `Gameplay/Statuses/`，Command / Query 放在该模块子目录。类型按职责拆分，避免每种异常创建一套脚本。

| 数据 | 必要内容 |
| --- | --- |
| StatusDefinition | 稳定 ContentId、本地化与图标引用、分类 / 标签、可驱散 / 可消耗、效果声明、层数 / 计时 / 重复 / 满层规则 |
| 运行时规则快照 | 从定义校验并冻结的规则；修改共享配置不能静默改写已经施加的层 |
| 目标键 | Session 代际、玩家或怪物稳定身份、目标注册代次 |
| 来源快照 | 来源种类、提供方稳定身份、可选来源角色身份；区分限时施加记录与需要持续维持的来源 |
| 状态层 | 实例 ID、施加次序、来源、冻结效果、到期点、下次周期时间；无限时长用显式类型表达 |
| 只读组快照 | 定义身份、持有 / 生效层数、当前生效层、各层剩余时间与来源、数据版本 |
| 操作结果 | 成功 / 无变化 / 失败或排队受理、原因、确切新增 / 刷新 / 移除记录；受理不等于已提交 |

效果承载属性修改器、周期伤害描述、行动限制或纯标记。强度比较使用显式的有限非负值；复合效果整体选择同一候选，不能逐属性拼接。未知效果或非法作用域明确报错；本阶段不实现通用触发脚本语言。

首期合法组合固定为：

| 数值模型 | 重复模型 | 时钟 | 满层默认与可选项 |
| --- | --- | --- | --- |
| 统一数值 | 覆盖刷新 | 共享或逐层 | 默认更新整组参数并刷新；可拒绝，或只刷新时间 |
| 独立数值 | 共存、仅最强生效 | 逐层 | 默认保留最强的候选集合；可拒绝新增 |
| 独立数值 | 共存、各层独立生效 | 逐层 | 默认替换最早到期层；可拒绝新增，或只刷新选中层时间 |

统一组每次施加增加请求层数，实际层数受上限限制；采用覆盖时所有持有层使用新单层参数。建议首期刷新统一组所有现存层的到期点，新层从本次施加时刻计时；逐层模式仍逐条保留来源与移除身份。最强及独立模式每次请求承载一个候选 / 数值层；多层调用在同一准备事务中按固定顺序展开，整体失败时不留下部分层。

只刷新时间不替换数值、来源、实例身份或周期相位。独立模式未指定刷新对象时，沿用最早到期、最早施加、实例 ID 的选择次序；指定对象已失效则拒绝。最强模式同强度优先保留较早实例。来源维持的相同目标 / 定义 / 来源键重复绑定幂等；不同参数需显式更新该来源，不能因重绑叠层。

以上组合收窄与统一组刷新范围属于工程实施默认，用户已确认的三种满层默认及可单独配置原则保持不变。七种异常的具体数值不在本阶段确定。

## 通用接口与事务

纯规则负责计算，StatusModel 拥有目标集合及版本，StatusSystem 编排操作及通知；Controller 通过 Command 写入、Query 读取。下列接口均进入同一规则实现：

| 操作 | 合同 |
| --- | --- |
| ApplyStatus | 校验目标、规则、来源、时长和数值，返回实际接受、刷新及替换情况 |
| GetStatusSnapshot / HasStatus / GetStatusStacks | 无副作用查询；可按定义、分类、标签筛选，区分持有与生效 |
| TryConsumeStatusStacks | 默认从持有层按最早到期足额消费；可限定生效层或指定实例，不足整次失败 |
| DispelStatuses | 按定义、分类、标签及数量筛选，仅移除可驱散层，返回实际移除记录 |
| ReleaseStatusSource | 只移除该持续来源的贡献；重复释放无变化；源物品消失不清除已提交的限时药剂状态 |
| RegisterTarget / UnregisterTarget | 管理核心目标记录和注册代次；注销使旧请求、准备结果及待结算记录失效 |

每次变更统一走以下流程：

1. 读取目标身份、注册代次、数据版本及逻辑时间，在分离的候选状态上准备变更。准备和预检不改变实际层、时间、ID 分配进度，不发布事件。
2. 提交前复核全部前置条件。期间发生施加、移除或时间推进时，旧准备结果失效；不同目标的操作不会互相污染。
3. 同步替换最终状态并生成不可变变更记录。准备结果只能成功提交一次；失败保留原层、来源、时间、周期相位和版本。
4. 默认在提交后发布通知；内部组合入口允许宿主暂存通知，待资源、背包等一并提交后统一发布。为组合失败保留精确恢复接点，不能用重新施加或反向操作模拟回退。
5. 通知期间的新写操作进入队列，当前批次通知结束后按顺序重新校验执行。查询只能看到已提交状态；排队结果与最终结果分开表达，旧版本请求不能绕过复核。

移除原因分别记录到期、消费、驱散、来源释放、替换和目标注销。普通到期不产生消费语义。失败原因至少覆盖无效目标、过期引用 / 版本、非法配置 / 数值、数量不足、不可消费和容量拒绝；合法但无变化可单独返回，供后续物品使用判断是否扣数量。

## 时间推进

核心接收显式游戏时间增量，使用双精度维护时间和确定性次序；负值、NaN、Infinity 及计算溢出拒绝。查询不推进时间。本阶段由测试或宿主显式调用，统一 UniTask 与暂停租约在生命周期阶段接入。

- 按计划发生时间处理周期和到期；同刻先结算当时生效层应有的周期，再移除到期层并重新择强。
- 第一跳位于施加后一个完整间隔；刷新保留周期相位，替换实例建立新相位，未满间隔的尾段不补跳。
- 受压制候选照常计时和推进自己的周期相位，不结算伤害；重新生效时不补发受压制期间的跳数。
- 每个周期先产出可被宿主同步处理的记录，再推进到下一事件。阶段 2 可在回调中提交伤害、处理死亡及移除；不会先生成目标死亡后所有未来跳数再统一扣血。
- 单次推进设事件预算，达到预算时返回已处理时间和剩余积压；宿主续处理，不能丢弃剩余时间或重复加入增量。在积压清空前暂停接受会改变事件次序的外部写请求。
- 同一输入序列按一次大步、多个小步或分批预算推进，排空积压后的最终快照与周期记录序列一致。浮点边界测试使用可精确表达的间隔，并补充小数间隔误差用例。

| 行为 | 核心断言 |
| --- | --- |
| 统一层 | 加层与满层刷新不超过上限；参数统一；共享到期整组移除，逐层到期保留其他层 |
| 最强接替 | t=0 施加强度 10、持续 10 秒；t=1 施加强度 20、持续 2 秒；t=3 弱层恢复，仍只剩 7 秒 |
| 满层选择 | 更弱候选被拒或无变化、同强度保留早实例；独立模式按到期、次序、ID 选中，有限层优先于无限层 |
| 独立数值 | 不同数值的层保留各自来源、周期和时长；刷新选中层不改另一层；替换清除旧层未来周期 |
| 周期边界 | 3 秒时长、1 秒间隔只在 1 / 2 / 3 秒结算；2.5 秒时长不补第三跳；刷新不立即追加一跳 |
| 候选周期 | 弱层受压制期间不结算，恢复后沿用原相位，不补跳、不重新计满间隔 |
| 消耗 / 驱散 | 足额一次成功；不足、保护属性、过期指定实例全部不变；筛选只影响匹配层，返回精确来源及移除原因 |
| 准备与提交 | 准备无写入 / 通知；重复提交、推进时间后的旧准备及失效目标被拒；组合失败准确恢复 |
| 事件重入 | 事件读取最终状态；回调再次消费排队复核，不重复消费同一层，不重复发送完成通知 |
| 来源与目标隔离 | 同来源重绑幂等，释放不误删其他来源；限时药剂不随物品销毁消失；同基底怪物、Session 重建与目标重绑隔离 |
| 时间分批 | 大步、小步、预算续处理的周期序列和最终状态一致；回调注销目标后不再产生其后续周期 |
| 无效输入与只读性 | 非有限值、非法组合、负时长 / 数量和溢出拒绝；调用方不能通过快照或修改配置反向改写现存层 |
