# alpha 0.1.6 基础随机打造执行计划

> 状态：已完成并归档
> 建立日期：2026-08-12
> 最近更新：2026-08-12
> 所属版本：`alpha 0.1`
> 前置阶段：`alpha 0.1.5` 已完成
> 后续依赖：`alpha 0.1.7` 多帧特效、稳定世界层级与综合验收

## 阶段目标

参考《流放之路》基础通货的职责划分，将现有四项定向打造扩展为一套由稀有度约束、随机范围和金币成本共同驱动的基础打造系统。玩家只能选择物品、操作和“任意 / 前缀 / 后缀”范围，不能指定具体词条、词条定义或结果。

完成后必须满足：

1. 普通、魔法、稀有、传奇拥有唯一且全局一致的前后缀容量与生成数量合同。
2. 升阶、还原、重随全部、增加、移除和数值重随全部采用原子事务，固定输入与种子可复现。
3. 越精准的范围成本越高；价格与当前 100 初始金币、普通装备约 30–54 买价保持可用但有取舍的层级。
4. 打造 UI 不再列出或选择具体词条，完整词条继续只由统一物品信息浮窗展示。
5. 物品生成、掉落、打造、价值计算、内容验证和 UI 使用同一份稀有度规则，不保留基底容量与稀有度容量两套事实。

## 当前基线与必须解决的冲突

- `ItemBaseDefinition` 当前为每个基底保存 `_maxPrefixCount / _maxSuffixCount`，七件正式装备都配置为 `3 / 3`；`ItemInstance.TryAddAffix` 直接使用该值，普通和魔法物品因此没有正确的稀有度容量限制。
- `ItemInstance.Rarity` 当前只读，无法在一个受控事务中同时变更稀有度与词条。
- `ItemGenerator` 和 `LootTableEntry` 直接接受前缀、后缀数量，只按基底容量静默截断，没有验证稀有度下限。
- 现有操作为添加、重随全部、定向移除重随、定向提升数值；Command、System 和 UI 仍可传入目标 `AffixInstance`。
- `CraftingSystem` 使用私有无种子的 `System.Random`，打造不能随 Main 根种子稳定重放。
- `GetCraftingSnapshotQuery` 和打造 UI 重复维护完整词条列表、选择状态和滚动区，与统一物品信息浮窗职责冲突。
- 正式打造池已有 25 个词条；旧金币消耗为添加 20、重随全部 40、移除重随 30、提升数值 25。
- 当前初始金币为 100，普通物品基础价值为 20–36，商人买入倍率 1.5、回收倍率 0.4，普通装备买价约 30–54。

## 冻结领域合同

### 稀有度规则是唯一容量来源

新增集中式 `ItemRarityRules`，所有运行时、生成器、打造、UI、价值快照和验证器只通过它读取容量与生成范围。

| 稀有度 | 最大前缀 | 最大后缀 | 正常生成总词条范围 | 说明 |
| --- | ---: | ---: | ---: | --- |
| 普通 `Normal` | 0 | 0 | 0 | 永远没有显式词缀 |
| 魔法 `Magic` | 1 | 1 | 1–2 | 至少一条，可为单前缀或单后缀 |
| 稀有 `Rare` | 3 | 3 | 2–6 | 至少两条，任一侧不得超过三条 |
| 传奇 `Unique` | 3 | 3 | 4–6 | 至少四条，任一侧不得超过三条 |

- 中文 UI 继续显示“传奇”，运行时枚举保留 `ItemRarity.Unique`，本阶段不进行破坏性枚举改名。
- `ItemBaseDefinition` 的前后缀容量字段退出正式配置；通过一次迁移删除七件正式装备中的重复序列化值，禁止长期保留双重事实。
- 正常生成总词条范围用于新生成、升阶补全和重随。随机移除是唯一例外：它可以让物品低于当前稀有度的最小词条数，甚至变为零词条，但容量、稀有度和物品价值倍率不变。
- 低于下限的物品是合法“损耗态”，可以装备、保存、出售、增加词条或再次打造；验证器只检查它没有超过容量。后续重随或升阶必须恢复到目标稀有度的正常生成范围。
- 普通物品容量为零，除升阶外不能执行增加、移除、重随全部或数值重随。
- 隐式修改器不计入显式前后缀数量，也不会被本阶段任何操作删除或重随。

### 正式入口不得指定具体词条

正式写入链固定为：

```text
CraftingPanelController
└── CraftItemCommand(operation, scope, item)
    └── CraftingSystem.Craft(operation, scope, item)
        └── CraftingOperations.TryPlan(operation, scope, item, pool, rootSeed)
            └── ItemInstance.TryApplyCraftingMutation(expectedRevision, newRarity, affixes)
```

- `CraftingOperation` 只表示操作族；`CraftingAffixScope` 固定为 `Any / Prefix / Suffix`。
- 删除公开 API 中的目标词条引用、索引和稳定 ID，不保留兼容重载或隐藏入口。
- 升阶和还原忽略范围；其余四类操作必须显式携带范围。
- UI、Command 和 System 不得先随机出具体词条再调用旧定向接口；候选计算、目标选择与结果生成全部位于纯逻辑层。

### 六类操作合同

| 操作 | 范围 | 结果合同 | 主要失败条件 |
| --- | --- | --- | --- |
| 提升稀有度 | 无 | 提升一级并随机补足目标稀有度最低词条数 | 已是传奇、无法补足合法词条 |
| 还原普通 | 无 | 删除全部显式词缀并将稀有度改为普通 | 已是无词缀普通物品 |
| 重随全部 | 任意 / 前缀 / 后缀 | 重建指定范围内的全部词缀，最终总数回到当前稀有度正常范围 | 普通物品、没有完整合法方案 |
| 随机增加一条 | 任意 / 前缀 / 后缀 | 在指定范围增加一条合法词缀 | 容量已满、没有合法候选 |
| 随机移除一条 | 任意 / 前缀 / 后缀 | 等概率移除指定范围的一条现有词缀 | 指定范围没有词缀 |
| 随机重随一条数值 | 任意 / 前缀 / 后缀 | 等概率选择一条可变词缀，仅重掷该定义的实例数值 | 指定范围没有可变数值词缀 |

四类带范围操作形成 12 个变体，加上升阶、还原，共 14 个正式操作变体。

### 提升稀有度

提升固定为单级：

```text
普通 → 魔法 → 稀有 → 传奇
```

- 普通升魔法：从合法池生成 1–2 条词缀，前后缀各不超过 1。
- 魔法升稀有：保留现有词缀并至少新增一条；若物品曾被移除到零词缀，则补到至少 2 条。最终通常为 2–3 条且不超过稀有容量。
- 稀有升传奇：保留现有词缀并补到至少 4 条；已有 4–6 条时只提升稀有度。
- 传奇已经是本阶段最高稀有度，不能继续提升。
- 升阶不降低现有词条数、不替换现有定义或数值；补词条时持续排除已有互斥组。
- “稀有升传奇”是本项目为满足统一四档进阶而增加的规则，不宣称与《流放之路》标准通货一一对应。当前传奇只是稀有度层级，不在本阶段建立固定传奇基底或专属传奇词条系统。

### 还原普通

- 一次删除全部显式前缀和后缀，并原子地把稀有度设为普通。
- 保留基底、实例 ID、物品等级、生成种子、隐式修改器、品质、耐久、占格和背包位置。
- 不允许只清前缀、只清后缀或保留玩家指定词条；这些属于后续高阶打造。

### 重随全部

- 任意：删除全部显式词缀，在当前稀有度的正常总数范围内等概率抽取新总数，再从所有可行前后缀分布中等概率选择一种分布并完整重建。
- 前缀：保留全部后缀，只删除并重建前缀。新前缀数至少为 1，同时保证最终总数位于当前稀有度正常范围且不超过前缀容量。
- 后缀：与前缀范围对称。
- 精准范围的目标侧数量从 `Max(1, 最小总数 - 保留侧数量)` 到 `Min(目标侧容量, 最大总数 - 保留侧数量)` 之间等概率抽取；下界大于上界时操作不可用。
- 指定前缀或后缀只锁定“另一侧保持不变”，不能锁定某条具体词缀。
- 每次重建按词条权重抽取定义，逐步排除等级、标签、类型、非正权重和已占互斥组；必须先规划出完整方案，不能生成一半后留下部分结果。
- 普通物品没有合法重随结果，按钮不可用。

### 随机增加一条

- 任意范围从仍有容量的前缀和后缀合法候选全集中按定义权重抽取。
- 前缀或后缀范围只从指定类型候选中按权重抽取；精准范围不会改变单个定义的配置权重。
- 已有互斥组、物品等级、生成查询、词缀类型、容量和正式词条池共同决定候选。
- 增加只保证不超过容量，不负责一次恢复稀有度最低词条数；被移除到零词条的传奇物品可以逐条补回。

### 随机移除一条

- 任意范围在全部现有显式词缀中等概率选择一条；前缀和后缀范围分别在对应现有列表中等概率选择。
- 目标选择不使用生成权重，避免高权重定义也更容易被移除。
- 移除可无视当前稀有度最低词条数，不降低稀有度、不改变容量，也不自动补词条。
- 移除最后一条后，魔法、稀有或传奇物品仍保持原稀有度；只有“还原普通”会降为普通。

### 随机重随一条词缀数值

- 任意范围在全部包含至少一个可变数值的现有词缀中等概率选择；前缀、后缀范围只选择对应类型。
- 保持原 `AffixDefinition`、前后缀类型、互斥组、修改器数量、Operation、Scope、伤害类型与标签条件，仅按原定义区间重新生成实例数值。
- 新值可以提高、降低或与旧显示值相同，不再使用“必须严格提升”的归一化品质比较。
- 全部数值范围固定的词缀不进入候选；随机过程已真实执行时，即使舍入后的显示值相同也算成功并正常扣费。

## 随机与原子事务

### 随机种子

- 在 `GameplayRandomChannel` 末尾追加 `Crafting`，禁止插入或重排已有枚举值。
- `CraftingSystem` 先完成配置、背包归属、金币和候选预检；不可执行的操作不取得根种子。
- 一次可执行尝试只取得一个打造根种子，并按操作、范围和稳定槽位派生独立子种子：数量、前后缀分布、目标选择、定义选择和每条实例数值互不串扰。
- 固定 Main 根种子、物品状态和操作序列必须得到相同的数量、分布、目标、定义、数值和金币变化；打造不得扰动刷怪、攻击与掉落通道。

### 原子提交

`ItemInstance` 不开放稀有度公共 setter。新增内部受控的词条状态快照与一次性提交入口，同时替换稀有度和完整显式词缀集合。

提交顺序固定为：

1. 验证物品属于玩家背包且未装备、配置有效、金币足够；
2. 计算完整候选与新状态，不修改原物品；
3. 获取根种子并生成完整计划；
4. 以预期修订号原子提交稀有度和词缀；
5. 扣除一次金币；
6. 发送一次 `ItemCraftedEvent` 并输出结构化日志。

任何失败都保持物品和金币原样，不发送成功事件。结构化结果至少包含：成功状态、失败原因、操作、范围、物品、根种子、旧 / 新稀有度、旧 / 新前后缀快照、随机命中目标、实际成本和操作后金币。

失败原因固定为领域枚举，至少覆盖：未配置、物品为空、物品不在玩家背包、已装备、金币不足、稀有度不支持、容量已满、指定范围为空、无合法定义、无法组成完整结果、无可变数值词缀、重复提交和配置错误。

## 成本与经济合同

### 正式价格

| 操作 | 任意 / 无范围 | 前缀 | 后缀 | 价值层级参考 |
| --- | ---: | ---: | ---: | --- |
| 普通 → 魔法 | 15 | — | — | 低阶升品 |
| 魔法 → 稀有 | 60 | — | — | 中高阶升品 |
| 稀有 → 传奇 | 160 | — | — | 项目扩展的最高阶升品 |
| 还原普通 | 20 | — | — | 清除全部显式词缀 |
| 重随全部 | 40 | 120 | 120 | 全随机中档；保留另一侧为三倍精准溢价 |
| 随机增加一条 | 60 | 180 | 180 | 高价值增词缀 |
| 随机移除一条 | 60 | 180 | 180 | 高价值随机剥离 |
| 重随一条数值 | 80 | 240 | 240 | 不换定义的高价值数值重掷 |

- `CraftingDefinition` 保存每个操作族的基础成本、三段升阶成本和统一精准倍率 `3`，不序列化 14 个重复数字。
- `Any` 使用基础成本，`Prefix / Suffix` 使用 `CeilToInt(baseCost × precisionMultiplier)`；升阶和还原没有范围倍率。
- 定价参考的是通货职责的相对层级，不绑定任何赛季的实时玩家交易汇率。
- 初始 100 金币可以完成一次完整的普通升魔法再升稀有，也可以进行两次普通范围重随；指定范围、传奇升阶和数值重随形成中后期金币目标。
- 现有价值公式按稀有度使用 `1 / 2 / 4 / 8` 倍率。稀有升传奇成本 160 高于当前正式基底在最有利词条数下的回收价值增量，避免“买入—升阶—卖出”的确定性套利。
- 成本只在原子提交成功后扣除。随机结果不理想、但操作真实成功时正常扣费；配置或候选失败不扣费。

## 物品生成与内容迁移

- `ItemGenerator`、`ItemGenerationOptions`、`LootTableEntry` 和商人库存统一调用 `ItemRarityRules`。
- 正式内容可以指定前缀数和后缀数，但必须同时满足该稀有度的总数范围与两侧容量；禁止继续静默 `Clamp` 成另一个结果。
- 非法正式配置由 `ContentConfigurationValidator` 阻止；运行时遇到非法动态请求返回结构化失败并记录上下文。
- 普通正式基底默认保持零词缀；魔法、稀有和传奇生成请求必须能够从当前 25 词条池组成完整、无互斥冲突的结果。
- 验证器按每个正式基底和支持的物品等级检查：至少可填满 3 个不同互斥组的前缀、3 个不同互斥组的后缀，并能组成 6 词缀传奇上限。
- 一次 Editor 迁移移除七件正式 `ItemBaseDefinition` 的重复容量字段，并更新所有显式掉落数量配置；迁移入口验证成功后删除，不保留永久菜单。

## 打造 UI 合同

`Crafting.uxml` 移除词条 `ScrollView`、词条列表、具体词条选择、选中词条详情和对应焦点状态。禁止只隐藏旧控件或保留定向参数后门。

打造页固定包含：

1. 目标物品、当前稀有度、前缀 `当前 / 上限`、后缀 `当前 / 上限` 和金币；
2. 升阶与还原普通两个无范围操作；
3. 共享的“任意 / 前缀 / 后缀”范围选择器；
4. 重随全部、增加一条、移除一条、重随一条数值四个操作按钮；
5. 每个按钮的动态成本、可用状态和简短失败原因；
6. 最近一次结果：稀有度变化、影响范围、随机目标、词条数量变化和金币消耗；
7. “不会指定具体词条、拖放不会直接打造、确认后立即消耗”的输入提示。

- 范围选择器只能限定前后缀类型，完整具体词条仍由统一物品信息浮窗查看。
- 无鼠标悬停或物品焦点时，浮窗继续隐藏；打造目标不会变成默认悬停目标。
- 操作可用性和价格由领域只读评估返回，Controller 不复制容量、候选或成本规则。
- 键鼠与手柄焦点顺序为共享玩家背包 → 升阶 / 还原 → 范围 → 四项操作 → 关闭回退。
- 打造页不得出现垂直或水平滚动条；在 `1280×720`、`1920×1080`、`2560×1440` 三档下无超框、遮挡或挤压共享玩家列。

## 执行阶段

### 阶段 A：冻结稀有度、迁移与旧行为特征

- 为四档稀有度、七件正式基底、掉落生成、价值计算、旧四项打造和 UI 结构建立迁移前特征测试。
- 新增 `ItemRarityRulesTests`，冻结容量、正常生成范围与随机移除例外。
- 冻结 14 个操作变体、正式价格和“无具体词条参数”的 API 形状。
- 追加 `Crafting` 随机通道并验证既有 Gameplay Random 固定输出不变。

验收：现有冲突均有失败测试覆盖；固定规则表、价格表和随机通道顺序不可被配置资产悄然改写。

### 阶段 B：统一物品稀有度与生成规则

- 实现 `ItemRarityRules`，让 `ItemInstance` 容量、生成器、掉落、商人、快照和验证器统一读取。
- 以内部原子提交替代只读稀有度无法变更和逐条修改导致的半成品状态。
- 迁移并删除 `ItemBaseDefinition` 的基底容量字段，修正非法掉落数量配置。
- 明确区分“正常生成有效”与“随机移除后的合法损耗态”。

验收：普通永远零词缀；生成的魔法 / 稀有 / 传奇分别满足 1–2 / 2–6 / 4–6；移除后的低于下限物品仍能保存、装备和继续打造。

### 阶段 C：实现六类随机打造与成本

- 集中候选过滤和完整方案规划，覆盖容量、类型、权重、等级、查询与互斥组。
- 实现升阶、还原、三范围重随、三范围增加、三范围移除和三范围数值重随。
- `CraftingSystem` 接入独立稳定随机子流，Command 和 Event 改为结构化结果。
- 扩展 `CraftingDefinition` 并通过 Unity Editor API 迁移正式价格。

## 完成定义

- 四档稀有度容量与正常生成数量由唯一规则源驱动，普通物品无显式词缀。

- 移除可以低于最低词条数且不降稀有度；升阶与重随一定恢复合法正常范围。
- 正式价格满足冻结表，精准范围成本更高，且与现有经济不存在确定性套利。
- 固定种子、事务、事件、UI、键鼠 / 手柄、三档布局和真实 Main 全部回归通过。
