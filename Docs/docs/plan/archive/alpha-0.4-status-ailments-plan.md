## 已确认与本次实施默认

用户已确认抗性按效果类型分别减弱，以及三种重复模型的满层默认行为并允许逐定义配置。以下效果映射沿用已有规则草案；抗性边界、快照时机和样例参数为本计划的实施默认，不宣称为用户确认的最终平衡设计。

| 异常 / 稳定 ID | 首期效果 | 重复与计时 | 抗性 ID |
| --- | --- | --- | --- |
| 虚弱 / `weakness` | 降低造成伤害，使用现有 Less 语义 | Strongest、PerLayer | `weakness_resistance` |
| 眩晕 / `stun` | 禁止移动、攻击、施法，保留独立物品许可 | Uniform、Shared、上限 1、覆盖刷新 | `stun_resistance` |
| 流血 / `bleeding` | 物理周期伤害 | Independent、PerLayer | `bleeding_resistance` |
| 燃烧 / `burning` | 火焰周期伤害 | Strongest、PerLayer | `burning_resistance` |
| 冰缓 / `chill` | 降低移动速度，使用现有 Less 语义 | Strongest、PerLayer | `chill_resistance` |
| 感电 / `shock` | TargetTaken 增加承受伤害 | Strongest、PerLayer | `shock_resistance` |
| 中毒 / `poison` | 混沌周期伤害 | Independent、PerLayer | `poison_resistance` |

七种定义归类为异常，可驱散；可消费与可驱散分别配置。异常不由元素伤害自动推导，周期伤害不递归触发异常。冰缓不增加当前不存在的攻击 / 施法速度属性。

正式 ID 固定，效果强度、持续时间、层数上限和间隔保留数据配置。实施时为样例选择明确、可复现的非随机参数，并在验收记录中列出；参数可后续调优，不改变接口。正式图标在阶段 4 按 Sprite 工作流补齐，阶段 3 不借用不对应的图标充作完成。

## 抗性计算与事务合同

- 默认基础抗性为 0；有效抗性 `R = clamp(value, 0, 100)`，减弱系数 `k = 1 - R / 100`。非法非有限值拒绝，不转成免疫或零抗性；不套用元素抗性的边界。
- 在施加 Prepare 时读取目标已提交属性，冻结抵抗前后数值与所用抗性；同批请求均按该批开始时的目标属性抵抗，避免列表顺序导致不同结果。Commit / Publish 仍校验目标属性版本。
- 属性异常的减益幅度乘 k，向无效果缩放；不能把属性最终结果整体乘 k。首期只开放明确支持的效果组合，Override、转换、混合控制等没有抵抗语义的配置须拒绝。
- 周期异常先执行来源伤害解析，再乘异常抗性系数；每跳仍读取目标当前类型抗性和 TargetTaken。状态快照显式标记已抵抗，避免重试、更新或后续恢复重复抵抗；伤害阶段与抵抗阶段分别表达。
- 眩晕仅缩短本次请求有效时长，不改变禁止行动位；100% 抵抗返回明确抵抗结果，不创建零时长、零效果或纯标签层，也不刷新已有层。
- 抵抗失败的施加在组合事务中整笔失败；多目标技能若未来需要部分成功，必须由宿主另行声明，不隐含在核心操作中。单次命中已经造成的伤害不会因附加异常被抵抗而撤销。
- 已有层不随抗性变化重新缩放。新层与覆盖刷新按新抗性计算；仅刷新时长策略保留原数值。Uniform 仍遵守整组统一参数规则，不能制造同组异构层。
- Strongest 使用抵抗后可比较幅度；燃烧使用来源解析及异常抵抗后的每秒伤害。类型防御仍实时结算，不参与候选重新排序。相同强度继续按现有稳定次序保留。
- 配置本地化说明与调试快照展示抗性来源、原值、有效值和结果；目标中途换装或资源变化导致准备失效时，不留下层或通知。

## 最小来源样例

1. **技能直接施加与驱散**：通过 Command 调用统一状态合同，目标与技能许可先校验。驱散按异常分类筛选，不移除不可驱散状态或普通增益。无匹配返回 NoChange；样例不引入额外法力收费规则。
2. **命中附加异常**：显式配置至少一个投射物来源样例。攻击发出时冻结定义规则及来源参数；命中存活目标后读取其当前异常抗性。未命中和周期伤害不施加，致死目标不再绑定异常；同一次实际命中只触发一次。不以最终扣血值倒推基础异常伤害。首期样例固定触发，不新增概率系统；若存在数值掷值，使用独立确定性子种子，保持原命中 / 暴击随机流。
3. **装备持续来源**：用一个来源维持增益验证，来源键由装备实例和能力稳定 ID 组成，不依赖槽位。相同来源重复协调幂等，移动槽位不复制；卸装只释放自身，其他装备与限时状态保留。穿脱失败不改变来源，状态准备失败也不能留下背包 / 装备半成功；以统一准备提交接点处理，不能依赖装备事件发出后补施加。
4. **标记消费**：同一目标足额消费指定标记并获得临时属性增益；两项组成一次 StatusMutation 批次。记录所消费层的来源和数值，失败保留原层、时长、资源与版本。不足、旧版本、非法增益均不消费；普通到期不触发该效果。
5. **天赋 / 消耗物品合同**：使用对应 StatusSourceKind 通过相同施加 / 驱散入口做集成测试。限时物品效果不要求物品实例继续存在；SourceOwned 天赋效果释放自身来源。此项只验证适配能力，不创建天赋树或提前实现物品使用事务。

装备恢复必须在角色状态身份有效后协调来源；初始化顺序不同则延后至绑定接点，不能静默漏施加。恢复与重绑只选择一个权威重建入口，通过来源键去重。已发出攻击的来源随后死亡或卸装，仍按冻结快照施加限时效果；校验稳定归属与当前提供方有效性应区分，不能放开失效角色发起新行为的校验。

## 实施顺序与验收

- 实现纯抵抗解析及快照，接入统一准备路径，补齐七项抗性与七异常定义。
- 校验异常身份 / 策略 / 效果 / 生命周期合法组合、稳定 ID、属性引用及本地化。接入 ContentCatalog 和 Addressables；图标缺失边界明确留给阶段 4。
- 检查现有“每属性词缀覆盖”合同，补充对应抗性词缀配置与合法装备候选；不通过放宽全量校验掩盖新属性无法获得。
- 审查新增目录内容对 core 内容版本、存档属性预检的影响；需要时新增兼容迁移并测试历史存档，不因添加内容立即宣称状态存档完成。运行版本暂保持 0.4.0-alpha。

### 2. 来源适配与调试

- 依次完成直接技能 / 驱散、命中附加、装备维持、消费标记样例；提供可显式启用的配置，沿正式调用链验证。
- 增加 Odin 调试入口：选择当前 Session 目标与状态定义、指定合法来源、施加、逐层检查、消费、驱散、显式推进时间和显示失败原因。
- 调试修改只走 Command，展示只走 Query；退出 Session 后目标失效，不能保留旧角色、监听或静态状态。采用编辑器工具，不增加运行时输入绑定。
