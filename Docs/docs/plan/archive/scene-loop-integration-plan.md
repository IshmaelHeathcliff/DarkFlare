## 目标

把现有战斗、掉落、背包、交易和打造能力串成玩家可重复完成的一轮流程：

```text
生成玩家 -> 战斗 -> 掉落 -> 自动拾取 -> 接近商人并交互
-> 买卖/整理 -> 接近打造台并交互 -> 打造/装备 -> 返回战斗
```

完成后，玩家不再依赖测试脚本或直接切页访问交易和打造；键鼠与手柄均可通过场景目标进入对应功能，并能在下一轮战斗中验证装备构筑变化。

## 已确认基线

- `Interact` 已绑定键盘 `E` 与手柄北键，但 `GameInput` 尚未向玩法层暴露触发事件。
- `GameMenuController.OpenPage` 已能定向打开背包、商店或打造页，关闭后会恢复 Gameplay 输入。
- `Main.unity` 当前只有战斗 Bootstrap、刷怪器、UIRoot、EventSystem 与基础场景对象，没有商人和打造台实体。
- 玩家由 Addressables 动态生成，因此玩家交互检测应挂在玩家 Prefab，而不是依赖场景预放玩家。
- 掉落物当前使用碰撞自动拾取，已经满足首版循环，不在 8f 改成按键拾取。
- 商人与打造配置仍由 `CombatPrototypeBootstrap` 初始化；8f 只增加入口，不扩展多商人或多打造配置。

## 范围

### 本步实现

- `GameInput` 暴露只在 Gameplay Action Map 生效的交互事件。
- 新增通用世界交互目标和玩家近距离目标选择。
- HUD 显示当前目标的 `E / Y` 交互提示。
- 商人只开放背包与商店页，打造台只开放背包与打造页；Tab / Start 只打开随身背包。
- 菜单打开时暂停战斗模拟，关闭后可靠恢复。
- 通过 unityMCP 在 `Main.unity` 创建商人与打造台并配置触发范围。
- 完成键鼠、手柄和一轮完整循环验证。

### 本步不实现

- 对话、任务、NPC 动画、正式美术和音效。
- 多商人独立库存、多打造台配置或场景间持久化。
- 把掉落拾取改为按键交互。
- 安全区、寻路、撤离、多场景与存档。
- 背包拖拽、旋转、堆叠或重量系统。

## 技术方案

### 输入与目标检测

1. 在 `GameInput` 增加 `InteractPerformed` 事件，统一转发 `Player/Interact.performed`，并在 `Dispose` 中解除订阅。
2. 在玩家 Prefab 增加 `PlayerInteractionController`。它维护进入触发范围的 `WorldInteractionTarget`，按距离选取最近目标，不通过 `Update` 轮询输入。
3. `WorldInteractionTarget` 保存中文显示名、目标菜单页和触发范围；首版仅允许 `Shop` 与 `Crafting`。
4. 玩家进入、离开或切换最近目标时发送 Command，由 Command 发布交互焦点事件；按下交互键时发送菜单打开 Command。Controller 不直接发送 Event，也不直接调用另一个 Controller。

### 菜单上下文

- `GameMenuController` 注册菜单打开请求事件，并根据来源建立本次菜单上下文。
- Tab / Start 打开时只允许背包页，避免在场景任意位置远程交易或打造。
- 商人上下文允许背包与商店；打造台上下文允许背包与打造。
- 不可用页签保持可见但禁用，便于玩家理解功能入口；菜单关闭后重置为背包上下文。
- 打开指定页后沿用现有默认焦点和 Gameplay/UI Action Map 切换逻辑。

### 交互提示

- 在现有 HUD 增加默认隐藏的交互提示区域，由 `InteractionPromptController` 消费焦点事件。
- 提示格式首版固定为 `E / Y · {目标名称}`，兼顾键盘和常见手柄布局。
- UI 模式、无目标和玩家死亡时隐藏提示；关闭菜单且目标仍在范围内时恢复。
- UXML/USS 创建与布局使用 unityMCP，并复用现有 `UIDocument`、PanelSettings 和 EventSystem。

### 战斗暂停

- 新增集中式暂停入口，由 Command/System 设置和恢复 `Time.timeScale`，不把暂停逻辑分散到怪物、刷怪器和技能循环。
- `GameMenuController` 只在输入模式真正变化时请求暂停或恢复；重复打开、关闭和组件销毁不会留下永久暂停状态。
- 暂停期间 UIToolkit 导航、Submit 和 Cancel 仍需可用。

### 场景实体

- 使用 unityMCP 检查当前 Editor 与 `Main.unity` 状态，不直接编辑已打开场景的 YAML。
- 在玩家出生点附近创建 `Merchant` 与 `CraftingStation` 原型对象，复用现有方块贴图，用颜色区分并配置非重叠的 `CircleCollider2D` 触发范围。
- 两个目标分别配置为商店页和打造页；位置应留出战斗移动空间，并保证玩家能明确逐个进入交互范围。

## 执行顺序

1. **补输入契约**：扩展 `GameInput` 与输入测试，验证 E、手柄北键、UI 模式禁用和释放后不再回调。
2. **建立交互领域消息**：增加交互焦点、菜单打开和暂停相关 Event/Command，保持 Controller 只注册 Event、发送 Command。
3. **实现世界交互组件**：完成 `WorldInteractionTarget` 与 `PlayerInteractionController`，处理进入、离开、最近目标、目标失效和玩家死亡。
4. **收紧菜单访问范围**：让 `GameMenuController` 支持背包、商人、打造三种上下文，并为不可用页签增加禁用状态。
5. **接入暂停与提示 UI**：加入集中暂停逻辑和 `InteractionPromptController`，使用 unityMCP 修改 HUD UXML/USS 与 UIRoot 组件。
6. **布置 Main 场景**：使用 unityMCP 创建、定位并配置商人与打造台，保存场景后检查组件引用和 visual tree。
7. **自动化验证**：覆盖输入、消息载荷、菜单上下文、暂停恢复和交互目标基础行为；运行全量 EditMode、Unity 编译与脚本校验。
8. **Play 完整循环**：通过输入设备测试验证键鼠与手柄绑定，并在 Play Mode 完成“战斗→拾取→交易→打造→装备→再次战斗”，确认 HUD、金币、背包、词缀、伤害和输入模式同步。
9. **收尾**：检查控制台、1920×1080 渲染、`git diff --check`，同步项目概览、目录结构和最小循环状态。
