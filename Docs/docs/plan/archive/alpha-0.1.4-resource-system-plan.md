# alpha 0.1.4 法力、耗蓝与恢复执行计划

> 状态：已完成
> 计划日期：2026-08-11
> 完成日期：2026-08-11
> 所属版本：`alpha 0.1`
> 前置阶段：`alpha 0.1.1–0.1.3` 已完成

## 阶段目标

建立生命和法力两种完整、可观察、可测试的运行时资源，并让技能耗蓝、生命恢复和法力恢复进入正式玩法链路。

本阶段完成后，基础投射物只有在伤害来源有效且法力充足时才能释放；成功释放只扣除一次法力，失败释放不生成投射物、不扣除法力，也不消费玩家攻击随机种子。恢复由架构级系统统一调度，不在每个角色 Controller 中创建独立 `Update` 或无管理异步循环。

## 当前基线

- `CombatActor` 只保存当前生命；最大生命来自聚合后的 `StatBlock`。
- 稳定属性 ID `mana` 和对应 `StatDefinition` 已存在，但目前只是面板数值，没有当前法力或运行时消费者。
- `PlayerController` 每隔技能冷却时间发送一次 `FireProjectileCommand`。
- `FireProjectileCommand` 已保证无有效伤害来源时不生成投射物、不消费 `PlayerAttack` 随机种子，但尚无资源预检和消耗。
- `CombatSystem` 已统一处理伤害、治疗、死亡和复活事件，可作为资源变更入口。
- HUD 只有当前 / 最大生命和金币；背包属性详情覆盖现有 21 个公开属性。
- 打开主菜单时 `GameplayPauseSystem` 将 `Time.timeScale` 设为零，恢复节拍必须遵循该暂停状态。

## 冻结合同

### 属性与单位

| 稳定 ID | 中文名 | 含义 | 合法范围 |
| --- | --- | --- | --- |
| `mana` | 最大法力 | 角色法力上限；保留现有稳定 ID，不迁移为 `max_mana` | `>= 0` |
| `health_regeneration` | 生命恢复 | 每秒恢复的固定生命值 | `>= 0` |
| `mana_regeneration` | 法力恢复 | 每秒恢复的固定法力值 | `>= 0` |

- `StatIds.All` 从 21 项增加到 23 项，并新增两份一一对应的 `StatDefinition` 资产。
- 恢复属性不是百分比，不受帧率影响；结算量为 `rate * elapsedSeconds`。
- `mana` 资产显示名改为“最大法力”，稳定 ID 和资产 GUID 保持不变。
- 旧配置新增字段默认值为零；正式玩家和技能必须通过精准迁移显式保存本阶段基线值。

### 当前资源

- `CombatActor` 保存 `CurrentHealth` 与 `CurrentMana`，上限分别来自有效属性 `max_health` 与 `mana`。
- 配置完成和复活时，生命、法力均恢复到当前有效上限。
- 死亡时当前生命为零；当前法力不参与死亡判定，复活时重置为满值。
- 伤害、治疗、法力消耗和法力恢复都裁剪到 `0..Max`，实际变化为零时不发送资源变化事件。
- 装备或其他修改器改变资源上限时，当前生命和法力都按原比例保持：
  - 旧上限和新上限都大于零时，保持 `Current / Max` 比例。
  - 旧法力上限为零而新上限大于零时，当前法力初始化为新上限。
  - 新法力上限为零时，当前法力归零。
- `CombatActor` 只维护局部状态；资源事件由执行变更的 System 或 Command 发送，Controller 不直接发送领域事件。

### 技能耗蓝事务

- `ProjectileSkillDefinition` 新增非负 `_manaCost`，旧资产默认零保证反序列化兼容。
- 正式基础投射物配置为每次成功释放消耗 `8` 点法力；玩家基础最大法力为 `100`。
- 发射顺序冻结为：
  1. 校验 Actor 存活、技能存在、伤害来源有效。
  2. 校验当前法力不少于技能消耗。
  3. 获取玩家攻击种子并创建攻击快照。
  4. 生成并初始化投射物。
  5. 提交一次法力消耗并发送攻击成功事件。
- 以上步骤在同一个 Command 的主线程执行路径内完成；生成失败时不得留下投射物或资源消耗。
- 无武器、空伤害、法力不足和 Prefab 生成失败都不发送 `ActorAttackedEvent`。
- 无武器、空伤害和法力不足都不得消费 `GameplayRandomChannel.PlayerAttack`。
- 法力不足后仍按技能冷却间隔重试，不允许进入无延迟循环；HUD 显示失败原因和所需法力。

### 恢复节拍

- 新增架构级资源恢复 System，由 `GameArchitecture` 统一注册和释放。
- System 使用一个带 `CancellationTokenSource` 的 UniTask 节拍，`OnDeinit` 必须取消并释放。
- 运行时使用固定 `0.25` 秒游戏时间步长；菜单暂停时不推进，恢复游戏后不补算暂停期间时间。
- System 遍历已注册且存活的 Actor，根据有效属性恢复生命和法力。
- 已死亡、已禁用、已注销或上限为零的 Actor 不恢复。
- 被动生命恢复只发送统一资源变化事件，不复用会生成治疗飘字的主动治疗反馈，避免每个节拍产生视觉噪声。
- 提供可直接传入 `elapsedSeconds` 的同步推进入口，自动化测试不依赖真实等待时间。

### 事件、HUD 与调试

- 新增结构化 `ActorResourceChangedEvent`，至少包含 Actor、资源类型、变化前值、变化后值、当前上限和变化原因。
- 伤害、主动治疗、被动恢复、法力消耗、法力恢复、上限重算和复活均使用可区分的变化原因。
- 释放 Command 在法力不足时发送结构化 `SkillCastRejectedEvent`，包含 Actor、技能、当前法力、所需法力和失败原因；Controller 不直接发送该领域事件。
- 保留现有 `ActorDamagedEvent`、`ActorHealedEvent`、`ActorDiedEvent` 和 `ActorRevivedEvent` 作为战斗表现事件；统一资源事件服务 HUD、调试和后续系统。
- `HudSnapshot` 增加当前法力、最大法力和归一化值。
- HUD 左上状态卡在生命条下增加法力条，显示 `当前 / 最大`；不重新加入属性详情或装备摘要。
- 法力不足时显示“法力不足（需要 N）”，下次成功释放时清除提示。
- 背包右侧属性详情继续覆盖全部公开属性，并增加生命恢复和法力恢复两项。

## 正式配置基线

以下数值用于验证玩法链路，不代表最终平衡：

| 配置 | 最大法力 | 生命恢复 / 秒 | 法力恢复 / 秒 | 技能耗蓝 |
| --- | ---: | ---: | ---: | ---: |
| 玩家 | 100 | 1 | 5 | — |
| 基础投射物技能 | — | — | — | 8 |
| 三种现有怪物 | 0 | 0 | 0 | — |

正式资产必须显式保存这些值，不能依赖新字段的 CLR 默认值。

## 实施步骤

### 1. 冻结基线与迁移前测试

- 为现有生命、治疗、复活、装备上限比例、空手攻击和攻击随机流补充迁移前特征测试。
- 记录正式角色、技能、三种怪物和 21 个属性资产的迁移前字段与 GUID。
- 先让新增测试表达资源合同，再修改运行时实现。

### 2. 扩展属性与配置模型

- 为 `StatIds`、属性面板定义和配置校验增加两项恢复属性。
- 扩展 `CharacterDefinition` 的最大法力与两类恢复基础值。
- 确保无独立角色配置的 `MonsterDefinition` 也生成完整资源属性，正式怪物保存零值。
- 为 `ProjectileSkillDefinition` 增加法力消耗字段与非负校验。
- 更新配置参考中的字段、默认兼容行为和运行时读取者。

### 3. 建立资源状态与统一变更入口

- 扩展 `CombatActor` 的当前法力、上限查询、裁剪和上限比例保持逻辑。
- 在 `CombatSystem` 中增加法力消耗、法力恢复和资源变化事件发送入口。
- 让伤害、治疗、装备重算、配置完成与复活都产生一致的资源快照。
- 保持 `ActorHealedEvent` 只表达需要治疗表现的主动治疗。

### 4. 接入原子技能消耗

- 让 `FireProjectileCommand` 返回结构化释放结果，区分成功、伤害来源无效、法力不足和生成失败。
- 在消费随机种子前完成伤害来源与法力预检。
- 只在投射物实际生成后提交一次法力消耗和 `ActorAttackedEvent`。
- `PlayerController` 继续使用现有可取消自动释放循环，不增加额外轮询；HUD 通过 Command 发送的技能拒绝事件显示法力不足提示，并在下次攻击成功时清除。

### 5. 接入统一恢复节拍

- 新增资源恢复 System 和同步推进方法。
- 注册到 `GameArchitecture`，验证初始化、暂停、恢复、场景退出和架构反初始化。
- 对玩家和怪物使用同一属性读取路径，不在 Controller 中增加角色类型分支。

### 6. 完成 HUD、配置迁移与文档

- 使用 UI Toolkit 修改 HUD UXML / USS，增加法力条和释放失败提示。
- 更新 `HudController`、`GetHudSnapshotQuery` 与属性详情快照。
- 通过一次性 Editor 迁移工具或 Unity MCP 精准修改正式资产，复跑必须为零变更；完成后移除一次性入口。
- 更新属性系统、玩法循环、战斗内容配置参考和 alpha 总计划。

### 7. 综合验证与归档

- 运行定向 EditMode、PlayMode、全量测试和相关程序集构建。
- 在 Main 场景验证持续自动释放、耗蓝、法力不足、恢复、受伤恢复、死亡、复活和菜单暂停。
- 检查 1280×720、1920×1080、2560×1440 下 HUD 无遮挡、超框或属性详情回归。
- Unity Console 不得出现新增错误；完成后总结模块文档并将本计划移入 `Docs/docs/plan/archive/`。

## 验收矩阵

### 领域与 EditMode

- 23 个 `StatIds` 与 23 份 `StatDefinition` 一一对应，无重复、缺失或非法范围。
- 当前生命 / 法力在消耗、恢复和上限变化后始终位于合法范围。
- 最大生命和最大法力变化按冻结规则保持比例，零法力上限转换行为有专项测试。
- 固定时间窗的恢复量精确等于属性值乘以时间；零变化不产生事件。
- 法力不足、无武器和空伤害不会生成攻击快照，也不会推进玩家攻击随机流。
- 配置验证器拒绝负法力、负恢复和负技能耗蓝。

### PlayMode

- 玩家出生与复活时生命、法力均为满值。
- 每个成功投射物只扣除一次 `8` 点法力；失败释放不扣蓝、不播放攻击动画。
- 法力不足时投射物数量不增加，HUD 明确显示失败原因；恢复到足够值后能再次释放。
- 玩家受伤后以每秒 `1` 点恢复，法力以每秒 `5` 点恢复；死亡、禁用和菜单暂停期间数值不变。
- 菜单恢复后不会一次性补算暂停期间的恢复量。
- 换装导致上限变化时 HUD、属性详情和当前资源在同一帧保持一致。

### 回归

- 接触伤害仍按每只怪物独立间隔结算，不引入无敌帧或全局受伤冷却。
- 命中、闪避、暴击、五类伤害、防御分解和在途攻击快照行为不变。
- 背包、装备、商店、打造、掉落、暂停和手柄导航不回归。
- 架构反初始化后没有仍在运行的恢复任务或重复事件订阅。

## 预计影响范围

- 运行时：`CombatActor`、`CombatSystem`、资源事件、`FireProjectileCommand`、`PlayerController`、`GameArchitecture`、HUD 查询与控制器。
- 配置：`StatIds`、`CharacterDefinition`、`MonsterDefinition`、`ProjectileSkillDefinition` 及其验证器。
- 内容：玩家、基础投射物技能、三种怪物、魔力属性资产和两份新恢复属性资产。
- UI：`Hud.uxml`、`Hud.uss`，不改动背包工作台总体布局。
- 测试：新增 `Alpha014ResourceSystemTests` 与对应 PlayMode 集成测试，并更新依赖属性数量的既有测试。
- 文档：属性系统、玩法循环、战斗内容配置参考、配置索引和 alpha 总计划。

## 明确排除

- 不增加受击无敌帧、玩家全局伤害冷却或怪物伤害合并。
- 不实现主动施法输入、技能栏、技能选择、技能等级、法力药剂或保留魔力。
- 不增加百分比恢复、击中回复、偷取、延迟恢复或脱战恢复规则。
- 不为怪物新增施法技能；怪物法力与恢复仅建立通用底层能力。
- 不提前制作 23 属性完整词条、怪物词条或多帧技能特效，这些分别属于 `alpha 0.1.5` 和 `alpha 0.1.6`。
- 不读取或修改 `Docs/design/`。
