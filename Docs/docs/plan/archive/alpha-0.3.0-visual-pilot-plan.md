# alpha 0.3.0：代表视觉组件与布局收尾

> 状态：已完成；2026-09-08 代表组件、组合线框和阶段回归通过
> 建立日期：2026-09-08
> 上位计划：[独立窗口与交互拆分](alpha-0.3.0-independent-ui-windows-plan.md)、[alpha 0.3 总计划](../alpha-0.3-plan.md)
> 实现基线：`bacc208`；运行版本仍为 `0.2.7-alpha`

## 目标与边界

完成 0.3.0 剩余的整体布局线框和一个可在真实窗口使用的正式视觉组件，为属性详情、HUD 与统一皮肤提供可测量的规范。成功标准是运行时可读、可操作、材质和像素密度一致，不能只交付概念图。

本切片以“暗石内容底板 + 旧铁边框 + 少量金铜角部强调”的窗口基础面板为 Pilot。先在背包验证，再复用到商店和打造窗口，验证同一资产在不同宽度下的表现。窗口标题、关闭按钮、文字、物品、数量和输入提示仍由 UI 控件呈现。

不在本切片批量制作按钮、槽位、HUD 或 Shell 全套位图；这些家族先建立语义与尺寸规范。实时属性解释属于 0.3.1，正式 HUD 属于 0.3.2，全套皮肤属于 0.3.3，十槽领域、内容和旧档兼容属于 0.3.4。

## 实施顺序

1. **测量与补齐线框**：通过 Unity MCP / Editor API 检查真实 Main 的窗口、层级、样式和资源依赖。补齐“背包 + 独立属性详情”以及底部双资源仪表的组合线框；十槽沿用已有空间参考并核对与标题 / 操作区的关系。临时属性与 HUD 只验证空间，标明未实现，不留下无消费者的假控件。HUD 比较圆形与切角容器在预留区中的可读性，形成有依据的后续推荐。
2. **冻结生产合同**：依据已保留的 Game UI Kit 风格参考、批准的项目资产和实测消费者，确定下表所有数值。保存生成提示、引用和审计 manifest；必需数值仍无法确定时，先解决该项再生成，不能套用模板尺寸或旧 Border。
3. **生成单个 Pilot**：按 ImageGen 和 Unity 单图流程生成一个 Default 基础面板。先做逐图自动审计、原生像素与材质检查；失败则重新生成或按合同编辑。通过前不扩展家族。若角件无法安全九宫格拉伸，拆成独立装饰资产，每张仍只含一个组件。
4. **接入真实窗口**：通过 Unity MCP / Editor API 导入和验证 Sprite，绑定背包，再复用到商店 / 打造；样式以 `Theme.uss` 为主题入口，`Windows.uss` 保留布局职责。装饰层输入穿透、不参与焦点导航，不改变物品和交易事务。保留现有唯一活动窗口与唯一物品选择语义。
5. **运行验收与收尾**：执行下述视觉和交互回归，修复本切片引入的问题，审查测试价值并清理临时工具。更新视觉规范、资产清单、物品工作台及证据索引；归档本切片。逐项核对 0.3.0 总阶段成功标准，全部有证据后才归档父计划并按项目版本规则更新为 `0.3.0-alpha`，随后进入 0.3.1。

## 生成前必须完成的资产合同

| 合同项 | 确定方式 / 规则 |
| --- | --- |
| 参考与身份 | Game UI Kit 保留图仅作视觉语言参考；接受后的 Pilot 固定为后续家族参考，不改写原图 |
| 文件与消费者 | 生产目录 `Assets/Art/Sprites/UI/Frames/`，拟用 `ui_item_window_base.png`；消费者限定独立物品窗口，实际新增或原位替换由依赖审计决定 |
| 生成 / 交付画布 | 执行第一步后填写准确宽高；优先相同。工具不能直接输出时，生成前声明唯一全画布等比导出因子与采样方式 |
| 可见范围 | 记录 Alpha 阈值、包围盒范围、覆盖率、四边留白、视觉中心容差；底板满幅与透明角部按实际用途分别声明 |
| 九宫格 | 明确左 / 下 / 右 / 上 Border、角件保护区和边缘可重复区；不得让切线穿过铆钉、斜角或独特纹理 |
| 运行尺寸 | 从真实消费者记录最小 / 常规 / 最大宽高及背景 Slice 缩放；不能仅按源图 PPU 推断 UI 屏幕尺寸 |
| 导入 | Sprite Single、Full Rect、Point、无压缩、无 Mipmap；PPU、Pivot、Alpha、sRGB、Wrap 和 Slice 参数在生成前明确并自动设置 |
| 像素与留白 | 从屏幕实际效果确定边框厚度、像素颗粒、内容安全区和装饰明度；保持现有 10×6 背包和商人完整格子 |

本计划不伪造尚未实测的数值，也不将旧资产参数当作新资产已批准规格。新规范和 manifest 是执行产物。

## 状态与视觉规范产物

- 建立窗口外框、内容底板、标题、分隔、按钮、槽位、详情和 HUD 的材质 / 字体 / 留白表；区分本切片已验证值与后续待验证家族。
- 暖色正文和金铜强调要与现有中英字体可读性一致；生命红、法力蓝、有效 / 无效落点及稀有度保留明确语义，不让装饰颜色冒充物品选中。
- 定义 Default、Hover、Pressed、Selected、Focused、Disabled 的职责和优先级。普通按钮的鼠标悬停与手柄焦点可区分；物品高亮仍由共享会话唯一管理，不能额外叠加第二份焦点选中。
- 有效 / 无效拖放目标可提示区域状态，但不能将另一件物品画成选中。装饰和状态变化不改变尺寸，不使文本、命中区或方向导航发生跳位。
- 本切片不新增装饰动画；后续动效规范遵守 Reduce Motion，不用缩放动画掩盖素材尺寸问题。

## 验收与测试维护

| 验证 | 通过条件 |
| --- | --- |
| 单图与导入 | 每张 PNG 一个组件；画布、可见范围、中心、Border、导入和引用通过审计；三档使用尺寸无拉坏角件、模糊边缘或突变纹理 |
| 真实窗口 | 1920×1080 × 中文 / 英文 / Pseudo Locale，覆盖背包、商店、打造、背包 + 商店、背包 + 打造、背包 + 展开属性；标题 / 关闭 / 操作栏 / 六词缀详情无超框或重叠 |
| 后续空间 | 独立属性详情、底部 HUD 与十槽线框有清楚的空间证据；不将占位线框记录成已实现功能 |
| 鼠标与手柄 | 复用现有窗口与物品用例，覆盖点击、拖放、快捷操作、跨窗方向导航、唯一高亮、隐藏页签不进导航，以及设置 / 返回确认往返；新装饰不能拦截输入 |
| 生命周期 | Session 往返后无残留装饰节点、旧引用或资源句柄；正常路径 Console 零新增 Error / Warning，日志按实际级别判断 |

不建立版本专属测试套件，不以图片数量、像素常量、USS 字符串或历史截图存在性作为长期行为断言。优先运行并补充现有 UI / Shell / 资源回归；只有出现尚未覆盖且需要长期防止的命中、布局或资源故障时新增测试。资产使用现成单图审计工具，避免重写验证器。

完成集成后运行相关回归；0.3.0 阶段归档前执行一次完整项目 EditMode / PlayMode，记录实际计数，不重复无变化测试。截图、线框与审计报告放入 `Docs/docs/assets/acceptance/alpha-0.3.0-visual-pilot/`；临时截图脚本、预览对象、测试素材及无消费者夹具验证后清理，保留可复用导入能力和正式资产合同。

仅达到本切片视觉标准，不自动代表整个 alpha 0.3 完成；最终 Addressables、Windows Player 构建和真实 Player 综合流程仍遵循总计划。
