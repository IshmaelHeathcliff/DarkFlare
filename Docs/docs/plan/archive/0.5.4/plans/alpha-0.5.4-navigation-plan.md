# Alpha 0.5.4：批量导航与怪物移动

状态：2026-09-19，H1–H7 已完成并归档。版本 `0.5.4-alpha`、core v6、Schema 5；EditMode 722/722、PlayMode 85/85、独立 Player 性能矩阵与 20 轮往返通过。实现以[导航模块](../../../../maps/navigation.md)为准，完整方法和边界见 [H 验收](../acceptance/maps/h/README.md)。以下保留实施前合同。

## 交付与边界

在正式野外交付 Grid Navigation + Flow Field + Spatial Hash + Separation，特殊单位通过配置使用 A*；两种策略共享网格、足迹、安全检查和局部避让。使用 Job / Burst 执行纯数据计算，以同一 Session 的怪物移动替换现有全表遍历。验收规模保持 **500 活动怪物、1000 压力测试**。

保留 Rigidbody2D、现有战斗 / 属性 / 状态和两图冻结合同，不要求迁入 Entities，不采用 NavMesh 替代用户指定方案。首期地面圆形足迹，水和实体障碍不可穿越；不扩展飞行、游泳、多高度、建造玩法或严格无碰撞编队。Separation 为软避让，密集时可发生怪物间重叠，硬障碍安全不能降级。

## 所有权、物理步与行动许可

Session 注册 NavigationModel / NavigationSystem；地图持有网格、缓存、搜索池、动态阻挡和 Agent 容器。Controller 经 Command 注册 / 注销，通过 Query 获取必要状态，仅监听事件。句柄携带 Session generation、MapGeneration、槽位及复用版本；结果再带 GridRevision、AgentRequestRevision 和策略版本，不使用 Unity Instance ID 充当持久身份。

集中驱动使用受地图生命周期管理的 UniTask 固定步入口，H1/H4 实测其相对 Physics2D 的执行顺序。每步采样一次所有活动单位，再构建哈希、跟随路径 / 流场、分离及速度约束，主线程提交 Rigidbody2D 速度。移除旧移动写入；攻击仍走 Command，可由集中驱动按有效目标调用，不另建每怪物导航循环。

拓扑 / 搜索 Jobs 分批推进；转向输出使用明确的依赖屏障。只有已完成的输出可以读取，不得通过未同步访问追求零等待。允许沿上一轮已完成方向行进时，必须按当前步长、实际位置、行动许可和最新障碍重新验证；无安全结果则停车。暂停不补算积压物理步，死亡、禁用、眩晕立即清零。线程池和 Job 分工明确，不能把托管 CheckSegment 塞进 Burst。

切图预备态可构建目标网格，但不能成为活动速度来源；提交前使源图请求失效并完成所有访问其缓冲的 JobHandle，保留源资源供回退。提交成功后释放源图原生容器；取消和回退完成候选 Jobs 后再释放。Token 仅停止新调度，不能中断已运行 Job。保存捕获停在稳定屏障，只取导航意图；不等待无关搜索达到终点。连续 Session、外部场景卸载和应用退出复用既有生命周期任务组。

## 网格、动态阻挡与内存

Profile 的半径不得小于实际圆碰撞器的世界半径，使用有限配置组合，运行时缩放不支持静默复用旧 Profile。以材质代价和合法边为权威，Safe 区只禁刷怪，不凭区域名加墙。正向边成本沿用目标节点材质 × 10 / 14；反向积分使用对应正向成本。成本及积分使用足够宽的整数和 checked / 饱和保护，Unreachable 哨兵不与合法大成本混淆。

首轮配置上限建议：4 个通行 Profile、8 个共享场缓存条目、2 个 Flow 构建工作区、4 个 A* 搜索工作区、1024 个活动 Agent、128 MiB 导航原生内存。数量上限不能替代字节预算：申请前计算网格、双缓冲、堆、路径、哈希和搜索池总量，切图源图与候选的同时驻留也计入预算；按使用引用及 LRU 淘汰无主缓存，有主资源不能强行回收。更大地图或组合超过预算时返回明确 Capacity / Busy，不无限扩容。H1 用正式 512² 网格核对实际布局字节再固化设置。

动态硬阻挡采用稳定 stamp ID、footprint 和重叠计数；同一固定步边界同步更新导航修订与 Physics2D 投影。添加阻挡若覆盖活动 Actor 则拒绝并返回 Occupied，首期不引入挤出 / 瞬移规则。移动单位不写成硬阻挡。H5 用调试 Command 验证增删、重叠和预算拒绝，不新增建造玩法；调试 stamp 明确为当前地图临时状态，离场清除，不伪装成可存档的门或建筑。

Job 中不能使用过期网格证明新墙安全；提交速度前用最新阻挡快照检查实际位移 swept circle，包括分离向量和接入路径。阻挡新增后立即停用不安全旧结果，移除后可等待重建。只有同修订完整网格 / 场 / 路径可作为新发布结果。

## 流场、A* 与目标更新

Flow key 包含地图 generation、网格修订、Profile、目标集身份及已接纳的目标节点。首轮最多每 100 ms 接纳一次目标格重建；同格微动只更新局部到达目标。每 key 一个进行中的候选和一个合并后的最新请求，持续移动不能不断取消同一个搜索而永远无结果。已接纳目标的完整结果可作有标记的短暂旧目标引导，前提是地图 / 拓扑 / Profile 仍有效、目标仍存在且局部段安全；它不代表最新目标已就绪，等待延迟继续累计。目标注销 / 显式换目标身份时立即失效，禁止绕开请求版本检查。

A* 使用同一合法边与成本，octile 启发式乘最小正代价；无法证明下界时使用零启发式。分批扩展保留前沿，搜索池在 Flow 与 A* 间保留公平配额，并加入等待时间防饥饿。移动目标同样采用已接纳搜索与最新待处理请求，不能每帧丢弃前沿。Pending / Busy / BudgetExceeded 与 Unreachable 分开；只有前沿穷尽才报告无路，不采用未到终点的部分路径冒充成功。路径返回时检查单位当前点能否安全接入；传送或过大偏移使结果失效。

旧目标场 / 路径的引导滞后上限首轮设为 200 ms（500）/ 400 ms（1000），超过即停车等待，不用持续发布旧目标掩盖目标延迟。该时限单独记录，不能把同一目标身份的连续移动都误判为目标已注销；显式换目标、拓扑变化仍遵守立即失效与安全检查合同。

路径平滑必须验证整段净空；最短代价测试用原始格路径。流场缺失不会令全体自动退化为 A*。切换模式先递增请求版本并释放原策略引用，等待期间安全停止，同一单位只有一种策略输出。接近目标后的直达也要验证足迹和视线，不能隔墙靠距离绕开导航；攻击可达检查与移动足迹检查分别定义，避免要求整个怪物身体穿入玩家中心。

空间哈希按格键和稳定 Agent ID 排序，查询范围随实际半径变化。候选访问先限制为每 Agent 96 次，再从候选中选至多 24 个邻居；不是扫描完整密集桶后才截断。稳定轮换覆盖和同点两方相反退让避免偏序与 NaN。记录饱和、等待和卡住原因；拥堵重算有冷却，不能诱发每单位每帧全图搜索。所有策略共用同一索引和分离链路。

## 导航意图与兼容

默认模式 / Profile 由 MonsterDefinition 读取；命令可切换模式或指定同地图稳定 Actor / 固定点目标。正式开放的运行时模式覆盖、语义目标和到达规则须随 MonsterRunStateDto 跨图冻结及恢复；默认追踪玩家用语义标记，不保存对象引用。目标死亡、注销或不属于当前图时输出 TargetUnavailable 并停止，不偷换成其他目标。

因此 H5 预计追加 Schema 4→5，历史怪物缺省为配置模式和玩家目标，保留 0→4 迁移、原身份 / 掷值 / 状态 / RNG；未知未来模式和非法目标引用在预检阶段拒绝。网格、搜索队列、路径和临时调试阻挡不入档。H1 冻结 DTO 合同，H5 实际接入时才修改版本；仅配置现有怪物模式不要求新增内容 ID，是否调整 core 版本以最终内容变化为准，不提前修改当前 core v6。

## 性能验收与失败处理

沿用[性能预算](../../0.5/plans/alpha-0.5/navigation.md#性能预算与测量)，首轮机器采用 G 的 Ryzen 7 PRO 8845HS / Radeon 780M，Unity 6000.6.0f1，1920×1080、正式画质及约 50 Hz 物理步。H1 补记核心数、后端、Burst 及安全检查状态，避免把不同构建互相比作优化收益。

| 场景 | 帧时间 P95 | 导航主线程 P95 | 导航关键路径 P95 | 最新目标 / 拓扑及 A* 路径可用延迟 P95 |
| --- | --- | --- | --- | --- |
| 500：480 Flow + 20 A* | ≤16.7 ms | ≤2 ms | ≤4 ms | ≤200 ms |
| 1000：950 Flow + 50 A* | ≤33.3 ms | ≤3 ms | ≤8 ms | ≤400 ms |

关键路径包含等待依赖的耗时，不把 worker 时间简单相加；新墙最迟下一物理步阻止穿越。预热后导航稳态 GC Alloc 为 0 B/tick，原生内存 ≤128 MiB。配置改变和受限扩容的分配单列。沿用 F 的有效 GC 采集探针，不把 ProfilerRecorder 的事件耗时当成分配字节。

每场固定种子，预热 10 秒、记录至少 60 秒、重复 3 轮；公布 P50 / P95 / P99 / 最大值、队列等待、候选饱和、缓存命中、原生内存峰值及实际活跃数量。压力工具持续维持目标规模，不能让怪物被杀后不足 500 / 1000 仍算通过。分别测纯导航、正式渲染 / 物理 / 动画 / HUD 集成、实际攻击 / 状态 / 掉落负载；隔离玩家数据，明确保活和补怪方法及其成本。

Development Player + Profiler 归因，普通 Player 复核帧率；关闭 VSync 和帧率上限，禁止 Deep Profile 数据作基线。测量全局目标移动、多个独立 A* 目标、U 形绕行、窄口、断路、集中出生、动态开闭、连续策略切换及请求饱和。20 轮切图后，预热稳定点的 Agent、owner、lease、路径池及原生容量回到相同基线，不能持续积累。

若总帧率不达标，分离导航、物理、表现、战斗与存档影响并修复热点；不得用只测 Jobs、降低单位数或关闭正式表现替代验收。G 的大 DTO 临时分配是已知观测：冻结 / 继续与导航原生峰值要联合测量，避免只在空存档测切图。与导航无关的性能工作须由实测证明必要，不顺便重构整套玩法。

## 验证、文档与首个执行单元
