# Alpha 0.6.3：普通怪物有限刷怪执行计划

状态：2026-09-23，**S1–S6 已完成并归档**。上位[Alpha 0.6 总计划](../../0.6/plans/alpha-0.6-plan.md)与[刷怪／重置合同](../../0.6/plans/alpha-0.6/spawning-and-reset.md)；现行实现见[有限刷怪模块](../../../../behavior/finite-spawning.md)、[地图生命周期](../../../../maps/world-map-lifecycle.md)和[本地存档](../../../../infrastructure/local-save.md)。启动基线为 `0.6.2-alpha`、地图 V3、core v8、Schema 7；S1–S6 初次交付为 `0.6.3-alpha`、V4、core v9、Schema 8，后续配额调整升至 core v10、地图 r9。阶段结果见[验收记录](../acceptance/behavior/README.md)。

## 目标与边界

新建刷怪地图实例时，预定固定的普通怪物名额 `N = 初始批次 I + 各范围触发批次之和 T`。初始批次在地图可交互前生成；触发批次仅在玩家首次进入各自范围后生成。怪物死亡不补充，同一批次不重复激活。正常离场、回图和存档继续保留每个名额与怪物的状态。Boss 使用已有独立点位及名额，不计入普通 `N`。

0.6.3 只交付有限刷怪。玩家手动重置地图、实例代次及重置后的再次刷新属于 0.6.4；本阶段不引入自动重置、击杀补怪或新 NPC 行为。旧档已访问地图无法推断历史击杀总量，保留现有怪物和 Boss 状态，停止旧式补满，不倒推新增名额；首次新建地图直接使用有限计划。

本阶段的成功标准是：对正式野外图，配置的初始数与触发数之和等于预定总量；重复触发、死亡、切图、保存继续和失败回退均不增生、不遗漏名额；未触发批次不创建怪物对象。自动回归和编辑器实际场景流程通过，文档与配置同步更新。`0.6.2` 的 Windows Player 豁免不写成实测通过；0.6.3 计划不以本机受签名策略阻断的 Player 启动作为完成条件。0.6.5 的 300 常规／600 压力综合目标暂保留。

## 当前接入点与数据合同

- `MonsterSpawner` 目前用 `SpawnInterval` 周期性补到 `MaxAliveCount`，只保存运行标记和下次尝试时间；这不能代表固定总量。替换为地图作用域内的名额调度，不以活着的 `MonsterController` 数量推断余量。
- 地图 V3 的 Spawn 区域已有 `spawnDefinitionId`，且运行时暂限同图只用一个定义；`bossSpawns` 独立。拟升地图交换格式为 V4，增加稳定的普通刷怪批次：批次 ID、关联 Spawn 区域 ID、数量、入图／范围触发模式，以及触发中心和半径。区域继续定义合法生成范围并引用加权怪物池；批次定义数量与激活条件。解除同图单定义限制，不把坐标复制进 `MonsterSpawnDefinition`。
- `MonsterSpawnDefinition` 保留怪物权重池；原 `MaxAliveCount` / `SpawnInterval` 只作为旧版迁移语义，正式 V4 不能再用它们补怪。是否保留分帧节流字段及内容版本升级，在 S1 冻结；不能把节流计时等同名额。
- 每个新实例保存一份不可因回图而重掷的计划：地图修订、计划种子、批次 ID、名额 ID、选中的怪物内容 ID、生成随机种子、生成区域与当前状态。名额状态至少区分 `Pending`、`Alive`、`Defeated`；已触发但暂未完成的名额仍是 Pending，并保存批次已激活标记。怪物实例 ID 只在真正创建成功时分配，之后与 Alive 名额一一对应。
- 活动图与冻结图使用相同 DTO。优先扩展 `MapStateDto` / `RunSaveData` 中的刷怪状态与 `SessionSnapshotSource`、`WorldMapRuntime`、恢复预检和严格校验链；不另建第二套地图状态。预计需 Schema 8 和显式 7→8 迁移，最终版本在 S1 以序列化合同确认。

位置从关联 Spawn 区域按名额种子确定候选，使用现有足迹、地表、障碍和 Safe 区规则。激活时复核占用与地图代次；位置被动态对象临时堵住时保留 Pending 并有界重试或明确报错，不消耗名额，也不传送到玩家脚下。资源在地图候选准备期预热，初始批次完成后才开放交互；触发批次按每帧预算分批创建，由 MapScope / Session 取消管理。触发范围用玩家上一位置到当前位置的线段与触发圆求交，覆盖高速穿越；它只决定生成，不改变怪物本身的激活、视野和攻击规则。

## 验收重点

1. 新图首次进入时仅生成 `I`，其余 `T` 保持 Pending；同种子、同地图修订的计划稳定，`I + T = N`，Boss 单列。重复进入触发区、多区同帧命中、玩家高速穿过或暂停均不重复生成。
2. 击杀后名额为 Defeated，不再补怪；尚未触发的名额跨切图与进程继续仍为 Pending。触发中保存／离场后继续只补该批未完成名额，已创建对象保持同一身份与状态。
3. 几何或动态占用失败、资源预热失败、候选切图取消和回滚均保留原图及名额；配置整体无法满足固定数量时在进入交互前失败并给出批次与区域。
4. Schema 7 的活动图与冻结图及更早历史链经迁移后不凭空补普通怪物或 Boss；真实历史存档的怪物、掉落和玩家数据保持不变。新游戏与旧档未访问地图采用 V4 计划。
5. 调试与自动证据分开记录。Windows Player、跨进程独立进程操作及 300／600 实测若仍受系统策略阻断，记为未执行；不以 PlayMode 结果替代。
