# 0.7.1 技能重构与六键施放合同

状态：2026-10-15，**阶段四已实现并通过验收**。当前 `0.7.1-alpha.4` / core v13 / Save Schema 12；见[运行模块](../../../../skill-board/manual-skills.md)、[效果规则](../../../../skill-board/effects.md)、[归档计划](phase-4-execution.md)与[验收](../acceptance/manual-skills/README.md)。合同继续保留，供阶段五正式界面复用。

2026-10-16 补充：实现与玩家操作均已完成，本文作为确认合同归档；现行行为见[玩家棋盘](../../../../skill-board/player-board.md)，历史阶段版本含义保留。

## 已确认目标与默认交互

- 移除玩家默认自动施放循环；进入游戏、遇到敌人、冷却结束、复活或继续存档，都不能自行施放技能。
- 提供 6 个技能输入槽，按键请求施放对应槽位的技能。空槽不能回退到默认技能；安装火焰获得火焰技能来源，与分配施放槽位是两种操作。
- 原技能改为武器普通技能：装备武器即可获得，不要求火焰、柴薪或天赋点；每种武器配置各自普通技能，换装 / 卸下同步更新来源。**普通技能使用独立普攻键，六槽全部留给火焰**。
- 六个输入槽不等同于棋盘六空洞编号，也不限定可拥有的技能总数；来源须区分武器能力与有效火焰实例，不能只存技能定义 ID。两个同定义火焰保留各自范围效果来源，**同一火焰最多分配一个槽**；换槽采用原子移动，不能复制绑定。
- 默认键鼠键位为 `1`–`6`，支持现有设置页重绑定、冲突校验、恢复默认和设备 Glyph。每次按下请求一次施放；本版不默认加入按住连发、自动重试或自动施放开关。
- 瞄准已确认：键鼠指针方向、手柄右摇杆方向，无有效方向沿用上次方向，首次默认向右。有效瞄准不被移动朝向或自动寻敌覆盖，目标出现不触发施放。

拟定默认输入（实施前核对手柄操作舒适性，所有槽位均可重绑定）：

| 输入槽 / Action | 键鼠 | 手柄 |
| --- | --- | --- |
| 普通技能 / `Attack` | 鼠标左键 | 西键（X / Square） |
| 1 / `Skill1` | `1` | 东键（B / Circle） |
| 2 / `Skill2` | `2` | 南键（A / Cross） |
| 3 / `Skill3` | `3` | 左肩键 |
| 4 / `Skill4` | `4` | 右肩键 |
| 5 / `Skill5` | `5` | 左扳机 |
| 6 / `Skill6` | `6` | 右扳机 |

世界交互继续使用 E / 北键，菜单与暂停沿用现有绑定。东键、南键、西键、肩键和扳机在 UI Context 仍属于 UI 操作；Map 切换与 suspension 必须阻止它们穿透施法。保留 `Attack` 的鼠标左键 / 手柄西键绑定，新增 `Skill1` 改用东键，不能一按触发两种技能。Gameplay 中左键点击 HUD 等可交互 UI 时也必须阻止同次普攻。本次规划未修改输入资产。

## 现有实现与重构范围

| 入口 | 当前实现 | 本版修改要求 |
| --- | --- | --- |
| `PlayerController` | `TryStartAutoCast` / `AutoCastLoopAsync` 按间隔调用默认技能；配置、启用和 Restore 都可能启动循环 | 移除自动启动与循环；角色 Controller 适配输入 / 角色生命周期，技能状态与冷却移入 Model / System。 |
| `FireProjectileCommand` | 校验伤害来源、动作权限、法力并生成投射物，没有槽位、火焰身份或冷却校验 | 玩家施放入口先证明槽位 / 来源、权限、输入上下文及冷却，再复用投射物和攻击快照管线；不得仅靠 UI 禁用防止绕过。 |
| `PlayerSkillStateRegistry` | 单个技能定义和剩余自动施放间隔的只读适配 | 提供六槽及其技能来源、剩余冷却、耗蓝、可用性和失败原因快照；查询和 HUD 不推进时钟。 |
| `ApplicationInputService` / `GameInput` | Application 唯一 Action Asset owner；Session 适配移动、交互、菜单等；`Look` / `Attack` 未驱动正式手动施法 | 在既有 Player Map 中接入六个 Action，完善 Session 订阅 / 解除、重绑定目录和显示；不创建第二套输入资产或轮询具体设备。 |
| 武器 / 场景配置与预热 | `ItemBaseDefinition` 无普通技能引用，场景 `PlayerSkill` 决定单一默认技能 | 武器分别引用普通技能，真实来源决定预热和内容校验；不再以场景默认技能作为所有武器的权威能力。 |
| HUD / 属性详情 | 显示单个自动攻击名称、间隔与状态 | HUD 显示六槽绑定、图标 / 名称、冷却、耗蓝和不可用原因，空槽可辨；属性详情按来源解释当前技能效果，不继续把单一默认技能当全部技能。 |
| `PlayerRunStateDto` | `SkillContentId` 与 `AutoCastCooldownRemainingSeconds` | 迁移至可证明的技能来源、六槽引用与技能冷却集合；旧自动施放字段只用于历史迁移，恢复不启动循环。 |

运行时合同依据见[技能配置](../../../../config-reference/skills.md)、[输入 UI](../../../../input-ui-system.md)、[战斗 HUD](../../../../hud-system.md)、[存档](../../../../infrastructure/local-save.md)。这些模块文档仍描述现有实现，完成实际重构后再同步功能合同。

## 状态、施放与失败边界

- 技能槽引用权威技能来源；火焰取回时相关槽位原子清除，失效时不得施放旧定义。普通技能绑定当前武器能力入口，执行时证明实际武器仍装备；换武器后的旧请求失效。旋转和重新连通重算火焰效果，不改变物品身份。
- 火焰拟按实例计冷却，普通技能拟按玩家普通技能入口计冷却；同定义不同火焰独立，普通技能换武器保留剩余等待。换槽、取回再安装、卸下再装备不能重置冷却。同一火焰的多槽引用直接拒绝，不采用“多槽共享”方案。
- 施放由 Command / System 校验：槽位与来源仍有效、角色存活、Gameplay 允许、未暂停 / 挂起、动作权限、冷却就绪、伤害来源合法、法力足够及瞄准有效。Controller 只发请求和读取状态，不自行扣法力或维护权威冷却。
- 成功后提交一次法力消耗、一次冷却和一次攻击事件；空槽、冷却中、法力不足、来源失效、生成失败或取消不扣法力、不启动冷却、不排队补发。攻击随机流仍沿用既有消费边界，不默认承诺生成失败回滚已取得的随机种子。
- 冷却遵循玩法时间与暂停，保存的是剩余值；输入和 HUD 查询不能推进冷却。读档、重绑定、打开 / 关闭菜单、重新分配槽位不能清除冷却。
- 进入 UI、重绑定捕获、失焦 / 平台挂起、死亡及 Session 关闭时，丢弃待处理的施放请求。恢复 Gameplay 后旧按住状态不自动施放，释放后重新按下才产生新请求。
- 请求捕获槽位 / 技能来源及瞄准快照；异步资源步骤绑定 Session / Scene 取消，提交前复核来源与权限。按键触发后的面板或装备变化不能让另一枚火焰 / 另一把武器继承旧请求。

## 天赋、余烬与普通技能

- 用户已确认局部范围按**已点亮网络的最短连线路径**计算：每条内部连线或裂缝连接计 1 步，跨空格长连线也只计 1 步，未点亮天赋阻断；普通天赋从自身节点、余烬从所在裂缝节点到火焰中心，包含范围边界。Radius = 0 沿用全局天赋含义，详见[阶段四规则表](phase-4-execution.md#已确认规则)。
- 火焰技能受所属柴薪激活及独立天赋点亮规则约束；天赋 / 余烬按具体火焰实例投影。武器普通技能不需要棋盘坐标，不作为余烬 / 局部天赋的火焰目标；角色全局效果和合法装备效果沿用已有管线。
- 火焰自身词条只作用于自己；同技能定义的武器普通技能与火焰也不能串用局部效果。攻击快照分别保留技能、能力来源和实际武器伤害来源，不能覆盖原 SourceItemId 的武器语义。

## 存档与设置迁移

- 六槽的技能分配属于玩家 / Session 数据，键鼠 / 手柄的 Binding Overrides 属于 Application 设置；不得把键位写入火焰道具或把技能分配写入共享设置。
- 旧 `SkillContentId` 与剩余间隔在阶段四迁移为武器普通技能来源及剩余冷却，独立普攻入口可用，六火焰槽初始为空。按当前装备武器解析技能，旧定义与新映射差异须有明确兼容处理；没有武器时保留不可用状态，装备合法武器后获得普通技能。新游戏沿用已有起始武器，不赠送柴薪 / 火焰或免费点亮，不改写成长账目。
- 旧设置中新 Action 使用默认绑定，若新默认与历史覆盖冲突，则保留历史覆盖并为新入口选空闲键；原有 Glyph 偏好保留；新 Action / Binding 身份稳定，已有身份不能因重新生成输入代码而重建。是否升级设置 Schema 根据实际格式变化决定。
- 保存 / 恢复预检覆盖来源类型、武器装备关系、同一火焰重复分配、重复 / 越界槽位、无所有权的火焰引用、非法冷却、内容缺失及技能与面板不一致；失败不污染当前 Session。

## 阶段落点

阶段二已按[归档实施计划](phase-2-execution.md)准备火焰稳定来源，保留当前可玩运行时；阶段三已交付[能量兑换与柴薪 / 天赋点亮](energy-progression-contract.md)。阶段四按本轮新增规则交付武器普通技能、六键手动施放、正式旧技能迁移、冷却、最小六槽 HUD，以及按路径计算的天赋 / 余烬效果。基础瞄准、重绑定与 UI 隔离在本阶段验证；阶段五完成正式棋盘、玩家技能分配和整体视觉 / 操作验收。不能把移除自动循环单独记作技能重构完成。
