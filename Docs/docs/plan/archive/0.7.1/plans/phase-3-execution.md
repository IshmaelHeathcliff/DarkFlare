## 交付与成功标准

交付中心瓶子选择 / 预览 / 消费、角色充能池、递增兑换、两类点数、力量 / 敏捷 / 智力分配、柴薪 / 普通天赋独立点亮，以及对应保存、恢复和开发验证入口。永久属性分配在本阶段进入实际属性管线；天赋词条、余烬效果、火焰技能资格消费和六键手动施法由阶段四统一接入。正式玩家棋盘和手柄完整操作仍由阶段五收尾。

成功标准：每份能量和点数都有唯一权威来源；整瓶消费与成长一次提交；取消或失败零部分变化；分瓶与合瓶兑换结果一致；花点、退款、换瓶和恢复均不降低累计兑换序号；当前玩家的永久属性只重建一次。点亮、拓扑与物品所有权一致，不能通过旋转、取回、交易或旧预览复制点数。

## 已确认规则

已确认：未满瓶也可充入全部实际能量并消耗整瓶；剩余能量跨瓶累计；每获得 1 天赋点同时获得 1 属性分配点；后续天赋点成本递增；柴薪与普通天赋分别花点。阶段二收集、容量舍弃和手动换瓶规则继续复用。

2026-10-15 用户要求“按照建议实施计划”，确认采用下表三组建议：首轮数值、按路径点亮、取回清除记录并退款。下表中的其他候选仅保留当时选择背景，不进入实现。

| 组 | 建议 | 选择影响 |

裂缝开放表示激活资格，不能改变阶段二的几何安装合同：未点亮柴薪仍可预先布置，连接裂缝与余烬保持互斥，中柴薪中心仍为空。中心火焰“开放”在本阶段提供资格查询，实际六槽消费在阶段四；保留当前单技能和剩余冷却，避免提前切换造成无法战斗。

采用路径方案，普通天赋只沿保存的显式边检查，不用格子相邻代替连线；跨空格连线可通行。大柴薪中心为起点，中小以实际连接到有效激活网络的裂缝为起点，未接入的裂缝不能凭空作为起点。多入口、环与第二根使用图遍历，不依赖安装先后或父子树。旋转 / 重连既不能自动花点，也不能悄悄丢弃激活；候选最终态须继续满足激活合同。

### 1. 状态与配置

新增独立成长 Model / System，绑定当前 Profile PlayerId。不可变状态保存角色池余额、累计获得天赋点数、可用天赋 / 属性点、三属性已分配点、柴薪与局部 Talent 节点激活及实花点数；节点键使用 ItemInstanceId + 稳定局部 NodeId。点数属于当前角色，不能写进可交易柴薪变体或共享资产。

成本配置采用 ScriptableObject / Odin，字段中文标注，先支持正基础值与正增量的线性曲线，避免为首轮无消费者的复杂曲线扩展。保存明确成本合同版本，配置变更不得自动重新兑换旧余额。角色池和累计成本用受检整数求和；点数范围与属性消费者精度预检，超限整次拒绝。计算采用累计成本与有界搜索或等价受限算法，避免按巨大输入能量无界逐点循环。

权威守恒覆盖：可用属性点 + 三属性已分配点 = 累计获得点数；可用天赋点 + 当前有效激活记录的实花点数 = 累计获得点数。返还天赋点不修改累计兑换序号；分配不依赖装备或瓶型。

### 2. 中心与消费

中心选择是短暂引用：持有玩家 / Session、原容器、实例 ID 和预览 Revision，原物品仍在背包或专栏，不增加持久化中心所有者。切换选择、取消、关闭或 Session 结束清除选择；物品已移动 / 出售 / 换装后选择失效，禁止自动改指另一瓶。

预检读取瓶内实际能量、所有权、背包 / 棋盘 / 成长状态和成本配置，生成完整最终态。充能允许未到下一阈值，仅消费瓶并增加池余量；零能量返回明确失败。专栏瓶被消费后专栏清空，不自动换瓶；背包瓶消费释放它的 2×1 占位。

复用 SkillBoardSystem / InventoryModel 的最终态提交模式，增加最小的内部协调接口，由一个正式提交边界更新容器和成长，不先调用一次“移除瓶”再另行发点。提交前复核身份、状态引用 / Revision、瓶 Revision、所有权、配置及 Session；预览后继续积蓄、分配、点亮或移动使预览过期。通知只在全部状态一致后发布并标脏，已消费预览不可重复提交。

### 3. 永久属性

为力量、敏捷、智力建立独立稳定成长来源，使用已有 GlobalActor / Flat 修改器和 CombatActor 的 PrepareEffects / SetModifierSource 管线；源数据始终来自分配记录，替换该来源，不累加到已派生 StatBlock 或 CharacterDefinition。

属性分配预检可用点数、当前玩家、目标 StatId、成长 Revision 与 Actor 属性 / 资源投影。复用 ActorEffectPreparation 的有限值 / IsCurrent 校验，准备成长与实际属性的完整最终态后一次提交，再发资源 / 成长通知。生命 / 法力按现有上限变化保持比例；力量每点派生生命 2、敏捷派生命中 / 闪避各 1、智力派生法力 2，沿用 PrimaryAttributeResolver，不增加第二份公式。

属性详情读取真实成长来源和已分配值，本地化使用既有 stats / ui 表；打开窗口查询不消费点、不改变资源、不推进随机流。复活和重复重建不会重复叠加；死亡或 Session 解绑的行为沿现有玩家生命周期明确验证。

### 4. 点亮与安装协调

点亮候选同时验证所属物品在当前棋盘、节点角色、未激活、余额和最终激活资格。大中心 / Crack 不能伪装为普通 Talent 扣点；柴薪与普通天赋各自有明确操作，点亮柴薪不批量点亮周围天赋。资格查询提供稳定 ID、可点亮 / 已点亮和失败原因，供阶段四、五共用。

SkillBoardSystem 的 Move / Remove 候选加入成长预检，旋转、重连与跨根仍按完整最终几何和激活网络判断；拆卸先取出火焰 / 余烬的顺序保持。按照最终取回政策在同一次事务处理资产返回、激活记录和返还点数；背包满、断根 / 断激活路径、记录损坏或旧预览均完整失败，不自动回收其他柴薪。

此阶段保存实际 Talent 效果但不应用天赋 / 余烬伤害词条；阶段四按正式激活查询重建全局 / 火焰局部效果。起始技能沿现有可玩路径保持，阶段四迁移到有效火焰来源时另确定起始供给 / 点亮政策，不能依赖尚未开放的技能获取第一份能量。

### 5. 持久化与版本

成长状态随 Profile 保存，物品继续只在统一 Items 表出现一次；临时中心选择不入档。SessionSnapshotSource、DTO、Mapper、Validator、Detached、SaveRestorePreparer、Restore initializer 和 SaveCoordinator 同步接入，不能由成长 System 单独读写文件。

拟升级 Save Schema 11，补 10→11 默认空成长迁移；旧瓶能量、棋盘拓扑、实际变体、原技能 / 冷却、资源和随机状态完整保留。预计正式配置接入时评估 core v12；Settings Schema 1、地图 V4 保持，只有实际合同变化才推进。运行版本仍为 alpha.2，本阶段验收后才进入 alpha.3。

Restore 在启动 / 替换 Session 前验证非负值、守恒、成本合同、三属性、重复激活、未知节点、非所属物品与资格网络。先恢复分配来源、装备和状态的实际属性，再恢复最终生命 / 法力，防止按旧上限裁掉资源。读档不再次消费瓶、兑换、退款或发点。

保留阶段二 Schema 10 基线及有真实玩家数据来源的历史夹具；新增旧档样本必须记录来源，不能把人工生成或历史迁移导出的样本称为原生玩家采集。恢复 → 再保存 → 再恢复验证完整幂等，新增长字段默认值的历史比较须明确验证，不能只删除字段后宣称兼容。
