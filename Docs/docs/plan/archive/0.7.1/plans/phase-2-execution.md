## 本阶段结果与边界

交付柴薪 / 火焰 / 余烬的正式道具身份与固定变体、权威棋盘安装状态、安装 / 旋转 / 连接 / 拆卸事务、背包取回和交易保存；交付三种 2×1 能量瓶、专属栏、怪物死亡积蓄及瓶内能量保存。通过开发调试入口完成可重复的运行验证，再交付正式玩家界面。

中心充能、兑换点数和点亮在阶段三实现；六槽手动技能、冷却与效果在阶段四同时切换；完整棋盘与手柄操作在阶段五收尾。本阶段仅保存火焰的稳定技能定义和安装来源，为后续六槽提供查询依据，保留当前单技能运行与冷却，不提前删除自动循环或生成一份不工作的六槽状态。

成功标准：所有道具始终只有一个所有者；失败事务不改变资产或拓扑；旋转、交易、切图和读档不重掷变体；装备瓶才能承接本玩家的有效击杀能量；恢复新状态不重放击杀或破坏原技能可玩性。

| 对象 | 规则 |
| --- | --- |

| 裂缝 | 已连接柴薪的裂缝不能再安装余烬；有余烬时也必须先取出才能连接，不静默替换。 |

| 末端判定 | 拆下当前单件后，其他所有柴薪仍须连接至少一个初始空洞；适用于成环和跨根网络，不用连接数或安装顺序代替连通性。剩余棋盘为空时允许取回最后一件。 |
| 中柴薪中心 | 始终留白，暂时不能安装任何道具；留白仍属于完整主体占位。小柴薪没有中心插槽。 |

| 获得渠道 | 柴薪、火焰、余烬、能量瓶四类均可从怪物掉落与商店购买获得，接入既有加权掉落与商店货池。 |
| 能量瓶 | 只有装备在专栏的瓶子能收集；超过剩余容量的部分直接舍弃，满瓶停止收集，必须手动更换装备瓶子。小 / 中 / 大容量暂定 **1000 / 2000 / 4000**。 |
| 瓶子价格 | 用户指定随容量档位类似增长，小瓶基价暂定 **100**；按前述容量倍率暂列中瓶 **200**、大瓶 **400**，复用现有交易定价。 |
| 怪物收益 | 每种怪物配置基础能量；词条数量越多、怪物整体稀有度越高、词条自身稀有度越高，能量收益越高。两种稀有度均影响收益，具体基础值与加成公式待定。 |

## 尚待确定的细则

以下平衡参数采用首轮暂定值推进实现，不视为用户确认的最终平衡。

| 待确认项 | 建议与影响 |
| --- | --- |
| 收益的平衡配置 | 首轮采用普通 / 魔法 / 稀有 / 独特四级（0–3），怪物和词条定义分别配置等级；不从生成权重推断。收益 = 基础能量 ×（1＋怪物等级）＋词条数 × 数量加成＋词条等级总和 × 稀有度加成。普通怪物基础值暂定 10、两项加成各 5；均可调，使用非负整数及溢出检查，不需浮点取整。 |
| 内容池与起始供给 | 掉落 / 商店渠道已确认，具体池权重与货品配置待实施时整理；起始柴薪 / 火焰供给结合阶段三 / 四的点亮与旧技能迁移确定，不在恢复时反复赠送。 |

专栏交换沿用现有背包装备事务：新瓶来自明确背包位置，旧瓶必须在候选最终背包中有合法位置，失败完整回退。中心操作拟定为选择背包或专栏中的瓶子并保留原所有者，关闭 / 取消只清除选择；阶段三确认充能时从原容器原子消费。中心选择是短暂引用，不新增持久化所有者，瓶子持续积蓄会使旧预览失效。

### 1. 配置与唯一实例

- 复用 `ItemBaseDefinition`、`ItemInstance`、`ItemInstanceId` 和 `item` 内容身份。新角色采用明确类型 / 能力与组合配置，不伪装为饰品；保留已有枚举值、十个战斗装备槽和它们的效果计算。四类新道具拟定单件不堆叠，防止不同布局 / 技能 / 瓶内能量合并。
- 柴薪引用阶段一生成模板；实例保存实际布局、局部节点 ID、显式边、端口方向、生成合同版本，以及已经生成的天赋内容 / 词条数值。火焰保存稳定技能内容引用与实际变体；余烬保存强化内容引用与范围配置。此阶段不应用天赋 / 余烬战斗效果，也不自动点亮。
- 为新道具明确词条能力和合法内容池；现有 `TryAddAffix` 只接受战斗装备，不可直接放宽所有非装备。复用已有修改器与数值抽取，新的节点效果元数据留给阶段四消费；不顺带增加打造配方或价格公式。
- 四类道具均接入现有 `LootTableDefinition` 与 `TraderDefinition` 货池，三档瓶均有合法内容引用；实际掉落 / 库存生成、拾取、购买、售卖与恢复共用实例创建 / 映射，保留已生成的布局与瓶内能量。
- 实例初始化覆盖 `ItemBaseDefinition.CreateInstance`、掉落、商店、起始供给等实际创建入口。种子从既有物品种子派生独立子流；不新增无消费者随机通道，不为了生成布局消耗攻击随机流。Restore 只读取实际结果，不调用生成器重掷。
- 新配置通过现有 Odin / 内容目录 / 配置校验 / Localization / Addressables 流程接入。阶段一生成模板属于非内容配置，新物品基底和需要独立身份的效果配置按正式内容登记，不能为凑目录把非内容模板变成第二套物品身份。

### 2. 权威棋盘与事务

- Model 持有当前玩家的已安装物品 ID、锚点、六档旋转、节点嵌入关系、端口配对及 Revision；System 计算候选最终态，Command 提交，Query 返回布局与失败原因。连接是可成环、可跨根的图，不以父子树决定所有权。
- 每件道具的权威归属为背包、棋盘柴薪位置、柴薪火焰 / 余烬插槽、能量瓶专栏或已有世界掉落 / 商店之一。棋盘从统一物品集合引用实例；嵌入物不能同时留在背包。当前背包仅服务当前玩家，沿用 Session / Profile 身份，禁止硬编码玩家或跨档共享 Model。
- 大柴薪安装到六个根，中 / 小从合法裂缝接入；用现有 `FirewoodPlacementValidator` 校验整个候选棋盘。显式选择 / 校验配对，每裂缝最多一个连接；连接与余烬互斥，中柴薪中心拒绝所有道具。棋盘无固定边界，三类棋盘道具的背包占位均 1×1。
- 柴薪仍含火焰 / 余烬时拒绝拆卸，先逐件手动取回嵌入物。柴薪逐件断连 / 取回，候选最终态中其他柴薪均须经有效连接到达至少一个剩余初始空洞，同时预检背包和恢复外伸格；通过第二个根仍连通可以拆，导致任何剩余柴薪断根则失败。
- 手动断连与取回单件使用同一提交边界。原位置只断线会使外伸格落入对方主体，不能先提交冲突的断线状态；预览 / 取消不改权威拓扑，背包不足或最终占位非法时整次失败，不自动拆掉其他柴薪。
- 预检捕获 Session、源容器、物品与棋盘 Revision，先算出最终背包 / 占位 / 嵌入 / 拓扑，再一次提交。重入、重复请求、源物品已移动、目标已改变或取消时失败，保留外部已发生的合法变化。Model / System / Command 在一致最终态后发事件并标记存档脏状态。
- 交易继续使用现有价格与原子所有权转移；棋盘上的柴薪、火焰、余烬先取回背包才能出售，不增加直接售卖整个安装网络的功能。买卖保留完整变体与实例 ID。

### 3. 能量瓶与击杀结算

- 专栏使用独立稳定身份与瓶子实例引用，不加入战斗装备加成聚合。每件瓶子保存整数能量，配置的小 / 中 / 大容量暂定 1000 / 2000 / 4000，均占 2×1；小瓶基价暂定 100，按容量倍率暂列中 200 / 大 400。瓶子可掉落和购买；创建为空瓶，移动、交易或恢复不清空 / 填满。
- 扩展怪物配置的基础能量与收益配置，收益使用实际怪物实例的词条数量、整体稀有度及各词条稀有度。`MonsterInstanceData` 现有固定词条可复用；现有 `MonsterAffixDefinition.Weight` 只是生成权重，没有独立稀有度字段，不能直接作为收益或稀有度。明确稀有度配置 / 赋值与纯收益计算，诊断显示各项来源；不修改共享资产或重新抽词条。
- 通过 `ActorDiedEvent` 的 `Source.ActorKey` / `Source.Team` 和死亡怪物稳定身份，证明当前 Run 中的玩家归属；普通命中、持续伤害和有效延迟死亡走同一结算。不能从 HUD、最近玩家或当前选中对象推断。
- 复用 `CombatSystem` 的实际存活到死亡转移及 Run 怪物生命周期，补足重复通知防护。去重状态归属当前 Run，恢复时从已完成死亡状态重建；读档、场景销毁、地图恢复和旧 Session 事件不发收益，不保留跨玩家全局死亡集合。
- 收集量为 `min(本次怪物能量收益, 容量 - 已存能量)`，超过剩余容量的部分直接舍弃。只有结算当时装备在专栏的瓶子参与；满瓶停止收集，玩家手动换瓶后才继续，新瓶不承接已舍弃收益，也不自动装备背包瓶或转存角色池。
- 成功能量变化推进实例 Revision，发一次变化事件并标脏；满瓶 / 空栏无能量变化，不发伪成功事件。收益计算与瓶内截取使用已验证的非负整数及溢出检查，不调用掉落 / 攻击随机流，不改变刷怪名额或重置规则。

### 4. 保存、迁移与兼容

- 扩展 `ItemInstanceDto` 实际变体 / 能量数据以及棋盘 / 专栏所有权引用，物品仍只在统一 `RuntimeStateDto.Items` 中序列化一次。快照、Detached 状态、Mapper、Validator、Restore Preparer 和最终提交均纳入同一流程；不由新 System 独立读写存档文件。
- 收益中的稀有度若属于生成结果，随现有怪物实例 DTO 捕获 / 恢复；属于固定定义时按稳定内容引用解析，不额外保存重复权威值。旧怪物档采用明确兼容映射，不重掷词条或在恢复时发放能量。
- Restore 预检覆盖错误角色 / 插槽、重复所有者、重复节点、损坏边或端口、碰撞、未知内容 / 生成合同、负能量 / 越容量以及不存在的物品引用。布局按已保存合同校验，不用当前模板重新生成；无效恢复不能清除现有 Session、污染有效存档或泄漏资源。
- 阶段二拟升级 core v11 与 Save Schema 10：正式内容登记和新权威字段落地时补齐兼容迁移再推进；Settings Schema 1 / 地图 V4 预计保持。只有本阶段完成验收后运行版本进入 `0.7.1-alpha.2`，规划文档不提前改版本。
- Schema 9 迁移显式初始化空棋盘 / 空专栏和新实例扩展默认状态；保留 `PlayerRunStateDto.SkillContentId` 与 `AutoCastCooldownRemainingSeconds`，不重复发放柴薪 / 火焰，也不丢原技能。阶段四才按最终起始点亮政策将旧技能一次性转为有效火焰来源、六槽与剩余冷却，并同时移除自动循环。
- 布局、瓶子与专栏随角色数据保存；场景离开先捕获再清理，取消解绑不把棋盘物品再次塞入背包。异步资源预热使用既有 Addressables 所有者和 Session 取消，失败释放本次资源。
