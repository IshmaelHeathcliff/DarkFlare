# Alpha 0.6.5：行为、Boss、刷怪与重置综合交付计划

状态：2026-09-24，**按用户调整的验收标准完成并归档**。基线为提交 `060b3bd`、`0.6.4-alpha`、core v10、存档 Schema 9、地图 V4；交付为 `0.6.5-alpha`。上位[Alpha 0.6 总计划](../../0.6/plans/alpha-0.6-plan.md)，现有[行为模块](../../../../behavior/README.md)、[手动重置模块](../../../../behavior/map-reset.md)和[0.6.4 验收](../../0.6.4/acceptance/behavior/README.md)作为实现依据。执行证据见[0.6.5 验收记录](../acceptance/behavior/README.md)。

## 目标与边界

本阶段交付 `0.6.5-alpha` 的**完整可玩链路与可复核验收**，不新增怪物、Boss 技能、NPC 玩法或刷怪配额。正式野外图保持每实例 100 个普通怪物名额：20 个入图、10 处触发点各 8 个；守卫 Boss 独立。正常离场保留状态，显式重置才刷新。Core 内 HFSM / 行为树继续独立，Animator 桥接和可视化仍在 Core 之外。

验收分为正式地图流程和受控压力场景。300 常规 / 600 压力单位是性能采样规模，**不是正式地图名额**；若使用临时注入或配置覆盖，只存在于隔离的开发验收环境，不能进入交付资源或正式存档。历史 0.6.1 的 500 / 1000 普通怪物结果可作对照，不能代替当前 Boss、范围触发和重置共存的实测。

0.6.2 对 Windows Player 的豁免只记录当时阶段；本阶段按[总计划](../../0.6/plans/alpha-0.6-plan.md)重新尝试独立 Player 与性能验收。此前本机 Windows Code Integrity 的 Enterprise signing level 阻止新 EXE 启动，先检查可用环境；若仍受阻，记录构建与启动阻止证据，改用可运行的受信任机器完成独立 Player 项目。不能把 Editor PlayMode 当作 Player 通过，也不在未完成必需验收时宣称综合交付通过。

## 验收记录与判定

- 每项标记为“通过／失败／环境阻塞／未执行”，附所用提交、Unity 版本、构建哈希、平台、场景、输入设备、存档根与原始结果。旧版本证据只作背景，不能作为 `0.6.5-alpha` 的当前结果。
- 性能沿用[0.6.1 方法](../../0.6.1/acceptance/behavior/performance.md)的分段与分位数口径；额外报告 Boss 同场、触发及重置的峰值，不把不同 ProfilerMarker 的包含时间相加。纯 Core 稳态零分配目标不外推为整场游戏零分配。
- 项目完整回归只统计实际执行的测试；Unity Pipeline 返回 0 项时视为无结果，重新检查运行器。第三方包自身的跳过与项目测试失败分开报告。
- Windows 签名策略、真实手柄或可运行测试机若仍不可用，保留阻塞证据及影响范围。可先交付代码修复和 Editor 回归，但不得把对应 Player、跨进程或性能门槛标为通过。

## 2026-09-24 验收调整与结论

用户将当前门槛调整为：**只有明确指定需要 Player 验收时才构建 Player**。上述 I1、I4、I5 中的 Player 构建、300 / 600 当前版本 Player 性能、实际手柄、画面矩阵及真实进程中断均保留为原计划目标和未执行项，当前不阻塞 0.6.5。调整发生在一次构建探测之后；该探测受 Windows Code Integrity 阻止，未生成新 Player，不计为验收通过。以后不再为常规阶段默认发起 Player 构建。

I2、I3 与 I5 的 Editor 部分已验证：完整 EditMode 819/819 通过，完整 PlayMode 104 项中 102 通过、2 项包内跳过、0 失败；传送门重置、存档提交前后边界及 20 轮资源收敛有长期回归覆盖。I6 据此完成文档和版本收尾，交付 `0.6.5-alpha`，core／Schema／地图版本不变。未执行项目见[验收记录](../acceptance/behavior/README.md)，不能被解读为通过。
