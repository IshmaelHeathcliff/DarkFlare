# Alpha 0.6：有限刷怪、手动重置与存档

状态：有限刷怪与手动重置均已实现，分别见[有限刷怪模块](../../../../../behavior/finite-spawning.md)、[手动重置模块](../../../../../behavior/map-reset.md)及[已归档的 0.6.4 计划](../../../0.6.4/plans/alpha-0.6.4-manual-map-reset-plan.md)。上位[总计划](../alpha-0.6-plan.md)。当前基线为地图 V4、core v10、Schema 9；离开保留状态，只有手动重置后刷新。

## 一个地图实例的固定总量

0.6.3 实现新图固定生成计划及恢复，普通切图和继续游戏复用同一计划。0.6.4 引入持久化的地图实例代次（InstanceEpoch），与源地图布局 Revision、运行装配 generation 分开；只有成功手动重置才开启新代次。

- 每实例普通怪物总量 N = 入图批次 I + 所有触发批次之和 T；Boss 单独固定配置 B。N + B 受当前每图 1024、全档 2048 容量约束，未生成的名额也需纳入容量设计，不能等触发时才发现总量不可容纳。
- 生成计划在新图建立时确定：批次 ID、名额 ID、怪物类型与实例随机种子、生成区域、生成方式；顺序稳定，不随玩家接近路线重新掷池。怪物实例 ID 仅在生成成功时分配。
- 名额采用 Pending → Alive → Defeated（或显式无奖励移除）状态；准备中的对象不能先标记 Alive。被击杀不补名额，离开 / 禁用不等于击杀。
- 同一触发批次只激活一次，重复进出不重复生成；一批数量可分帧实例化，但成功、未完成和失败名额需逐项可恢复。计数不以当前场景 GameObject 数量替代。
- 稳定名额 ID 与 MonsterInstanceId 映射持久化，Boss 是固定名额；对象池回收、重新装配和地图重置不复用旧实例身份。

新图准备期间完成入图批次合法性与资源预热，开放交互前保证预定初始数量就绪；大批量需有 Busy 反馈和取消。触发生成允许配置每帧创建预算，待生成数可诊断；请求不得绕过地图资源 owner 与取消门禁。

## 布局与配置

| 配置责任 | 拟定内容 |
| --- | --- |
| MonsterSpawnDefinition | 普通怪物加权池；旧版存活上限和补怪间隔不再驱动正式 V4 地图。分帧预算及失败策略在 S1 冻结 |
| 地图源区域 / 批次 | Spawn 区域保存合法出生范围和怪物池引用；V4 批次保存稳定 ID、关联区域、入图／范围触发、触发中心与半径及批次数量；Boss 继续使用独立点位 |
| 怪物 / Boss 定义 | 行为、攻击、属性、词条、掉落与资源；不复制地图布局坐标 |
| 运行态 / 存档 | 保存生成种子、已确定名额、激活批次、活跃怪物、已消耗名额、未拾取掉落和 0.6.4 加入的实例代次 |

地图源是布局唯一权威。现有 Spawn 区域与 V4 批次在地图工作台 / AI Patch 中共享事务、Undo / Redo、导入导出及冲突检查；刷怪 SO 不重复保存坐标。旧 V1–V3 地图只在内存升为无批次 V4，正式野外源图显式配置 20 个入图和 10 处各 8 个范围触发名额。

触发半径检测只决定是否激活批次，不等于怪物感知；建议触发距离大于该批怪物激活范围，避免玩家面前突然出现。配置必须区分“初始生成数”“固定总数”“当前存活数”“待触发数”。正式野外图现配置 100 个普通名额，其中 20 个入图生成、10 处各 8 个范围触发；这些数量来自地图配置，不硬编码进运行逻辑。

位置校验复用同源圆足迹、障碍、水域和 Safe 区域规则，Boss 使用实际体型 Profile。确定候选后仍需在发布时复核地图代次和占用；失败有界重试并保留名额，不能先消耗预算再丢怪，也不能把非法位置静默挪到玩家脚下。配置无法容纳目标数量时预检失败并显示具体批次。

## 手动重置：已实现的首版交互

已确认：正常离场保留所有地图进度，返回继续；显式手动重置后怪物重新刷新。

城镇地图入口提供“进入”与“重置并进入”两个操作；重置有二次确认，说明普通怪物 / Boss 及未拾取掉落的处理。键鼠和手柄同等可达，沿用 Application Shell Modal / Busy / Toast，不新增全局快捷键。

首版只允许重置非当前活动刷怪图，城镇 / 无刷怪图不可重置；玩家须先离开野外，再从城镇操作。如后续要原地重置，应另行扩展合同。

重置清单：

| 数据 | 处理 |
| --- | --- |
| 目标图普通怪物、Boss、触发批次、地图状态计时 | 全部创建新实例，Boss 可再次出现 |
| 目标图未拾取掉落及只被这些掉落引用的物品 | 清理，并在确认框明确提示 |
| 玩家背包、装备、金币、材料、玩家状态 | 保留，不能因地图重置重复发放初始物品 |
| 商人库存、打造事务、其他地图、全局稳定身份分配器 | 保留，重置不补货、不回滚身份序号 |
| 静态地表 / 地图布局、入口、配置资产 | 不改变 |

首版不增加费用、重置次数限制或真实时间自动刷新。实现与异常边界以[模块文档](../../../../../behavior/map-reset.md)为准。

## 重置事务

1. 验证目标地图资格、当前实例代次、玩家所在图、输入 / 拖放 / 打造工作区已结清，无保存捕获或切图冲突；重复请求不排成多次重置。
2. 在源状态仍完整保留时，生成候选新实例计划，校验名额、Boss、资源、几何和容量；按“运行种子 + MapId + 新实例代次”派生新随机流。同一次失败重试不会重新掷候选。
3. 若操作为“重置并进入”，先准备新图及合法入口，再通过现有 Scene Flow / MapScope 编排提交。禁止先删冻结图再尝试加载资源。
4. 在保存协调门禁下，提交完整候选世界快照与持久化结果；掉落物品引用和图状态一起替换，不能出现一半新名额、一半旧物品。成功提示只能在持久化完成后发布。
5. 提交前失败 / 取消恢复旧图及旧快照，释放候选；提交后清理失败沿用既有 Fatal 合同，不能把已落盘的重置再静默撤销。进程在落盘前退出恢复旧代次，落盘后退出恢复新代次。

0.6.4 通过 SaveCoordinator 排他保存租约、候选世界快照与持久化回执复用现有存档代际文件；实现边界见[手动重置模块](../../../../../behavior/map-reset.md)。旧批次生成和旧 Boss 动作在重置后不能再发布。

## 保存、迁移与兼容

- 0.6.3 由 Schema 7→8 增加固定生成计划、名额状态和激活批次；0.6.4 由 Schema 8→9 增加活动图和冻结图的 InstanceEpoch。行为与 Boss 动作数据由 Schema 6／7 承载。所有身份与物品仍接受全档去重 / 归属校验。
- 同步更新 SnapshotSource、RestorePreparer、DataValidator、MapStateData、地图准备 / 导入及故障回退；恢复顺序为验证计划 → 恢复已存活对象 → 恢复行为 → 恢复未生成名额，不重新执行“新地图初始生成”。
- 未触发名额不创建 GameObject / Animator / 导航 Agent；必须仍有稳定计划数据，不能在保存时遗漏。暂停和离场不会消费触发次数或计时。
- 旧 Schema 7 以及更早的已访问图都使用无限补怪，无法推断历史总击杀数。7→8 迁移为“保留现有活怪，停止补满，不追补新名额”的 LegacyPreserved 状态；直到用户手动重置才采用新有限计划。保留现有 Boss 名额与状态，不凭空增加怪物、抹掉伤害或重掷既有词条。
- 旧图迁移提示说明首次手动重置后启用新分布；新游戏及旧档未访问地图直接用新规则。已迁移的旧状态继续游戏保持一致，不能每次加载重复迁移。
- 生成配置引用版本 / 内容哈希参与恢复预检；配置变更不能在读取旧图时重新掷整张计划。历史配置如何映射需要显式迁移，超容量明确拒绝，不截断。

## 验收

1. 同种子与代次得到相同计划；I + T = N，每批名额唯一；初始只生成 I，触发后恰好增加对应数量，击杀后不补怪。
2. 玩家高速穿过、重复进入、多个触发区同帧命中、部分批次失败 / 取消 / 保存，均不多生或漏失名额；非法布局可诊断。
3. 普通怪物 / Boss 被击杀、Boss 强化中、部分批次未触发时离场，等待再返回与跨进程继续保持进度。
4. 成功重置产生新代次和新怪物，玩家数据及其他图不变；无权限地图、当前活动图、重复请求、准备失败、保存失败、取消和提交边界退出按事务规则收敛。
5. 使用真实 Schema 7 及更早历史夹具验证迁移：旧怪物与掉落不丢、Boss 状态不变；手动重置后进入有限规则。
6. Player 验收重置入口的键鼠 / 手柄路径、中英与伪本地化、确认取消、Busy 期间输入门禁及结果反馈；连续循环验证资源与注册回到基线。
