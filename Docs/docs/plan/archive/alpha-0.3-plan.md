## 版本目标

本轮 alpha 0.3 以 UI 体验迭代为主，并以完整装备栏及配套内容收尾，交付五项成果：

1. 背包、商店、打造各自拥有独立窗口，支持单独显示和按需同时打开。
2. 属性展示从数值列表扩展为可解释的实时详情。
3. HUD 重构为暗黑像素风格，突出战斗时真正需要的信息。
4. 面板、边框、背景、槽位、按钮与提示形成统一视觉规范和可复用组件。
5. 装备栏扩充为头部、身体、手部、腿部、主武器、副手、左戒指、右戒指、项链、腰带十槽，每个部位至少有两件可实际使用的装备配置。

用户已明确选择“独立窗口，可按需同时打开，例如商店旁打开背包”。窗口独立性必须体现在开关、焦点、内容和功能可用性上。

本轮同时修复现有设置 / 返回主菜单与背包的交互阻塞，并统一拖动装备、丢弃、买卖、打造放入 / 取出及对应右键、手柄操作。全窗口最多一个物品高亮，详情不超框、面板对齐是功能验收条件，不能留到皮肤阶段才处理。具体规则见[交互合同](alpha-0.3-item-interaction-contract.md)。

| 背包边缘只有部分向右导航补丁 | 按实际屏幕位置建立四向导航，覆盖跨窗口边缘、不同物品尺寸和拿起 / 放置模式 |

## 独立窗口体验

| 窗口 | 独立显示时 | 与背包同时显示时 |
| --- | --- | --- |
| 背包 | 10×6 格子、装备栏、金币、整理 / 穿脱及属性入口；首阶段沿用四槽，收尾交付十槽 | 保留本窗口选择和物品拖放；关闭另一窗口不关闭背包 |
| 商店 | 可浏览和购买；出售来源通过本窗口的玩家物品选择视图取得 | 商品拖入背包指定格购买，玩家物品拖入明确出售区卖出；右键快速交易 |
| 打造 | 独立目标槽、选取目标 / 取回、随机操作和结果；选择器读取真实背包 | 支持背包与目标槽双向拖动及右键放入 / 取回，关闭背包后仍可操作已放入物品 |
| 属性详情 | 从背包或 HUD 入口打开，展示当前角色的分组详情 | 不占用背包格子或商店 / 打造操作区 |

- 默认采用固定停靠与受控排列，优先保证“背包 + 商店”“背包 + 打造”“背包 + 属性”的常用组合；不把自由移动、任意缩放和桌面式窗口管理纳入首轮。
- 商店和打造仍要求有效世界交互上下文。已有内容不提供两者同时授权时，不因改为窗口就开放远程交易 / 打造。
- 延续现有菜单暂停体验：有玩法功能窗口时保持 UI 输入与玩法暂停；最后一个关闭时，只释放这些窗口拥有的状态。Settings、Modal、平台挂起仍遵循各自所有权。
- 关闭当前窗口不会重置其他窗口；返回前台、Session 结束或交互目标失效时按所属作用域清理。
- 打开设置或返回主菜单确认时，先由应用上层接管 UI 输入和暂停，再隐藏背包及其他玩法窗口、取消拖放和物品提示；返回 / 取消后按有效上下文恢复，确认离开则清理。关闭底层窗口不能使上层失去操作能力。
- Esc / 手柄返回优先处理顶层 Modal / Settings，再取消拖放，再关闭当前窗口；一次输入只消费一层，手柄提供可重绑定的窗口切换操作和持续可见的焦点。
- 手柄上下左右根据物品 / 槽位的实际视觉位置移动；到达边缘时自然进入该方向相邻的可见背包、商店、打造窗口。窗口循环快捷键仅是补充，不能代替方向键跨面板导航；详细规则见交互合同。
- 详细的来源选择、上下文和暂停合同见[首阶段计划](alpha-0.3.0-independent-ui-windows-plan.md)。

## 实时属性详情

| 信息组 | 本轮必须展示的详情 |
| --- | --- |
| 资源 | 当前 / 最大生命、法力、比例、有效每秒恢复量；区分正常恢复能力与死亡 / 暂停等当前状态 |
| 基础与移动 | 力量、敏捷、智力、移动速度；展开显示基础值、装备来源与主属性派生贡献 |
| 攻击 | 当前武器 / 技能伤害来源、武器基础范围、技能耗蓝和间隔、有效暴击率与最终暴击倍率 |
| 防御 | 护甲、闪避值、四类抗性；同时解释原始聚合值、实际生效值及上限裁剪 |
| 修改器 | 全局 / 类型伤害、Flat / Increase / More 等按语义展示；条件和适用范围可查看 |

- 属性摘要保持紧凑，分组可展开；详情允许分组滚动，避免把全部解释挤进现有固定双列短行。物品浮窗保留其独立可读性合同。
- 无条件可计算的值显示当前结果；依赖敌人或伤害包的命中率、减伤率等必须标明计算条件。没有有效上下文时显示“依目标 / 条件计算”，不编造固定百分比。
- 武器基础伤害范围不能标成最终伤害；通用 `damage` 修改器数值不能标成每秒伤害。首轮不提供无目标假设的综合战力或模拟 DPS。
- 来源分解复用现有属性 / 装备解析规则，必要时为纯解析器增加解释结果；不在 UI 复制一套战斗公式。
- Query 不调用攻击发起或随机种子推进接口，不消费金币 / 法力，不修改模型；重复刷新不能改变下一次攻击、掉落或打造结果。
- 装备、资源、金币、角色及语言事件触发对应区域刷新。窗口打开时立即取最新快照；暂停时状态随玩法冻结，恢复后继续更新。
- 当前技能剩余冷却由已有运行状态经受控 Adapter / Query 提供；UI 不反向轮询另一个场景 Controller，不每帧重建全部属性与物品列表。

## HUD 与统一视觉方向

HUD 采用底部双资源仪表的方向：生命偏左、法力偏右，中间展示当前自动攻击技能状态和常用窗口入口；世界交互提示位于仪表上方，金币使用较轻的独立区域。先验证线框与一个正式组件，再确定仪表是圆形容器还是带切角的像素容器。

- 显示生命 / 法力的真实比例和清晰数字，覆盖满值、低值、零值、恢复、死亡和复活。
- 当前技能只展示已有自动攻击能力、实际冷却 / 耗蓝和无武器 / 法力不足等原因；窗口按钮接入现有输入与 Glyph，不摆放无消费者的技能、药水、经验或地图占位控件。
- 低生命、施法受阻和交互提示有明度、形状或文字反馈；Reduce Motion 下关闭非必要晃动 / 脉冲，数值变化保持可读。
- 统一使用暗石材 / 炭黑内底、旧铁边框、少量金铜角件、暖色正文；生命红、法力蓝和焦点色承担稳定语义。
- 面板分为外框、内容底板、分区标题和内嵌槽位；大框提供轮廓，内框保持轻量，装饰不侵占物品、文字和命中区域。
- 按钮、槽位、窗口关闭与操作提示共享 Default / Hover / Pressed / Selected / Focused / Disabled 规则；鼠标悬停和手柄焦点分别可辨识。
- 保持像素硬边、有限色阶和统一像素密度；中文与英文首先保证阅读质量，不因像素化而损坏字形。
- `Theme.uss` 保持主题入口，布局与装饰分离；FrontEnd、Settings 和错误 Modal 复用主题材质与基础控件，不重写其已有流程。

## 美术生产与验收边界

- 视觉参考沿用[当前视觉规范](../../visual-style.md)与已保留风格板；首阶段产出 UI 线框和代表组件视觉样例后，冻结这一版的材质、像素密度和尺寸规则。
- 资产家族覆盖窗口底板 / 外框、标题与分隔、按钮、物品 / 装备槽位、HUD 仪表外框与填充、浮窗和提示底板。
- 严格遵循[美术资产生成规范](../../visual-asset-generation.md)：生成前声明画布、主体范围、Pivot / PPU、九宫格保护区、最小 / 常规 / 最大使用尺寸和消费者。
- 一张生产 PNG 只含一个组件、一个状态或一帧；文字、数量、示例装备不烘焙进底图；不可拉伸角件与可拉伸背景分离。
- ImageGen / 可用美术工具先生成单个 Pilot，通过自动审计与原生像素视觉验证后再逐张派生。组合概念稿只作参考，不导入 Unity 或手工切图。
- UI 创建、布局、导入和绑定通过 Unity MCP / Editor API 验证。独立窗口仍可共享 Main 的一个 UIDocument，Bootstrap 保持唯一 EventSystem。
- 正式视觉验收沿用当前文档的 **1920×1080**；旧版其他分辨率记录保留为历史，不在本轮默认为新的交付范围。通用生命周期 / 输入测试继续保留。

## 验收与版本约束

- 新增及受影响测试遵循[测试维护规范](../../testing/test-maintenance.md)：优先扩展长期行为回归；临时验证完成后清理，不新增锁定当前版本或历史发布记录的测试。

- 领域层保留背包占格、装备原子交换、既有价格、14 个打造操作变体及随机通道隔离；为指定格购买、世界丢弃及十槽装备补充必要事务。新装备显式配置价格及内容池权重，不借此改背包容量或经济公式；内容池扩充后的固定种子序列单独建立新基线，保留旧版历史证据。
- 用行为测试替换已失效的“固定工作台宽高 / 单页签 / 无背景图”源码断言；保留物品唯一归属、输入可达、无重复提交和无丢失资源的测试。
- PlayMode 使用已有隔离存储根；覆盖 NewGame / Continue、功能窗口组合、Settings / Modal 往返、保存、返回前台与重新进入。
- 在 1920×1080 验证中英与 Pseudo Locale、长名称、最高词条容量、背包满 / 商店空、打造目标失效、低生命 / 零法力、手柄跨窗口导航。
- 每项物品操作覆盖拖动 / 右键快捷入口 / 手柄等价路径、取消和失败；覆盖设置 / 返回确认接管后仍可点击和导航、全局单一物品高亮、详情文字边界及窗口对齐。
- 版本号随阶段实际落地递增；调整当前版本断言时保留 alpha 0.2 历史发布证据。纯 UI 窗口状态不写入存档；装备扩槽和内容变化单独核对 ContentVersion、SaveSchemaVersion 与兼容 / 迁移策略，不能继续按纯外观改动处理。
- 最终执行适当的全量 EditMode / PlayMode、Addressables 内容构建和 Windows Player 构建，补做真实 Player 完整操作流程；以新证据记录当时测试计数。
