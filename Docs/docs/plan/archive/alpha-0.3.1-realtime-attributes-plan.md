## 目标与范围

让玩家从背包或 HUD 打开独立属性窗口，查看当前角色的资源、基础与移动、攻击、防御、修改器五组信息，并展开了解数值来源和生效条件。换装、资源变化、死亡 / 复活、语言切换后显示正确；查询不改变玩法数据或随机序列。

本阶段沿用正式窗口底板与现有 HUD，仅添加真实属性入口。底部战斗 HUD 属于 0.3.2，完整皮肤属于 0.3.3，十槽装备与每槽两件内容属于 0.3.4。不新增战力评分、模拟 DPS、目标选择器、技能切换或新的战斗公式；不修改经济、装备容量与存档格式。

## 核对后的代码基线

| 入口 | 当前实现 | 本阶段处理 |
| --- | --- | --- |
| `GetHudSnapshotQuery` / `HudAttributeSnapshot` | 提供资源、金币及属性汇总；普通值统一非负，抗性裁剪，法力恢复转成有效每秒值 | 详情使用独立 Query；摘要与详情共享相同的有效值语义，避免两处读数冲突 |
| `CombatActor` | 保存私有基础属性、有效 `Stats` 和无来源标识的 `Modifiers` | 增加受控的基础值快照入口，不向 UI 暴露可写基础对象 |
| `CombatStatResolver` / `StatAggregator` | 筛选非伤害 `GlobalActor` 修改器；按既有顺序处理 Flat / Override，再 Increase / More，最后主属性派生 | 在同一纯解析路径提供可选解释结果，保留现有执行顺序与标签筛选，不另外复制公式 |
| `EquipmentEffectResolver` / `ItemInstance.CollectModifiers` | 从 Loadout 收集隐式、前后缀修改器，汇总后不保留装备槽和词条来源 | 在收集阶段补充只读来源描述；同一来源追踪服务计算与显示，不靠数值相等反推来源 |
| `ResourceRegenerationSystem` | 每 0.25 秒推进；死亡、禁用、暂停时不恢复；法力恢复已有共享计算方法 | 复用恢复能力计算，并独立展示当前能否推进及原因 |
| `AttackSnapshotFactory` / `DamageCalculator` | 发起攻击生成随机基础包；局部伤害修改器在正式伤害管线消费 | 读取配置范围与修改器，不通过发起攻击或抽样生成详情；需要共享的边界函数从正式消费者抽取 |
| `PlayerController` | `DefaultSkill` 和 `AutoCastCooldownRemainingSeconds` 已可读，倒计时使用 `Time.time` | 经 Session 内受控 Adapter / Query 提供数据，不让属性 Controller 查找或轮询另一个 Controller |
| `GameMenuPage` / `GameMenuAccess` | 当前只枚举背包、商店、打造 | 添加独立属性窗口并显式处理映射、访问与焦点，不让新增枚举落入背包默认分支 |

以上以代码为准。[属性模块](../../stat-system.md)和[输入模块](../../input-ui-system.md)存在早期布局与流程描述，实施时按实际落地同步修正受影响段落；不以历史描述替代当前消费者行为。

## 信息与数值合同

| 分组 | 摘要 | 可展开解释 |
| --- | --- | --- |
| 资源 | 当前 / 最大生命和法力、比例、每秒恢复能力 | 基础上限、装备修正、主属性派生；生命固定恢复、最大法力 5%/秒与固定恢复加成；暂停 / 死亡 / 禁用及已满状态 |
| 基础与移动 | 力量、敏捷、智力、移动速度 | 基础值、装备槽 / 物品 / 隐式或显式词条、直接聚合和派生步骤 |
| 攻击 | 当前自动技能及伤害来源、分类型基础范围、耗蓝、施放间隔、剩余间隔、有效暴击率和最终暴击倍率 | 武器或技能配置来源，局部 / 全局修正的适用范围；命中值、依目标计算的说明；无有效伤害来源和法力不足原因 |
| 防御 | 护甲、闪避值、四类有效抗性 | 原始聚合值、消费者生效值与裁剪边界；抗性超上限或负值；护甲减伤依赖来袭物理伤害，闪避依赖攻击者命中值 |
| 修改器 | 按属性和 Scope 分组的已有修改器 | Flat、Increase、逐项 More、Override、Conversion、GainAsExtra 等实际操作语义；标签作用域、必需 / 任一 / 排除条件与来源 |

- 明确区分基础值、直接聚合、主属性派生、最终属性和消费者裁剪。百分比只在对应操作或属性确有该语义时使用；不把所有属性统一裁为非负再解释。
- `Override` 与 Flat 的先后会影响结果，解释记录必须保留正式顺序；More 是逐项乘算，不汇总为 Increase。多来源不能简单标成可相加的“最终贡献”，改为展示计算步骤。
- 暴击率沿用实际 0–100% 边界；暴击伤害的额外百分比与最终倍率分开，例如额外 50% 对应最终 1.5 倍。负值等边界以正式消费者为准。
- 攻击基础范围明确标注为武器 / 技能的配置基础范围，局部修改器单独列出，不将其称为最终命中范围。`damage` 与类型伤害修改器不能因未直接进入 Actor 聚合而显示为“没有加成”。
- 无目标 / 伤害包时，命中率、闪避率、护甲减伤率显示“依目标 / 来袭伤害计算”；不使用虚构敌人或随机样本生成固定结果。本阶段不新增数值模拟器。
- 修改器展示区分“当前直接生效”“需攻击或目标上下文”“条件不匹配 / 当前解析器不消费”。Scope、条件、转换类型均使用已有语义，不把尚无消费者的配置标为生效。
- 恢复能力保留正常每秒数值，另显示“已暂停”等状态。打开窗口本身会暂停玩法，因此暂停时不能把正常恢复能力误标为 0，也不能为了看到变化解除暂停。
- 无玩家 / Session 未就绪时显示明确空态，不能将一组 0 当作有效角色；快照不持有可供 UI 修改的 Model、列表或装备实例。

## 窗口与输入合同

1. 背包增加“属性详情”入口，HUD 增加可聚焦的同功能按钮；沿用现有 Input Actions、重绑定提示和 Glyph，不新增无消费者的快捷键。背包中的完整旧列表收敛为紧凑摘要和详情入口，避免维护两套完整属性视图。
2. 属性无需世界目标授权，可单独打开，也可与背包、商店或打造共存。关闭属性不关闭其他窗口；关闭背包不关闭属性。商店 / 打造页签仍按有效上下文隐藏，属性入口不能扩大交易或打造授权。
3. 沿用固定停靠与共享窗口宿主。1920×1080 中优先落实属性单窗、背包 + 属性、商店 / 打造 + 属性、背包 + 商店 / 打造 + 属性；保留现有网格尺寸和底部 HUD 安全区。先用真实文本验证三窗宽度，再冻结属性宽度，不为容纳文字压缩背包格子。
4. 三窗时的物品浮窗是额外空间风险：优先贴近来源与安全边界；空间不足时可临时覆盖属性的非交互说明区，但不能遮挡属性标题、关闭 / 分组操作、当前焦点、来源物品或放置目标。退出物品预览后恢复完整阅读区；不能同时弹出两个物品详情。此布局在接入完整数据前通过运行时验证。
5. 属性使用分组折叠、独立滚动和行内来源展开。长名称和来源描述可换行，数值保持对齐；不把长说明塞进一行 tooltip。沿用现有底板、关闭图标和主题，装饰不参与命中或导航。
6. 四向导航按实际矩形跨窗口；属性组标题、展开入口和关闭按钮参与导航，纯文本不制造大量焦点节点。滚动后显露焦点；窗口间往返保留有效焦点、展开状态和阅读位置。窗口循环按键作为补充。
7. 属性不是物品来源或放置目标；拖动物品经过属性不能误装备、交易或丢弃，也不能抢走拖放捕获。普通属性焦点沿用现有唯一物品高亮合同，不产生额外选中物品。
8. Settings / Modal / Busy 接管、取消返回、设备断开及 Session 清理复用既有规则。Esc / 手柄返回按上层界面、动作菜单 / 拖动、当前窗口顺序处理，一次只消费一层；最后一个玩法窗口关闭才释放自身输入和暂停所有权。

## 数据边界与刷新

- 新增属性详情只读快照和 Query，Controller 只查询和注册事件。格式化在 View / Formatter 使用 Localization 的 `stats`、`affixes` 与 `ui` 表，快照保存稳定 ID、来源身份、数值与条件，不缓存当前语言文本。
- 来源收集及解释属于领域纯解析器 / Utility；可选 trace 与正常计算共用路径。装备修改器保留物品实例 ID、槽位及词条身份；非装备来源如存在则显式描述，不能伪归属到装备。UI 不重复 `PrimaryAttributeResolver`、恢复、暴击或抗性公式。
- 技能状态 Adapter 在有效 Session 注册，禁用 / 注销 / Session 结束解绑；Query 仅读取已注册状态，缺失返回空态。沿用现有冷却时钟，不另建会推进攻击的计时器，也不改存档中既有冷却语义。
- 窗口打开立即取最新值。装备、有效属性、Actor 身份变化重建静态解释；资源事件仅更新资源区及相关可用状态；技能事件更新攻击状态；金币不触发无关属性重建。若当前缺少有效属性重建事件，在 System / Model / Command 的实际提交边界补齐，不能由 UI 发送领域 Event。
- Locale 改变仅重排文本，保留分组、滚动和焦点，不重新执行装备解析或物品操作。可见窗口需要剩余间隔刷新时，仅对动态区使用有取消令牌的低频 UniTask；隐藏、解绑即取消，暂停时沿用冻结时间，不每帧重建整棵 UI。
- 查询不得执行 Command、修改资源或装备、申请资源加载、推进随机流、产生攻击 / 掉落 / 打造结果。重复查询后下一次正式随机结果必须与未查询的等价状态一致。
