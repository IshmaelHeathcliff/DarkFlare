## 规划范围待确定

目前读取的常规开发文档中没有既定 Alpha 0.5 功能清单。当前仍是单 Main 地图的功能原型；多地图 / 关卡、手动存档槽与 Profile、背包旋转 / 重量、交易回购 / 多商人、打造配方 / 批量等边界见[项目概览](../../../../project.md#当前边界)。这些只是现状边界，不自动纳入 Alpha 0.5。

开始总计划前需要明确：

- 本版优先改善的玩家流程，以及希望新增或改变的具体行为。
- 必须交付的范围与明确暂缓的内容。
- 首个可独立体验的最小阶段及可观察验收标准。

范围明确后建立 `alpha-0.5-plan.md` 总计划，并从 `alpha-0.5.0` 拆分执行阶段；本启动文档保留基线，待正式计划接管后归档。

## 开工顺序与成功标准

1. 明确目标后，阅读相关模块文档并核对实现、配置及现有测试，列出依赖和实际差距。
2. 每阶段写清范围、非目标、玩家操作路径、失败路径、验收标准和存档 / 内容版本影响；涉及 UI 同时考虑键鼠、手柄与本地化。
3. 沿用 QFramework 分层与 Command / Query / Event、可取消 UniTask、Addressables 资源所有权及现有 Session 边界。
4. 复用领域长期回归；必要时补充核心规则、事务回退、历史迁移、输入可达或数据隔离覆盖，遵守[测试维护规范](../../../../testing/test-maintenance.md)。测试使用隔离数据目录。
5. 阶段完成后更新模块文档、保存本次证据并归档计划；版本交付验收覆盖最新代码，不能借用旧 Player 结果证明新增功能。

准备完成标准：当前版本、能力、历史证据与验证边界有来源，Alpha 0.5 计划入口可访问。开始实现条件：本版目标及首阶段范围和验收标准明确。
