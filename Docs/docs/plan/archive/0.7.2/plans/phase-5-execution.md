# 0.7.2-alpha.5 双地图缩小、300名额与综合收尾计划

状态：2026-10-27，实施与验收完成，五阶段全部收尾。当前`0.7.2-alpha.5` / core15 / Save12 / Settings1 / 地图V4，城镇r3 / 野外r11；本轮尚未提交。EditMode993/993、PlayMode119/119，无失败 / 跳过。见[地图综合验收](../acceptance/compact-maps/README.md)。

以下保留实施前目标、基线与验收合同；实际实现和未执行项以上述验收为准。原有字体修改独立保留。

## 目标与边界

落实[优化总计划](alpha-0.7.2-optimization-plan.md)最后一阶段：减少地图空跑，在更紧凑的野外提供50个入图普通名额和10处各25个范围名额，同时保留旧存档、普通进出和手动重置的区别。

- 保留MapId、格宽1、角色 / 怪物 / 碰撞 / 移速及四地表视觉尺度，通过重排地形、障碍、入口和对象缩小地图。
- 新建或明确手动重置的野外实例共300个普通名额，Boss独立；不会定时补怪，普通回图与继续保持实例进度。
- 已访问旧实例迁移后保留原名额，不为了凑300自动增加200只。旧100计划、`LegacyPreserved`及历史迁移链的边界见[存档兼容方案](map-save-compatibility.md)。
- 不重做伤害、装备、成长、HUD或怪物AI；阶段一的按住连放、三枚投射物及一次穿透在新地图联合验证。

## 地图布局与路线

### 城镇候选

- 保留`new_game / return / respawn`入口身份，且唯一Respawn；继续绑定原商人、打造配方和通往野外`arrival`的出口。
- 当前功能点本就靠近中心，先测最短合法站位和键鼠 / 手柄实际步行，避免把“面积少75%”当作路线已经改善。
- 32×32内按出生 / 返回→商人→打造→传送形成清晰动线；保留互动站位和绕行净空，装饰置于边缘，不堵触发范围。
- 记录每条路线距离与耗时，功能往返总路程应缩短，不能引入新的明显绕路；调整依据及结果入验收。

### 野外候选

- 保留`arrival / return / respawn`、出口`exit`、Boss点`guardian`及十个范围批次ID，单位与对象不缩放。
- 安全区按真实玩家、传送门和回退站位重新确定，不能机械缩小到旧区一半而失去净空。
- 50入图名额的`wild_spawn`优先放在安全区外的近场战斗区域，避免仍散布到整张地图而使首战遥远；Safe排除持续有效。
- 十个范围点可先以旧中心的一半作为布局起点；触发半径先试约4格，各Spawn区给25只足迹和绕行留余量。中心圈不在出生处被一次全触发，十区必须能沿实际道路到达。
- Boss与玩家入口、返回门及普通怪群留出战斗空间；检查四个现有导航Profile、近墙、薄墙和拉扯路线。相机使用新Bounds，不能照旧Clamp。

候选尺寸及局部坐标在B阶段通过后冻结为实际布局清单；入口 / 批次身份和“50+10×25”是合同，候选半径、装饰位置与像素不锁为永久测试。

## 刷怪与实例语义

| 情况 | 名额与进度 |
| --- | --- |
| 新游戏的新野外、从未访问的新图 | 当前300计划，50入图、250等待十区触发 |
| 明确重置并进入 | 新InstanceEpoch与300计划；旧目标图掉落按原确认规则清理，Boss重新准备 |
| 当前300实例普通返回 / 继续 | 原计划、种子、已触发批次、Pending / Alive / Defeated不变 |
| 迁移的旧100实例 | 保留100及原状态，使用紧凑布局；手动重置后才采用300 |
| 旧`LegacyPreserved`实例 | 保留已有怪物 / Boss / 掉落，不推测或补发历史名额；重置后采用300 |

在现有传送选择 / 重置确认中简明说明保留原进度与重置后300名额，必要数字读取真实实例；不增加窗口体系，也不把地图修订、Schema等实现信息放进玩家流程。

- 范围生成先保留每帧4个Pending的预算；失败保留Pending及诊断，不在一点叠25只、不补已击败名额。
- 不重新启用旧`SpawnInterval / MaxAliveCount`定时补满。提高遭遇频率靠近场入图分布、十区路线和触发密度。
- 如果50只同步生成造成明显尖峰，可在禁用的候选准备阶段分帧准备，但玩家可交互前仍必须全部合法完成；失败仍走原候选回滚。
- 暂停、离场、取消和Session结束取消任务、完成Job并释放地图owner；不新增逐怪Update或第二套对象池。

遵循[测试维护规范](../../../../testing/test-maintenance.md)，优先补`WorldMapStateTests`、`MapEditTests`、`WorldMapPlayModeTests`及现有保存 / 迁移 / 导航 / 资源 / 施法套件。

| 事务与隔离 | 迁移、资源预热、准备、切图和重置保存失败保留旧数据；落盘后清理失败仍按Fatal；测试不改正式玩家文件 |

旧套件中的100 / 20 / 80和“触发横跨80格”不能直接沿用为当前布局断言：当前数量改为明确300合同，跨度改为可达、分布和入口不误触发；100名额及r7扩容断言作为真实历史兼容覆盖保留，不改写旧历史夹具凑新值。

性能在同机、同Unity与1920×1080下记录基线与新图：50入图、单区25、连续多区、实际持续战斗和尽量接近300存活的压力样本。分别记录实际活怪 / Pending、帧时间P50/P95/P99 / 最大值、主线程与导航耗时、GC分配、准备 / 提交 / 保存耗时、地图owner数量；冷加载与暖机样本分开。既有Profiler与导航诊断优先，采样探针必须有效，不把分段P95相加。

对持续超过约16.7ms或相对基线新增的尖峰定位并处理；压力样本未达到300实际存活时明确数量及原因。不得用300总名额或历史Player测试冒充本次同时存活 / 性能通过。默认只做Editor验证，未构建Player、真实设备与跨进程项目如实记未执行。
