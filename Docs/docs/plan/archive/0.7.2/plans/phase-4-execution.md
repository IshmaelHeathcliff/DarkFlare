按[体验优化总计划](alpha-0.7.2-optimization-plan.md)和[界面分计划](ui-optimization.md)，将宽技能卡片与文字入口改为底部紧凑结构，减少遮挡，并保留真实资源、技能状态、绑定和输入所有权。

- 实施起点：`main` / `998893da7d3a6b6361fb61bd1f6adffadb1341ca`，Unity `6000.6.7f1`。原有 `GameCjkFont.asset` 修改独立保留。
- 当前数据：core v14、Save / Settings Schema 12 / 1、地图 V4、城镇 r1 / 野外 r9。本阶段改变表现、只读图标信息与悬停交互，预计这些版本全部保持。
- 目标运行版本：`0.7.2-alpha.4`，实现及验收完成后才推进。
- 阶段三历史验证为 EditMode 985/985、PlayMode 117/117、三语言前后 21 张画面和保存继续，见[阶段验收](../acceptance/board-simplification/README.md)。不作为本阶段重新测试的结果。
- 地图缩小、300 名额及综合战斗密度继续留在阶段五；背包格子、天赋界面、技能伤害 / 冷却 / 耗蓝与保存规则保持当前职责。

## 确定的布局与信息层级

结构采用生命在左、法力在右，中间普通技能与六火焰槽，窗口图标组紧邻技能组；延续炭黑、旧铁、少量金铜和像素硬边。资源容器先复用已有九宫格底板，填充与数字继续由 UI Toolkit 绘制。

| 区域 | 常驻信息与候选尺寸 |
| --- | --- |
| 左右资源仪表 | 当前 / 上限、资源比例、死亡 / 等待 / 低生命等必要反馈；单侧先以约 160×104px 排版，主数字保持至少 16px |
| 普通技能 | 独立于六槽，使用当前武器图标，保留真实攻击绑定、冷却遮罩 / 数字、无武器与不可用标识 |
| 六火焰槽 | 图标槽先以 56×56px、间隔 4–6px 为候选；显示各槽真实绑定、占用、冷却及状态角标，空槽明确为空 |
| 四窗口入口 | 背包、属性、天赋、暂停；图形 24–28px，点击区域至少 40×40px，沿用共享 Hover / Focus / Pressed，不用按下缩放改变命中区 |
| 金币与短状态 | 金币为次级信息；法力不足、死亡、暂停等关键反馈保持可见，完整参数进入详情 |
| 说明与独立提示 | 鼠标悬停显示名称、耗蓝、间隔、剩余冷却和原因；世界交互提示、Toast、低生命提示与右上状态条单列安全区 |

初版主体宽度按约 1100px、默认总高度不超过 136px 排版。真实长绑定可使键位区换行或横向伸展；优先保留可读文本与可靠命中，不把长键位硬塞进图形或伪造简称。属性 / 天赋没有独立 Gameplay Action，入口只展示真实名称和现有菜单路径；背包 / 暂停显示已有实际绑定。

### 面积与可读性目标

统计固定在 Gameplay、物品窗口关闭且 Shell 未接管的状态；修改前后使用同一组资源、槽位和绑定。

- 1920×1080、相同场景、相同空槽 / 满槽及绑定下，常驻主 HUD 的可见背景矩形并集面积比修改前减少至少 40%；同时记录整体包围框宽高。候选像素不是通过与否的唯一依据。
- 主 HUD 统计包含资源、七个技能位置、四入口、金币与必要读数；单独记录状态条、交互提示、Toast 和悬停层的边界，不靠只统计图标 Alpha 或隐藏资源达标。
- 中文、英文、伪本地化分别测量默认空槽、满槽和长绑定；技能名可以进入详情，键位、冷却数值和关键不可用反馈必须在 HUD 自身可读。
- 冷却以现有比例遮罩配合剩余数字表达；就绪清除遮罩。空槽、无来源、无蓝、暂停、死亡与冷却使用文字 / 符号 / 明暗组合区分，保留统一状态优先级。

## 输入与详情合同

1. 技能槽维持按绑定施法，鼠标点击槽位只消费界面点击；新增悬停不会增加一套点击施法或自动施法规则。
2. 技能悬停区、可见说明面板和窗口按钮统一参与指针屏蔽；只有装饰透传。按住普攻后进入这些交互区也终止原鼠标保持意图，离开或关闭窗口后须释放再按。
3. 悬停说明由 Pointer 事件驱动，离开卡片与说明区域、来源变化、开窗、Shell 接管、禁用和解绑时关闭或刷新。说明层保持在视口内，避免遮住所指图标与资源数字。
4. Gameplay 继续只启用既有 UI 指针支持；HUD 不接受方向导航，角色移动与技能按键保持可用。手柄用现有背包 / 暂停 Action 进入菜单，属性 / 天赋沿窗口入口和窗口循环进入，状态沿现有「状态」页签进入，读取同一份名称、耗蓝与状态信息。
5. 窗口打开或 Shell 接管时，四入口、火焰技能组与悬停层服从当前可见性；资源和普通技能信息继续可读。保留原暂停、Modal、Settings 与返回所有权。
6. 绑定与 Glyph 从 Application 输入服务读取，缺少 Sprite 时保留真实文字；换装、换槽、语言、设备族和重绑定即时反映，悬停期间源发生变化也不能保留旧说明。

主要修改集中在 `Hud.uxml/.uss`、`HudController`、必要的 `GameMenuController / GameMenuBoard` 可见性、`PlayerSkillStateRegistry.Capture` 的只读图标字段及 `ui` 表。详情可拆入现有 HUD 的小型表现模块；沿用 Query / Command / Event 分工，不改变 Player 控制器的输入世代规则，不引入第二份 InputActionAsset 或冷却计时器。

## 图标与资源接入

| 消费者 | 已有来源 / 计划 |
| --- | --- |
| 背包入口 | 优先复用 `ui_icon_inventory.png` |
| 属性入口 | 优先复用背包属性按钮当前使用的 `ui_icon_armor.png`，在目标尺寸复核识别度 |
| 天赋入口 | 新增独立的棋盘 / 构筑语义图标；轮廓在 24–28px 仍可辨识 |
| 暂停入口 | 新增独立暂停语义图标；与现有关闭、返回图标区分 |
| 技能图标 | 火焰用真实 `IconGuid`；普通技能补齐当前武器 GUID；缺图沿用明确占位，不能误显示为空槽 |
| 槽与仪表 | 复用 `ui_slot_base.png`、`ui_control_base.png`、`ui_hud_resource_base.png`，复核缩小后的 Slice 保护区与装饰重量 |

新增入口图标先按固定 UI 家族拟定：交付 96×96、透明底、主体最长边 64–78px、边距至少 5px、Alpha 加权中心偏差不超过 3px，Pivot 中心、PPU 64、Point、Full Rect、无压缩 / Mipmap、Sprite Single。生成画布及共用导出方式在开始生成前记录并冻结；需要统一导出时只允许全画布等比处理。

复用图标若在目标尺寸无法清楚区分语义，先将替代图纳入同一家族合同，再逐张生成；原有资产不按新图合同逐件裁切或缩放。

先用现有入口材质作为风格参考，生成一张 Pilot，通过数值审计与实际 24–28px 视觉检查后再逐张扩展；每张 PNG 只含一个图标，无烘焙文字。Hover / Pressed / Focus 优先用 USS，保持命中边界。执行时使用 ImageGen、[单图生产技能](../../../../../../.agents/skills/unity-2d-sprite-workflow/SKILL.md)和[美术规范](../../../../visual-asset-generation.md)，不拼生产组件表或人工切片。

固定图标沿现有 UXML / USS 依赖加载，动态图标沿 Session 的 Addressables / `SpriteAssetLoader`。新增资产必须有实际消费者，解除绑定释放持有引用；不为每次刷新发起独立加载。
