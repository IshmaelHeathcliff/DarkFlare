# 0.7.2-alpha 战斗与地图优化分计划

状态：2026-10-27，实施与验收完成，五阶段全部收尾。当前`0.7.2-alpha.5` / core15 / Save12 / Settings1 / 地图V4，城镇r3 / 野外r11；本轮尚未提交。EditMode993/993、PlayMode119/119，无失败 / 跳过。见[地图综合验收](../acceptance/compact-maps/README.md)。

以下保留实施前目标、基线与验收合同；实际实现和未执行项以上述验收为准。原有字体修改独立保留。

## 按住按键连续施法：阶段 1

普通技能 Attack 与六个火焰技能入口均支持：首次按下正常请求一次，持续按住时在冷却完成且满足条件后再次请求；松开立即停止。单击操作继续成立。

### 行为边界

- 沿用 Application 输入服务作为唯一输入来源。区分真实按下、保持、释放、设备与输入世代，不用键盘系统重复事件模拟施法，不读取全局键码绕过重绑定。
- 每次重放从当前输入取得瞄准，鼠标移动 / 右摇杆转向能改变下一次方向；方向为空沿用现有有效方向策略，已发射投射物不转向。
- 每槽只保留一个保持意图，不因多个绑定或逐帧请求叠加任务。各技能保留独立冷却；多个技能同时满足条件时以稳定顺序复核并提交，共享法力不能透支。
- 冷却或无蓝时不积攒待发次数；恢复条件且仍有效按住时可以继续。不用高频失败 Command 和日志刷屏，最终施法仍走原有权威校验。
- 窗口 UI、暂停、Shell、失焦 / 输入挂起、重绑定、设备断开、死亡 / 复活、切图、读档、Session 结束都使旧保持意图失效；恢复 Gameplay 后须释放再按。
- 换武器 / 换槽 / 取回火焰使对应来源的保持意图失效，不能拿旧输入自动触发新来源；其他仍有效技能不被无故重置。
- HUD 点击和消费输入要同时阻止首发与建立保持意图；保留现有帧末提交校验，避免进入 UI 的这一帧多发一次。

### 实现与验收

重点修改 `ApplicationInputService`、`GameInput`、`PlayerController` 和必要技能状态查询。保持任务归属 Session / 组件作用域，使用可取消 UniTask；玩法暂停不推进冷却，不在每次读取 HUD 时推进战斗。

在 `ApplicationInputServiceTests`、`PlayerSkillsTests` 和现有输入 / 资源 PlayMode 用例中验证：短按一次、长按跨多个冷却、冷却中松开、无蓝后恢复、多键同时按住、重绑定、扳机释放、瞄准更新、来源变化以及上述全部中断边界。重点证明一份保持意图只产生合法次数，旧 Session 不能操作新角色。

更新[手动技能](../../../../skill-board/manual-skills.md)、[输入](../../../../input-ui-system.md)与必要生命周期说明。

## 默认技能三投射物与一次穿透：阶段 1

这里的“提高性能”按战斗能力增强处理。当前新角色默认技能为大剑普通技能 `skill:great_sword_normal`，不再是历史单一 `skill:basic_projectile`。

### 参数与结算

- 为 `ProjectileSkillDefinition` 增加可校验的投射物数量、散射角与穿透次数配置；旧资产缺省仍为一枚、零穿透。
- 大剑普通技能设为三枚、一次穿透，先试相对瞄准方向 `-10° / 0° / +10°`；保留现有单枚伤害、法力与冷却作为首轮对比基线。战斧与火焰技能保留各自配置。
- “穿透一个怪物”指穿过第一个合法敌对目标后仍能结算第二个不同目标，随后结束；单枚最多两个目标。同一 Actor 的多个碰撞体或重复接触不能重复结算。
- 每枚分别维护已结算目标和剩余穿透次数；三个投射物不共享这份集合。友方、死亡和非法目标不扣次数；合法目标的命中 / 闪避仍遵守原伤害规则，不能因未命中反复撞同一目标刷判定。
- 一次施法只扣一次法力、启动一次冷却并发一次攻击通知；三枚使用本次施法冻结的来源与属性，飞行中换装不改伤害。随机子流按投射物稳定序号区分，明确哪些掷值共享，不能通过循环三次单发 Command 意外消费三份费用 / 根种子。
- 三枚必须全部准备成功后才提交。任何一枚生成失败，清理本次已生成对象，不扣蓝、不启动冷却、不发成功事件；延续既有攻击根种子失败后不保证回退的边界。
- 保存继续只恢复既有技能 / 冷却语义，不保存正在按住的输入意图，也不重放离场投射物。

### 改动与验证

复用 `FireProjectileCommand`、`SpawnSystem`、`AttackSnapshotFactory` 和 `ProjectileController`，不另建平行伤害管线。检查生成结果接口的既有消费者，使多枚结果与历史单枚读取兼容；生成对象必须归当前地图和 Session，失败、离场和生命周期结束全部回收。

长期用例补入 `PlayerSkillsTests` 与既有伤害、资源、随机和生命周期套件，覆盖三方向、两目标上限、同 Actor 去重、友方过滤、不同投射物独立、部分生成失败、一次扣蓝 / 冷却 / 通知、来源冻结。正式场景实测持续按住三投射物、怪群穿透和切图清理。

更新[技能配置](../../../../config-reference/skills.md)、[手动技能](../../../../skill-board/manual-skills.md)及相关战斗 / 资源说明；内容语义变化评估 core 版本，纯配置扩展不自动提升 Save Schema。

## 缩小城镇与野外：阶段 5

### 布局候选与路线

实际执行顺序、完整候选导入、版本和验收门槛以[阶段五计划](phase-5-execution.md)为准。现有SetMapMetadata不裁剪旧数据，缩图不能只修改宽高。

| 地图 | 当前 | 首轮候选 | 保留的功能 |
| --- | --- | --- | --- |
| 城镇 | 64×64，r1 | 32×32 | 新游戏、返回、唯一复活入口、商人、打造与野外传送门 |
| 野外 | 128×128，r9 | 64×64 | 入场安全区、返回门、唯一复活入口、Boss、50 入图名额与 10 处触发区域 |

尺寸是待实测候选；若 50 入图落点、通路或对象净空无法满足，先调整布局或候选尺寸，不能减少名额、叠怪或缩小碰撞体凑数。

- 保留格宽 1 和既有单位尺度，重绘地表、障碍和区域，重新布置对象、入口与 Boss；不是只改 width / height 截掉外圈。
- 城镇围绕出生 / 返回位置缩短商人、打造和传送路线；野外缩短安全区到首战及各怪群之间的空走，仍给绕行和拉扯留空间。
- 调整地图 origin / Bounds、相机、导航编译和对象足迹检查；出生点不能在障碍或怪物碰撞内，Safe 排除继续有效。
- 通过既有 `MapEditApi` 批量预览、原子应用和保存；同时检查两图出口目标、入口身份与内容引用。不手工另建一份布局 SO。

### 旧存档兼容是地图实施前置

当前 `WorldMapCatalog` 只支持已知野外 r1 / r4 / r7 到 r9 的特定语义迁移，且当前恢复要求地图修订及刷怪计划数量匹配；不能直接把 r9 的文件缩小并假定旧档可继续。

1. 修改源图前保存可复现的旧布局 / 语义基线，明确城镇 r1、野外 r9 及更早迁移链的接续方案；分别覆盖活动图和冻结图。
2. 先完成兼容方案与夹具验证，再替换正式地图。优先明确迁移已知旧修订：确定角色、活怪、掉落、行为锚点、导航意图的坐标映射与合法落点政策，保留实例身份、已掷结果、资源、Boss 与击败进度。
3. 按用户已确认的新建 / 手动重置实例规则，当前r9旧实例保留100名额及全部状态和种子，不在继续时补200个Pending；新实例才建立300。通过完整批次、名额集合与原算法种子识别已登记旧 / 新计划，不仅凭数量放行；历史r7→r9先按既有链在冻结旧布局上接续。`LegacyPreserved`不凭空推算击杀或收益，见[兼容方案](map-save-compatibility.md)。
4. 不把升级实现为自动重置，不截断掉落、不删除越界对象、不重复发收益；迁移无法满足合法位置和容量时，应完整拒绝并保留原档。若需要改为保留旧布局或由玩家明确重置，再单独确定该方案后实施，不能临时静默降级。
5. 未知修订继续明确拒绝；不能只替换修订号绕过校验。地图 Revision 单独推进；仅在 DTO / 格式确有变化时升级对应 Schema / FormatVersion。

## 300 名额与遭遇频率：阶段 5

用户已确认保留有限刷怪：每个新建或手动重置的野外实例提供 300 个普通名额，普通离开返回 / 保存继续均保持进度。Boss 名额独立于这 300 个普通名额。

| 批次 | 数量与触发 |
| --- | --- |
| `initial` | 50，沿用 `OnEnter`；在地图可以交互前完成合法生成 |
| 10 个其他批次 | 每批 25，沿用 `PlayerRange`；分布于压缩后地图的不同路线与区域 |

- 当前已有十个触发点，本轮重点是重新布点、提高每点名额和遭遇密度；不为“增加点位”机械增加到十个以上。
- 触发圆随新布局重算，不能因为地图变小而在出生处一次命中全部范围；保证正常路线和高速穿越都能激活应触发批次。
- “提高频率”通过缩短群间距离与分批投放实现，不启用旧的 `SpawnInterval` / `MaxAliveCount` 定时补满逻辑；已击败名额不补怪。
- 首轮保留范围批次每帧最多处理四个 Pending 的预算，先测触发后的可见等待与帧耗时，再决定是否调预算。合法落点不足继续保留 Pending 与诊断，不能把 25 只强行堆在一点。
- 新游戏 / 手动重置可以创建新计划；普通切图与继续保持批次激活和 Pending / Alive / Defeated。击杀、掉落及瓶能量仍严格去重。

## 地图与联合验收

- 同条件记录城镇功能路线、野外到首战、群间空走时间及前后地图截图，证明缩小改善路线，而不仅是宽高数字变小。
- 新实例核验 50 初始与 10×25 范围名额；50 入图落点合法、离开安全区能正常遇敌，遍历十点后可以清空全部普通名额，Boss 独立。
- 覆盖触发重叠 / 高速穿越、落点暂时阻塞 / 解阻、暂停 / 离场停止、普通返回不刷新、手动重置及失败回退。
- 旧档覆盖城镇 / 野外活动与冻结组合、已击败 / 存活 / Pending、Boss、掉落和已装备瓶；未知修订与失败恢复不修改原档。
- 使用当前版本测量 50 入图、单 / 多批次触发、持续三投射物和尽量接近 300 存活单位的 Editor 场景，记录实际数量、帧时间 / 峰值 / 分配、加载和保存耗时；与同环境基线比较，调查持续超出约 16.7 ms 帧预算及新增尖峰的主要原因。不能把总名额当成同时存活数量，也不能用历史 Player 结果替代本次采集。

复用 `WorldMapStateTests`、`MapEditTests`、`WorldMapPlayModeTests`、保存迁移和现有生命周期套件；保留真正历史存档夹具，清理一次性采集脚本。更新[有限刷怪](../../../../behavior/finite-spawning.md)、[地图生命周期](../../../../maps/world-map-lifecycle.md)、[手动重置](../../../../behavior/map-reset.md)、[导航](../../../../maps/navigation.md)与配置参考，证据统一随 0.7.2 归档。
