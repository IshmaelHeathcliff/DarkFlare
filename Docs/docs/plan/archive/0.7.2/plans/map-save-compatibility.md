# 0.7.2 紧凑地图的旧存档兼容计划

状态：2026-10-27，实施与验收完成，五阶段全部收尾。当前`0.7.2-alpha.5` / core15 / Save12 / Settings1 / 地图V4，城镇r3 / 野外r11；本轮尚未提交。EditMode993/993、PlayMode119/119，无失败 / 跳过。见[地图综合验收](../acceptance/compact-maps/README.md)。

以下保留实施前目标、基线与验收合同；实际实现和未执行项以上述验收为准。原有字体修改独立保留。

## 已确认的数据事实

旧档保存MapId、地图Revision、世界位置、完整刷怪名额与随机种子，不保存地图原始JSON或地图语义Hash。现在的`WorldMapCatalog`仅支持野外r1 / r4 / r7到r9，且依赖从当前r9反推旧布局；有限计划又要求数量与当前地图批次相同。直接替换为缩小的300名额图，会同时破坏旧几何基线和数量校验。

`SaveRestorePreparer`先执行已知地图升级和数据校验，再进行地图落点检查及运行态恢复；部分路径当前会直接修改传入的文档。本阶段必须先复制候选，在完整成功前保持调用者对象与磁盘原档不变。

## 实例与计划政策

用户已确认“新建或手动重置实例300、普通返回保留进度”。据此区分如下，不将内容升级当作隐式重置：

1. 新野外、从未访问的野外与明确重置使用当前300计划。
2. 已访问r9有限实例保留原100个SlotId、BatchId、怪物内容、两类种子、激活、Pending / Alive / Defeated和存活实例ID；不增加200个Pending。
3. 已发布r7→r9的12→100历史迁移保留原有兼容含义，先在冻结的旧128布局上完成，之后将100计划移到紧凑图。不能用新图重建这段历史，旧12个名额也不重掷。
4. `LegacyPreserved`只保留已有怪物 / Boss / 掉落，继续不补怪、不推算击杀或瓶收益；显式重置后才建立300计划。
5. 迁移不修改实例代次。只有原有重置事务成功才递增Epoch；新怪物 / Boss与掉落收益不能借迁移重复生成。

旧有限计划仍正常工作：已激活Pending继续按预算尝试，未激活批次可由玩家在新布局中正常触发；不是把有限图整体冻结为`LegacyPreserved`。迁移本身不补名额或主动改激活标记。

### 计划识别与严格校验

优先复用现有Mode、批次及名额字段，不增加保存字段：在统一的兼容入口登记“旧100”和“新300”两份有限计划合同，以完整批次 / SlotId集合、怪物定义及按原算法生成的MonsterSeed / PositionSeed识别。运行生成、恢复预检与再次保存读取同一结果。

不能只用`Slots.Count == 100`放行，也不能任意放宽到“≤300”；新增负例必须证明截短的新300计划、混合两种种子的计划、缺批次 / 重复名额 / 伪造存活身份仍被拒绝。旧100在新Revision下保存继续仍能识别，普通回图不再尝试扩容。

当前生成器跨批次共用顺序Random，改数量后后续名额掷值会变化。因此保留旧预选与原怪物池，不用新300生成结果覆盖同名旧槽；也不为本阶段另改全局随机算法。

若实现验证证明现有字段不能无歧义表达这些已知合同，先补明确的计划版本字段及对应Save Schema迁移再发布；不得临时依靠内存标志、通配数量或关闭校验完成恢复。默认仍以Save12 / 地图V4不变为目标。

## 坐标迁移与落点

两图目标为等比压缩空间布局，单位自身尺度不变。位置初值使用旧 / 新边界归一化映射：`u = (旧世界坐标 - 旧origin) / 旧extent`，`新位置 = 新origin + u × 新extent`；只有被登记的旧布局可用此映射，不能对未知修订套公式。

先按已知旧几何及原有接触容差校验源位置，不能靠新图重定位把原本越界或损坏的数据洗成合法。未使用的可选行为点沿旧语义保留，不因默认占位值而拒绝正常历史档。

| 数据 | 处理 |
| --- | --- |
| 活动图玩家、活怪 / 活Boss、掉落Position | 映射后按新几何、实际足迹与可达性确定合法落点 |
| 怪物Behavior.Anchor、有效LastSeen、HasWanderGoal时的WanderGoal | 同图空间点一并转换，不把旧世界坐标留在行为中 |
| Boss.LastSeen、Navigation.Target为Point时的Point | 转换并复核边界 / 语义；玩家 / Actor身份目标保持原身份 |
| Facing等方向向量、速度 / 半径配置、动作剩余量、冷却、资源、词条、技能与状态层 | 不做坐标缩放，不重掷、不重新施加收益或治疗 |
| 导航路径 / 网格 / 搜索缓存、飞行中投射物、按住输入 | 沿原规则不保存，恢复时重建或清空 |

落点规则在候选上按稳定顺序执行：先玩家与Boss，再按实例ID处理普通怪物，掉落独立处理。先试投影点，再复用现有几何 / 导航查询搜索附近合法点，固定同距裁决顺序、不消费玩法RNG。玩家 / Boss / 怪物避免相互占用；重新安置的怪物避开入口安全区。掉落需要地形合法、能拾取，但不强求每件物品独占一格，保留所有实例和统一Items所有权。

纯数据阶段检查已知旧布局、坐标与初始候选；资源预热后以实际Prefab圆足迹、对象障碍和候选占用再次决策 / 校验，全部完成后才激活目标图。中间候选不对外发布；半径不能靠缩小碰撞体通过。保留有效行为 / 动作余量和HitResolved，不能借迁移重复结算预警攻击。

搜索和容量有界；找不到合法位置时整次恢复失败，说明具体地图 / 实例原因，原文档与原档不变。不得静默删怪、吞掉落、删除其独占Items或借升级调用重置；也不悄悄退回旧地图大小。如果常规历史样本无法容纳，先调整候选布局 / 尺寸。

## 迁移顺序、幂等与版本

1. 原有文件 / Schema / 内容迁移后，为地图转换创建独立候选文档；校验已登记旧布局快照及合同，不假称原档保存了地图Hash。
2. 接续历史野外r1 / r4 / r7→r9；town r1与wilderness r9分别映射到最终紧凑修订。活动与冻结图都处理，不能只改活动图。
3. 保留源图计划，转换所有有效空间点，完成几何与足迹预检；冻结地图的状态时间、实例 / Items引用、Boss状态、玩家资源和两类RNG均保持。
4. 最终修订只在对应地图候选完全成功后替换；已是新修订的图再次Prepare不能二次压缩，保存继续 / 普通切图不改变名额。
5. FrontEnd摘要 / Continue共用严格预检，读摘要不写盘；实际恢复成功后的保存仍走原协调器 / 原子代际文件。候选失败不能部分推进Header或其他冻结图。

未知修订与篡改历史布局继续拒绝。Schema3→4已有真实历史链会产生野外Revision0，不能把0当作所有新图的通配Revision；必须从原夹具 / 已登记早期布局确定其坐标基准并保留恢复能力，不能删除这些历史测试来绕过。

core预计14→15，因为源图与新实例配额语义变化；更早内容链继续接续。Save / Settings Schema及地图格式只在实际持久化合同变化时推进，不为单纯位置 / Revision值变化升级格式。

## 长期验收

补入现有`WorldMapStateTests`、保存迁移 / 预检 / 恢复和`WorldMapPlayModeTests`，新增真实alpha.4隔离存档样本并记录捕获来源、校验值和字段含义；保留已发布历史夹具，不从新图临时拼“旧图”。

- 活动城镇 / 冻结野外与活动野外 / 冻结城镇，未访问图，旧100各类名额、LegacyPreserved、r7及Revision0历史链；Boss Ready / Alive / Defeated / LegacyAbsent，掉落与瓶 / 技能冷却。
- 投影越界、落障碍、拥挤、有效 / 无效行为点、固定导航点、足迹失败；不改朝向、资源、掷值、实例 / Items集合与随机序列。
- Prepare两次、迁移后保存继续、普通往返、手动重置：坐标只迁移一次，旧计划保持，新重置准确300。
- 未知修订、伪造100计划、迁移中途失败、预热失败、落盘前失败：调用者对象图、原文件Hash、代次与其他地图完整不变；原有落盘后清理失败语义保留。

一次性坐标分布图、路线 / 容量探查和截图代码验收后清理，证据随阶段五归档。真正的历史迁移输入和独有覆盖长期保留。
