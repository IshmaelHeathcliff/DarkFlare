# 0.7.2-alpha 界面优化分计划

状态：2026-10-27，实施与验收完成，五阶段全部收尾。当前`0.7.2-alpha.5` / core15 / Save12 / Settings1 / 地图V4，城镇r3 / 野外r11；本轮尚未提交。EditMode993/993、PlayMode119/119，无失败 / 跳过。见[地图综合验收](../acceptance/compact-maps/README.md)。

以下保留实施前目标、基线与验收合同；实际实现和未执行项以上述验收为准。原有字体修改独立保留。

## 能量瓶装备入口：阶段 2

### 目标与布局

- 在现有背包窗口的装备区域放置独立能量瓶槽，显示图标、已存 / 容量及满瓶状态。它是装备界面的专栏，不并入十个战斗装备槽，不贡献普通装备属性。
- 沿用瓶子 2×1 的物品比例和现有槽位视觉语言，调整装备区局部布局；不压缩背包物品格，不为瓶子另开常驻窗口。
- 背包中能量瓶可通过拖放、动作菜单及键盘 / 手柄拿起放置进行装备；已装备瓶可卸下或替换。不可用时给出真实失败原因。
- 天赋页移除装备 / 卸下瓶按钮和装备投放区。中心仍用于选择背包或已装备瓶并确认整瓶充能，可以显示当前瓶的只读能量信息。

### 改动边界

复用 `EnergyBottleSystem`、`SkillBoardOperation.EquipBottle / UnequipBottle` 与现有预检 / 提交事务；不把 UI 迁移改成一套新的瓶子所有权系统。保存字段继续使用现有 `EnergyBottleInstanceId`，不用新增装备槽枚举来存放同一件瓶子。

装备区实际位于 `ItemWorkbench.uxml`，阶段二调整了它及 `Windows.uss`、`ItemWorkbench.uss`、`InventoryPanelController`、`ItemActionRouter`、共享来源 / 投放目标和棋盘面板，副边操作复用现有控件。原路由直接寻找 `board-bottle-drop`，现已改为背包内可见的 `inventory-bottle-slot`，关闭棋盘后仍可换瓶。

具体操作与回退以[已归档阶段二计划](phase-2-execution.md)为准：已增加独立已装备瓶来源及可选卸瓶目标格，快捷卸下仍自动找位，换瓶成功留在背包。瓶栏利用装备区左上空位，保持原高度和格子尺度；原 `board-bottle-drop` 已替换为只读摘要和明确的装备瓶充能选择入口。

### 验收

| 场景 | 结果 |
| --- | --- |
| 天赋窗口关闭，背包打开 | 鼠标与手柄均能装备、替换和卸下瓶子 |
| 旧瓶换新瓶 | 旧瓶回填新瓶原背包位置，能量与实例身份保持 |
| 背包空间不足 / 来源变化 | 整笔失败，瓶子、格位、能量和成功事件保持原状态 |
| 击杀、满瓶、换瓶、继续游戏 | 仅当前装备瓶收集；溢出规则不变；保存恢复唯一归属 |
| 天赋中心充入装备瓶 / 背包瓶 | 明确确认才消费，装备槽同步更新；取消不转移所有权 |
| 商店 / 打造 / Shell / Session 切换 | 旧目标失效，拖动与预览取消，不操作隐藏界面或新 Session |

长期回归优先补充 `SkillBoardTransactionsTests` 与现有物品 / 棋盘 PlayMode 套件；复用 `EnergyBottleTests` 的收益与收集覆盖，不重复编写未变化的规则。更新[能量瓶](../../../../skill-board/energy-bottles.md)、[安装事务](../../../../skill-board/items-installation.md)、[装备](../../../../equipment-system.md)和[物品工作台](../../../../item-ui-workbench.md)。

## 天赋界面：阶段 3

具体布局、方位映射、输入路线、实施顺序及验收条件见[阶段三实施计划](phase-3-execution.md)。本节范围已交付，当前模块见[玩家棋盘](../../../../skill-board/player-board.md)；实际画布占比默认 84.63%–84.98%、详情展开 68.13%–68.41%，三语言与保存 / 输入闭环通过。

### 精简与画布

- 去掉常驻的六根定位按钮，以及重复的放大 / 缩小文字按钮、格坐标等调试读数；调试信息保留在既有开发窗口。
- 将“回到中心 / 适配网络”收为紧凑工具入口。滚轮 / 中键保留；先提供并验证手柄平移、缩放和回中操作，再移除对应常驻按钮，操作提示读取实际绑定。
- 顶部只保留天赋点、属性点、能量池和下一兑换成本等必要摘要；按当前选择显示操作，不同时铺开所有不相关按钮。
- 六技能槽使用紧凑分配区；只在对应槽有内容时提供清除动作，不常驻六个重复“清空”大按钮。多连接选择、拆卸退款和整瓶充能继续提供明确确认。
- 详情区按选择展开，长说明可滚动；默认浏览把面积让给棋盘。背包保持可用，拖放时可直接找到来源。
- 记录优化前后同条件截图及画布实际面积，初版目标为棋盘画布占棋盘窗口内容区至少 65%，且比基线明显增加；在默认浏览和展开详情两种状态分别记录，不以隐藏必要操作换比例。

### 朝向与显示一致性

用户已确认最终布局：力量在中心上方、敏捷在左下、智力在右下。实施前属性沿 `NeighborDirections[i * 2]` 放置，力量在右、敏捷左下、智力左上；严格整体顺时针 15° 不能得到目标布局。阶段三现已采用显示顺时针 30°，将力量 / 敏捷 / 智力分别映射至邻格索引 4 / 2 / 0，保留领域坐标与实际属性身份。

1. 以最终方位定义统一的显示角度与属性到显示格的对应关系；属性选择和说明必须读取同一映射。中心属性分配身份不变，不改已存的属性数值。
2. 在投影层统一处理格中心、六边形顶点、连线、裂缝、预览、标签锚点和效果高亮，文字保持正向可读。不能只转外层容器或只移动标签。
3. 点击使用逆变换，缩放 / 平移 / 适配使用旋转后的边界；手柄按屏幕方向寻找相邻逻辑格。
4. 领域轴坐标、大柴薪六根、60° 安装旋转、连通规则、节点和存档身份保持原有规则，不为视觉调整重排历史网络。

### 验收

- 三属性在目标方位，选择后分配到正确属性；中心、六根及已安装网络完整可读。
- 在不同缩放和平移位置点击节点，命中与画面重合；手柄方向与视觉一致，远处网络仍可到达并回中。
- 从背包安装、60° 旋转、连接选择、嵌入、点亮、取回、拆卸、技能分配 / 清除与中心充能均能完成；删除快捷按钮不删除实际能力。
- 返回逐层取消，关闭后恢复原窗口组合；三语言文本、焦点和预览不越界。
- 同一存档在优化前后安装坐标、连接、点数及六槽一致。

主要入口为 `PlayerBoard.uxml/.uss`、`SkillBoardViewport`、`SkillBoardPanelController / Actions`、`GameMenuBoard`；复用 `SkillBoardGeometryTests`、`SpatialNavigationTests` 和 `Phase1UxPlayModeTests`。模块更新[玩家棋盘](../../../../skill-board/player-board.md)及[几何](../../../../skill-board/geometry.md)。

## 主界面 HUD：阶段 4

详细布局、面积口径、图标合同、输入与验证顺序见[阶段四实施计划](phase-4-execution.md)。本节范围已交付；运行版本 `0.7.2-alpha.4`，主HUD面积减少52.32%–62.46%，三语言、真实输入和保存恢复通过。

### 视觉与信息层级

- 按暗黑刷宝游戏的常见底部结构重排：生命在左、法力在右，中间为普通技能和六火焰槽；窗口入口在相邻的紧凑图标组，金币降为次级信息。上方世界画面尽量留给移动、战斗和掉落。
- 延续项目炭黑 / 暗石、旧铁、少量金铜及像素硬边语言。资源形状可结合现有底板调整，先验证紧凑轮廓，不照搬其他游戏的专属装饰。
- 用图标、真实绑定、冷却遮罩 / 数字和状态角标代替宽文字卡片；普通技能来源与六槽数量不变。空槽、无来源、法力不足、暂停、死亡、冷却均可区分。
- 名称、耗蓝及完整状态说明放到悬停 / 焦点详情中；生命 / 法力真实数值、关键不可用反馈与绑定不依赖鼠标悬停才能获得。
- 背包、属性、天赋、暂停入口各提供独立图标，配本地化名称与实际输入提示；图形缩小但保留可靠点击区域。商店和打造仍由世界交互授权，不新增远程入口。
- 状态条、低生命提醒、世界交互提示和 Toast 与底部技能栏留出明确间隔；Reduce Motion 保留静态可读反馈。

### 图标与接入

先盘点可复用图标；需要新增时为入口图标确定统一画布、主体占比、线条、中心和透明安全边距，生成并审计单张样图后再扩展家族。每个生产图标独立 PNG / Sprite Single，无烘焙文字；焦点、悬停和按下反馈优先使用既有样式。详情与数据由 UXML / USS / Controller 组合。

改动集中在 `Hud.uxml/.uss`、`HudController`、共享组件样式及必要图标引用。继续使用真实技能 Query、资源事件和已有低频刷新，不因缩小卡片新增第二份冷却计时器。窗口打开和 Shell 接管时继续遵守原有可见性与输入规则。

### 验收

- 同一场景、同一画布对比优化前后截图：技能卡片和入口明显缩小，底部遮挡减少，主要数字与键位可读。
- 1920×1080 × 三语言覆盖空槽 / 全槽、长名称、长绑定、冷却与法力不足；详情不遮挡关键反馈。
- 鼠标点击任一 HUD 入口不触发本次普通攻击，也不能建立后续按住连放；关闭窗口后旧按住状态不复活。
- 键盘 / 手柄沿用既有窗口入口与窗口循环到达功能；Gameplay 保持原输入隔离，不为图标组常开 UI 导航而截走移动。
- 换装、换槽、资源变化、暂停、设备族 / 绑定变化即时反映；禁用、切图和 Session 结束后任务与资源正确释放。

复用 `GameplayUiFoundationTests`、`ApplicationInputServiceTests`、资源和 `Phase1UxPlayModeTests`；更新[HUD](../../../../hud-system.md)、[输入](../../../../input-ui-system.md)、[组件规范](../../../../ui-component-style.md)及[视觉资产](../../../../visual-assets.md)。截图 / 生成与审计证据随 0.7.2 归档，临时采集脚本清理。
