## 持续施法的确定行为

| 情况 | 行为 |
| --- | --- |
| 首次按下 / 冷却中按下 | 允许首发时请求一次；尚在冷却时保留保持意图，到期再请求，不囤积次数 |
| 持续按住 | 当前来源、存活、玩法输入、冷却和法力均允许时继续；每帧每槽最多一次，不追补低帧率期间错过的次数 |
| 松开 | 清除保持意图，取消尚未提交的重复请求；已发出的投射物正常运行 |
| 法力不足 / 暂时不能攻击施法 | 不扣蓝、不起冷却，不高频提交失败命令；状态恢复且输入仍有效时可继续 |
| 多技能同时按住 | 普通技能优先，再按火焰槽 1–6 的固定顺序逐个复核法力；每槽独立冷却，不增加全局冷却 |
| 瞄准变化 | 每次实际提交前读取当前鼠标 / 右摇杆；无新方向沿用最后有效方向 |
| 换武器 / 换槽 / 取回火焰 | 只清除对应来源的保持意图；同槽恢复原物品也须重新按下，不借换装重置原有冷却 |
| UI、暂停、Shell、失焦、重绑定、拔设备、死亡、切图、读档、Session 停止 | 清除旧意图与排队请求，恢复后须释放再按，不跨上下文和 Session 延续 |
| HUD 点击 | 同次点击不能首发，也不能建立连放；从 UI 拖出后仍按住也不触发，必须释放后重新按下 |

`ApplicationInputService` 继续是唯一输入所有者；按动作维护真实保持状态、设备和输入世代，读取实际绑定。`GameInput` 转发只读状态；`PlayerController` 在原有组件作用域中保留一个可取消的 UniTask 调度循环，仅在有有效意图时工作，最终仍通过 `CastPlayerSkillCommand` 提交。

首次按下与连放共用同一提交路径，保留 `LastPostLateUpdate` 的 UI 消费校验；不同时运行“首发任务”和“重复任务”造成双发。每次提交同时检查按下代次、输入世代、来源 ID、角色和地图身份，失效后不能改用当前新来源。

## 三投射物与穿透的确定行为

- 通用配置候选字段为 `ProjectileCount`、`SpreadAngleDegrees`（总散射角）、`PierceCount`（可额外穿过的目标数）。缺省分别为 `1 / 0 / 0`，数量和穿透设置有界校验，拒绝非有限角度和非法数量，不隐式修剪配置。
- 本阶段正式大剑为 `3 / 20° / 1`，方向为中心、左 10°、右 10°；稳定序号 0 为中心。实际散射如需调优，在收尾前同步配置和验收，不改变三枚及一次穿透要求。
- 战斧、火焰和其他投射物配置保留原有默认行为；大剑冷却 0.6 秒、法力 1、原单枚伤害 / 速度 / 半径 / 寿命作为对比基线，不另加伤害系数或递减。
- 每次施法只取一个 `PlayerAttack` 根种子；序号 0 保留原种子语义，其他枚由根种子和稳定序号派生。各枚分别冻结伤害掷值、命中 / 暴击及状态应用快照，来源、施法时属性与修改器一致；不额外消费全局随机通道。
- 同一枚穿透到第二个目标时沿用这枚已冻结的掷值，防御者按现状结算；本阶段不改为碰撞时重新抽取全局随机。
- 每枚最多对两个不同的合法敌人结算；同一 Actor 多碰撞体、离开后再碰到仍只结算一次。合法敌人的闪避消耗本次目标次数并去重；友方、死亡、未登记等无效目标不消耗。
- 三枚互相独立，同一目标可以被不同投射物分别结算；不引入整组共享去重、伤害叠加限制、弹射或追踪。
- 一次施法只发布一次攻击 / 施法通知。现有单枚结果 `Projectile` 与事件 `Attack` 继续指向序号 0 的真实结果；需要遍历多枚的消费者通过只读集合读取，不能伪造额外“施法成功”。

### 整组提交与回收

`SpawnSystem` 目前单枚实例化后立即 `Init`。扩展时增加本次发射内部的准备边界：先取得所有实例并完成组件 / 资源检查，准备期关闭碰撞与有效命中；全部成功且再次确认提交条件后，扣一次蓝、提交一次冷却、激活整组，最后发布一次成功通知。

任一实例获取或初始化失败，先使本组所有实例无效，再经既有 `SessionObjectRegistry` 释放，不仅依赖帧末 `Destroy`。失败不产生伤害、状态、击杀收益、费用或成功通知；已取得的攻击根种子沿用现有“不承诺回退”的合同。不要为本阶段扩建通用事务框架。

命中去重在调用伤害命令前占用当前目标，防止事件重入重复命中；第二个合法目标结算完成后立即停用该枚的后续命中。寿命仍沿用原可取消任务，结束、失败和切图均释放碰撞、排序及地图注册。

## 内容与保存兼容

core v14 明确表示默认大剑技能语义增强；追加 core 13→14 接受路径，原有 stable ID 不变，已有角色装备同一大剑后使用新配置。旧物品、火焰实例实际变体、成长、槽位、冷却和随机通道原样恢复，不补物品 / 点数或重掷词条。

当前 `SaveRestorePreparer` 的旧迁移多处将目标上限写为 13，12→13 还要求目标正好为 13。必须让已登记的 v1–v13 历史链能够接续到 14，并继续拒绝未知目录、未知未来版本和不合法旧字段；不能只添加最后一条分支造成早期档无法继续。

本阶段不改 Save Schema 12、Settings Schema 1 或地图内容；保持现有历史迁移夹具。保持输入、调度任务和在途投射物不入档，读档后不会自动施法。文件路径修复也不等于授权恢复或覆盖已存在的临时 / 正式存档，处理规则见存档前置计划。
