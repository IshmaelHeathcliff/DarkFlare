## 目标与基线

按[总计划](alpha-0.7.2-optimization-plan.md)和[界面分计划](ui-optimization.md)交付阶段二：玩家只打开背包，就能在装备区装备、替换、卸下能量瓶；天赋中心继续承担整瓶充能。

- 实施起点：`main` / `479f9018dee4d37ed217f9f11d828092fa6c9ebc`，Unity `6000.6.7f1`。已有 `GameCjkFont.asset` 修改保持独立，不纳入本阶段。
- 实施前数据：core v14、Save / Settings Schema 12 / 1、地图 V4，城镇 r1 / 野外 r9。本阶段预计全部保持；装备瓶仍由现有棋盘状态保存，不扩展十个战斗装备槽。
- 目标运行版本：`0.7.2-alpha.2`，仅在实现及验收完成后推进。本计划不提前修改版本或把规划登记为交付。
- 阶段一历史验收：EditMode 982/982、PlayMode 112/112，两轮普通 Play 继续保存及原文件恢复通过，见[验收](../acceptance/continuous-casting/README.md)。这些数字是起点记录，不替代本阶段测试。
- 天赋精简与方位、HUD、地图缩小和 300 名额仍由阶段三至五交付。本阶段复用瓶子图标和共享样式，不新增美术家族。

## 实施前核对的实现与缺口

| 现状 | 本阶段处理 |
| --- | --- |
| 装备纸娃娃实际在 `ItemWorkbench.uxml`，十槽由 `EquipmentSlots.All` 绑定；`Inventory.uxml` 是副边操作区 | 在纸娃娃附近增加独立瓶专栏；不把瓶伪装为 `EquipmentSlot`，不挤掉原十槽 |
| `ItemActionRouter.EquipBottle` 要求天赋页可见，目标固定为 `board-bottle-drop` | 改为背包装备区可见目标；提交仍走 `PreviewSkillBoardQuery` / `CommitSkillBoardCommand` |
| 共享来源仅区分背包、普通装备等；已装备瓶没有独立来源；拖回格子会被当作普通移动 | 增加已装备瓶来源与卸瓶动作，校验当前玩家、真实持有和窗口可见性 |
| `ItemInteractionSession` 将换瓶后的焦点切到天赋页，未订阅瓶状态与能量变化 | 成功后留在可见背包装备区或返回物品；同步来源、反馈和旧预览失效 |
| `SkillBoardRequest` 未提供背包目标格；卸瓶只自动找空位；换瓶已精确回填新瓶原格 | 为卸瓶补可选目标格，沿用同一预检 / 提交事务；无目标格保持现有行为 |
| 天赋 `board-bottle-drop` 同时是装备投放目标和选择装备瓶充能按钮 | 移除装备投放用途，保留独立、明确的“选择装备瓶充能”操作，继续确认后才消费 |

依据为[能量瓶](../../../../skill-board/energy-bottles.md)、[安装事务](../../../../skill-board/items-installation.md)、[中心成长](../../../../skill-board/growth.md)、[装备](../../../../equipment-system.md)、[物品工作台](../../../../item-ui-workbench.md)及对应脚本。本轮未读取 `Docs/design/`。

## 确定的操作行为

| 操作 / 情况 | 结果 |
| --- | --- |
| 背包内选择能量瓶 | 显示实际图标、名称、能量 / 容量；通过拖放、动作菜单或键盘 / 手柄拿起放置到瓶专栏进行装备 |
| 空专栏装备 | 瓶从背包移到专栏；统一物品动作执行时预检并提交，不进入天赋确认流程 |
| 用新瓶替换旧瓶 | 新瓶进入专栏，旧瓶精确回填新瓶原 2×1 格；保持实例身份与能量，满背包也能完成有效交换 |
| 已装备瓶快捷卸下 | 在同一事务内自动寻找可容纳 2×1 瓶的空位；失败给出原因，原状态不变 |
| 拖动 / 手柄放回指定背包格 | 只尝试指定 2×1 区域；越界或被占则失败，不偷偷改放其他格，不先卸下再移动 |
| 装备瓶出售 / 丢弃 / 放入打造 | 不直接跨所有权操作；先成功卸到背包后才能使用背包的出售 / 丢弃规则；打造目标仍拒绝瓶子 |
| 商店等窗口并存 | 保留原有出售等上下文默认动作，不让瓶子默认装备抢走出售；显式选择可见瓶专栏仍可换瓶，不改其他物品路由 |
| 点击天赋中心的背包瓶 / 装备瓶选择入口 | 仅选择并预览整瓶充能，不装备、不卸下；明确确认才消费，取消无状态变化 |
| 来源、格位、玩家或 Session 已变化 | 拒绝过期操作并刷新；禁止操作隐藏目标、旧 Session 或其他玩家的瓶子 |

背包打开即可完成装备职责，不要求天赋页打开。天赋画布不再接受“把能量瓶拖到棋盘来装备”的含混操作；中心充能继续沿用现有选择、预览、确认路径。普通换装沿用共享物品动作的即时事务提交，整瓶消费保留明确确认。

## 界面、数据与生命周期

- 在 `inventory-equipment` 内设独立能量瓶专栏，保持瓶子 2×1 比例，显示空槽 / 实际图标、已存能量 / 容量和满瓶状态。沿用真实 Addressables 图标与 `ItemVisualPresenter`，不复制十槽装备属性逻辑。
- 保持原十槽和背包格尺度；用局部布局容纳专栏。最终位置通过 Unity MCP 创建、调整和实测，不在计划中锁死像素或用缩小物品格换空间。
- `InventoryPanelController` 通过现有 Query 读取装备瓶，分别处理普通装备与瓶子的选择、装备和卸下；操作使用 Command，不直接改状态或发送领域 Event。
- 瓶来源校验读取当前玩家的实际装备瓶及背包归属，不依赖天赋 Controller 的可见状态，也不把装备瓶按钮的 `userData` 误判为背包物品。
- 给 `SkillBoardRequest` 增加可选背包目标格，仅 `UnequipBottle` 使用；缺省调用保持自动找位，换瓶仍使用原格回填。预览保存最终布局，提交沿用格位 / 实例 / Revision / 玩家 / Session 校验，失败不发布成功事件。
- 在现有刷新与交互生命周期中接入 `SkillBoardChangedEvent`、`EnergyCollectedEvent`。能量变化立即刷新读数；已生成事务预览不得越过 Revision 校验；保留有效的充能选择身份，不复制一份瓶能量。
- 天赋移除装备 / 卸下按钮与装备目标，改为只读装备瓶摘要及明确的充能选择入口；复用 `SelectEnergyBottleQuery`、`PreviewEnergyChargeQuery` 和现有确认事务。
- 共享拖放继续负责鼠标、动作菜单、键盘 / 手柄和空间导航。换瓶成功后焦点留在可见背包装备区，卸下后可回到返回的物品；空专栏仍可导航和投放，不跳回旧棋盘按钮。
- 关闭窗口、取消、失焦接管、设备移除、Shell / 场景 / Session 切换及 Dispose 时，清除拖动、指针捕获、旧目标、预览和延迟焦点任务；取消不改变物品归属。
- 新文案接入 Unity Localization 的 `ui` 表，使用中文 / 英文及现有 Pseudo Locale 验证；描述区分“装备 / 卸下”与“选择用于充能”，复用真实绑定提示。

持久化继续使用现有 `EnergyBottleInstanceId` 和能量字段，中心成长、击杀收益、容量与溢出规则保持。指定格属于瞬时请求，不写入存档；无需新增 Schema 或内容版本迁移。

自动化始终使用测试隔离路径。普通 Play 保存验收须保护正式文件，记录并恢复原文件身份，不认领遗留临时档；本阶段不改阶段一已修好的路径策略。默认只做 Editor 验收，不构建 Player，真实设备、跨进程和 Player 结果分别标为未执行。
