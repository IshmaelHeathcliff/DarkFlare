## 交付与边界

让地图对象正式表现、玩家、怪物、交互物、掉落、投射物和实体特效遵守接地点遮挡；长障碍可拆为独立排序段。编辑器和运行时消费同一份表现配置，提供可取消、可释放的对象表现装配入口，供 0.5.3 地图作用域接入。

本阶段保留 Main 的现有玩法与存档语义，只迁移必要的渲染配置和组件。不实现 ChangeMap、离场冻结、正式双地图、怪物寻路、存档迁移或可进入的多层建筑。E 的两张草稿仍是布局样例；地图对象表现不私自生成商店、打造或刷怪领域状态。F 完成后再升级为 `0.5.2-alpha`，规划不提前修改版本。

## F1：排序身份、注册门禁与有界运行

1. 保持较高量化 Y 在后、类别、Ordinal 稳定 ID 的比较规则及现有类别相对顺序。新增独立特效类别必须有明确同 Y 规则，建议排在 Player 之后；它只破同序，不能压过不同 Y 的对象。
2. 静态表现身份使用无歧义的 `MapId / ObjectId / PartId` 组合，不使用列表下标、名称匹配、Unity Instance ID 或资源加载完成顺序。动态实体沿用 Actor / Monster / WorldDrop 身份。临时特效使用来源身份 + 本次发射 / 反馈身份；短期播放序号只用于无持久身份的表现实例，不冒充可存档身份。
3. 注册返回可追踪的所有权凭据，注销只释放自己的登记；配置身份、禁用、销毁、池回收和作用域释放须幂等。重用同一稳定 ID 后，旧凭据或异步回调不能删掉新实例。兼容现有自动注册对象，地图对象使用显式激活。
4. 批量提交前预检重复身份、非法锚点、非有限坐标和可用 Sorting Order 容量；失败不留半批注册，不修改已有顺序。最大参与者数包含所有独立段和特效；依据连续非负 Order 的有效上限定义常量并做边界验证，不允许溢出后重号。正式装配超限拒绝提交，瞬时特效超限可跳过并计数。
5. 记录活动数、拒绝数、刷新键数、排序次数、实际 Order 写入数和 CPU 标记。先测现有全表排序；若不能达到 F5 预算，再引入静态键缓存 / 动态合并。不得以标记 Static 后忽略合法位置或身份变化换取低耗时。

验收：注册顺序打乱结果相同；同 Y 不闪烁；跨量化边界正确；无变化不重复写入；关闭 / 重开、池重用及过期回调不泄漏；容量失败保留原状态。F1 是首个实施单元。

## F2：地图对象表现目录与分段装配

新增 ScriptableObject 表现目录，键为地图对象 DefinitionId；每项提供默认外观、显式 AppearanceVariant 对应的 Addressables Prefab。先复用已有树木、岩石、帐篷、残墙、商人和打造台美术。目录不改地表、footprint 或交互数据；外观只能改变表现，不绕过地图校验。空外观取显式默认，未知非空变体报错，不能静默取另一外观。

每个表现 Prefab 声明固定 PartId、类别和显式 SortAnchor。单段对象只有一个排序单元；多段对象使用不带 SortingGroup 的逻辑根，下面是互为兄弟的独立 Group，每个 Renderer 只能归一个单元，禁止嵌套 Group。段身份来自配置，不能因数组重排而变化。阴影、轮廓、主体、火焰仍是所属单元的局部 Order；确属贴地的独立碎屑可声明为 Ground 装饰，不参与 Y 竞争。

长墙 / 建筑按真实可独立遮挡的图像段制作；不能多次复制整张建筑图片冒充分段。至少交付一个有多个锚点的长障碍样例，覆盖两端及前后通过。各段共用一个逻辑对象，D 的 footprint 碰撞仍只由几何层生成一次。定义中的旋转同步作用于局部位移和锚点，世界锚点必须与 D 的局部到世界换算一致；不通过 Transform Z、物理层或 Collider 修补排序。不能正确支持的朝向在表现校验时报错，正式样例覆盖允许的 0/90/180/270 朝向。

装配流程固定为 Prepare → Activate → Dispose：先校验配置、申请 owner 资源并创建未激活候选；全部通过再成批注册 / 显示；取消或失败释放已申请资源。对象实例先注销 / 销毁，再释放资源 lease。异步完成需复核 owner 状态与 generation，旧加载结果不能覆盖新地图或预览。此处只提供表现 owner 与 generation，不提前建设完整 MapScope / 切图事务。

运行时使用 ApplicationResources / Addressables；Editor 允许通过 AssetDatabase 解析同一引用，但必须使用独立预览所有权。商人 / 打造台现有 Prefab 含玩法组件时，抽取可复用的视觉子结构或制作纯表现 Prefab；预览不运行 Controller、Collider、交互注册或领域事件。

验收：默认 / 指定外观正确；缺资源、坏段 ID、嵌套 Group、重复 Renderer、取消及中途失败可定位且无残留；同一对象重载稳定；多个 MapId 下相同 ObjectId 不冲突。多段渲染不能改变几何查询结果。

## F3：投射物与实体特效遮挡

明确区分两类表现：独立飞行投射物 / 世界落点效果使用自己的 WorldObject 排序单元和接地点；受击、火焰或身上状态效果需要跟随宿主时，作为宿主 Group 内的局部 Renderer，不额外嵌套 Group。视觉中心可以偏离地面锚点，不能直接用抬高后的特效坐标充当脚底。

扩展现有 VisualEffectPool / PooledSpriteEffect 的播放上下文，包含 owner、地面锚点或宿主单元、播放身份及局部顺序。回收时清除父级、排序登记和上下文，再允许复用。目标死亡 / 销毁、特效超时、Session 结束和播放版本失效均走统一取消 / 回收路径；旧延迟完成不能回收已重用的新播放。保持命中判定、伤害、暴击颜色和池容量原有语义。

WorldEffect 层暂保留兼容，但不再承载应被世界物件遮挡的普通投射物 / 命中特效。WorldInfo 中的战斗文字继续作为可读性例外；现有血条、词条和交互提示保留宿主局部层级，不在本阶段同时重做 UI。

验收：投射物与命中特效在树 / 墙两侧正确遮挡；角色受击效果随所属对象遮挡；同位置多个反馈身份唯一；连续池复用、目标销毁、场景结束及暂停后无遗留注册。用真实渲染截图 / 短录屏与顺序数据交叉确认。

## F4：编辑器接入、生产配置与光照

地图工作台增加正式表现 / 诊断轮廓切换；对象选择继续以源 ObjectId 为准。修改位置、旋转、外观、Undo / Redo、AI Patch 后更新同一表现入口；只改变对象时不强制重建全部地表。完整重建采用候选替换，保留旧帧时必须标注过期；删除、关闭、切舞台、Play 和域重载释放对象、材质及引用。

表现目录在 Odin 配置中心可编辑；给现有样例目录配置树木、商人和打造台表现，并增加长障碍验收样例。正式资源登记 Addressables；若现有图片无法提供真实分段，实施时先按 `unity-2d-sprite-workflow` 建立画布 / pivot / PPU 合同再生成所需资源，不扩大为整套场景美术重制。

通过 Unity Editor API 修改生产 Prefab / Main 必需的排序组件与引用，保留玩家位置、碰撞、交互距离和玩法对象数量。复核 Sprite-Lit 材质、Global Light 2D 目标层和新增层引用。沿用 ContentConfigurationValidator 主入口，扩展实际消费范围，不为每个阶段再建重复全量扫描器。纯 `.dfmap` 编辑不强制要求具备正式美术；正式预览 / 运行时装配必须验证表现绑定完整。

验收：人工移动和 AI 修改产生相同接地点与遮挡；样例可打开、撤销和重做；Main 交易 / 打造 / 战斗 / 掉落仍可用，物理与数据语义不变；光照无漏层黑图。

## F5：回归、性能与交付

优先扩展现有 Alpha017WorldSortingTests / PlayMode、特效池与 MapEditTests；名称包含旧版本不作为新建重复套件的理由。替换“普通特效永远 WorldEffect 固定 Order”的旧合同，保留独立覆盖。新表现装配器的事务失败、取消及资源释放如无适合入口，可新增按模块命名的测试。

| 矩阵 | 验收与证据 |
| --- | --- |
| 可见遮挡 | 树前 / 树后、长墙两端、同 Y 交叉、怪物与掉落、投射物经过树干、附着特效；包含多段对象各允许旋转，保存画面与对象键 / Order |
| 生命周期 | staging 不注册；准备失败、取消、激活失败、反复创建释放至少 20 轮、旧异步回调、Reload Scene Only；最终参与者与 owner lease 回到基线 |
| 纯排序压力 | 500 / 1000 动态参与者，加 1000 静态段、128 瞬时特效；分别测全静止、全移动、同 Y 密集、突发注册 / 回收，不把注册成本混入稳态 |
| 阶段性能预算 | Windows Player 中排序采样 + 排序 + Order 写入主线程 P95 ≤1 ms（500 动态）/ ≤2 ms（1000 动态）；预热后稳态排序路径 0 B GC。这是本阶段工程预算，超出先诊断优化，不静默放宽 |
| 测量方法 | 固定机器、1920×1080，预热后每组 60 秒、三轮，记录 P50/P95/P99、实际参与者 / 段 / 特效数量、CPU 与 GC；基线与改动后相同场景。GC 计数不可用时改用有效 Profiler 证据，不把返回 0 当作零分配 |
| 生产集成 | 当前完整 Main 带正式 Animator / Renderer / 光照及真实玩家输入，单独记录总帧时间；完成独立 Windows Player 构建和遮挡冒烟。500 / 1000 导航及完整战斗总帧预算仍由 0.5.4 验收，不能以纯排序压力替代 |

最终运行项目 EditMode / PlayMode、内容 / 地图 / 配置文档校验；只在新改动或失败解释未收敛时重复测试。临时性能 / 截图采集脚本用后清理，证据归入 `Docs/docs/maps/acceptance/f/`。不得写正式玩家存档，验证结束恢复原场景和 Reload Scene Only。

完成时更新世界渲染、地图编辑器和配置模块文档，记录真实性能与已知限制；归档本计划并更新总计划 / 文档入口。完成判据是 F1–F5 均有行为、视觉和生命周期证据，不以“配置已添加”代替验收。

## 实施顺序

F1 → F2 → F3 → F4 → F5。先冻结注册所有权和同 Y 身份规则，避免地图装配与池播放分别造排序入口；F2 的纯表现生命周期通过后再接编辑器和生产配置。F1–F5 已按上述顺序完成。当前模块说明见世界渲染与对象表现文档；下一阶段为 0.5.3 双地图与作用域，尚未实施。
