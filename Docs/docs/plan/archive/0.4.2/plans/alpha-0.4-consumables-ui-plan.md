# 消耗品阶段 2：正式内容与背包使用交互

2026-09-15：已完成。EditMode 563/563、PlayMode 74/74 通过；三语言与两档分辨率截图、真实设备注入事件、物品掉落与状态显示验收完成。实现见[消耗品模块](../../../../consumables.md)与[验收记录](../acceptance/consumables-ui/README.md)。运行版本保持 0.4.1-alpha，core v5、Schema 3。

## 目标与边界

玩家可以向商人购买消耗品，在背包中使用，立即看到资源、状态和数量变化；键鼠与手柄共用 ItemActionRouter 和 UseItemCommand。首批覆盖回血、回蓝、临时增益和异常驱散，并以一个复合物品验证实际 UI 链路。

保持现有窗口、拖放、买卖和打造操作。快捷栏、冷却、充能、拆分数量窗口、投掷与目标选择留待后续需求。本阶段保持运行版本 `0.4.1-alpha`；阶段 3 综合验收后再交付 `0.4.2-alpha`。

## 首批内容

以下为可调整的首轮配置默认值，用于实现与验收，不视为最终平衡。物品均为普通品质、1×1、可堆叠上限 10、可消耗且每次使用 1 件。

| 物品 / 建议稳定 ID | 有序效果 | 基础价值 |
| --- | --- | ---: |
| 生命药水 / health_potion | 即时恢复 40 生命 | 10 |
| 法力药水 / mana_potion | 即时恢复 60 法力 | 10 |
| 坚韧药剂 / fortitude_potion | 获得 30 秒最大生命 Increase +20% 状态 | 20 |
| 净化药剂 / cleansing_potion | 恢复 20 生命，再驱散自身全部可驱散异常（最多 4096 层） | 20 |

实际售价沿用商人倍率与现有取整规则，不在 UI 写死价格。坚韧状态采用 Timed、Uniform、上限 1、重复施加覆盖刷新、Show 显示；属性上限变化继续沿用现有生命比例规则，详情明确说明，不能另加隐藏治疗。全满但能延长有效状态、或满血仍有可驱散异常时允许使用；所有效果均无变化则不扣除。

新增物品、item_use 能力和坚韧状态均通过稳定 ID、内容目录及 Addressables 登记。正式内容加入时核对 content version 兼容策略：必要时提升 core 内容版本并提供旧版本到当前的兼容路径；没有 DTO 变化不提高 Schema。不能只改目录版本而遗漏历史读取支持。

商人每类新增 3 份、每份数量 1，沿用 TraderStockEntry.Count 的“独立实例份数”语义。买入后按现有规则合并，交易仍按整堆处理。无需为本阶段增加商人堆叠数量字段。新游戏初始化可以获得新增库存；旧存档恢复保留已经保存的库存，不无条件重置或补发商品，说明该获得路径适用于新建库存。怪物装备 100、金币 2000、矿石 500 权重保持不变，不新增药水掉落。

## 使用动作与预览

| 场景 / 来源 | 默认快捷动作 | 明确操作菜单 |
| --- | --- | --- |
| 普通背包的可用物品 | 使用 1 件 | 使用、移动、丢弃等合法动作 |
| 商店打开时的玩家背包 / 出售来源 | 保留出售 | 额外提供使用，只操作玩家拥有的实例 |
| 商人物品 | 购买 | 不提供直接使用 |
| 打造窗口 | 装备沿用放入 / 取回；消耗品不可打造 | 玩家背包中的可用物品仍可通过明确菜单使用 |
| 装备槽、地面或失效来源 | 沿原合同 | 不提供使用 |

ItemActionKind 新增 Use，Primary / Validate / Execute 和动作菜单统一接入，不能只给背包面板增加专用按钮。鼠标右键与现有手柄动作菜单提供同一动作集合，确认 / 取消沿既有输入映射；单击选择和按阈值拖动行为保持原合同，不新增双击使用。

运行时在操作开始时生成一次请求；同一次确认只提交一次。完成后刷新当前选择对应的预览请求，不能跨 Session 缓存、跨物品复用，不能每帧新建操作号。既有单调操作号会淘汰更早请求，UI 遇到过期请求应重新预览并允许用户再次确认，不自动重放使用。

余量大于 0 时保留原实例、位置和选择，更新数量与预览；末件移除后清除浮窗 / 菜单失效引用，焦点按现有邻居恢复规则转移到可达物品或窗口入口。状态图标同步更新，物品耗尽不撤销临时状态。Shell 接管、关闭窗口、场景切换时取消交互并释放订阅，不让旧菜单操作新 Session。

## 详情、反馈与本地化

- 在 ItemDetailSnapshotFactory / Formatter / View 现有链路添加能力说明，保留数量、价格与装备对比逻辑。商品详情可显示静态效果，玩家实例再显示当前预计恢复量、用量与可用性。
- 静态说明从使用配置生成；动态结果使用 GetItemUseSnapshotQuery，UI 不重写回血、上限、层数或驱散计算。当前核心结果若不足以表达逐项说明，仅补有实际消费者的只读数据。
- 本地化覆盖四物品、一状态、四效果、使用动作、用量与所有 ItemUseCode / 相关 StatusCode。分别显示资源已满 / 无可驱散异常、行动受限、数量不足、状态拒绝和物品失效等原因；不直接显示枚举或技术异常栈。
- 成功通过既有数量、资源与状态事件刷新；消费只扣一件，不把整堆数量当成用量。失败保留物品且给出可读反馈，不自动重试。异常发生在通知之后时先刷新真实状态，不能假定尚未扣除。
- 新状态采用现有 HUD / 状态窗口与隐藏合同。验证中文、英文、Pseudo 和 1280×720 下的动作菜单、长说明、焦点与浮窗边界。

## 资产与工具

四个物品图标及一个新状态图标遵循 unity-2d-sprite-workflow：先读取现有物品 / 状态家族规格，再生成每图独立 PNG，统一画布、透明边距、Pivot、PPU、Sprite Single 与可测量视觉尺寸。状态家族已有 96×96 基线，物品家族须按实际资产核对，不能直接假定相同规格。

使用 imagegen 生成所需位图，通过 Unity 工具完成导入、资源注册与绑定；UI 创建和布局使用 Unity MCP。调整现有 UI 代码与样式时保持共享组件与资源生命周期合同，不直接修改打开场景的 YAML。校验正式资源引用、重复 ID、可消耗标记、层数与使用能力，不保留临时采集入口。

## 执行顺序与验收

1. 核对动作菜单、详情及商人库存消费者，确定本地化键与资产家族规格；补齐内容版本兼容策略。
2. 新增正式配置、图标、目录和商人条目，保证购买、保存与恢复可用；校验器覆盖新增能力和状态引用。
3. 接入 Use 动作、预览、详情、反馈与选择恢复，验证普通背包和商店 / 打造联动上下文。
4. 扩展已有物品交互及存档 PlayMode 回归：购买合并后只扣所选实例、连用、末件移除、复合无变化、眩晕下净化、Shell 阻挡与新 Session 隔离。保留核心现有 22 项使用回归，不为四件商品复制同类算法测试。
5. 运行项目 EditMode / PlayMode 全量；以可见运行场景和真实输入事件验证菜单与焦点，记录是否为设备注入，不能宣称实体手柄人工测试。三语言 / 小分辨率截图归档到模块验收目录，清理临时代码与自动序列化噪声。
6. 更新物品、使用、交易、输入和配置说明，归档本阶段计划；整体 Windows Player、完整跨进程链路与版本发布由阶段 3 收尾。

完成条件：新库存提供四类商品；键鼠和手柄均可完成购买 → 使用 → 数量 / 资源 / 状态反馈；错误不误扣，最后一件焦点有效；旧档和现有装备 / 交易 / 打造行为无回归。达到这些条件后再标记阶段 2 完成。
