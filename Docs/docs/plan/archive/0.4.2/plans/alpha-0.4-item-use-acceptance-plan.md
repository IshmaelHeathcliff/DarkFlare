## 执行顺序

### 1. 核对合同与构建条件

- 对照[使用系统](../../../../item-use-system.md)、[消耗品](../../../../consumables.md)及现有测试，整理事务、输入、状态与存档覆盖；只补缺失的长期行为保护，不重复阶段 1、2 的测试。
- 核对当前未提交改动、正式内容引用和版本，区分已有实现与本阶段修复。
- 复核 Windows 构建工具、可见 Player 控制与采集方式。沿用[状态综合验收](../../0.4.1/acceptance/status-acceptance/README.md)的数据隔离经验，先验证存档、设置及日志的实际路径，再执行写档流程；不假设已有数据根命令行参数。
- 在独立输出目录构建当前脚本和正式 Addressables，保留旧版本输出。受控初始资源或异常只能通过现有 Command / System 准备，临时验收入口不得进入正式交付构建。

完成条件：验收包对应当前代码，数据与真实玩家目录隔离，可取得实际 Player 渲染和操作证据。

### 2. 验证独立 Player 玩法闭环

| 场景 | 必须验证的行为 |
| --- | --- |
| 获得与消费 | 新游戏商人提供四种药水；购买合堆、金币与库存准确；只消耗所选实例一件；末件移除后焦点有效 |
| 恢复与反馈 | 回血、回蓝裁剪到上限；满资源不扣药；净化在回血或驱散任一有效时只扣一次，两者均无变化时不扣 |
| 状态联动 | 坚韧刷新、自然到期与生命比例符合状态规则；末件药剂消失不撤销状态；七种异常按可驱散规则清除，不误删坚韧和受保护状态 |
| 输入与上下文 | 鼠标、键盘与手柄事件到达统一使用入口；普通背包默认使用，商店默认出售、打造保留原语义，菜单可明确使用；设备切换和末件焦点可继续操作 |
| 暂停与门禁 | 背包暂停允许即时使用且状态不倒计时；恢复玩法后继续计时；眩晕不误用施法门禁阻止净化；Shell 接管和 Session 退出拒绝使用 |
| 原有玩法 | 装备穿脱、买卖、材料打造及掉落规则无回归；金币、材料不会因可消耗而出现使用动作 |

复用现有自动化覆盖验证事务拒绝、重入和失败回退，Player 优先验证完整操作链路。记录输入是原生操作、Input System 注入还是实体设备，不把注入验证写成人工手柄验收。

### 3. 验证存档与生命周期

- 在隔离 Player 中使用部分药水并保存，退出进程后继续：堆叠身份、位置、余量、生命和法力一致，不再次执行即时恢复或扣除。
- 用尽最后一瓶坚韧药剂后保存，重启核对剩余时间、属性和来源显示；恢复不要求原物品仍存在，不发生离线补算。
- 用真实历史格式夹具验证 core v4 / Schema 3 升到 v5 后背包、商人库存和状态保持，旧商店不自动补药；v1–v3 的完整迁移链继续由既有回归保护。
- 返回主菜单、新建 / 继续 Session，验证旧使用请求失效、焦点和浮窗无残留、资源租约回到基线；不串用前一角色的数据或重复注册回调。

完成条件：跨进程与跨 Session 均有实际结果，数据隔离可追溯，无重复使用、库存补发或状态丢失。

### 4. 复核 Player 显示与发布

- 检查四种药水及坚韧图标从正式 Addressables 加载；核对背包、地面物品、详情、菜单、右上角 HUD 和状态窗口。
- 中文、英文和 Pseudo 在 1920×1080 / 1280×720 下检查详情可见、长文本、窗口边界及焦点。沿用阶段 2 的矩阵，保存 Player 代表证据；发现布局差异时补齐对应场景。
- 修复问题后运行项目 EditMode / PlayMode 全量回归，记录当次结果。保留真实缺陷回归，清理临时采集代码、编译定义和无关自动序列化变更，保持 Reload Scene Only 基线。
- 验收通过后将运行版本更新为 `0.4.2-alpha`；没有新持久化结构或内容兼容变化时保持 core v5、Schema 3。
- 生成不含验收入口的普通 Windows x64 最终包，建议输出 `Builds/Alpha042/DarkFlare.exe`。版本调整后重新确认构建结果和隔离启动；若沿用独立产品名进行干净启动验证，明确区分其与正式产品名交付包，不能宣称未启动的包已运行验收。
- 将构建信息、版本、校验值、测试摘要、关键日志和截图归档到 `Docs/docs/plan/archive/0.4.2/acceptance/item-use-acceptance/`，说明实际验证方式、警告影响及未覆盖边界。
- 更新物品使用、消耗品、存档、输入与项目索引中的实际变化；完成后归档本计划与总计划，修复文档链接。Git 提交按用户后续指令执行。

## 交付判据

四种正式药水在独立 Player 中可获得、可使用、反馈正确，效果与指定实例消费一致；存档恢复不重复执行即时效果，状态与来源不依赖已耗尽的物品；原有装备、交易和打造行为正常。最终构建、回归和数据隔离具有当次证据，无未处理的阻断缺陷。

未满足判据时保留计划进行中，记录具体缺口，不以 Editor 结果替代 Player 验收或提前标记版本交付。
