# Alpha 0.5.0 D：同源碰撞与静态导航几何

状态：2026-09-18，D1–D4 已完成并归档。前置 C 提交 `9a3f7a9`。本轮 EditMode 676/676、PlayMode 77/77，内容校验 0 项问题；0.5.0 地图基础收尾，运行版本 `0.5.0-alpha`，core v5 / Schema 3 不变。当前实现见[地图几何](../../maps/map-geometry.md)，证据见[D 验收](../../maps/acceptance/d/README.md)。

上级：[地图基础阶段](alpha-0.5.0-map-foundation-plan.md)；依赖：[分区合同](../../maps/terrain-partition.md)、[地图数据](../../maps/README.md)、[导航总方案](../alpha-0.5/navigation.md)。

## 目标与范围

让同一份 `.dfmap` 和内容定义派生出地表、静态阻挡、带半径的通行与落点查询，并在隔离场景中用真实 Physics2D 验证一致性。D 完成后收尾 0.5.0，后续地图编辑器与双地图直接复用这套基础。

本轮交付静态几何及统一查询。Flow Field、A*、动态障碍、Spatial Hash、Separation 和 Job / Burst 调度按总计划在 0.5.4 实现；D 的邻接、代价与足迹规则由两种寻路策略共享。Main 正式地表替换、城镇 / 野外和存档迁移在 0.5.3，避免在几何试验期间改变现有游戏流程。

## 已核对的代码事实

路径相对 `Assets/Scripts/`，下列事实用于限定本计划，不代表已经有几何实现。

| 现有入口 | D 的处理 |
| --- | --- |
| `Runtime/Maps/CompiledMapDocument.cs`：地表数组、规范 JSON、SourceHash；对象 / 区域可从编辑副本读取 | 主线程一次解析并拷贝纯值快照，查询期间不重复解析 JSON 或查找 SO |
| `TerrainPartition.Sample/Rasterize`：按四角权重归属，等值按 ContentId 排序；正式纹理使用 64×64、端点采样 | 从同一分区产生几何，不读纹理颜色 / Alpha；明确像素覆盖与连续世界坐标的映射 |
| `TerrainRuleSnapshot.RuleHash`：材质身份及变体规则，不含 Walkable / MovementCost | 增加独立几何依赖签名，通行配置变化不能复用旧结果 |
| `DualGridCoordinates`：逻辑范围与额外半格显示范围不同 | 物理 / 导航可玩范围使用逻辑矩形，外侧视觉样本永不可走 |
| `MapObjectDefinition.Footprint`：世界单位矩形；对象位置为局部世界坐标，旋转仅四个直角 | 加一次 origin，90 / 270 度交换宽高；只对 Obstacle 能力生成阻挡 |
| `MapRegionDefinition`：Named / Safe / Spawn；点为逻辑坐标，可为矩形或简单多边形 | 独立提供区域覆盖和落点约束，Safe 不生成墙；不引入未定义的区域代价 |
| 玩家 / 怪物 `CircleCollider2D`、`GameplayPhysicsLayers.WorldObstacle` | 原始障碍只生成一次；查询按 Agent 半径检查，不把 Collider 和查询各膨胀一遍 |

实测世界半径：玩家约 0.32、Basic / Heavy 0.30、Swift 0.36，见 [C1 尺度记录](../../maps/acceptance/c1/scale.json)。0.75 宽直道对半径 0.36 的单侧余量仅 0.015；这只是连续直道计算，尚未证明网格可达或拐角可过。

## D1：几何表达与尺度合同

先完成纯数据原型和尺度对照，再冻结默认值；D2、D3 以 D1 的记录为前置。

1. 明确三种不同分辨率：逻辑格、64×64 地表分区、导航子格。显示分区的第 i 个样本位于 `i/63`，对应纹理像素的世界覆盖区间却是 `[i/64,(i+1)/64]`；禁止把二者混用而让岸线错位。
2. 首选以现有 64×64 分区的像素覆盖区域生成可复用 Wang 几何模板，合并连续阻挡跨度 / 边界，实例化时缩放平移并裁到逻辑范围。保留孔洞、孤岛和对角接触；不为全图分配每像素导航节点，也不为每像素创建 Collider。比较模板边界与正式渲染，记录台阶、接缝和形状数量。
3. 在每逻辑格 4×4 导航节点的候选上试验，同时对照 2×2；只有出现有价值通道的离散误拒绝时再比较 8×8。导航中心点只是候选，节点和连边的合法性必须由同一精细几何检查。粗网格允许保守拒绝，不能批准穿越真实阻挡。
4. 样例包含 0.75 / 1 / 1.5 / 2 世界单位直道、直角 / 斜角、鞍点、U 形、水岛、贴边障碍、跨 chunk 狭口。分别测试 0.30 / 0.32 / 0.36 半径；增加略小 / 略大于直径的临界通道和不对齐网格的平移，防止只对齐中心线才通过。
5. 固定边界接触规则与非负安全余量；从本机 Physics2D 查询对照确定数值容差，单列浮点容差与游戏安全距离。单点对角连接不算通道。记录正常世界坐标、负 origin、cellSize=0.5，以及大 origin 下的浮点精度限制。
6. 记录 64² / 128² / 256² 地图的节点、边界片段、预估常驻 / 峰值内存；在分配前设置子格总数与几何容量上限，超限明确拒绝，不能裁掉部分地图。源文档可支持 1024²，不代表派生器必须无预算接受全部最坏情况。

D1 完成条件：保存尺寸对照、精度 / 误拒绝说明、默认细分数、安全余量、模板表达及容量上限；无越界 / 穿水 / 切角的误放行。优先让 1 单位宽标准通道支持现有最大半径，0.75 临界通道明确列出哪些尺寸与网格偏移可用，不用缩小角色半径掩盖问题。若模板数量或物理精度不能满足目标，先修订表达并重测，不直接继续接入。

## D2：静态快照与统一查询

拟新增纯模块放在 `Runtime/Maps/`，名称按职责确定，避免为本版本创建独立架构。用现有 `MapDocumentCompiler`、`IMapDefinitionLookup` 和 `TerrainPartition`，不另建地图权威源。

- 编译入口接收已校验地图、定义快照、D1 配置和取消令牌；输出不可变几何 / 通行快照。内容身份转紧凑索引、纯数值数组，便于后续拷贝到 Native 容器；D 不提前创建无人使用的 Job 调度器。
- 派生签名包含布局、地表 Walkable / MovementCost、障碍能力 / footprint、区域语义与几何、分区 / 几何算法修订、细分设置。外观变体与随机选图不改变通行结果。SourceHash 可用于来源追踪，不能独自充当导航依赖签名。
- AgentProfile 首期只支持当前地面行走，有限半径配置共享派生结果；预留材质许可与代价的明确合同。选择 A* 不改变通行权限。未来游泳 / 飞行还需相应物理层规则，本阶段不宣称已经兼容。
- 提供范围、区域、圆形足迹净空、带半径线段通过性、合法邻接 / 移动代价，以及有界合法落点查询。非法数值 / 半径、地图外、阻挡、无候选、预算不足和取消给出明确结果，不静默夹坐标或把预算耗尽当无路。
- 八邻接采用固定方向顺序和 10 / 14 整数基础成本；阻挡独立表示。对角同时满足两侧正交节点和 swept circle 检查；中间阻挡不能被两个合法端点绕过。区域不添加当前定义里不存在的通行规则。
- 地表代价首期取目标节点所属材质的 MovementCost，与基础成本相乘，并记录这是离散图代价而非连续路径积分。边成本可能有方向性，未来反向 Flow Field 必须读取同一正向边成本；溢出在编译 / 查询边界显式处理。
- 落点先检验给定点，再在请求半径和候选数量上限内按距离、稳定格序选点；返回的是合法位置，不承诺与某起点连通。需要连通性的调用方以后使用同一图搜索，不能用落点成功替代寻路成功。
- 区域返回稳定有序覆盖集（priority 降序、regionId 序）；Spawn 候选要求足迹完全处于所选刷怪区，且不与任意 Safe 区相交。Safe 只约束刷怪，普通行走仍可通过；Named 只承担标记。重叠 Spawn 保留身份，具体刷怪配置由请求指定。

D2 完成条件：核心规则、签名失效、平移 / 缩放、变体不影响通行、失败与取消均有长期回归。参考验证用解析矩形 / 圆距离等独立几何结论，不能只比较两个调用同一实现的接口。

## D3：碰撞投影与诊断接入

- 从 D2 的原始阻挡模板、对象矩形和边界派生 Physics2D 静态碰撞，在独立预览 / 隔离 PlayMode 场景验证。使用 Editor API 创建对象，沿用 WorldObstacle 层；不修改开放场景 YAML。
- 优先验证 Unity 现有 PolygonCollider2D / CompositeCollider2D 对轮廓合并、孔洞和分块的支持，再确定最少组件的投影方式；不自行加入另一套通行算法。实施时核对本机 Unity 6.6 API、路径顶点限制及物理查询同步点。
- 全局内部边不得产生窄缝 / 卡边；对象重叠不挖洞，地表边缘与地图外不可玩边界一致。Collider 描述原始阻挡，单位半径只通过真实圆 Collider 或查询足迹体现。
- 复用现有 `MapTerrainPreviewSession/Window` 展示碰撞、可走节点、半径净空和查询线段，标出失败原因、修订、节点 / 形状数量、构建耗时。控件仅用于诊断，正式画笔工作台仍属于 0.5.1。
- 构建先产生独立候选；发布前复核来源修订 / generation。完成后替换整套一致的显示与几何，失败 / 取消保留旧快照并明确标旧，不能旧渲染配新碰撞。窗口关闭 / 重导入取消工作并释放所拥有的根对象和资源，迟到结果不可回写。
- 主线程负责 Unity 对象与 SO 快照；耗时纯计算沿用可取消 UniTask。需要接入 QFramework 的 Controller 只发 Command / Query、注册 Event，状态通知由 System / Command 发送。D 不建立逐单位 Update 循环。

D3 完成条件：真实 CircleCast / Overlap 与纯查询对照；对称直道、转角、水岸、重叠障碍、鞍点和地图边界无误放行。渲染中的地表线、原始碰撞线与半径内缩线能同时观察；取消 / 替换 / 关闭之后无残留对象或资源。

## D4：整链路验收与阶段收尾

1. 复用正式四材质样例，增加最小障碍与区域夹具，走通 `.dfmap` 导入 → 校验 → 正式显示 / 碰撞 / 通行 → 导出 → 重导入。保持稳定 ID、语义和派生结果；定义变更后重新生成，不保存第二份手工碰撞数据。
2. 负 origin、非整格位置、cellSize=0.5、四边 / 四角、chunk 接缝、孤岛、不可达候选、半径临界值和容量拒绝加入行为矩阵；往返编辑无旧碰撞或迟到发布。
3. 对 64² / 128² / 256² 记录三轮构建时间、峰值 / 常驻内存、形状数量、取消延迟和释放后基线。分别计纯编译与 Unity 投影，报告环境与首次成本；不把 Editor 几何构建耗时当 500 / 1000 单位的 Player 导航性能。
4. 运行地图 / 几何定向测试、受影响的预览与导入测试，再运行项目 EditMode / PlayMode 全量与内容校验。保留旧 Main 的有效回归；本阶段不接入怪物移动，不宣称已经验证怪物绕障。
5. 依照[测试维护规范](../../testing/test-maintenance.md)审查新增测试；保留几何规则、依赖失效、事务回退与生命周期覆盖，清理一次性截图 / 跑分脚本和无消费者夹具，证据放在 `maps/acceptance/d/`。
6. 编写当前实现文档 `maps/map-geometry.md`，同步地图配置、模块与导航计划；D1–D4 完成后归档本计划及 0.5.0 总执行计划。运行版本只在完整阶段验收后按项目发布流程更新；计划期间保持 `0.4.2-alpha`、core v5、Schema 3。

## 实施结果与后续

D1 冻结默认 4×4 子格、64×64 像素覆盖矩形、0.0125 物理余量及分层容量；D2 完成不可变快照 / 独立签名、静态圆足迹与移动段、八邻接代价和区域落点查询；D3 完成 CompositeCollider2D 投影及既有窗口叠加、完整帧事务；D4 完成持久开发样例、导出重导入、物理 / 取消 / 释放验证、三种地图尺寸测量与完整回归。

验收明确保留两项边界：0.75 临界直道有离散误拒绝；C4 的逐格随机 256² 地图超过当前几何容量，被完整拒绝，连续区域 256² 通过。峰值仅有 Editor 阶段采样，未宣称精确模块峰值或 500 / 1000 导航性能。Main 未迁移，未构建 Player。下一阶段为 0.5.1 手工 / AI 地图编辑器。
