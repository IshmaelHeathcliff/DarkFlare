## 完成记录

- 已落地具名基础伤害、命中与暴击随机子流，正式区分 `InvalidTarget`、`Missed`、`Evaded`、`Hit`、`NoDamage` 与后续预留的 `Invulnerable`。
- 武器来源技能不再具有空手或技能配置回退；新游戏在刷怪器启用前事务性授予并装备初始大剑。
- 五类伤害均输出防御前后、承伤修正、有效护甲 / 抗性、减免和最终伤害分解；表现层按结算结果与实际生命损失分流。
- 玩家、三种怪物和基础投射物配置已精准迁移，一次性迁移工具经二次执行幂等验证后移除。
- 全量 EditMode `141/141`、PlayMode `11/11` 通过；Runtime、Editor、EditMode 与 PlayMode 程序集均以 `0` 错误、`0` 警告构建通过。

## 目标

本阶段把当前“必定命中、默认不暴击、空手仍有技能伤害”的临时战斗链改为可解释、可复现的正式命中伤害链：

1. 武器来源技能只能从有效武器取得基础伤害，空手不再回退到技能或代码常量。
2. 一次攻击能明确区分无效目标、未命中、闪避、普通命中、暴击命中和命中但无伤害。
3. 命中、闪避和暴击消费正式属性，并与基础伤害使用互不干扰的确定性子随机流。
4. 物理、火焰、冰霜、闪电、混沌五类伤害继续经过统一转换、增益、承伤、护甲和抗性管线。
5. `DamageResult` 能解释判定概率、随机结果、各类型防御前后数值和减免来源，供调试、飘字和后续无敌帧使用。
6. 新游戏在第一只怪物启用前已经可靠装备初始武器，不因移除空手伤害而软锁。

## 当前事实

- `AttackSnapshot.IsHit` 默认固定为 `true`，`IsCritical` 默认固定为 `false`，没有正式命中或暴击判定。
- `CharacterDefinition` 只写入生命、移速、护甲和四类抗性；`accuracy`、`evasion`、`critical_chance`、`critical_damage` 虽已登记为属性，但没有正式基础值来源。
- 三个正式 `MonsterDefinition` 未引用角色定义，当前实例属性只有最大生命和移动速度，不能配置命中、闪避、暴击、护甲或抗性。
- `basic_projectile` 的伤害源是 `EquippedWeapon`，但空手时会使用技能配置的 `10–14` 物理伤害；技能伤害池为空时又会生成固定 `12` 点物理伤害。
- `FireProjectileCommand` 在构建攻击前就消耗 `PlayerAttack` 随机种子，即使攻击源无效也会推进随机序列。
- 怪物接触攻击用同一个根种子生成基础伤害和攻击快照，没有明确的基础伤害、命中和暴击子流。
- 当前 `DamageResult` 只有 `IsHit`、`IsCritical`、总伤害和防御前后字典；无法区分未命中与闪避，也不能解释护甲或抗性减少了多少。
- `CombatSystem` 对有效、未命中和零伤害结果都会发送 `ActorDamagedEvent`；表现层只检查 `IsHit`，因此命中但零伤害仍会闪白并显示 `-0`。
- 启动流程生成玩家后立即启用刷怪器，没有初始物品或自动装备步骤。

## 冻结合同

### 1. 基础伤害所有权

| 来源 | 合法基础伤害 | 无有效来源时的行为 |
| --- | --- | --- |
| `ItemType.Weapon` | 必须至少有一个合法 `DamageRollDefinition` | 配置错误，验证器拒绝 |
| 非武器物品 | 必须为空 | 只要非空即为配置错误 |
| `ProjectileDamageSource.EquippedWeapon` | 只读取 Weapon 槽有效武器及其 LocalItem 修改器 | 攻击构建失败，不生成投射物、不发送攻击事件、不消耗攻击随机种子 |
| `ProjectileDamageSource.Skill` | 必须由技能配置至少一个基础伤害包 | 配置为空时攻击构建失败，不使用代码常量 |
| 怪物接触攻击 | 继续读取 `MonsterDefinition.ContactDamages` | 正式配置必须非空；不改变其“非物品攻击”职责 |

正式 `basic_projectile` 保持 `EquippedWeapon`，并清空当前 `10–14` 技能基础伤害。`ProjectileSkillDefinition.CreateDamagePackets` 和 `MonsterDefinition.CreateContactDamagePackets` 不再制造隐藏伤害常量；正式内容依靠验证器保证配置完整。

### 2. 初始武器

- `CombatPrototypeBootstrap` 新增必填的初始武器引用，正式场景引用现有 `great_sword`，不新增重复图标或临时物品基底。
- 初始实例固定为普通品质、物品等级 1、无随机词条；实例 ID 和种子使用稳定启动值，不进入掉落或玩家攻击随机通道。
- 增加一个事务性初始装备 Command/System 入口：检查玩家、武器类型、Weapon 槽和重复初始化，使用无事件背包事务完成“授予 → 装备”，失败时完整回滚。
- 初始装备成功后才启用 `MonsterSpawner`。失败时输出带资产上下文的 Error，并保持刷怪器关闭，禁止进入无法反击的软锁状态。
- 重复初始化时，如果同一玩家已有合法 Weapon 槽装备，则返回成功而不重复创建物品。
- 手动卸下武器后，物品正常回到背包；自动攻击仍按技能冷却检查，但不会生成空伤害投射物。重新装备后恢复攻击。

### 3. 正式基础战斗属性

`StatDefinition` 的 21 个稳定 ID 不变。本阶段只给现有属性增加正式来源，不新增属性 ID。

| 角色 | 命中值 | 闪避值 | 暴击率 | 暴击伤害 | 护甲 | 四类抗性 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 玩家 | 100 | 20 | 5% | 50% | 0 | 0% |
| 荒原游魂 | 90 | 15 | 5% | 50% | 0 | 0% |
| 裂爪猎犬 | 110 | 30 | 8% | 50% | 0 | 0% |
| 铁壳尸傀 | 80 | 5 | 3% | 50% | 40 | 0% |

- `critical_damage` 继续表示额外百分比；`50` 表示暴击总倍率 `150%`。
- `accuracy` 必须大于 0；`evasion`、`armor` 不得小于 0；暴击率限制为 `0–100`；暴击伤害不得小于 0。
- 怪物基础数值写入各自 `MonsterDefinition`，不创建只为绕过字段缺失而存在的空 Prefab `CharacterDefinition`。
- 玩家和怪物的基础属性仍先进入 `StatBlock`，再由现有装备 / 修改器聚合；命中计算不直接读取配置资产。

### 4. 攻击根种子与子随机流

每次实际可以开始的攻击仍只从 `GameplayRandomSystem` 的 `PlayerAttack` 或 `MonsterAttack` 通道取得一个根种子。由纯逻辑工具按固定用途常量派生：

```text
AttackRootSeed
├── BaseDamageSeed
├── HitRoll      [0, 1)
└── CriticalRoll [0, 1)
```

- 子流通过稳定混合函数派生，禁止依靠一次 `System.Random` 的调用顺序串行取值。
- 增减基础伤害包或修改其内部随机次数，不得改变同一次攻击的 `HitRoll` 或 `CriticalRoll`。
- `AttackSnapshot` 保存根种子、已掷出的基础伤害、`HitRoll` 和 `CriticalRoll`；不保存目标依赖的最终命中结论。
- 攻击者属性、技能、来源物品和修改器继续在发射 / 攻击开始时冻结；目标闪避、护甲、抗性和承伤修改器继续在投射物命中时读取。
- 无武器等攻击构建失败不取得根种子，保证失败尝试不推进后续正式攻击序列。

### 5. 命中与闪避公式

```text
accuracy = max(0, attacker.accuracy)
evasion  = max(0, defender.evasion)

rawHitChance = accuracy <= 0
  ? 0.05
  : accuracy / (accuracy + evasion)

hitChance = clamp(rawHitChance, 0.05, 0.95)
```

单个 `HitRoll` 的判定顺序固定为：

1. `HitRoll < hitChance`：命中。
2. 否则，如果 `evasion > 0` 且 `HitRoll < 0.95`：闪避。
3. 其余失败：未命中。

这样保留 5% 最低命中与 95% 最高命中，并把目标闪避造成的额外失败与自然未命中分开。示例：命中 100 对闪避 25 的命中率为 80%；`0.79` 命中、`0.85` 闪避、`0.97` 未命中。

按正式基础值，玩家对三种怪物的基础命中率约为 `87% / 77% / 95%`；三种怪物对玩家约为 `82% / 85% / 80%`。这些数值是 alpha 基线，不在本阶段追加动态平衡曲线。

### 6. 暴击公式

```text
criticalChance = clamp(attacker.critical_chance / 100, 0, 1)
isCritical = hitSucceeded && CriticalRoll < criticalChance
criticalMultiplier = 1 + max(0, attacker.critical_damage) / 100
```

- 未命中或被闪避时不产生暴击，即使预生成的 `CriticalRoll` 小于暴击率。
- 暴击结论在命中确认后产生；暴击倍率在攻击方 Flat / Increase / More 结算后、目标承伤与防御前统一应用。
- 同一攻击只有一次暴击判定，混合伤害包共享结论和倍率。

### 7. 结算顺序

```text
攻击源与目标有效性
→ 命中 / 闪避判定
→ 暴击判定
→ 基础伤害与 LocalItem
→ Conversion
→ GainAsExtra
→ 攻击方 Flat / Increase / More
→ 暴击倍率
→ 按最终伤害类型汇总防御前数值
→ TargetTaken
→ 对应抗性或物理护甲
→ 汇总最终伤害
→ 生命变更与事件
```

暴击“判定”发生在转换前，暴击“倍率”仍放在攻击方缩放后，使当前数学结果保持一致。伤害标签继续由 `DamagePacket.CurrentType` 和 `ScalingTypes` 派生，不回退到平面标签拼接。

### 8. 护甲与抗性

物理护甲保留当前伤害相关公式：

```text
armor = max(0, defender.armor)
armorReduction = armor <= 0 or physicalDamage <= 0
  ? 0
  : armor / (armor + physicalDamage * 10)
physicalAfterArmor = physicalDamage * (1 - armorReduction)
```

- 护甲只处理最终类型为 `Physical` 的命中伤害。
- 护甲按同一次命中汇总后的物理伤害计算，不逐包重复减免。
- 公式天然小于 100% 减免，本阶段不增加额外硬上限。

抗性保留当前边界：

```text
effectiveResistance = clamp(resistance, -100, 75)
damageAfterResistance = damage * (1 - effectiveResistance / 100)
```

- 火焰、冰霜、闪电分别读取对应元素抗性；混沌只读取混沌抗性。
- 护甲不处理元素或混沌伤害；抗性不处理物理伤害。
- 负抗性增加对应伤害，75% 为当前最大减免。

### 9. 结果模型

新增 `HitOutcome`：

| 结果 | 含义 | 扣血 | 受击反馈 |
| --- | --- | --- | --- |
| `InvalidTarget` | 攻击、目标或阵营关系无效 | 否 | 无事件、无文字 |
| `Missed` | 命中判定失败且不是目标闪避区间 | 否 | “未命中”文字 |
| `Evaded` | 目标闪避造成失败 | 否 | “闪避”文字 |
| `Hit` | 命中且最终伤害大于零 | 是 | 伤害文字与受击反馈 |
| `NoDamage` | 命中但最终伤害不大于 epsilon | 否 | “无伤害”文字，不闪白、不播放 Hit |
| `Invulnerable` | 为 `alpha 0.1.3` 预留 | 本阶段不生产 | 本阶段不实现 |

`IsCritical` 与 `HitOutcome` 正交；只有命中后才能为真。`DamageResult` 继续提供兼容只读属性 `IsHit`、`IsCritical`、`TotalDamage`、`DamageBeforeDefense`、`DamageAfterDefense`，并增加：

- `Outcome`、`DidDealDamage`。
- `HitChance`、`HitRoll`、`CriticalChance`、`CriticalRoll`。
- 每种最终伤害类型的 `DamageTypeBreakdown`：防御前值、承伤倍率后值、有效抗性、护甲值、护甲减免率和最终值。
- 使用稳定顺序的 `ToDebugString()`，能从一次结果还原判定和防御步骤。

### 10. 事件与临时表现

- 增加统一的伤害结算结果事件，合法目标上的 `Missed`、`Evaded`、`Hit`、`NoDamage` 均只发送一次。
- `ActorDamagedEvent` 收缩为“目标实际损失了正数生命”后才发送；现有 Animator、闪白和血条继续只消费该事件。
- 未命中、闪避和无伤害不扣生命、不触发 Hit 动画、不刷新受伤血条、不生成 `-0`。
- `DamageNumberVisual` 扩展为伤害、暴击伤害、治疗、未命中、闪避和无伤害文本；继续按目标阵营区分敌我颜色，暴击只增加字号 / 字重或轮廓，不新增美术资产。
- 投射物在判定失败后仍被消费，但只在实际命中时播放现有临时冲击表现；未命中或闪避不伪装成命中特效。
- 现有治疗事件和敌我 / 伤害 / 治疗配色保持不变。

## 实施阶段

### 阶段 0：冻结迁移前基线

1. 记录当前大剑、战斧、技能回退、三种怪物接触伤害和五类伤害结果。
2. 补测试证明当前空手回退、固定命中 / 非暴击、零伤害仍发受伤事件等待替换行为。
3. 保存固定根种子下玩家 / 怪物攻击与掉落的跨通道基线，明确本阶段只允许攻击结果序列发生预期变化。

验收：基线测试稳定，且没有先修改正式配置以掩盖现状。

### 阶段 1：纯逻辑判定与结果结构

1. 实现稳定子种子 / Roll 派生工具和边界测试。
2. 实现 `HitResolutionCalculator`、`HitOutcome` 与概率 / Roll 调试数据。
3. 增加 `DamageTypeBreakdown`，重构护甲与抗性计算为可记录的纯函数。
4. 保持现有标签血统、转换、额外获得与攻击方缩放数值回归。

验收：不依赖 Unity 场景即可覆盖命中边界、闪避区间、暴击边界、五类防御和混合伤害。

### 阶段 2：攻击快照与武器来源

1. 让 `AttackSnapshot` 保存独立 Roll，并在命中时解析目标结果。
2. 为玩家武器来源与怪物接触攻击统一使用攻击根种子子流。
3. 移除武器技能的技能 / 常量回退，并保留真正 `Skill` 来源技能的配置能力。

验收：空手武器技能不能造成伤害；测试技能来源仍可使用自己的配置伤害；在途投射物继续冻结发射时攻击者属性。

## 风险与控制

- **空手后无法攻击**：初始装备在刷怪前完成；手动卸下保持可恢复背包路径。
- **随机重放整体漂移**：失败攻击不消费根种子，攻击内部使用具名子流；更新快照而不改掉落 / 刷怪通道。
- **事件语义回归**：先新增结算结果事件，再把既有受伤消费者收缩到正伤害；逐个验证 Animator、血条和飘字。
- **在途投射物读到新装备**：攻击者属性、武器和 Roll 继续由快照持有；只有目标防御在命中时读取。
- **配置默认值让旧资产命中率异常**：正式资产必须由迁移工具显式写值；验证器拒绝攻击角色零命中。
- **结果模型重复兼容层**：只保留现有公开只读属性的投影，不长期维护两套判定入口；生产代码统一使用 `HitOutcome` 与结构化分解。
- **跨入后续范围**：`Invulnerable` 只保留结果扩展位，本阶段不创建计时器、不改变碰撞或受击冷却。

- Miss / Evade / NoDamage 不扣血、不触发受伤反馈、不显示零伤害。
- 正式配置中心扫描为零错误；Runtime、Editor、EditMode 和 PlayMode 程序集编译通过。
- 全量 EditMode 与 PlayMode 零失败，现有物品 UI、装备事务、交易、打造、掉落和标签系统无回归。
