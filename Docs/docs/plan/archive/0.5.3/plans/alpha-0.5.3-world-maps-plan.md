# Alpha 0.5.3：城镇、野外与地图生命周期

状态：2026-09-18，G1–G7 已完成。版本 `0.5.3-alpha`、core v6、Save Schema 4、地图文档 V2。最终 EditMode 713/713、PlayMode 83/83，独立 Windows Player、两图重启恢复、30 秒冻结与 20 轮往返通过。当前模块见[地图生命周期](../../../../maps/world-map-lifecycle.md)，证据及测量限制见 [G 验收](../acceptance/maps/g/README.md)。下文保留原计划，完成差异见末尾记录。

本计划细化[总计划](../../0.5/plans/alpha-0.5-plan.md)与[双地图生命周期方案](../../0.5/plans/alpha-0.5/world-maps-lifecycle.md)。用户已确认 500 活动怪物、1000 压力测试，以及离场保留状态并暂停模拟。

## 交付与边界

交付 `map:town`、`map:wilderness` 两份正式地图，复用现有四材质 Dual Grid / Wang 地表、编辑器、几何和对象表现。新游戏进入城镇，玩家可交易、打造、前往野外战斗并往返；保存退出后继续，地图状态保持一致。

保留 Bootstrap + Main。Main 成为通用玩法容器，玩家和玩法 UI 随 Session 存在；离场地图只保留冻结数据，不保留后台模拟的 Unity 对象。继续使用 QFramework Command / Query / Event、UniTask 受管任务和 Addressables owner。

0.5.4 负责 Grid / Flow Field / A* / Spatial Hash / Separation / Job / Burst 和真实 500 / 1000 怪物导航性能。本阶段使用静态通行查询约束落点、刷怪与物理阻挡，野外战斗在开阔区验证；绕障追逐仍是后续未完成项。F 的排序压力结果不能代替导航或完整战斗性能。

## 已核对的接入点

| 当前代码 | 必须解决的差距 |
| --- | --- |
| `MapDocument` V1 只有地表、对象和区域；交互只有 Trader / Crafting | 增加显式 EntryId、入口用途及出口目标，覆盖编译、Schema、编辑器和 AI 事务 |
| `GameplaySceneConfiguration` 强制商人、打造、刷怪器同时存在 | 分离 Session 启动配置与地图能力，允许无商人的野外和无刷怪器的城镇 |
| `SessionObjectRegistry` 只有全局对象集合及 ReleaseAll | 增加地图 owner 定向释放，玩家 / UI 保留原 Session 所有权 |
| `SceneFlowService` 只有 StartGame / ReturnToFrontEnd 等场景请求 | 在现有 active + latest pending 仲裁中加入 ChangeMap；Main 不反复卸载 |
| `WorldInteractionTarget` 直接关联菜单页 | 保留现有菜单交互，增加地图出口动作；请求交给系统和 Scene Flow |
| `MapObjectPresentationBatch` 已可 Prepare / Activate / Dispose；几何投影 Populate 完成会启用 | 地表、碰撞、领域对象统一支持不可见且不参与物理 / 战斗的候选态，不能直接把预览激活行为用于切图 |
| `RunSaveData` 的怪物、掉落、商人、刷怪器均为单地图结构 | 分离 Session 数据和按 MapId 存储的状态；恢复不能调用全 Session 初始化替代切图 |
| 状态专用 ImportSave 已支持恢复；时钟和随机通道仍为 Session 级 | 补充按地图冻结 / 转入，保持状态相位与来源规则，划分随机通道所有权 |
| `MonsterSpawner` 失败后夹到矩形边界；相机使用旧 Bounds | 改用区域、足迹净空和地图范围；采样失败明确跳过 |

## 实施顺序

每一步通过针对性验证后再进入下一步；中间成果不能提前标为完整双地图已交付。

| 步骤 | 实施内容 | 退出条件 |
| --- | --- | --- |
| **G1 数据与兼容合同** | 地图入口 / 出口、地图能力、冻结状态、容量及历史映射合同；补充文档升级与校验 | V1 地图可读，V2 导入导出及手工 / AI 编辑一致；非法目标、重复身份、坏入口可诊断；迁移夹具和容量样本已确定 |
| **G2 地图作用域与装配** | MapScope / MapGeneration、owner 定向释放、地表 / 几何 / 表现 / 交互候选装配；取消与资源回收 | 候选不进入活动物理、排序、状态、刷怪；失败不污染源图；反复准备 / 释放后资源收敛 |
| **G3 冻结与恢复原语** | 活动地图导出、Actor 解绑 / 专用恢复、状态时间平移、RNG / 刷怪 CD、库存和掉落身份 | 内存往返不重掷、不首跳、不发死亡奖励；玩家时钟独立继续；冻结地图不参与系统查询 |
| **G4 切图事务与仲裁** | ChangeMap、预检 / 准备 / 提交 / 回退、Busy 与输入门禁、保存捕获互斥 | 快速请求和取消恰好结算一次；准备 / 提交故障保持唯一活动地图与玩家；保存只能取得稳定快照 |
| **G5 分地图存档** | Schema 3→4、core 内容迁移、全图身份校验、Snapshot / PreparedRestore / Restore 接入 | 新旧档、1000 怪物容量、磁盘失败和进程重启回归通过；历史链保留，源档不改写 |
| **G6 正式地图与 Main 接入** | 两份正式布局、入口 / 复活 / 刷怪区域、交易 / 打造绑定、相机与新游戏 / Continue | 城镇安全，野外合法刷怪与掉落，双向交互与键鼠 / 手柄可达；去除已被替代的 Main 世界消费者 |
| **G7 综合验收与归档** | Windows Player 往返 / 冻结 / 退出继续、故障矩阵、资源基线、回归与模块说明 | 满足下述成功标准，版本更新为 0.5.3-alpha；更新模块文档并归档本计划 |

## G1 首个执行单元

1. 扩展地图交换格式为 V2：增加 `entries`（稳定 EntryId、局部世界坐标、出生 / 返回 / 复活用途）；出口仍是对象交互，显式保存目标 MapId 和 EntryId。每类交互只接受自身字段，拒绝歧义组合。位置沿用 Object Position 的尺度，不混用区域逻辑坐标。
2. 增加 V1→V2 纯数据升级：旧文档保留布局、身份、变体和 revision，补空入口；工具可编辑旧样例，但运行时正式地图必须通过入口 / 出口完整性校验。跨图引用在整套地图预检中验证，不让单图编译依赖加载顺序。未知未来版本拒绝。
3. 同步 JSON Schema、规范序列化、导入器、Odin / SceneView 入口绘制、Undo / Redo 和 AI 原子 Patch。编辑器仍以 `.dfmap` 为唯一布局源，不另建一份入口坐标 SO。升级另写目标文件或由显式保存落盘，不在预检中改写源文件。
4. 地图能力从绑定推导：Trader / Crafting 对象决定交互能力，Spawn 区域决定生成能力；Session 配置只保留玩家、初始物品、共享服务及默认地图入口。表现目录仍独立于领域配置，商人 / 打造台不能叠加旧场景 Sprite 或第二套实体碰撞。
5. 定向审计历史夹具、旧 Main Bounds 与有效 Actor / 掉落范围，形成迁移映射和容量样本；先补现有 `MapDocumentTests`、`MapEditTests`、导入测试和迁移测试中的长期规则。

## 所有权与切图提交合同

Session 持有玩家、物品总表、背包 / 装备、全局实例分配器和地图状态集合。MapScope 是受 Session / 场景生命周期约束的子 owner，拥有地表、几何投影、地图对象、怪物、掉落、刷怪任务、交互绑定及地图资源 lease。身份校验同时包含 Session generation 和 MapGeneration；旧结果必须在发布前拒绝，不只依赖取消 Token。

切图按 `预检 → 排空并冻结 → 准备候选 → 提交 → 清理源图` 执行：

- 取得现有暂停 / 输入 lease，关闭并结清菜单、拖放和打造工作区；等待领域事务及状态积压收敛。冻结源图和玩家回退状态，保存捕获进入互斥门禁；已获得冻结 DTO 的磁盘写入可继续。
- 源图保留但暂停。目标加载、几何构建、落点和恢复图验证均可取消；候选不得自动注册战斗、状态、排序或启用 Collider，不发正常出生 / 进入事件。
- 提交在主线程不跨 await：停用源图活动绑定，交换活动 MapId / generation 与领域所有权，导入目标状态，绑定玩家、相机、交互和刷怪。所有易失败的资源操作尽量前移，提交步骤仍支持故障注入。
- **提交点**是完整目标上下文安装并通过唯一性检查；此前发生异常均回退源图及玩家。成功后才发布完成事件、标脏并调度保存；清理源图先取消 / 排空任务，再注销与销毁实例，最后释放资源。
- 提交之后的取消不再声称切图未发生；最新请求基于已提交地图执行。清理失败且无法证明唯一性进入既有 Fatal 路径，不能简单宣称已回退。提交后的磁盘失败保留新地图状态并可重试。
- ReturnFrontEnd、退出 / 挂起检查点、手动保存与 ChangeMap 共用稳定快照边界；明确等待顺序，禁止保存持有门禁同时等待切图、切图又等待保存的循环。暂停前状态与各 lease 的原 owner 保持一致。

## 冻结、身份与存档

冻结怪物资源 / 词条 / 位置、接触攻击冷却、有效状态和周期相位、掉落身份与物品归属、商店库存、刷怪倒计时和地图随机流。离场卸载使用专用解绑原因，不触发死亡、击杀、奖励或补货。已提交死亡奖励先收敛再捕获；在途投射物和纯表现按既有存档边界清理。

状态恢复保留层 ID、顺序、周期整数索引，并把 apply / expiry / nextTick 一起平移到当前 Session 时钟。仅冻结离场 Actor；玩家限时状态按活动游戏时间继续。SourceOwned 必须保留现有来源证明，地图来源失效时释放；独立限时效果遵循既有脱离来源合同，不把所有源引用简单清空。

地图随机流稳定派生自运行根种子和 MapId，不使用进程相关字符串哈希。SpawnPosition / MonsterInstance / MonsterAttack / Loot 归地图，PlayerAttack / Crafting 留在 Session。旧图流迁入野外时保留原根种子、序号与混合算法，不能因增加 MapId 改变历史流的下一次结果；新城镇流独立派生。

Save Schema 计划升至 4，正式地图内容进入 core v6，均以实现时完整迁移验证为准。保留 Schema 0→1→2→3，再追加 3→4；保留 core v1→v5 路径并追加地图映射。运行时当前图与冻结图统一保存状态合同，静态地图引用 MapId / 修订，渲染与导航缓存不入档；尚无消费者的可破坏物或运行时地形差量不提前实现。

旧单 Main 存档映射到野外，原商人库存归城镇同一商人，玩家与所有物品 / 怪物 / 掉落实例身份不变。野外中央预留旧 `-16..16` 范围及所需足迹净空；最终兼容范围必须由 G1 的真实边界和夹具核对决定，不能仅凭该数值承诺全部旧档可恢复。非法位置明确拒绝且保留原档，不静默夹坐标、丢对象或新开游戏。首次访问、再次访问、Continue 三条路径分别处理，避免重复发放。

容量初始方案：每图最多 1024 存活怪物、全存档 2048；物品 8192、掉落 4096、状态总层 16384 / 单 Actor 4096、文档 16 MiB 继续作为全局保护。地图状态只允许已登记且不重复的 MapId。G1 / G5 测量 1000 怪物加代表性词条、状态、掉落及城镇库存的实际规范 JSON 大小和恢复峰值；容量边界需联动 Validator、状态目标数量、实例序列和预检，不能只改 MaximumMonsters。组合超限明确报错，不截断；若样本超过预算，记录数据并调整合同后再交付。

## 正式地图与交互验收

初始工程尺寸为城镇 64×64、野外 128×128，CellSize 1，默认每格 4×4 导航节点；用 G1 兼容范围和 G2 几何容量实测确认后固化。连续地表区域优先，避免高频随机水岸导致碰撞矩形失控。两图覆盖四地表与变体，野外实际使用全部四类。

城镇提供 NewGame、Return、Respawn 入口，商人、打造台、出口和安全区；野外提供 Arrival、Respawn、回城出口、Spawn / Safe 区及供后续导航使用的开阔区、窄路、绕行障碍。常规通路按最大角色足迹留净空，入口与关键交互之间验证连通，FindPoint 成功本身不代表连通。

复用 D 的 Safe 排除规则，不受 Spawn priority 压过；刷怪采样验证整个圆足迹，失败跳过并记录原因。相机范围来自地图 Bounds 和视口尺寸，小地图采用居中处理。出口复用现有 Interact Action / Glyph 和本地化提示，入场点与出口触发区分离，等待一次输入释放后重新开放。

## 完成标准与维护

- 独立 Windows Player：新游戏城镇交易 / 打造 → 野外战斗掉落 → 回城等待至少 30 秒活动游戏时间 → 返回野外。冻结怪物生命、状态剩余 / 下跳、攻击 CD、掉落、刷怪倒计时和 RNG 一致；玩家状态正常推进。两图分别保存退出并继续，结果同样成立。
- 故障矩阵覆盖目标 / 入口无效、资源缺失、准备取消、提交各边界失败、清理失败、快速替代、保存失败、挂起 / 退出交错、连续 Session、旧 generation 回调。每个请求仅有一个最终结果，不出现两张活动地图或重复玩家。
- 历史 Schema / core 夹具保留真实迁移语义；1000 怪物快照往返验证身份、状态和数量，全图分配器不得重用冻结图 ID。所有存档测试使用隔离用户目录。
- 连续至少 20 次往返后，在清理与共享资源预热完成的稳定点比较 owner / 排序 / 状态 / 交互注册、Unity 对象和资源 lease；记录地图加载时间与内存峰值，排除只增不减的泄漏。不把可共享缓存强求归零。
- 运行项目 EditMode / PlayMode、内容校验、配置覆盖和正式 Player 构建；真实键鼠 / 手柄验证交互和 Busy 焦点，不只通过直接调用领域 API 代替玩家流程。
- 长期测试优先补现有地图、Scene Flow、Session ownership、Save、状态、交易与输入套件；地图冻结纯规则可独立建模块测试，不按版本复制。一次性采集脚本验收后移除，证据放 `Docs/docs/plan/archive/0.5.3/acceptance/maps/g/`。
- 更新地图生命周期模块，以及场景流、应用生命周期、本地存档、状态时间、随机、刷怪 / 游戏循环和配置参考中受影响合同；执行测试维护审查后归档本计划。尚未完成的绕障和批量导航明确留给 0.5.4。
