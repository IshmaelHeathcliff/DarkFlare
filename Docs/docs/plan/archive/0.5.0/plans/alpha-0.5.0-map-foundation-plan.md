## 执行顺序

1. 核对现有角色 / 怪物半径、镜头、像素密度、地表与 Content Catalog / Addressables 导入入口；记录 1 单位逻辑格和整数细分导航格的尺度试验。先确认通道宽度，再定正式像素和 PPU。
2. 定义纯地图 DTO、ContentId 引用、chunk 坐标、五类记录、稳定对象 ID、格式版本和规范序列化；提供最小 JSON Schema / 样例及拒绝规则。
3. 实现不依赖场景的 Validate / Compile / Export 接口；ScriptedImporter 产生稳定只读 MapDefinition，接入配置中心和现有内容校验。单元验证先于场景替换。
4. 实现 Dual Grid 坐标、四角 Key、边界虚拟样本、四材质拓扑和稳定变体；提供全部 Key 技术调色板与局部 / 全量重建对照。技术贴图仅用于验证，不作为正式美术。
5. 通过 Unity MCP / Editor API 建立独立预览入口，验证水岸、孤点、鞍点、三 / 四材质交点、道路转弯、chunk 接缝及视角尺度。开放场景不得直接改 YAML。
6. 冻结地表家族资产合同，按单 PNG / Single Sprite 先完成代表 Pilot，再生成泥土 / 草地 / 水 / 道路及纯地表变体；自动编译过渡并逐一验证兼容边。无法实现多材质一致过渡时先修编译规则，不掩盖缺失 Key。
7. 根据同一拓扑和障碍 footprint 生成碰撞 / 静态导航查询，提供半径净空、合法出生候选和地图范围查询，供 0.5.3 复用。
8. 运行相关 EditMode / PlayMode、导入器和内容校验、可见预览验证，清理一次性采集脚本；更新地图 / 地表模块说明，再归档本计划。

## 主要合同与测试

| 合同 | 验证 |
| --- | --- |
| 数据表示 | JSON 往返保持五层语义、稳定 ID、布局与变体；导入产物稳定，无双份权威数据 |
| 校验 | 负坐标正确，非法尺寸 / 非有限数值 / ID 冲突 / 未知版本 / 缺引用明确拒绝 |
| Wang 解析 | 256 四角语义 Key 全部有结果；二元 16 模式、三 / 四材质中心、鞍点规则确定 |
| 接缝 | 邻边材质与签名一致时，跨 Key / 变体无裂缝；局部重建等价于全量重建 |
| 资产 | 正式四种地表可辨识，纯地表至少两个变体作为首批工程目标；固定规格、Single、Addressables 无缺引用 |
| 几何 | 水岸 / 障碍 / 区域语义与碰撞、导航一致；不同半径不越界、不切角 |
| 生命周期 | 反复预览 / 重导入、取消、窗口关闭后无残留根对象、租约或 Native 内存 |

现有 Main 尚使用旧地表时，保留 GroundTilemapTests 的有效覆盖；实际迁移消费者后才调整旧 5×5 / 固定 Tile 数量假设。新纯规则套件按 MapDocument / TerrainResolver 等模块命名，不按 Alpha050 建重复测试。

## 完成条件

从最小源地图完整走通导入 → 校验 → 显示 / 碰撞 / 通行派生 → 导出 → 重导入，四种材质及多材质交界可见且一致。相关长期回归通过、无缺失引用、资源可释放、文档反映实际行为后，才标记阶段完成。

正式人工绘制工作台与 AI Patch 入口在 0.5.1 实现；本阶段暴露共享文档服务，避免下一阶段推翻地图表示。后续导航的 Job / Flow Field 不提前混入地表渲染器。
