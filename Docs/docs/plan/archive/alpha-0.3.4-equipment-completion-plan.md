## 收尾目标

装备栏最终交付头部、身体、手部、腿部、主武器、副手、左戒指、右戒指、项链、腰带十个真实可用槽位，每个部位至少两件正式装备配置。穿脱、替换、属性效果、物品详情、拖动、右键、手柄和存档必须形成完整流程，不能只增加空槽图案。

本阶段同时完成 alpha 0.3 综合回归、Player 验收和文档封板。四向跨面板导航在 0.3.0 先落地，本阶段覆盖完整十槽与扩充后的内容池。

## 当前代码基线与兼容边界

- `EquipmentSlot` 当前为 `Weapon = 0`、`Armor = 1`、`RingLeft = 2`、`RingRight = 3`；对应 Mask 位为 0–3。旧配置和存档引用这些身份，禁止按新视觉排列重编号或复用旧位。
- `EquipmentLoadout` 已使用 Dictionary，事务通过 `CanEquipTo(slot)` 校验；扩槽优先复用，不建立第二套十槽状态。更新统一槽位登记、Mask、Validator、查询、效果解析及所有四槽假设。
- 旧 Weapon 在 UI 显示为“主武器”，旧 Armor 显示为“身体”；保留旧枚举身份和内容 ID，新增六槽使用新的稳定编号 / Mask 位。UI 排列与持久化顺序解耦。
- `RuntimeStateMapper` / `SaveDataValidator` 校验槽位枚举及兼容性；必须覆盖旧四槽存档继续、新十槽保存恢复、重复实例拒绝和未知未来数据拒绝。旧档新增部位为空，不自动发放或重掷装备。
- 正式目录计划升级为 `core` v2，SaveSchemaVersion 保持 1：装备 DTO 已为槽位列表，扩槽不改变序列化结构。`SaveRestorePreparer` 与 `RestoreGameSessionInitializer` 当前均要求内容版本相等，须先实现明确的 `core` v1 → v2 内容兼容转换，在分离 DTO 上验证并更新目录版本，再进入严格恢复流程。未知目录、未知槽、未来版本仍拒绝，恢复成功前不覆盖源档；既有 Save v0 → v1 结构迁移继续保留，两条版本路径分别验证。

## 装备配置覆盖

| 部位 | 现有可复用配置 | 收尾最低覆盖 |
| --- | --- | --- |
| 头部 | 无 | 两件独立配置 |
| 身体 | 皮甲、板甲 | 两件，保留原内容身份与效果 |
| 手部 | 无 | 两件独立配置 |
| 腿部 | 无 | 两件独立配置 |
| 主武器 | 大剑、战斧 | 两件，保留现有攻击来源语义 |
| 副手 | 无 | 两件独立配置，效果由现有属性管线消费 |
| 左戒指 | 铁指环、翡翠戒指、黑曜戒指均兼容 | 至少两件可装备配置 |
| 右戒指 | 同一兼容戒指池 | 至少两件可装备配置 |
| 项链 | 无 | 两件独立配置 |
| 腰带 | 无 | 两件独立配置 |

内容预算按至少 20 个独立装备基底安排：八个非戒指部位各两件，共 16 件；戒指池至少四件，共至少 20 件。左右戒指保持共享兼容池，不人为锁成左用 / 右用；现有七件计入覆盖，计划至少补充十三件。不能把同一基底的随机稀有度、词缀变体或两个实例计作两件配置。

- 每件具有独立稳定 ID、合法部位、占格、价格、基础效果 / 隐式、词条兼容、双语文本和正式独立图标；两个配置要有可观察的已有属性差异，不能只改名称。
- 副手默认提供防御或辅助属性，主武器继续提供当前攻击来源。不得因副手存在而重复计算主武器伤害，也不把旧大剑名称自动解释为新的双手占槽规则；本阶段不新增双持攻击、格挡公式或武器组切换。
- 新部位复用当前 ItemType / AllowedEquipmentSlots 及已支持属性，逐项审计标签派生和词条过滤；不能把戒指专属词条无条件扩给所有饰品，也不能让非主武器 LocalItem 词条成为无效正式配置。
- 新配置进入正式 ContentCatalog，并接入可获得的商店 / 掉落来源及合法打造候选；逐件检查生成、购买、穿戴、打造、卸下、出售 / 丢弃，不以测试专用发放代替正式获取。
- 商店采用固定视口内的纵向滚动商品网格，保留 10 列、真实占格和完整商品，不新增分页或轮换库存。`MerchantGridLayout.Pack` 已支持动态行数，但当前 `shop-merchant-frame` 是固定 324 px 的普通 VisualElement，需增加 ScrollView，防止新增行覆盖下方来源和操作区。复用已有焦点恢复与 `ScrollTo`；玩家背包保持 10×6。
- 图标沿用当前单图 Sprite 生产规范：每件独立 PNG、Addressables 引用、规定 PPU / Point / 无压缩导入，通过可见尺寸审计；新空槽剪影、装备栏边框和背景使用本轮统一风格。

## 十槽布局与交互

- 首阶段预研十槽布局，本阶段接入真实数据。人物部位按空间含义排列，名称与图标对应；布局完成后冻结上下左右预期导航，不用枚举顺序代替视觉邻居。
- 头部、身体、手部、腿部、主武器、副手、双戒指、项链和腰带都提供可聚焦空槽、详情、兼容提示和原子替换 / 卸下；手部、腿部分别是一个装备槽，不额外增加左右手套 / 左右腿槽。
- 普通装备的唯一兼容目标可自动确定；戒指或其他多兼容配置必须明确目标，避免快捷装备覆盖另一槽。拖动和手柄放置仍指定目标槽并预检旧物品回包空间。
- 十槽同时穿戴后，属性详情来源分解和 HUD 事件刷新都反映完整 Loadout；多槽同类词条按正式规则聚合，重复穿脱不累计残留或恢复资源套利。
- 装备区 ↔ 背包 ↔ 商店 / 打造沿实际相邻关系双向导航；无论槽位已装备还是空置，都不能形成焦点死角。方向导航、拿起放置、快捷操作与跨设备唯一高亮复用同一合同。
- 1920×1080 下验证十槽与背包、商店 / 打造组合；不得靠压小文字、裁切详情、遮挡装备槽或让窗口超出安全区塞进内容。

## 执行与验收

1. 盘点所有四槽假设、内容数量断言、Save / Catalog 兼容路径，先补旧档和装备原子性回归；确定新编号、副手合法效果、内容清单及商店容量方案。
2. 扩展槽位登记和数据入口，接通配置校验、领域事务、十槽快照及来源聚合；验证无重复归属、替换失败回退、资源比例保持及在途攻击快照不受换装影响。
3. 逐件配置、生成 / 导入图标、本地化、登记正式目录和内容池，执行每槽覆盖校验；更新当前内容计数测试，不改历史验收数字。
4. 使用 Unity MCP / Editor API 接入十槽 UI 并检查布局；以真实输入完成四向视觉邻居、边缘跨窗、快捷穿脱和精确放置矩阵。不能直接修改已打开场景 YAML。
5. 验证旧四槽存档继续及新十槽保存 / 恢复，结合新旧内容目录版本核对兼容；所有测试使用隔离数据根，不修改玩家正式存档。
6. 执行适当的 EditMode / PlayMode、Addressables 与 Windows Player 构建；真实 Player 覆盖完整物品循环、菜单交接、三语言布局及三次 Session 往返，记录证据和实际测试计数。

封板条件：十槽全部可用、每槽至少两件正式配置且达到上述独立内容预算；旧档不丢装备，新档十槽正确恢复；四向导航与视觉位置一致且跨窗口顺畅；全局单一物品高亮、详情无超框、正常路径零新增 Error / Warning。

完成后更新[装备模块](../../equipment-system.md)、[内容池](../../content-system.md)、[输入与 UI](../../input-ui-system.md)、[物品工作台](../../item-ui-workbench.md)、[属性](../../stat-system.md)、[内容与迁移](../../infrastructure/content-identity-migration.md)、[存档](../../infrastructure/local-save.md)及视觉资源文档，归档本阶段与 alpha 0.3 总计划。交互合同已在 archive 中，不重复归档；运行版本只在实际交付时更新为 `0.3.4-alpha`。

## 核对后的实施决策

| 事项 | 执行约束 |
| --- | --- |
| 新槽编号 | 旧 0–3 保留；追加 Head=4、Hands=5、Legs=6、OffHand=7、Necklace=8、Belt=9，Mask 使用对应位；视觉顺序独立登记 |
| 类型与槽位 | 主武器沿用 Weapon；身体 / 头部 / 手部 / 腿部 / 防御副手使用 Armor；戒指 / 项链 / 腰带使用 Accessory。Validator 使用明确的类型与合法槽集合，拒绝未知位、空掩码和跨类非法组合 |
| 自动装备目标 | 从统一槽集合枚举兼容目标，替代只判断 Weapon / Armor 的分支；唯一兼容目标自动选择，多目标必须明确槽位，不默认覆盖另一戒指 |
| 词条适用范围 | CombatTagResolver 目前只给兼容 Rings 的饰品派生 ring；项链 / 腰带不能伪装成戒指。补必要的饰品适用标签与明确词条范围，逐件验证存在真实前后缀候选；不放行非主武器 LocalItem |
| 主副手关系 | 副手只提供已有防御 / 辅助属性，不产生第二份攻击基础伤害；旧大剑、战斧继续允许搭配副手，不追加双手或格挡规则 |
| 旧档内容 | 新槽为空；旧装备、金币、背包坐标、实例 ID、已掷数值和商人库存精确恢复，不补发装备或重置库存。新增基底接入正常掉落，保证旧档也可获取；新游戏商店提供完整扩充内容 |
| 内容登记 | 沿用至少 20 基底预算，先登记每件 ID、槽位、占格、价格、已有属性效果、词条范围和中英名称，再生成图标；不扩展新战斗公式 |

`InventoryPanelController` 虽已遍历 `EquipmentSlots.All` 绑定控件，自动目标、本地化 Key 和空槽图标仍有硬编码；`EquipmentConfigurationValidator` 仍限制护甲为身体、饰品为戒指。实现须定向检查枚举、Mask、四槽数组、比较快照、来源列表、属性说明、Editor 工具和测试，不能只扩枚举与 UXML。
