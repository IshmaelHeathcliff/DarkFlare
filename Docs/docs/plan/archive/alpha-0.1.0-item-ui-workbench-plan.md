# alpha 0.1.0 物品 UI 工作台重构计划

> 状态：已完成并归档
> 建立日期：2026-08-09
> 完成日期：2026-08-09
> 所属版本：alpha 0.1
> 视觉参考：用户提供的布局草图、项目 Game UI Kit 保留参考

## 实施结果

- 建成单一物品工作台：四槽空间装备区、玩家 10×6 真实背包和右侧上下文共同复用一套布局。
- 运行时只保留一个顶层物品信息浮窗；宽屏时停靠在主面板外侧，紧凑屏幕内自动夹紧，不再固定占用内容列。
- 商人库存改为确定性虚拟格子，打造直接复用玩家背包选择；商店与打造均不再维护玩家物品长列表。
- 支持鼠标拖拽、键盘与手柄拿起/放置：背包精确移动与单目标交换、背包装备/替换、装备精确卸回、双戒指移动/交换均通过原子 Command 提交。
- 页面切换、关闭、取消与非法落点统一回滚；拖到商店或打造上下文不会隐式触发购买、出售或打造。
- 采用纯 USS 的 1 px 细边框和统一状态语言，避免旧 Frame 缩放过粗；本阶段无需新增生产 PNG，也未重新引入 SpriteSheet。
- `1280×720`、`1920×1080`、`2560×1440` 三档布局回归通过；宽屏浮窗与主面板不重叠。
- 后续验收修正将装备与背包改为同一列上下排列，并把共享列限制为内容区 49%；同时修复 Button Pointer Capture 竞争及浮窗子节点拦截输入，真实 Mouse 可完成背包换位、拖拽装备和装备拖回。

验证结果：领域/输入/结构 EditMode 9/9，相关 PlayMode 4/4；其中真实 Mouse Pointer 覆盖背包换位、拖到装备槽和装备拖回。两个 Phase5 视觉约束用例通过 Editor 内反射直接执行 2/2。运行时与 Editor 程序集均为 0 warning / 0 error。Phase5 用例通过 Test Runner 启动作业时发生初始化作业丢失，因此同时保留结构测试、PlayMode 边界断言和运行时截图作为交叉证据。

## 阶段目标

将背包、装备、商店、打造和物品详情从三套重复页面重构为一个统一的“物品工作台”。玩家在任意物品上下文中都能看到一致的格子、装备槽、选择状态和物品信息，不再因为固定详情栏、长列表或粗重边框挤压有效内容。

完成后玩家应能：

- 在独立浮动物品信息窗口中查看悬停、焦点或固定选择的物品。
- 在参考《流放之路》空间语义、但只包含当前四个有效槽位的装备区中完成装备、替换和卸下。
- 在背包、玩家出售区、商人库存和打造选物中使用同一种格子交互，不再使用物品长列表。
- 通过鼠标拖拽或键盘 / 手柄“拿起—放置”模式整理玩家背包，并在背包与四槽装备区之间移动装备。
- 在键鼠和手柄下清楚区分悬停、焦点、固定选择、可操作和禁用状态。
- 在 1280×720、1920×1080 和 2560×1440 下完成完整操作，不出现信息遮挡、按钮越框、文字截断或焦点丢失。

## 当前基线与主要问题

| 区域 | 当前实现 | 问题 |

现有交易、打造、装备事务和 QFramework 领域边界已经稳定。本阶段在重构表现、快照和输入导航的同时，为玩家背包补充指定坐标移动 / 交换，并为装备与背包之间补充精确放置的原子事务；不改变交易价格、打造成本、物品占格尺寸、装备兼容或既有按钮操作的回滚语义。

## 目标信息架构

标准布局采用一个共享工作台，而不是三个重复页面：

```text
┌────────────────────────── 共享菜单标题 / 上下文切换 / 关闭 ──────────────────────────┐
│                                                                                      │
│  ┌──── 顶层浮动物品信息 ────┐   ┌──── 四槽装备区 ────┐   ┌──── 当前上下文 ─────────┐ │
│  │ 名称、图标、基础、词缀   │   │ 武器 / 护甲 / 双戒 │   │ 背包：比较与操作        │ │
│  │ 比较、价格或打造补充信息 │   └────────────────────┘   │ 商店：商人格子与交易    │ │
│  └──────────────────────────┘   ┌──── 玩家 10×6 背包 ┐   │ 打造：词缀与打造操作    │ │
│                                  │ 真实占格与实例位置   │   └────────────────────────┘ │
│                                  └────────────────────┘                                │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

浮动信息窗口位于顶层 overlay，不参与主布局宽度分配。它优先放在当前物品左侧，空间不足时翻转到右侧，并在菜单安全区内上下夹紧；不得遮住当前焦点控件和底部主要操作按钮。

### 三种上下文

| 上下文 | 始终可见 | 右侧上下文内容 | 主要操作 |
| --- | --- | --- | --- |
| 背包 | 四槽装备、玩家格子背包 | 当前槽位、装备比较和操作反馈 | 拖拽整理、装备 / 替换、卸下 |
| 商店 | 四槽装备、玩家格子背包 | 商人虚拟格子背包、金币、价格与交易反馈 | 整理玩家背包、购买商人物品、出售玩家物品 |
| 打造 | 四槽装备、玩家格子背包 | 当前词缀、容量、价值和四项打造操作 | 整理玩家背包、添加、重随、替换、提升 |

打造中的词缀仍可使用文字列表，因为它不是物品背包；“不再使用列表”只约束可选物品集合。

## 交互合同

### 选择与浮动信息

- Pointer Enter 或 Focus In 只改变临时预览，不直接改变操作目标。
- Click 或 Submit 固定选择；Pointer Leave 或 Focus Out 后恢复固定选择。
- 浮动窗口统一绑定 `ItemDetailSnapshot`，上下文只追加装备比较、买卖价格或打造摘要，不复制基础详情结构。
- 无预览也无固定选择时隐藏窗口；固定选择存在时窗口保持显示。
- 浮动窗口本身默认不可聚焦，滚动详情通过专用详情输入或鼠标滚轮处理，不能截断菜单 Cancel。

### 装备区

- 只展示现有 `Weapon`、`Armor`、`RingLeft`、`RingRight` 四槽。
- 采用中央人物暗纹 / 轮廓作为空间参照：护甲位于躯干，武器位于身体一侧，双戒指分列左右。
- 不显示头盔、手套、鞋等不可交互假槽位，避免暗示不存在的系统。
- 武器和护甲仍自动确定唯一目标槽；戒指仍要求显式选择左槽或右槽。
- 槽位图标、物品格图标和浮动详情使用同一稀有度与缺失图标规则。

### 格子背包

- 抽取无领域写入能力的 `ItemGridView`，统一创建背景格、跨格物品按钮、图标、稀有度、悬停和焦点状态。
- 玩家背包直接使用 `InventoryItemSnapshot.Placement`；整理成功后由领域事务更新真实 Placement，视图不得自行重排或伪造位置。
- 打造直接选择玩家背包中的真实物品，不再生成独立物品列表。
- 商人库存保持 `EconomyModel.MerchantStock` 所有权不变，通过纯只读、确定性的虚拟格子排布生成展示位置。
- 商人库存变化后按原库存顺序重新排布，并按旧格子中心选择最近存活物品恢复焦点。
- 任意物品无法放入当前商人格子页时增加滚动行或分页，不允许逐件缩小图标或忽略物品尺寸。

### 拖拽整理与精确放置

- 拖拽只以玩家背包物品和已装备物品为合法来源；商人库存为只读展示，不允许从商人格子开始拖拽。
- 背包物品拖到空白区域时按目标左上格精确移动；拖拽预览保留物品真实占格和按下时的格内偏移，不能吸附成单格图标。
- 目标只与一个背包物品相交时，可尝试原子交换：被替换物必须能完整放入来源位置；目标越界、与多个物品相交或交换后任一物品无合法位置时整笔失败。
- 背包装备拖到兼容槽位时执行装备；槽位已有装备时，旧装备优先精确回填到拖拽物品的来源位置，放不下则整笔失败，不允许静默塞入其他空位。
- 已装备物品拖回背包时必须落到玩家指定的合法位置；装备在 `RingLeft` 与 `RingRight` 之间拖动时允许移动或原子交换，其他不兼容槽位始终拒绝。
- 拖拽到商人格子、打造操作区或上下文按钮不会隐式购买、出售或打造；这些领域操作仍由明确按钮 / Submit 二次确认触发。
- 无效目标、拖出菜单、按 Cancel、页面切换、菜单关闭或刷新代次变化都应取消会话并恢复原状，不发送背包或装备变更事件。
- 成功事务完成后才统一发送领域事件并重建快照；拖拽期间只维护表现层 ghost、来源占位和目标高亮，不提前写入 Model。
- 来源物品降透明度并保留占位；ghost 显示完整占格，合法目标显示形状与亮度双重提示，非法目标显示明确阻止标记。交互反馈优先用 USS overlay 和现有槽位 Frame，不为拖拽状态复制一套结构不同的 PNG。

### 键鼠、手柄与焦点

- 格子导航按物品占格中心寻找目标，不按 Visual Tree 插入顺序猜测方向。
- 明确四个焦点区：顶部上下文、装备、玩家背包、右侧上下文；跨区移动具有固定出口和返回位置。
- 鼠标悬停、键盘方向键和手柄左摇杆共享预览语义，Submit 共享固定选择语义。
- 增加独立的“拿起 / 放置”输入动作，避免与固定选择和购买 / 打造确认共用 Submit；拿起后方向键或左摇杆按格移动目标，动作键确认放置，Cancel 先取消拿起状态。
- 手柄拿起装备后可在兼容装备槽与玩家背包之间跨区移动；进入背包时以最近合法格为起点，不能用自动首空位替代玩家选择。
- Escape / B 始终优先关闭菜单；浮动详情不能形成 Cancel 死区。
- 刷新、交易、打造、装备、页签切换和菜单重开后，优先按 InstanceId 恢复选择，再按旧格子中心选择邻近项。

## 响应式布局

不再只依赖 `max-width` 自动压缩。根据 UIDocument 实际可用尺寸切换明确布局类：

- 标准布局：1920×1080 及更宽画面，完整显示装备、玩家背包、右侧上下文和侧向浮动详情。
- 紧凑布局：1280×720，保留四槽空间语义和 10×6 格子；浮动详情改用固定安全角或覆盖式位置，格子尺寸使用经原型测量冻结的紧凑规格。
- 宽屏布局：2560×1440，不拉伸槽位纹理和物品图标，只增加安全留白、上下文宽度和详情最大高度。

断点、标准 / 紧凑格子尺寸和各区最小宽度必须先在真实 UXML 原型中测量，再写入样式和自动化测试；不得凭资产画布大小反推运行时控件尺寸。

## 视觉语言与资产生产

第一份视觉交付物采用“参考 / mockup”模式，只用于确认层级、密度和比例，不导入 Unity。通过后才进入生产资产模式。

### 视觉原则

- 延续 Game UI Kit 的深色石板 / 暗铁底、细暖金边、低对比纹理和克制角饰。
- 减少当前粗重金属包边；边框服务于分区，不与物品图标争夺视觉权重。
- 固定选择使用暖金，键盘 / 鼠标焦点与手柄焦点必须同时具备形状和亮度差异，不能只依赖颜色。
- 拖拽来源、合法落点和非法落点必须在不依赖文字的情况下可区分；ghost 不遮挡目标格边界和浮动详情的关键信息。
- 稀有度颜色只用于物品名称、细边和小面积强调，不整块染色面板。
- 文字、价格、槽位名称和物品图标保持为独立 UI 内容，不烘焙进 Frame PNG。

### 生产资产族

- 细边主面板 Frame。
- 浮动物品信息 Frame。
- 格子 / 装备槽 Default、Focused、Selected、Disabled 状态。
- 装备区人物暗纹 / 轮廓装饰。

生产前必须冻结每个资产族的固定画布、可见边界、九宫格 Border、禁切角饰区、最小 / 标准 / 最大控件尺寸和验收分辨率。槽位所有状态必须使用完全相同的画布、Border 和结构，只允许材质亮度、描边或辉光变化。

全部生产图继续遵守：

- 一张 PNG 一个 `Sprite Mode: Single` 资产或交互状态。
- 不生成 SpriteSheet，不依赖 Sprite Editor 手动切割。
- Point、Compression None、MipMap Off、Full Rect；具体 PPU、Border 和画布由 Pilot 合同冻结。
- 先审批一个槽位 Default Pilot，再逐张生成和审计其他状态；主面板和浮窗分别审批 Pilot。
- 每张图都通过自动尺寸、边距、中心和九宫格安全区审计，并在 Unity 最小 / 标准 / 最大控件上复核。

现有四张粗 Frame 在新资产完成绑定并通过零依赖扫描前保留；不得边做边删。

## 实施步骤

### 1. 布局原型与合同冻结

1. 用纯 UXML / USS 调试色块实现标准和紧凑布局，不先生成正式 Frame。
2. 在 1280×720、1920×1080、2560×1440 测量工作台、四槽区、10×6 背包、右侧上下文和浮窗安全区。
3. 制作一张非生产 mockup，确认层级、密度、装备槽位置和边框粗细。
4. 冻结 Frame、槽位状态和装备暗纹资产合同，审批各族 Pilot。

### 2. 共享视图基础

1. 抽取 `ItemGridView`、方向焦点算法和 InstanceId 选择恢复。
2. 将 `ItemDetailView` 重构为唯一 `ItemTooltipView`，实现 anchor、翻转和夹紧。
3. 建立统一状态类和 Theme token，删除页面私有的重复稀有度、焦点与按钮规则。

### 3. 背包与装备重构

1. 为 `InventoryGrid` 增加精确放置、移动和单目标交换的纯逻辑预检与原子提交，并补齐失败不变式测试。
2. 为背包—装备、装备—背包和双戒指互换建立显式 Command / System 事务，保留既有按钮路径。
3. 保持 10×6 真实 Placement，迁移背包到共享工作台，并接入 Pointer drag 与拿起 / 放置状态机。
4. 用空间化四槽装备区替代纵向装备列表，接回装备 / 替换 / 卸下、戒指目标槽、比较和操作反馈。

## 测试与验收

### 纯逻辑 / EditMode

- 背包物品可精确移动到空位；越界、重叠多个物品和无效目标失败后 cells 与 Placements 完全不变。
- 背包内单目标交换仅在双方都能落入目标 / 来源区域时成功，并只产生一次完成态刷新。
- 背包装备到空槽、替换已装备物品、装备精确卸回背包和双戒指交换均保持原子性；任一步失败时背包、装备和属性效果同时回滚。
- 商人虚拟格子排布确定、无重叠、尊重物品尺寸，输入顺序相同则结果相同。
- 方向焦点对跨格物品、空洞、边界和跨区出口返回稳定结果。
- tooltip 在四个边缘、三档分辨率和长内容下正确翻转、夹紧。
- 刷新后按 InstanceId 恢复；实例消失后选择旧格子中心最近项。
- 所有生产 UI PNG 均为 Single，画布、Border、状态映射和审计合同一致。

### PlayMode

- 鼠标完成背包移动 / 交换、背包到装备、装备回指定背包格和双戒指互换；非法落点回弹且不改变领域状态。
- 键盘和手柄通过拿起 / 放置模式完成与鼠标相同的整理路径，并可取消后回到原焦点；既有按钮装备 / 卸下路径继续可用。
- 商店在玩家格子与商人格子之间移动焦点，完成购买、出售、金币刷新和邻近项恢复。
- 商店和打造上下文允许整理玩家背包，但拖到商人格子或打造操作区不会隐式购买、出售或打造。
- 打造从玩家格子选择物品，完成四项操作、词缀选择、金币刷新和焦点恢复。
- 鼠标悬停与手柄焦点只预览，Click / Submit 固定选择；关闭重开保留合理状态。
- 1280×720、1920×1080、2560×1440 下所有关键元素位于父容器内，操作按钮不重叠、不越框，长文本不覆盖相邻区域。
- 切页、关闭、重复进入和 Addressables 资源释放后 Console 为 0 error / 0 warning。

### 视觉验收

- 物品信息、装备、玩家背包、商人背包和打造上下文使用同一边框、槽位、字体层级和状态语言。
- 物品详情不固定挤占主列，也不遮挡当前焦点和主要操作。
- 四槽装备位置无需阅读文字即可辨认；不存在误导性的假槽位。
- Default、Focus、Selected、Dragging、DropValid、DropInvalid、Disabled 在灰度观察和键鼠 / 手柄两种输入下仍可区分。
- 九宫格边缘无角饰变形、接缝、重复纹理跳变或粗细不一致。

## 非目标

- 不新增头盔、手套、鞋、双手武器副槽等装备规则。
- 不实现物品旋转、自动整理、堆叠、重量、分页仓库或物品过滤；本阶段只支持玩家明确指定位置的手动整理。
- 不改变交易库存所有权、价格规则、回购、刷新和多商人状态。
- 不增加打造材料、配方、锁词缀、撤销或批量打造。
- 不在本阶段加入完整菜单过场、音效或战斗标签改进。
- 不照搬《流放之路》的具体美术资产、图标或布局比例，只借鉴装备槽空间语义。

## 风险与回退

- 共享工作台会改变现有 UXML 命名和测试查询路径。先保留旧页面到新工作台端到端通过，再一次性切换根模板。
- 商人虚拟格子不能反向写入 `EconomyModel`；若排布失败，仅回退到可滚动虚拟格子页，不回退成长列表。
- 当前 `InventoryGrid` 只有自动首空位写入。精确移动与装备替换必须先在纯逻辑层完成事务模拟并验证不变式，再接 UI；不得在拖拽 Controller 中用 Remove / Add 拼接临时状态。
- Pointer capture、菜单关闭、页面切换和快照刷新可能中断拖拽；统一取消入口必须释放 capture、销毁 ghost、清理样式并恢复焦点。
- tooltip 定位必须在布局完成后执行，并使用刷新代次取消陈旧回调，避免重建后跳到旧锚点。
- 正式 Frame 接入与功能重构分离提交；若视觉 Pilot 不通过，功能原型继续使用调试样式，不用旧粗 Frame 掩盖布局问题。
