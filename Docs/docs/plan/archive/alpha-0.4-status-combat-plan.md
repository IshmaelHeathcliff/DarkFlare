# 状态系统阶段 2：角色效果与战斗接入

所属总计划：[alpha 0.4 状态系统](../alpha-0.4-status-system-plan.md)。已实现合同见[状态模块](../../status-system.md)，完整目标见[规则](../status-system/rules.md)和[工程接入与验收](../status-system/integration-and-validation.md)。

2026-09-13：阶段 2 已完成并归档，EditMode 507/507、PlayMode 68/68 全部通过。以下代码核对表保留实施前问题与计划，实际合同见[状态战斗模块](../../status-combat.md)。运行版本仍为 0.4.0-alpha，自动时间、正式异常与存档 UI 不在本阶段交付范围。

## 目标与边界

让状态核心真正影响已配置的玩家和怪物：属性与装备 / 怪物词条共存，周期记录进入战斗结算，行动限制阻止新的移动、攻击和施法。状态变更、角色属性、资源比例、标签及通知必须一致，不能只在图标或查询中表现为“已生效”。

本阶段包含角色身份绑定、死亡 / 注销所必需的清理，以及伤害反馈和属性来源说明的适配。七种异常及异常抗性正式配置、来源玩法样例仍在阶段 3；Session 自动时间循环、保存恢复与图标 UI 仍在阶段 4。周期接入先通过显式推进和真实角色测试验证，不提前启用没有保存恢复保障的正式状态玩法。

不新增普攻体系、经验奖励或通用触发编辑器。具体异常数值、药水配置和掉落权重沿用既定阶段安排。

## 1. 角色绑定和基础生命周期

建议由 StatusSystem 的角色适配层维护 CombatActor 与 StatusTargetId 的映射，纯 StatusStore 继续只认识值身份。玩家使用 PlayerController.Id，怪物使用 MonsterController.Instance.Id，不能使用怪物基底 ActorId。

- OnEnable 的战斗登记可以早于配置完成；此时不制造临时怪物身份，不接受面向该角色的状态施加。Configure / Restore 配置完成后显式通知 System 绑定。
- 已有身份的对象重新启用时创建新的状态注册代次；同一次有效登记重复通知幂等。注销立即使映射失效，排队请求在执行前再次检查目标。
- 目标死亡后，在后续周期到达前撤销状态绑定和临时效果；保留基础属性、装备与怪物固有词条。复活重新绑定，有效持续提供方通过重新绑定接点恢复，旧控制和限时伤害不自动复活。
- 来源角色死亡 / 注销时，遍历该来源维持的贡献并释放；它已经施加的限时状态继续依靠来源快照运行。一次性释放可以先采用有界遍历，不先建立复杂索引系统。
- Session 结束清理角色映射和订阅。复用阶段 1 的代际、注册代次和队列规则；同基底怪物及复用对象不能串状态。

死亡 / 禁用清理属于本阶段战斗正确性的必要部分；阶段 4 再接统一自动计时、完整恢复顺序和保存策略。测试中的无控制器 CombatActor 使用显式测试身份绑定，生产代码不回退到名字或 Unity Instance ID。

## 2. 来源集合、属性与标签

角色持有按稳定来源键划分的修改器集合，提供替换某来源、移除某来源及批量重建。建议来源分为装备负载、怪物实例词条和状态有效组；来源键按种类与稳定身份排序，集合内部保留原修改器顺序，避免 Override 结果随字典顺序变化。

迁移所有正式 SetModifiers 调用点，包括换装、卸装、RestoreLoadout、装备注销与怪物 ApplyDefinition。旧入口如需保留兼容，只能表示独立的兼容来源；禁止继续表达“清除所有模块”。基础 StatBlock 永远从角色定义 / 怪物实例的基础数据开始，不能用带临时效果的最终属性反向重建。

状态只投影生效层：

| 模型 / 效果 | 聚合语义 |
| --- | --- |
| Uniform 的 Flat / Increase / More | 单层幅度乘有效层数后只提交一个对应修改器；三层 More 10% 为 More 30% |
| Uniform 的 Conversion / GainAsExtra | 按层数线性汇总幅度，继续走既有转换 / 额外伤害规则；校验数值溢出 |
| Override、行动限制、纯标记 | 不乘数值；Override 保留确定顺序，限制按位合并 |
| Strongest | 整体选取同一个有效候选的全部效果，不能拼接各层最优属性 |
| Independent | 保留每层修改器，各层 More 分别乘算；三层 More 10% 为 1.1³ |
| 周期伤害 | 沿用核心逐层周期记录，每跳只结算记录对应层；不能再乘组层数造成重复伤害 |

非伤害 GlobalActor 进入现有 StatAggregator / PrimaryAttributeResolver，伤害属性、Skill 和 TargetTaken 留在伤害管线。状态的寿命由 StatusStore 管理，Temporary 枚举不成为新的隐式计算通道。

状态标签按持有层派生，与角色静态标签合并；移除一个来源后，其他持有层仍提供同一标签。普通角色属性条件只读取当前角色上下文；需要技能、伤害包或目标的条件在对应伤害上下文解析，缺少上下文的配置明确校验，不能把所有域混成标签并集。状态是否生效不由自己增加的数值属性反复决定，避免属性重建循环。

每笔状态 / 装备变更从事务前资源比例计算最终资源，最多做一次属性重建和资源缩放。例如 50/100 生命增加到 200 上限后为 100/200，不能因逐层重建重复缩放。仅刷新时间、推进周期相位而有效参数不变时，不增加属性版本或重建。

ModifierOrigin 扩展来源种类、状态定义 / 层身份及有效层数，保留装备和词缀原说明。属性详情从正式聚合步骤生成状态来源解释；本阶段只适配数据与现有格式，不制作状态图标布局。

## 3. 一致提交与回调顺序

不能仅注册 StatusChangedEvent 后再补改角色属性：这会使其他观察者看到新状态和旧属性，也无法在属性计算失败时准确回退。

实施时为受管理目标建立一个内部效果参与接点，作用于 Apply / Consume / Dispel / ReleaseSource 和时钟到期变更：

1. 准备状态候选快照，再准备其有效修改器、标签、行动限制、最终属性和资源；预检非有限值、非法组合与溢出，准备不修改角色。
2. 提交前复核目标代次、状态版本和角色属性版本，同步提交状态与角色派生数据。失败精确恢复原状态、资源与版本；保留阶段 1 的延迟 Publish / Rollback 能力。
3. 全部数据就绪后，发布状态与资源通知。所有观察者读取到最终一致状态，通知处理中的新操作继续排队。
4. 周期记录由内部战斗接点结算后再向外发布观察事件；每跳完成并处理死亡 / 队列后，再推进下一事件。不能依赖外部订阅顺序保证战斗正确性。

纯核心通过不依赖 Unity 对象的接口接入参与者，未绑定角色的纯规则测试继续可用。正式角色入口统一走协调器，不能通过公开 Store 变更绕过角色投影；明确区分底层测试入口与游戏调用入口。

本阶段不实现跨多个角色、背包和资源的完整物品事务，但必须让单角色的状态及派生资源作为一个可准备 / 提交 / 回退的参与者，供后续 UseItemCommand 组合。

## 4. 周期伤害管线与归属

增加 DamageForm（Hit / Periodic），现有命中构造入口默认 Hit。HitOutcome 增加明确的 NotApplicable 表示周期不进行命中判定；IsHit 同时受 Form 限定，DidDealDamage 根据有效结算和正伤害判断。周期零伤害或无效目标也不能显示“未命中 / 闪避”。

提取并复用 DamageCalculator 的来源阶段和目标阶段：

- Base：在施加准备时读取来源属性、修改器和施加上下文，执行来源转换 / 额外伤害 / 增伤，冻结为 SourceResolved；周期不暴击。来源侧条件在施加时解析，包括其需要的施加目标标签。
- SourceResolved：每跳不再重复来源转换、固定伤害添加或增伤，仅按当前目标的 TargetTaken 和类型防御计算。来源后来换装、状态到期或离场不改变已冻结数值。
- 物理周期伤害跳过命中护甲；火焰、冰霜、闪电及混沌周期仍读取当次类型抗性。异常抗性的缩放接点保留给阶段 3，不能把类型抗性充当异常抗性。
- 不调用命中 / 闪避 / 暴击随机流，周期不会改变下一次普通攻击的随机序列，也不自动施加新的异常。

冻结来源上下文至少包含稳定来源身份、施加时阵营、技能 / 物品来源以及需要保留的标签。当前 StatusSource 没有阵营，不能在来源对象销毁后回头查找或默认为敌对；应补入独立伤害来源快照。没有角色的机制来源必须显式提供合法上下文，缺少时拒绝。

CombatSystem 提供明确的周期入口，并与命中共用生命变化、资源事件及“刚死亡”判断。DamageResolved / ActorDamaged 结果携带 Form，死亡通知携带稳定归属；现有只读 Actor 的消费者保持兼容。归属本阶段用于事件、日志与验证，不新增经验或任务奖励系统。

伤害提交前检查目标活跃、代次和阵营；已死亡目标不重复扣血或再次发布死亡 / 掉落。来源死亡后其已发出投射物、已冻结限时周期继续按原归属运行。LootSystem 保持现有生成规则，只消费一次死亡事件。

## 5. 行动许可与反馈

Query 返回角色当前 CanMove / CanAttack / CanCast / CanUseItem 及阻止来源；不存在、未就绪、死亡或已注销目标不能开始新战斗行为。只使用有效层的 BlockedActions，最强层接替后立即更新。

- 玩家 / 怪物移动在 FixedUpdate 读取 CanMove，受限时及时清零主动速度；眩晕不暂停其他状态、资源恢复或菜单操作。
- 当前投射物技能检查 CanCast；武器来源的投射物还检查 CanAttack。怪物接触攻击检查 CanAttack；不按伤害元素推导行动类型。
- FireProjectileCommand 在取随机种子、生成投射物和扣法力前再次校验，增加明确的受控失败结果。旧投射物命中与周期结算不重新检查来源行动许可。
- 接触攻击将许可、冷却判定、随机种子、攻击通知和伤害发起集中为一次命令编排；失败不更新接触冷却、不发送攻击动画通知。Controller 只发命令并接收结果。
- 自动施放沿现有调度检查许可，不积攒施放请求，解控后按后续调度恢复；直接调用最终命令也不能绕过限制。
- CanUseItem 独立于 CanCast；眩晕类控制样例只阻止 Move / Attack / Cast，后续净化物品可以按使用规则执行。

受击动画、闪白、命中特效和命中触发仅用于 Hit。Periodic 可显示普通伤害数字并更新血条，不显示暴击、闪避或未命中，不重复播放每跳受击动作。死亡反馈仍统一发生一次；没有必要的新美术资产不在此阶段生成。

## 实际交付说明

- 来源集合、统一 / 独立聚合、角色标签、状态来源解释和资源比例已接入。
- 状态和角色效果在 Publish 时一致公开；准备后资源变化或维持来源离场会拒绝发布。未发布期间双方均保留原值，Rollback 不反向施加效果。
- 周期共用来源与目标伤害阶段、资源及死亡提交；行动许可覆盖移动、施法和接触攻击，表现层区分 Hit / Periodic。
