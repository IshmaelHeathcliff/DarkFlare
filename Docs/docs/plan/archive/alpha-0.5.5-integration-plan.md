# Alpha 0.5.5：全范围综合交付

状态：2026-09-19，I1–I5 全部完成，交付 `0.5.5-alpha`；core v6、Schema 5、地图文档 V2。基线 `65429e0`，综合结果见 [I 验收](../../maps/acceptance/i/README.md)。本计划已归档。

## 目标与范围

将[总计划](alpha-0.5-plan.md)的编辑、数据、地表、对象表现、双地图与导航作为同一条交付链验证。复用 A–H 的实现与长期测试，只修复本阶段实际发现的缺陷；不新增玩法、地表种类、寻路策略或网络服务。

H 的 722 项 EditMode、85 项 PlayMode 和 500 / 1000 单位矩阵是已完成阶段的历史基线，不能代替最新提交的综合验收。G 的 Player 已验证交易、打造、冻结和跨进程继续，但当时还没有 H 的导航；I 必须在包含 H 的构建上串联这些行为。

## 采样与隔离合同

- 正式性能规模保持 500（480 Flow / 20 A*）和 1000（950 Flow / 50 A*）；10 秒预热、60 秒记录、三轮。500 / 1000 总帧 P95 ≤16.7 / 33.3 ms，导航主线程 ≤2 / 3 ms、提交关键路径 ≤4 / 8 ms、路径响应 ≤200 / 400 ms，导航原生内存 ≤128 MiB，稳态 0 B/tick 必须有有效正向探针。
- 使用相同固定种子、物理步、分辨率和画质，公布构建身份、后端、Burst、安全检查及全部轮次。性能采样期间不并行运行 Editor 测试或构建；保留失败轮次及修正原因。
- 临时 Player 使用独立产品数据根，历史档只从夹具复制。正式产品名保持 `DarkFlare`；生产包不带自动建档 / 压力采集入口。不读取、覆盖或删除真实玩家存档。
- 地图制作使用独立临时资产目录，不覆盖正式 `.dfmap`；通过 AssetDatabase / 编辑器接口操作导入资产、场景和资源，结束后删除自建临时资产。
- 采集输出放 `Docs/docs/maps/acceptance/i/`。一次性工具不进入长期测试程序集；图像证据区分 SceneView、Main Camera 和包含 UI 的整屏截图。

## 已知边界与处置

- H 的普通 Player GC 记录器不可用；零分配结论来自探针有效的 Development 测量，普通 Player 仅复核帧时间。
- H 的 20 轮切图曾与 Editor 工作并行，足以验证容量回归，不能作为独占机器时的切图耗时基线。I4 单独采集切图 / 保存耗时。
- G 的 1000 怪物 DTO 诊断曾观察到较大的临时托管分配；I4 按冻结、序列化、继续恢复分阶段记录存活量 / 观察峰值，只有实测影响预算或稳定性时才做针对性优化。
- Separation 为软避让；临时 stamp 离场清除；不将这两项误写成严格群体无重叠或持久化建造功能。
- Pipeline 缺少运行配置和 TMP 旧 shader pragma 属既有构建警告，复核是否仍出现并分类记录，不顺带升级包。
- 编辑器菜单已由 `65429e0` 收敛；需要重建的诊断样例从实际支持入口调用，文档不再指向已移除的历史一次性菜单。
