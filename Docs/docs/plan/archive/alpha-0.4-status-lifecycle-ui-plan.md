# 状态系统阶段 4：自动计时、存档与图标界面

## 状态与目标

2026-09-14：阶段 4 实现完成。交付唯一 Session 时钟、Schema 3 状态保存恢复、八个独立图标、玩家 / 怪物查看与键鼠手柄详情。长期回归 EditMode 534/534、PlayMode 72/72 通过；模块总结见[状态生命周期与 UI](../../status-lifecycle-ui.md)。运行版本保持 `0.4.0-alpha`、core v4。

本阶段让状态随游戏时间自动运行，保存并准确恢复玩家与怪物状态，并通过图标、层数、剩余时间和焦点浮窗向玩家解释效果。按 4A、4B 顺序实施；先完成时间与持久化，再接入界面。完整状态系统仍须通过总计划阶段 5 综合验收，之后才实施统一物品使用与消耗品。

依据：[状态核心](../../status-system.md)、[战斗接入](../../status-combat.md)、[异常与来源](../../status-ailments.md)、[本地存档](../../infrastructure/local-save.md)、[HUD](../../hud-system.md)、[工程接入与验收](../status-system/integration-and-validation.md)。本计划不调整已确认的异常抗性、叠层和刷新规则，不改变首批平衡数值。

## 4A：自动时间与持久化

### 单一时间驱动

- 在有效 Session 的 Running 生命周期启动唯一 UniTask；停止、切换 Session、销毁或初始化失败时统一取消。UI 和 Actor 不另行推进时钟。
- 采样实际经过的缩放游戏时间。暂停、平台挂起与非 Running 阶段不产生新时间，恢复后不补算现实时间差。
- `HasPendingTime` 时以 `Advance(0, budget)` 续算；期间新增的有效游戏时间由驱动累计，当前批完成后再提交。禁止直接丢弃积压或用固定帧数代替实际经过时间。
- 暂停不增加时间，但允许在保存准备过程中结清暂停前已接受的积压。每帧有事件预算，不能在主线程无限循环；取消和失败必须有明确退出结果。
- 保持既有同刻先跳伤再到期、刷新不重置周期、死亡与来源释放规则。跨 Session 回调必须验证代次。
- 调试窗口明确显示自动 / 手动模式、时钟及积压。手动推进仅在暂停并取得独占推进权、无未发布事务时可用；释放后自动驱动重置采样基点，避免重复计时。

### 保存合同

Schema 升为 3，保留历史 0 → 1 → 2 迁移并追加 2 → 3 的空状态迁移。历史无状态存档继续可用；运行版本在完整状态验收后再升级。内容版本只在实际目录内容变化时按现有迁移规则处理。

保存玩家及存活怪物的状态，DTO 使用稳定定义 ID、角色键和纯数值，不序列化 Unity 对象、旧 Session 代次、图标路径或现实到期时间。至少覆盖：

- 定义与冻结规则、来源类型及稳定键、来源角色归属、状态层身份及确定性排序。
- 各层冻结效果、修改器及标签、伤害来源快照、抵抗前后数据和原始持续时间。
- 剩余时长、周期相位和跳数；保留足够的施加时间偏移信息，使下一跳及后续周期不因多次保存发生漂移。
- 持有层与候选顺序；生效层由同一规则重新推导，不保存第二套可冲突的结果。

保存准备先停止接收新时间并分帧结清已累计时间、排队操作；到无推进、无通知、无未发布事务的边界，同步捕获状态与资源，再恢复驱动。回调内或忙碌时发起保存，应交给协调器可取消地延后重试，不递归推进或捕获半提交快照。保存失败不能破坏当前 Session。

接入现有 dirty revision：施加、消费、驱散、到期与伤害等提交及时标脏；有活动计时状态时，自然经过时间也必须使下一次保存获取新快照，但不因此每帧触发磁盘写入。退出 Flush 必须包含最新剩余时间与周期相位。

### 恢复与来源所有权

1. `SaveRestorePreparer` 在分离数据图中验证定义、规则组合、数值、容量、重复身份、层数、相位和来源关系；沿用文件大小 / 深度限制，新增状态总量及逐角色容量校验。未知定义、非法所有权或未来 Schema 明确拒绝，不部分恢复。
2. 创建玩家与怪物，建立稳定角色键到新注册身份的完整映射。保留存档中的确定性事件顺序，不能依赖恢复时字典遍历或角色创建顺序。
3. 恢复装备等属性来源，再导入状态，统一建立最终属性投影。专用导入只用于已验证的恢复事务，不调用普通施加路径，不触发首跳、施加奖励或新的随机数消耗。
4. 以存档绝对值恢复生命 / 魔力并校验最终上限；避免先按比例恢复、状态投影后又缩放一次。死亡玩家沿用死亡清理合同；随后复活重新绑定。
5. 全部成功后才发布恢复完成、进入 Running 并启动时钟；任何失败由 Session 恢复事务整体回滚。

来源恢复采用明确分工：装备提供的 SourceOwned 状态由已恢复装备权威重建，导入阶段按物品实例与定义键去重，不再次叠加。其他 SourceOwned 必须有可验证的恢复提供方；本阶段补充最小提供方恢复合同及测试，不建设完整天赋或光环模块。无恢复提供方的临时调试来源在保存预检明确报错，不能静默丢弃。Timed / Infinite 层按已验证记录恢复。

已死亡或离场来源留下的限时 DoT 仍可恢复：保留其不可变伤害归属，不能强求来源 Actor 仍然存在。仍在场的来源映射到新 Session 身份，旧代次不能获得操作新角色的权限。

## 4B：图标、详情与输入

### 只读展示

- 玩家 HUD 上方新增状态条，每种定义一个图标。角标显示持有层数；最强候选并存时，详情另列实际生效层数及候选状态。
- Shared 显示共享剩余时间；PerLayer 显示下一层到期时间，浮窗逐层列出来源、抵抗后数值、生效情况和剩余时间。来源维持 / 无限状态显示对应文字，不显示虚假的倒计时。
- 名称、类别、描述、层数、时间单位和来源说明均使用 Localization；动态效果读取实际快照，不能用固定描述数值冒充抵抗后的效果。
- 通过 Query 获取专用展示快照，Controller 只注册事件并刷新节点；低频刷新倒计时，复用图标节点，UI 不推进状态也不直接修改 Model。

### 焦点与怪物查看

- 鼠标悬停和键盘 / 手柄焦点打开同一详情；浮窗贴近图标并约束在可见区域内。状态消失、目标失效或面板关闭立即清除旧详情，焦点转移到相邻状态或查看入口。
- 在现有菜单加入“状态”查看入口，支持玩家状态和当前存活怪物的只读选择列表。怪物用本地化名称及稳定区分标识显示，默认玩家；不新增战斗锁定系统，也不要求所有怪物头顶显示完整状态条。
- 键鼠和手柄通过同一菜单入口选择角色、导航图标、查看详情和返回；目标死亡 / 离场时退回玩家或安全入口。列表排序稳定，不在刷新时跳动抢焦点。
- Gameplay 保持 Point / Click，不启用 Navigate 抢移动；菜单查看时使用现有导航上下文，Back 按既有窗口规则返回。暂停菜单也应可进入只读状态查看，不释放其暂停租约。
- 覆盖输入重绑定、设备切换、暂停查看和连续 Session 重绑。减少动态效果设置下不依赖动画传达状态。

### 正式美术与资源

首批交付七异常与 `equipment_guard` 共八个独立图标。实施时应用 `unity-2d-sprite-workflow`，先确定固定画布、有效内容边界、PPU、Pivot 和家族规格，再生成每图一个 PNG，自动审计后以 Sprite Mode Single 导入；不能使用生产组件图集手工切片。

使用 Unity MCP 创建和验证 UI 布局，复用 PanelRenderer、共享皮肤和焦点样式。图标经 Addressables / Resource Service 加载，由 Session 的界面作用域持有并取消、释放。缺失图标仍须保留文本信息与可导航节点；首批正式配置不能以占位图通过最终验收。

## 执行顺序与验收

| 顺序 | 交付 | 关键验收 |
| --- | --- | --- |
| 1 | Session 时间驱动及调试独占模式 | 自动到期 / 跳伤；暂停、挂起、取消；预算积压分帧与一次推进结果一致；重复绑定只有一个驱动 |
| 2 | Schema 3、捕获边界与专用导入 | 同时存在多来源、多强度状态时保存恢复一致；剩余时间、下一跳、同刻顺序无变化；不重复抵抗或投影 |
| 3 | 来源、资源与失败回滚 | 装备维持来源不翻倍；失效来源的限时 DoT 延续；生命 / 魔力上限先恢复；坏档、取消和忙碌边界安全 |
| 4 | 展示快照、图标及 UI | 七异常和装备状态可见；真实层数 / 数值；键鼠手柄同等可达；图标消失后的焦点与资源释放正确 |
| 5 | 回归与文档收尾 | 中英 / Pseudo、暂停 / 重绑定、连续 Session 与可见 Player 检查；更新模块与验收记录，归档本阶段计划 |

优先补充既有状态、存档迁移、Session 生命周期、HUD 与输入测试，保留行为与玩家数据隔离覆盖。至少包含独立 DoT 不同相位、最强层到期后候选接替、100% 异常抗性读档、暂停积压保存、连续保存恢复不漂移、恢复失败清理、焦点状态被驱散等回归。沿用历史存档夹具并新增真实 Schema 2 迁移覆盖，不以固定文件数或版本字符串代替行为验证。

4A 完成后先跑受影响 EditMode / PlayMode；4B 完成后编译、项目全量 EditMode / PlayMode 和可见 UI 验收。截图覆盖 1920×1080 中英 / Pseudo 与一个较小窗口，检查溢出、浮窗边界及导航；证据放入 `Docs/docs/assets/acceptance/alpha-0.4-status-lifecycle-ui/`。临时截图工具验证后清理。

收尾同步状态、存档、HUD、输入和资源模块文档，归档本计划并更新总计划与索引；不在计划阶段提前修改运行版本或宣告测试通过。阶段 5 综合验收通过后，进入已规划的统一物品使用与消耗品阶段。
