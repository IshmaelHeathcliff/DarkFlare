# 消耗品阶段 1：统一使用核心与复合事务

2026-09-15：已完成并归档。承接[统一物品使用总计划](alpha-0.4-usable-items-plan.md)。基线提交 `26509e3`，运行版本 `0.4.1-alpha`、core v4、Schema 3；最近 EditMode 540/540、PlayMode 73/73，状态综合验收已完成。

## 本阶段目标

提供可以通过同一 Command 使用背包内指定物品的核心闭环，支持恢复生命、恢复法力、临时状态、异常驱散及组合效果。成功时效果与扣除同时可见；失败或全部无变化时不扣物品。用受控配置和真实 Session 回归验证，为正式药水及背包交互提供可直接调用的接口。

本阶段不加入正式商品、图标、背包使用按钮或快捷栏。后续阶段完成内容与 UI，再做整体 Player 验收并交付 `0.4.2-alpha`。本阶段保持版本、core 与 Schema 不变，不把核心完成描述为消耗品已可玩。

## 代码核对与改动边界

| 现有接点 | 实施要求 |
| --- | --- |
| `ItemBaseDefinition`、`ItemInstance.Quantity` | 添加可选使用能力；不以 `IsConsumable` 或物品类型推断可主动使用 |
| `InventoryModel.TryConsumeWithoutEvents` | 当前按定义跨堆消费；另加指定实例的准备与扣除接点，保留金币 / 打造原语义 |
| `CombatSystem.ApplyHealing` / `RestoreMana` | 当前立即写资源并通知；提取可复用的候选计算和延迟通知接点 |
| `StatusStore.Prepare / Commit`、`StatusCombatBinding.Projection` | Publish 再检查资源及属性；不能先回血，再让旧状态投影覆盖资源或拒绝发布 |
| `GetActorActionsQuery.CanUseItem` | 已与 CanCast 独立，直接复用；保留独立 UseItem 阻止规则 |
| Session 生命周期与架构注册 | System 随 Session 注册 / 释放；旧角色、旧准备结果和重入请求均需校验 |
| `ItemActionRouter` | 本阶段只明确后续 Use 接点，不提前改变商店 / 打造快捷动作 |

重点修改范围为 Data/Items、Gameplay/Inventory、Combat 的资源准备接点、Statuses 的投影协调接点及现有架构注册。避免新增通用事务框架，避免让状态核心直接依赖背包或具体药水。

## 配置与请求合同

- `ItemBaseDefinition` 可选引用 `ItemUseDefinition`，配置每次扣除数量及有序效果列表；采用项目现有 ScriptableObject / Odin 中文字段规范，复用内容目录的引用校验。
- 首期仅对使用者自身生效，请求仍携带有效 Session、使用者 / 目标身份、选定物品身份与一次操作身份。Query 返回实际预计效果、消费量及结构化失败原因，不预先保留物品或改变资源。
- 恢复支持有限非负固定量或最大值百分比；非法引用、非有限数值、溢出及非法数量整次拒绝。正消费量必须满足 IsConsumable，非消耗型能力允许扣除量 0。
- 从玩家实际背包确认实例归属、当前位置及数量；商人、地面、装备槽、外部角色和已移除实例不能被该入口使用。失败不回退到其他同基底堆叠。
- 暂停查看背包时允许即时使用，状态按游戏时间推进；Shell 接管、恢复和退出期间拒绝使用。存活目标且 CanUseItem 为真才接受；眩晕仅封锁移动 / 攻击 / 施法时仍可净化，显式 UseItem 封锁则拒绝，本阶段不增加绕过该封锁的特权。

## 事务与效果顺序

1. 冻结请求及配置值，校验归属、目标与许可；捕获背包位置 / 数量、状态版本 / 时间及角色属性 / 资源的一致性依据。当前背包无统一版本，不假设已有版本字段；优先使用完整相关快照，若需要版本则覆盖全部相关写路径。
2. 按配置顺序在候选上下文模拟四类效果。状态施加 / 驱散复用既有规则，属性上限变化沿用现有资源比例规则；恢复按执行到该项时的候选上限计算并裁剪。例如“增加最大生命 → 按百分比恢复”与相反顺序可有不同结果，预览与提交必须一致。
3. 同一使用操作的来源属性与身份在开始时冻结，后续效果不意外重复捕获同次增益。临时状态使用稳定物品 / 操作来源及独立时长，末件消失不能撤销已经提交的状态。
4. 在通知之前复核所有一致性依据，统一落实资源、状态投影和精确物品扣除。扩展现有状态投影协调能力，使外部候选资源与状态候选共同提交；不通过放宽旧版本检查来掩盖冲突，也不让 Query 看到半笔操作。
5. 发布之前失败时，精确恢复本事务的层、属性、资源、周期相位、数量、身份和位置；保留导致旧版本失效的合法外部变化。未发布回执释放时自动回退。提交与回退区间不跨异步等待。
6. 成功后才统一通知资源、状态、背包变化和一次 ItemUsedEvent。首个通知的订阅者即可读取全部最终结果；状态通知排队写入和物品回调重入不能穿入半提交阶段。发布后不因订阅者异常重放效果或补偿已公开结果，异常处理遵循已有事件机制。

合法但无变化的单项允许与其他有效项组合；全部无变化时返回 NoChange 且不扣物品。有效状态刷新算变化，驱散只处理可驱散的匹配异常。组合物品整次只扣配置数量一次。

准备回执只允许提交一次；同一操作身份重试不再次恢复或扣除，新操作可再次使用。去重记录限定在当前 Session 并明确有界生命周期；已淘汰或旧代际操作不能被当作新操作重放，不建立跨存档的永久操作账本。

## 执行顺序

1. 落实使用能力、请求 / 结果与 Query / Command；确定候选上下文及四类效果的顺序合同。
2. 完成精确实例消费和资源候选计算，接通状态投影协调与一致提交，先跑组合失败 / 回退和首个事件观察最终结果的测试。
3. 接入 Session、行动许可、暂停、来源快照与重入保护，用核心 Command 验证四类效果和组合使用。
4. 扩展长期回归，审查新增测试和配置校验；运行项目 EditMode / PlayMode 全量，记录实际结果，不固化测试数量。
5. 新建统一物品使用模块说明，写明真实 API、顺序与回退边界；更新总计划，将本阶段归档，继续规划正式内容与背包交互。

## 验收标准

| 合同 | 必须验证的行为 |
| --- | --- |
| 使用能力 | 可消耗但不可用、可用但不消耗、不可堆叠消耗品；缺配置拒绝 |
| 精确扣除 | 只扣选中堆、末件移除、余量保留原身份位置；不足和所有权错误无副作用 |
| 组合效果 | 回血 + 回蓝、恢复 + 状态、恢复 + 驱散；上限变化的不同配置顺序与 Query 一致 |
| 无变化与失败 | 全满无变化不扣；部分无变化仍可成功；后一项失败不遗留前项效果 |
| 状态合同 | 延续刷新、层数、抗性、驱散保护及来源快照；末件消失后临时状态继续存在 |
| 原子性 | 旧资源 / 状态 / 物品准备失效不覆盖外部变化；发布前失败精确回退；首个事件已见全部最终状态 |
| 重入与生命周期 | 重复操作只成功一次；通知重入安全；暂停可用、退出拒绝、新 Session 不接受旧请求 |
| 存档联动 | 使用后数量与状态共同往返；恢复不再次治疗；旧物品缺省能力仍保持不可主动使用 |

优先扩展 InventoryGrid、StatusCombatIntegration、状态 / 存档 PlayMode 等现有套件；独立的跨模块使用合同可集中到按模块命名的 ItemUseTests，不为每个药水或本版本建立重复套件。调试入口只报告结构化预检 / 结果，不保留临时截图或迁移核验测试。

## 完成记录

四类效果、候选顺序、精确扣除、资源 / 状态一致提交、Session 门禁与去重已实现。新增 22 项 ItemUseTests，并扩展既有内容身份及真实 Session 保存恢复回归；最终 EditMode 562/562、PlayMode 73/73，零失败 / 跳过。模块说明见[统一物品使用](../../item-use-system.md)，证据见[阶段验收](../../assets/acceptance/alpha-0.4-item-use-core/README.md)。无正式商品或 UI 变更，版本、core 与 Schema 保持基线。

实现采用有界的 Session 单调操作号：较新请求成功后旧号全部失效；未发布阶段仅候选状态暂存，物品和资源在最终 Apply 才同步写入。新增配置按项目合同登记 item_use 身份和字段参考；完全抵抗视为单项无变化。上述实际接口与边界以模块文档为准。
