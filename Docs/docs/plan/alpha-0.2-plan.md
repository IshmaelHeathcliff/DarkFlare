## 版本定位

`alpha 0.2` 不以扩充战斗、物品或地图内容为目标，而是把当前单场景功能原型改造成可持续迭代的游戏运行基础。存档与本地化是本版本的两条主交付线；应用生命周期、稳定身份、数据迁移、用户设置、场景流、错误处理和资源治理共同保证后续玩法能够遵守统一规范，而不是继续把基础行为散落在场景脚本中。

本版本完成后，后续玩法模块必须能够回答以下问题：

- 状态由谁拥有、何时创建、何时释放。
- 哪些数据需要持久化，使用什么稳定身份和版本迁移。
- 玩家可见文本从哪里取得，如何切换语言和处理缺失内容。
- 场景、输入、时间、资源、日志和异步任务通过哪个唯一入口使用。
- 新代码违反基础设施规范时，由哪项本地自动测试或验证器发现。

## 当前基线与主要缺口

- 当前只有 `Main.unity`，没有启动场景、游戏状态机、统一加载流程或失败恢复页。
- `alpha 0.2.0` 已建立场景加载前的唯一 `ApplicationHost`、Application / Profile / Session / Scene / Component 作用域及 `GameArchitectureProvider` 独占入口；当前单场景兼容请求采用 latest-wins，场景预置组件只绑定同场景且已 Running 的有效 Session，完整游戏状态机与通用 SceneFlow 仍未建立。
- `CombatPrototypeBootstrap` 已收缩为场景配置与宿主请求入口；新游戏与恢复分别由可回滚的 `NewGameSessionInitializer` 和 `RestoreGameSessionInitializer` 执行。
- `alpha 0.2.1` 建立的纯 DTO、分离对象图 Mapper、版本合同和迁移管线已在 `alpha 0.2.2` 接入确定性 JSON、`Application.persistentDataPath` 代际存储、损坏回退和退出 Flush；`Assets/Data/Saves` 继续不存放正式玩家数据。
- 背包、装备、经济和物品实例仍可在玩法内使用对象引用，持久化边界统一转换为 ContentId 与强类型实例 ID；`auto` 保存和 Restore Session 已有真实菜单消费者。
- Application 级唯一内容目录 `core` v1 已收录 90 个正式配置，并由配置验证器冻结零空值、零重复、零遗漏。
- Unity Localization `1.5.12` 已安装，但没有 Locale、String Table、运行时语言服务或玩家可见文本迁移。
- 用户设置、输入重绑定、按键图标、音频服务、全局异常处理和结构化日志尚未建立。
- Addressables 已用于 Prefab 和 Sprite 加载，Prefab GUID 单飞与精确句柄释放已有自动验证；当前内容主要位于本地默认组，仍缺少完整分组、标签和跨加载器治理。
- 运行时代码仍存在直接 `Debug.Log*` 调用，可见字符串规则尚未启用；直接业务文件 IO、`PlayerPrefs` 和散落场景加载已由 `alpha 0.2.0` 策略测试冻结。

## alpha 0.2.0：应用宿主、作用域与规范验证

当前实现与使用边界见[应用生命周期与会话作用域](../infrastructure/application-lifecycle.md)；现状审计、冻结决策、执行切片、实际偏差和验收证据见[归档执行计划](./archive/alpha-0.2.0-application-lifecycle-plan.md)。

### 目标

建立唯一应用入口和可验证的生命周期，使基础设施不再依赖 `Main.unity` 中脚本的偶然执行顺序，并先用本地自动测试冻结新增代码的使用边界。

### 范围

- 建立唯一 `AppHost` / Composition Root，负责应用级服务注册、启动、关闭和根取消令牌。
- 明确 `Application`、`Profile`、`Session`、`Scene` 四级作用域及所有权；任何常驻对象必须声明所属作用域。
- 统一 `GameArchitecture.Interface.Init()` 与 `Deinit()` 的调用位置，保证重复启动、退出和测试清理幂等。
- 将当前 Bootstrap 拆分为资源预热、创建新游戏、恢复存档、场景绑定和摄像机绑定，不允许新游戏发放逻辑在读档后再次执行。
- 建立 `Booting`、`Ready`、`ShuttingDown`、`Failed` 等技术状态和结构化失败结果。
- 所有长期 UniTask 由作用域拥有并统一取消；禁止不可追踪的后台任务。
- 新增首批基础设施策略测试和临时债务白名单；白名单必须记录移除阶段，不能无限扩张。
- 建立模块文档模板，至少包含职责、依赖、生命周期、线程、错误、配置、测试和禁止事项。

### 成功标准

- 连续执行新游戏 → 退出会话 → 再次新游戏，不重复注册 Model、事件、输入或 Addressables 句柄。
- 应用关闭或测试 TearDown 后，架构、输入和异步任务均已释放，Console 无新增异常。
- 新游戏与读档入口互斥，且不会重复发放初始武器、金币或商人库存。
- 新增直接文件 IO、`PlayerPrefs`、场景加载等本阶段已启用规则的违规代码时，本地策略测试能够失败；日志规则留在 `alpha 0.2.6` 启用。
- `Main.unity` 不再决定应用服务的初始化顺序。

### 完成记录

- `ApplicationBootstrap` 已在 `BeforeSceneLoad` 创建唯一 `ApplicationHost`；`GameArchitectureProvider` 是架构的唯一正式所有者，并以所有者 lease 与单调 generation 隔离连续 Session。
- NewGame 初始化、取消和失败回滚已经事务化；当前场景卸载、直接重载与快速重复请求由 latest-wins 协调器处理，场景预置组件通过 `SceneSessionBinding` 等待有效 Running Session。
- 长期任务已纳入只跟踪活动任务的作用域 TaskGroup；默认停止时限为 10 秒，`Abandoned` 为不可逆终态并向祖先粘性传播，污染作用域拒绝新任务、子作用域和场景组件重绑。迟到 continuation 不得改写状态、回调新作用域或访问下一代架构。
- Prefab Addressables GUID 单飞、精确句柄释放、保存原始所有者的 `SessionObjectRegistry` 注销与首批策略扫描已经落地。
- 最终验证为 Unity 编译 0 error、EditMode `255/255`、项目自有 PlayMode `45/45`；PlayMode 完整运行 `49` 项中 `47` 项通过、`0` 失败，另有 `2` 项 Input System 包集成测试因上游 issue 1252825 跳过。最终修复后两次真实 Play / 退出均达到 Application `Ready`、Session `Running`、有效 lease、宿主 / 玩家 / 已提交刷怪器各 `1` 个，退出 Console Error 为 0。
- 本阶段未实现存档、本地化或 `alpha 0.2.4` 的完整 SceneFlow。

## alpha 0.2.1：稳定身份、内容目录与迁移框架

当前实现与使用边界见[稳定身份、内容目录与迁移框架](../infrastructure/content-identity-migration.md)；审计基线、冻结决策、执行切片和验收证据见[归档执行计划](./archive/alpha-0.2.1-content-identity-migration-plan.md)。

### 目标

让所有持久化数据只依赖稳定业务身份，并为配置、设置和存档的版本演进提供同一套可测试迁移机制。

### 范围

- 冻结内容稳定 ID 规则、大小写和命名空间；ID 不使用文件路径、Asset GUID、显示名称或运行时 Instance ID。
- 建立按内容类型查询的只读内容目录，将稳定 ID 映射到 ScriptableObject 配置，并检测重复、空值和类型冲突。
- 为玩家、物品实例、怪物实例、世界掉落和存档槽位定义各自的实例 ID 语义。
- 将背包格子、装备槽、经济库存和 Actor 所有权从对象引用转换为可映射的 ID / DTO 边界。
- 区分 `GameVersion`、`ContentVersion`、`SaveSchemaVersion` 和 `SettingsSchemaVersion`。
- 建立按版本逐级执行、可重复测试且失败不修改原文件的迁移 Pipeline。
- 为删除或缺失内容定义恢复策略：阻止加载、替代占位、跳过条目或回滚备份必须由数据类型明确选择。
- 内容验证器覆盖所有可持久化配置及其 ID，新增配置类型时自动要求注册。

### 成功标准

- 保存 DTO 中不存在 `UnityEngine.Object`、场景对象、资源路径、Asset GUID 或运行时引用。
- 正式内容稳定 ID 全局符合规则，同类型零重复、零空值；无效引用能在进入运行时前被验证器发现。
- 旧版本样本只能按已登记迁移链升级，不允许在业务加载器里散落版本 `if` 分支。
- 相同 DTO 经映射到运行时再映射回 DTO 后，持久字段保持等价。
- 内容被删除或改名时，加载结果可解释、可测试且不会静默生成错误状态。

### 完成记录

- 已登记 12 个内容命名空间；唯一目录 `core` v1 收录 90 个正式配置，配置验证达到非法 ID 0、重复 0、空 ID 0、遗漏 0、未登记类型 0。
- 已接入 Profile 物品 ID 生成器与 Session Run ID 生成器，玩法中的物品、怪物和世界掉落使用各自强类型身份。
- 已建立物品、背包、装备、商人和 Actor 纯 DTO，以及提交前验证完整引用闭包的 `RuntimeStateMapper`。
- 已建立四类版本值对象和只接受唯一完整 `N → N+1` 链的内存 JSON 迁移管线。
- 最终验证为 Unity 编译 0 error、EditMode `287/287`、项目自有 PlayMode `45/45`；PlayMode 完整运行 49 项中 47 项通过、0 失败，2 项 Input System 包测试因上游 issue 1252825 跳过。
- 本阶段未实现文件存储、正式序列化封装、备份、存档槽位或 Restore Session。

## alpha 0.2.2：本地存档闭环

当前实现与使用边界见[本地存档与 Session 恢复](../infrastructure/local-save.md)；冻结的数据合同、代际存储方案、生命周期顺序、实际偏差和验收证据见[归档执行计划](./archive/alpha-0.2.2-local-save-plan.md)。

### 目标

提供可恢复、可迁移且错误可定位的本地存档，并让当前最小循环能够真正“保存 → 重启会话 → 继续”。

### 数据边界

- `UserSettingsData`：语言、音频、输入、显示和可访问性；独立于游戏存档加载。
- `ProfileSaveData`：玩家长期持有的物品、背包位置、装备、金币及后续档案级状态。
- `RunSaveData`：玩家位置与资源、随机通道状态、刷怪进度、存活怪物、世界掉落、商人运行时库存和必要计时器。
- `SaveSlotMetadata`：槽位 ID、显示摘要、创建 / 更新时间、版本、校验值和恢复来源。
- 临时 UI 焦点、动画、在途投射物、特效和纯缓存不持久化；恢复后由当前状态重建。

### 范围

- 存储根目录使用 `Application.persistentDataPath`，不得写入 `Assets/Data/Saves`。
- 建立 Serializer、Storage、Snapshot、Restore、Migration 和 Save Coordinator 分层，领域模块不直接操作文件。
- 快照在主线程取得，纯 DTO 序列化和文件 IO 可转入后台；同一槽位使用单写者队列，防止交错覆盖。
- 写入采用临时文件、完整性校验、原子替换和有限备份；启动时能恢复中断写入或回退上一有效版本。
- 存档包含明确 Header：格式标识、Schema、游戏 / 内容版本、槽位、时间和校验信息。
- 支持多槽位的存储接口；本版本至少提供一个自动槽位和可测试的继续 / 新游戏流程，不要求完整手动槽位 UI。
- 使用 Dirty 标记和集中检查点保存；暂停、显式退出、关键事务完成和平台挂起可请求保存，不允许每个事件直接写盘。
- 存档过程中禁止修改已捕获 DTO；退出阶段设置有界 Flush，并记录未完成结果。
- 提供损坏、空间不足、无权限、迁移失败、内容缺失和并发请求的结构化错误及玩家可理解反馈。
- 测试使用临时目录和固定夹具，不读取或覆盖开发者真实存档。

### 成功标准

- 玩家拾取并装备物品、改变金币和生命、推进刷怪后保存，重建 Session 并读档，持久字段保持一致且不重复发放初始资源。
- 固定种子的随机通道、怪物 / 物品实例和世界掉落在恢复后继续可复现，不仅保存根种子。
- 模拟写入中断、主文件损坏和最新备份损坏时，系统按契约恢复或安全拒绝，不产生半加载状态。
- 旧 Schema 样本迁移成功，新 Schema 未知版本被安全拒绝，原文件始终可恢复。
- 连续快速触发保存不会并行写同一槽位，退出 Flush 有明确成功、超时或失败结果。

### 完成记录

- 已冻结 `darkflare-save` V1 / Save Schema 1，完整保存 Profile、物品关系图、四槽装备、金币、玩家状态、随机通道、实例序号、刷怪进度、存活怪物、世界掉落和商人库存。
- `NewtonsoftSaveSerializer` 生成确定性 UTF-8 JSON 与 Payload SHA-256；`LocalSaveStorage` 使用同目录临时文件、严格递增提交代际、读后验证和两份有效代际保留，当前损坏可回退 Backup。
- Profile 级 `SaveCoordinator` 实现 generation-bound 快照、Dirty revision、单写者与密集请求合并；`SessionSaveFacade` 为菜单提供 `auto` 保存、继续和不覆盖旧档的新游戏入口。
- `ApplicationHost` 已接入 Restore Session、退出前 5 秒有界 Flush 和桌面 quit gate；预检失败不停止当前 Session，Restore 失败沿用初始化事务回滚。
- 最终验证为 Unity 编译 0 error、EditMode `310/310`、项目自有 PlayMode `48/48`；PlayMode 完整运行 52 项中 50 项通过、0 失败，2 项 Input System 包测试因上游 issue 1252825 跳过。两次真实 Play / 退出回到唯一宿主、Running Session、玩家和菜单绑定基线，最终 Console Error 为 0。
- 本阶段未实现 Settings、Locale、手动槽位 / Profile UI、云同步或完整 SceneFlow；这些边界分别由后续阶段处理。

## alpha 0.2.3：用户设置与本地化

冻结的数据合同、启动顺序、文本迁移范围、实施切片和验收矩阵见[独立执行计划](./alpha-0.2.3-settings-localization-plan.md)。

### 目标

让语言和其他用户偏好在任何玩家 UI 创建前生效，并移除运行时玩家可见硬编码文本。

### 范围

- 建立独立 Settings Service、默认值、合法范围、迁移、原子保存和变更事件。
- 设置至少覆盖语言、主 / 音乐 / 音效音量、输入绑定、输入图标偏好、基础显示项和本版本接入的可访问性项。
- 设置在 Profile 和 Session 之前加载；设置损坏时回退默认值并保留有限损坏副本。
- 基于 Unity Localization 建立 `zh-Hans`、`en` 和仅用于测试的 Pseudo Locale。
- String Table 按 `ui`、`items`、`stats`、`affixes`、`monsters`、`system` 等职责拆分，禁止建立无边界的单一总表。
- 本地化 Key 与内容稳定 ID 分离；Key 重命名视为迁移，显示文本变化不影响存档身份。
- 数值、百分比、时间、货币和复数使用文化感知格式或 Smart String，不拼接假定语序的句子。
- 建立字体与 fallback 链，覆盖简体中文、英文、数字和项目所需符号。
- 将当前所有玩家可见的 C#、UXML 和配置显示文本纳入清单并迁移；日志、内部 ID、测试名不本地化。
- 提供缺失 Key、空翻译、孤儿 Key、非法表引用和可见硬编码文本扫描。
- 语言切换在运行时即时刷新 UI，保留当前页面与输入焦点。

### 成功标准

- 首次启动按系统语言或默认设置选择语言，之后优先使用已保存偏好；不会先显示一种语言再闪切。
- `zh-Hans` 与 `en` 可在运行时往返切换，HUD、菜单、物品、属性、词条、商店、打造和系统错误同步更新。
- Pseudo Locale 与长文本检查在目标分辨率下无关键按钮截断、遮挡或不可操作。
- 正式表中零缺失、零空翻译、零重复 Key；新增玩家可见硬编码文本会触发自动检查失败。
- 字体回退不会产生缺字方框，格式化结果符合当前 Locale。

## alpha 0.2.4：游戏状态、场景流与 UI 外壳

### 目标

建立可取消、可失败恢复的启动和场景流，使新游戏、继续游戏、加载、暂停和返回形成统一技术路径。

### 范围

- 建立应用启动场景 / 入口和唯一 Scene Flow Service；具体场景拓扑在阶段执行计划中通过最小原型冻结。
- 状态至少覆盖 `Boot`、`FrontEnd`、`Loading`、`InGame`、`Paused`、`Recovering` 和 `FatalError`。
- 所有场景加载、卸载、激活和进度反馈通过统一服务；业务代码不得直接调用 `SceneManager`。
- 加载事务组合设置、本地化、存档元数据、Addressables 预热、场景加载、Session 创建和失败回滚。
- 建立 Loading UI，支持真实进度阶段、取消条件、超时、重试和安全返回，不伪造百分比。
- 建立 UI Page / Modal / Toast / Busy Overlay 外壳、焦点栈和输入模式协调，供存档错误、本地化和后续页面复用。
- 暂停统一通过 Time / Pause Service，不允许其他模块直接写 `Time.timeScale`。
- 场景退出先阻止新事务，再取消场景任务、保存、释放场景资源，最后卸载。

### 成功标准

- 冷启动、新游戏、继续游戏、读档失败重试和返回前台均通过同一状态机完成。
- 快速重复提交或取消加载不会产生双场景、双玩家、重复输入或悬挂任务。
- 任一步骤失败都能回滚到可交互状态，错误包含阶段、原因和可用恢复动作。
- Page / Modal 的打开关闭保持手柄与键鼠焦点，Modal 阻止底层输入，Toast 不抢占焦点。
- 项目运行时代码除 Scene Flow 实现外不存在直接场景加载调用。

## alpha 0.2.5：输入、音频、可访问性与平台生命周期

### 目标

让输入和音频成为可保存、可替换的正式服务，并补齐应用失焦、挂起、恢复和退出行为。

### 范围

- 在现有 `GameInput` 上建立重绑定服务，支持键鼠 / 手柄、冲突检测、恢复默认和持久化覆盖。
- 建立输入设备族与 Glyph Resolver，交互提示不再硬编码键名；设备切换只改变显示，不改变绑定数据。
- 保证 UI 与 Gameplay Action Map 的切换仍由统一输入入口管理。
- 建立 AudioMixer 分组和 Audio Service，至少覆盖 Master、Music、SFX、UI，支持音量、静音、淡入淡出和生命周期取消。
- 至少让一个现有真实交互通过 Audio Service 播放，验证加载、并发和释放，不要求本版本补齐全部音频内容。
- 接入文本缩放、降低动态效果、屏幕震动强度或等价的当前真实消费者；没有消费者的设置不得伪装为已支持。
- 统一处理焦点丢失、平台挂起、恢复和退出：暂停输入、请求检查点、恢复设备、限时 Flush 和释放服务。
- 输入、音频和可访问性设置沿用 0.2.3 的 Settings Service，不另建存储。

### 成功标准

- 自定义绑定重启后恢复，冲突有明确反馈，恢复默认后 Glyph 立即更新。
- 键鼠与手柄均可完成启动、新游戏 / 继续、暂停、背包、商店、打造和错误恢复流程。
- 音量设置实时生效并持久化；场景切换和取消后没有残留音源或失效句柄。
- 已声明支持的可访问性项至少有一个可测运行时消费者。
- 失焦 / 挂起 / 恢复不会重复注册输入、丢失设置或跳过必要存档；退出有明确 Flush 结果。

## alpha 0.2.6：日志、错误处理与 Addressables 资源治理

### 目标

让游戏运行故障可以定位并向玩家提供可恢复反馈，同时保证资源加载和释放具有明确所有权。

### 范围

- 建立结构化 Logger，包含等级、类别、事件 ID、作用域、实例 / 槽位上下文和异常；生产代码不再直接调用 `Debug.Log*`。
- 日志输出支持 Unity Console 和有限内存环形缓冲，避免无边界累积。
- 捕获主线程异常、未观察 UniTask 异常和关键生命周期失败，防止递归记录并保留失败阶段。
- 为存档、场景和资源错误建立稳定错误码、本地化玩家提示以及重试、回退或返回前台动作。
- 冻结 Addressables 分组、Label、地址命名、加载 / 释放所有权、预热和失败回退规范。
- 正式运行时代码只通过资源服务 / Loader 使用 Addressables；加载句柄与实例句柄分别跟踪。
- 建立资源引用、重复地址、错误分组、缺失 Label 和生命周期泄漏验证。
- 场景退出、Session 重建、对象销毁和取消后统一释放资源、实例与对象池租约。

### 成功标准

- 一次读档、场景或资源加载失败可以通过事件 ID、状态、槽位和错误链定位，玩家获得明确且可操作的本地化提示。
- 项目 Runtime 中除 Logger Adapter 外零直接 `Debug.Log*` 调用。
- 场景往返和重复创建 Session 后，Addressables 句柄、实例和常驻对象回到稳定生命周期基线。
- Addressables 配置验证可在 EditMode 重复执行，资源缺失和所有权错误在运行前被发现。
- 资源加载失败、取消或对象提前销毁时，不留下悬挂句柄或不可恢复的半初始化状态。

## 跨阶段工程约束

- [基础设施约束契约](./alpha-0.2-infrastructure-contract.md) 对全部阶段生效；阶段计划只能收紧，不能静默放宽。
- 遵守 QFramework 分层。基础设施通过 System / Utility / Command / Query 或明确的应用服务接入，Controller 不直接持久化、切场景或修改全局状态。
- 所有异步入口必须声明所有者、取消令牌、超时和失败路径；退出作用域后不得继续回调 Unity 对象。
- 配置或存档 Schema 变化必须同时提交迁移、旧版本夹具、验证器和文档。
- 新增玩家可见文本必须先定义本地化 Key；新增内容必须先定义稳定 ID。
- 新增随机行为继续使用登记的稳定随机通道；可持久化随机过程必须保存完整继续状态。
- 场景和 Prefab 修改在 Editor 可连接时使用 Unity CLI / Editor API，不直接编辑打开场景的 YAML。
- 开发、实现与测试期间禁止读取、引用或修改 `Docs/design/`。
- 每个阶段只提交该阶段依赖的基础设施和必要迁移，不提前扩展玩法内容。

## 每阶段完成定义

- 阶段执行计划中的接口、数据边界和失败策略已冻结并实现。
- 至少一个真实生产消费者接入，不交付仅测试使用的空抽象。
- 领域测试、EditMode、PlayMode 和相关配置验证通过；测试失败不会被日志吞掉。
- 新旧数据迁移可复现，测试不会触碰开发者真实用户数据。
- Runtime Console 无新增错误，异步任务、事件、资源和场景对象均按作用域释放。
- 模块文档记录职责、所有权、线程、Schema、错误恢复、配置、测试、禁止事项和扩展方式。
- 规范自动验证已覆盖新入口；任何临时例外都有明确移除阶段。
- 工作区没有混入场景自动序列化、测试设置或其他无关修改。

## alpha 0.2 完成定义

- 应用具有唯一、幂等、可关闭的生命周期入口，新游戏与读档职责完全分离。
- 内容和实例使用稳定身份，设置、存档与配置具有独立 Schema 和可测试迁移链。
- 当前最小循环可保存、退出和继续；原子写入、备份、损坏恢复和错误反馈均通过故障测试。
- 玩家可见文本进入正式本地化表，语言可在运行时切换，中文 / 英文 / 伪本地化和字体回退通过验收。
- 用户设置、场景流、UI 外壳、输入重绑定、音频和声明支持的可访问性项形成最小可用闭环。
- 日志、异常和资源状态可以定位，Addressables 具有稳定所有权和配置验证。
- 后续模块若绕过基础设施规范，将在本地自动测试或验证器中被发现。
