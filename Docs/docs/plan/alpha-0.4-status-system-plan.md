## 交付范围

角色统一持有状态，玩家和怪物共用规则。状态可以限时、持续存在、可叠层、逐层到期或被其他机制消耗；允许只提供可查询标记。状态承载属性修改器、周期伤害和行动限制，不绑定物品前后缀、稀有度或生成容量。

本期包含：

- 通用施加、查询、消耗、驱散和来源释放接口，供技能、天赋、装备、消耗物品及其他机制调用。
- 覆盖刷新、候选共存且仅最强生效、各层独立生效三种重复施加策略。
- 数值统一的叠层与每层独立数值；共享倒计时与逐层倒计时。
- 光环效果、特殊技能效果和异常状态分类；分类与有益 / 有害、可驱散、可消耗分别配置。
- 虚弱、眩晕、流血、燃烧、冰缓、感电、中毒七种异常及各自抗性。
- 图标、层数、剩余时间、焦点详情，键鼠与手柄可达。
- 暂停、死亡、禁用、Session 退出、保存恢复、历史存档兼容和调试工具。

天赋树、完整消耗品玩法、范围光环寻敌和复杂触发编辑器继续由其所属模块建设；本期完成通用接口、来源生命周期及最小接入样例，不以尚不存在的完整来源模块作为交付前提。光环首期支持“来源有效时持续提供效果”；空间范围只是后续调用施加 / 释放接口的提供方。

## 用户已确认的规则

2026-09-13 确认：

1. 异常抗性按效果类型减弱：属性异常降低幅度，伤害异常降低伤害，眩晕缩短持续时间。
2. 满层默认：覆盖型刷新现有效果；最强生效型保留更强层；独立生效型替换最早到期层。每种状态可配置自己的合法策略。

七种异常的具体幅度、基础时长、层数上限、伤害间隔和来源触发概率尚未指定。规则文档中的效果映射、抗性取值范围、快照时机和死亡处理为实施建议，需在创建正式配置前落实；不把示例数值当作已确认平衡数据。

## 实施前问题与处理方向

| 实施前实现 | 对状态系统的影响 | 计划处理 |
| --- | --- | --- |
| `CombatActor.SetModifiers` 清空后重建唯一修改器列表；装备和怪物都调用它 | 状态与换装可能互相覆盖 | 增加按来源替换 / 移除的修改器集合，统一汇总后重建一次属性 |
| `CombatStatResolver` 只聚合非伤害 `GlobalActor` 修改器 | `Temporary` 枚举本身不能让状态生效或到期 | 状态寿命由状态系统管理；数值继续使用实际计算作用域 |
| `ModifierOrigin` 只表达装备和词缀 | 状态来源无法在属性详情中解释 | 扩展来源种类及稳定身份，保留现有装备解释 |
| `CombatSystem.ApplyDamage` 先判命中；`DamageCalculator`、`DamageResult` 按命中设计 | 持续伤害不能直接伪装成命中 | 加入伤害形式，复用防御与资源提交，独立处理周期伤害语义 |
| 玩家 / 怪物移动与施法入口尚无状态门禁 | 仅显示眩晕图标不能真正阻止行动 | Query 提供统一行动限制，命令入口再次校验，防止绕过 |
| HUD 通过只读快照与可取消 UniTask 刷新 | 可复用展示与作用域模式 | 状态图标读取独立快照，UI 不推进状态时间 |
| 存档保存玩家 / 怪物及随机状态，当前 Schema 2、core v3 | 退出重进不能清除负面效果或刷新周期 | 保存状态实例、剩余时间与快照，增加迁移及恢复顺序验证 |

代码依据：`Gameplay/Actors/CombatActor.cs`、`Gameplay/Combat/EquipmentSystem.cs`、`EquipmentEffectResolver.cs`、`DamageCalculator.cs`、`CombatSystem.cs`、`Commands/FireProjectileCommand.cs`、`Gameplay/Actors/MonsterController.cs`、`Infrastructure/Persistence/SaveDtos.cs`。路径均相对 `Assets/Scripts/Runtime/`。

- 实现施加、刷新、择强、到期、消耗、驱散；将数值模型、计时方式、重复策略和满层处理分开。
- 校验不合法配置组合、非有限数值、非法时长 / 层数、过期引用及容量边界。
- 完成独立时钟推进与纯规则测试，确保一次推进与分段推进一致。

完成条件：规则可不依赖场景执行，失败不改变状态，所有模式都有确定性行为案例。

### 2. 角色效果聚合与战斗接入

2026-09-13：已完成并[归档阶段 2](./archive/alpha-0.4-status-combat-plan.md)。来源共存、角色绑定、一致提交、周期伤害、行动限制与反馈均已落地，EditMode 507/507、PlayMode 68/68 通过。

- 将装备、怪物词条和状态接入同一个来源集合；保留资源上限变化时的比例语义。
- 扩展来源解释与状态标记查询，新增周期伤害形式和统一行动限制。
- 眩晕拦截移动、攻击及施法；持续伤害正确提交死亡与击杀归属。
- 调整现有动画、受击反馈、伤害文字等事件消费者，避免把周期伤害视作命中触发。

完成条件：换装不清除状态，状态到期不清除装备；周期伤害、眩晕与原命中回归均通过。

### 3. 异常、抗性与来源接入样例

- 创建七种异常配置、对应抗性属性及内容校验；所有正式字段使用中文 Odin 标注。
- 接通技能施加 / 驱散样例、装备持续来源样例，以及状态层消耗后触发效果的最小机制。
- 为天赋和消耗物品提供同一请求合同与集成测试；驱散接口不依赖具体来源类型。
- 增加 Odin 调试工具：选目标、施加指定状态、查看逐层数值 / 时间、消耗、驱散、查看失败原因。

完成条件：七种异常可通过统一入口获得、检测、减弱及驱散；来源重复绑定和解绑不会重复叠加或误删其他来源。

### 4. 生命周期、存档与界面

- 在 Session 中统一启动并取消状态时间推进；接入暂停、禁用、死亡和恢复。
- 新增状态 DTO 与历史空状态迁移，恢复时先重建状态和属性，再恢复生命 / 法力。
- 经 Unity MCP 创建 UI 与布局；状态图标遵循独立 PNG、Addressables、Sprite Single 和统一视觉规格。
- 显示层数、计时和生效情况；鼠标悬停 / 键盘与手柄焦点显示本地化详情；处理图标消失后的焦点转移。

完成条件：保存重进保持数值与计时，不重复生效；中英及伪本地化、键鼠 / 手柄、暂停 / 重绑定可用。

### 5. 综合验收与收尾

- 按配套验收矩阵补充现有模块测试；新建的状态规则套件按模块命名。
- 完成项目 EditMode / PlayMode，记录当前实际结果，不以历史测试数量作为通过条件。
- 清理临时测试与截图工具，保留必要视觉和回归证据。
- 编写状态模块文档，更新属性、伤害、标签、HUD、存档及配置参考。
- 验收完成后升级版本，将本计划及配套规则归档，更新文档索引。

## 完成判据

任意状态在“施加 → 生效 → 刷新 / 到期 / 消耗 / 驱散 → 保存恢复”链路中，层数、数值、时间、来源和显示一致。旧装备、命中伤害、资源、背包及 Session 隔离行为保持可验证；所有计划范围完成后才标记状态系统已交付。
