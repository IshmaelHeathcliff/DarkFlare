# Alpha 0.6.1：普通怪物行为接入

状态：2026-09-22，**计划就绪，尚未实施**。前置 0.6.0 已提交为 `e20e62c`；当前仍为 `0.6.0-alpha` / core v6 / Schema 5 / 地图 V2。上位见[总计划](alpha-0.6-plan.md)，共用规则见[普通怪物与守卫 Boss](alpha-0.6/monster-and-boss.md)。

## 目标与范围

正式普通怪物接入 Core 中已有的独立 HFSM 与行为树，走通“范围外静止 → 范围内未发现玩家时闲逛 → 看见玩家后寻路追逐 → 攻击范围内攻击”。运行时可观察当前状态、节点、感知依据与中断原因；行为独立于 Animator，离场、保存和继续游戏保持进度。

本阶段复用现有怪物、属性、词条、伤害、状态、掉落、地图与导航。Boss 留在 0.6.2，固定总量 / 触发生成留在 0.6.3，手动重置留在 0.6.4；当前间隔补怪规则继续有效。离开地图保留状态的用户约定不变。

## 执行合同

以下是本阶段采用的工程方案，初始平衡数值仍是可调配置，不代表用户确认了具体视距、等待时长或伤害数值。

### 感知、状态与导航

- 激活范围以怪物与存活玩家的距离判断，进入 / 退出距离采用迟滞；视野由视距、朝向视角和当前地图同源遮挡共同决定，不依赖相机。没有有效玩家时进入休眠。
- HFSM 采用“存活 → 休眠 / 活动 / 受控；活动 → 闲逛 / 战斗；战斗 → 追逐 / 攻击”，死亡最高优先。树负责闲逛走停、追逐结果处理和攻击阶段编排，运行数据只归单个实例。
- 感知按实例错峰，使用有界刷新间隔；死亡、禁用和行动许可撤销不等待下一轮低频感知。命中时必须使用当前几何与目标状态重新校验。休眠零速度、无路径请求，活跃地图中的状态效果和恢复仍正常推进。
- 只在看见玩家时使用玩家导航目标；丢失视线立即改为最后可见位置，记忆到期返回出生锚点附近闲逛，不能继续跟踪墙后玩家的新位置。回到锚点的过程仍须正常寻路。
- 本阶段受击不额外提供攻击者位置，也不突破激活距离唤醒；有无视野仍由同一感知判断。这样保持“范围外静止”，避免先引入未定义的仇恨系统。受击警觉作为后续可选扩展。
- 闲逛点限制在出生锚点半径内，并通过同源通行检查；导航确认可达前不视为成功。采样次数、重试间隔和请求队列有界；区分 Pending / Busy 与 Unreachable，失败等待后再选点。
- 保留现有 Flow Field / A* 模式和预算。大量不同闲逛目标不得挤满共享流场后无限创建搜索；M2 明确点目标的预算内策略、缓存释放和公平调度，并用密集闲逛验证。
- Move 禁止只撤销移动，仍可原地攻击；Attack 禁止立即取消攻击，仍可导航；双禁止进入受控。解除后重新判断，不补发旧攻击。追逐停车距离不得大于实际攻击距离。

### 时钟、攻击与动画

- `MapScope` 拥有唯一地图模拟调度，复用 UniTask FixedUpdate 与所属取消令牌。顺序为“完成上轮任务 / 提交动态障碍 → 采集感知 → 行为决策和动作授权 / 到期命中 → 导航与唯一速度提交 → 表现”。候选地图不 Tick，暂停不推进领域计时。
- 正常行为不得直接写 Transform / Rigidbody 速度；导航承担运动安全，生命周期停止可清零速度。导航调试工具若需临时改意图，必须显式交接控制权并在结束时重新决策，不能每帧相互覆盖。
- 攻击采用“前摇 → 至多一次命中 → 后摇”。接纳时校验目标、范围、视线、阵营、攻击许可与冷却，分配动作 ID 并开始冷却；前摇取消或挥空不退还冷却。冷却结束也不能跳过当前后摇启动下一动作。
- 命中点再次检查存活、实例 / 地图代次、范围、视线、阵营和攻击许可；检查成功才消费一次现有 MonsterAttack 随机流，并以当时的攻击属性创建伤害快照。被拒绝、取消或挥空不消费伤害随机数。结算标记与伤害在同一同步动作中完成，保存不得插入其中。
- 行为随机使用稳定实例种子派生的独立序列，只在实际选点 / 等待抽样时推进，保存序号；不向现有全局随机通道枚举随意追加通道，也不改变掉落、刷怪和攻击的抽样序列。
- `ContactDamageInterval`、攻击半径和伤害列表先继续作为权威来源，行为配置不复制同义字段。冷却从 `Time.time` 截止值迁移到可冻结的剩余时长，旧 DTO 冷却字段保持兼容映射。
- `ActorAnimatorController` 的行为驱动开关与桥接在正式绑定时启用，移动 / 攻击动画只有一个驱动来源；受击和死亡沿用既有管线。动画事件仅供表现同步，缺失 Animator 或迟到回调不能改变命中、冷却或动作完成。

### 保存、迁移与生命周期

- M1 先定义带版本的行为 DTO：出生锚点、朝向、高层状态、最后可见位置 / 剩余记忆、闲逛目标 / 剩余等待、行为种子 / 序号、动作 ID / 阶段 / 剩余时间 / 结算标记及目标稳定身份。保存语义状态，不保存 Core 节点对象、委托、句柄、路径或 Animator Hash。
- 暂停、保存捕获和地图冻结使用同一模拟边界。离场不推进行为、冷却或记忆；回到地图或跨进程继续时恢复剩余时长，不能补 Tick 或重复命中。状态系统原有离场时间语义保持不变。
- 恢复先预检内容与 DTO，再重建 Actor / 状态、行为、导航意图和表现；初始化不得触发伤害或推进 RNG。目标无效时安全取消当前动作，保留已消耗冷却。行为状态是正式怪物导航意图的来源，禁止恢复一条与休眠 / 攻击状态冲突的旧追逐指令。
- Schema 5 → 6 同时处理当前地图和所有冻结地图：锚点取旧位置，朝向用明确默认方向，行为置安全休眠态并在首个有效 Tick 重新感知；保留身份、生命、词条、状态、原有冷却与所有既有随机序列。未知行为版本、非法阶段、非有限数、跨图目标引用在预检拒绝，不静默重置。
- 源地图冻结、候选准备、提交失败回滚和 Session 退出覆盖行为注册 / 停止。注销使用新生成的 BehaviorHandle 与地图作用域；持久化动作 ID 不可绕过新句柄校验，旧地图和旧 Session 的回调一律失效。
- 正式怪物全量切换须在 M4 持久化门禁通过后进行，不能先发布接入再补存档。新配置缺失或无效应在内容预检中定位并拒绝，不悄悄退回旧的无限追逐。
