# alpha 0.4：统一物品使用与消耗品计划

## 状态与前置依赖

2026-09-13 新增后续计划。按用户要求，在[状态系统](./alpha-0.4-status-system-plan.md)完成并验收后实施，建议交付版本为 `0.4.2-alpha`。当前运行版本仍为 `0.4.0-alpha`；状态核心、角色效果与准备 / 提交 / 回退接点已实现，正式异常、自动计时、存档与状态 UI 仍待后续阶段，主动使用物品尚未实现。

前置交付必须提供状态施加、驱散、来源快照、行动限制、保存恢复，以及可供复合事务使用的准备 / 提交能力。物品使用不能另建一套 Buff、驱散或持续时间逻辑。

## 目标

所有具有主动使用能力的物品共用配置、校验、执行、反馈与输入入口。首批加入恢复生命、恢复法力、获得临时状态和驱散异常的消耗物品；单件物品可以组合多个效果。

本期优先完成背包中对自身使用的完整闭环。请求合同保留明确使用者 / 目标身份，后续投掷、目标选择或非消耗型使用能力沿用相同入口；具体玩法在对应阶段扩展。快捷栏、充能、施法条和公共冷却不作为本期默认新增系统。

## 当前代码接点

| 现状 | 需要的改动 |
| --- | --- |
| `ItemBaseDefinition.IsStackable`、`IsConsumable` 与 `ItemInstance.Quantity` 已存在 | 保留原语义，另行声明主动使用能力 |
| 金币支付和材料打造均使用消耗属性 | 不能因为可消耗就自动出现“使用”动作 |
| `InventoryModel.TryConsumeWithoutEvents` 按定义跨堆消费 | 使用物品必须扣除选中的具体实例；不误扣其他堆或不同数值实例 |
| `CombatSystem.ApplyHealing` / `RestoreMana` 已有资源裁剪和通知 | 复用资源规则，增加支持复合提交的最小事务接点 |
| `ItemActionRouter` 已统一移动、穿脱、交易、打造和丢弃 | 新增 Use 动作并调用同一 UseItemCommand，界面不直接扣数量 |
| `Consumable` 类型当前仅预留 | 创建首批正式配置、图标、效果说明及可获得路径 |

## 统一架构

使用能力由 `ItemBaseDefinition` 引用可选 `ItemUseDefinition`；物品类型、堆叠性、可消耗性与可主动使用性分别表达。没有使用配置的金币、材料和装备沿用当前行为。未来任何类型增加主动效果时，也接入此能力，而不是为药水、卷轴等分别写一套流程。

| 层 | 建议职责 |
| --- | --- |
| 配置 | ItemUseDefinition 保存目标规则、使用条件、每次消耗数量及效果列表，Odin 中文标注与合法性校验 |
| System | ItemUseSystem 组织校验、准备、提交和使用结果，不负责 UI |
| Command | UseItemCommand 接受使用者、目标、物品实例身份及期望版本，串联背包、资源和状态事务 |
| Query | CanUseItem / GetItemUseSnapshot 返回可用性、失败原因、实际预期效果与消耗数量 |
| UI | ItemActionRouter、动作菜单和详情共用查询 / 命令，监听完成后的领域事件 |

类型名为计划名。首期采用少量可组合的效果数据与处理器，不为每个具体物品创建执行脚本。配置按能力决定是否可用，禁止只按物品名称、类型枚举或图标分支。

非消耗型使用能力允许每次扣除数量为 0；消耗品首期建议每次扣除 1 个，配置数量必须合法且具有消耗资格。可用性由使用能力校验，IsConsumable 不等于 IsUsable。未来非消耗型效果仍使用相同请求 / 结果合同。

## 首批效果与物品

| 效果 | 执行入口 | 首批代表物品 |
| --- | --- | --- |
| 恢复生命 | CombatSystem 生命恢复规则，裁剪到最大生命 | 生命药水 |
| 恢复法力 | CombatSystem 法力恢复规则，裁剪到最大法力 | 法力药水 |
| 获得临时状态 | StatusSystem.ApplyStatus，沿用状态层数、时长和刷新规则 | 增益药剂 |
| 驱散异常 | StatusSystem.DispelStatuses，按类别 / 标签 / 指定异常筛选 | 净化药剂 |

恢复量支持配置固定值或最大资源百分比，具体数值在内容阶段确定。首期直接恢复为即时效果；若配置持续恢复，应通过限时状态提供恢复属性或状态系统已有周期效果，不在物品脚本中另开恢复循环。

药剂生成的状态持有独立时长及数值快照。消费最后一个物品、原堆叠消失、出售剩余物品都不能撤销已提交的临时效果；来源仅保留稳定物品 / 使用记录身份用于解释，不把该状态绑定为“物品必须仍在背包”的持续来源。

驱散遵守状态的可驱散属性；没有匹配异常时返回无变化，不误删有益状态、不可驱散状态或其他角色状态。允许组合“恢复生命 + 驱散异常”“恢复法力 + 临时增益”等效果，整个使用只扣一次配置数量。

首批物品需有正式获得途径，优先加入商人库存以便玩法闭环。具体恢复量、价格、堆叠上限、状态引用和可驱散范围在配置阶段落实；怪物现有装备 100、金币 2000、矿石 500 的权重规则继续保持，是否新增消耗品掉落另行明确。

## 使用事务

1. 校验有效 Session、使用者 / 目标、物品实际归属、主动使用配置、数量及行动许可；不能使用商人库存、世界掉落、其他玩家或已失效的实例引用。
2. 读取资源、背包及状态版本，准备效果列表的预期变化与精确消费记录。Query 和准备阶段均不修改实际数据、不发送事件。
3. 按配置的明确顺序在临时状态上模拟全部效果，识别非法配置和无变化效果；不能让前一项效果先对外生效，后一项才发现失败。
4. 提交前复核版本和所有权，同步完成资源、状态及选中物品数量变更。失败恢复原数值、层数、时长、周期相位和堆叠位置。
5. 成功后统一发布资源 / 状态 / 背包变化及一次 ItemUsedEvent；事件消费者只能观察完整最终状态。

当前资源接口会立即发送事件，因此不能直接顺序调用几个公开接口再补扣物品。实施时增加有界的准备 / 提交及延迟通知接点，复用原计算规则；回退不能使用“反向治疗”或“重新施加状态”，以免改变上限裁剪、来源或时间。

建议无效使用规则：硬失败（目标非法、数量不足、状态配置失效等）整次拒绝；合法但无变化的效果允许与其他有效效果组合。所有效果均无变化时不消耗物品并显示原因。满生命不妨碍复合药水恢复法力或驱散异常；只是生命恢复一项变化为零。状态有效刷新时间或增加层数也算实际变化。这些为实施默认建议，不等于已确定的物品平衡规则。

使用默认仅接受存活目标，不隐式复活。状态门禁应区分 CanUseItem 与 CanCast：眩晕不自动等同于禁止用药；净化 / 解控物品需要能够按配置通过使用门禁，否则会出现无法解除自身控制的死锁。具体允许状态在配置阶段落实。

物品窗口导致的玩法暂停不应使其“使用”动作整体不可用；即时提交仍成立，临时状态按游戏时间等到恢复运行后再推进。Shell 接管、恢复事务或 Session 退出期间拒绝新使用；同一使用操作的重复提交、重入回调及旧版本请求不能重复扣除或重复产生效果；两个独立且合法的使用操作按各自请求处理。

## 交互、存档与资源

- 背包显示明确的“使用”动作及用量，键鼠和手柄调用同一命令。普通背包中可使用物品的快捷动作可选择使用；商店 / 打造上下文保留原有动作语义，同时通过明确菜单项提供使用，避免误卖或误用。
- 使用一件时仅减少该实例数量，剩余堆叠保留身份和位置。最后一件消失后更新焦点与浮窗；消耗数量不自动等同于当前整堆数量。
- 详情从效果配置生成本地化说明，显示恢复方式、临时状态 / 时长、驱散对象及使用条件，避免 UI 独立维护另一份效果公式。
- 图标通过独立 PNG、统一家族规格及 Sprite Single 导入，以 Session Addressables 加载；状态图标复用状态系统资产。正式生成 / 导入遵循 unity-2d-sprite-workflow，UI 创建与布局使用 Unity MCP。
- 保存背包剩余数量和状态系统已经提交的状态；不持久化半完成的使用事务，不重复恢复药水即时效果。物品用尽后的限时状态仍能正确保存恢复。
- 历史物品新增的使用能力默认缺省，不让旧金币 / 材料变为可主动使用；新增状态等字段沿用状态阶段的迁移链，实施时按实际新增数据判断是否需要进一步升级 Schema / 内容版本。
- Odin 调试工具显示使用预检结果、无效原因及实际消费 / 效果记录，正式行为与调试入口共用 System。

## 实施顺序

1. 状态系统完成验收，核对 Apply / Dispel 的事务准备、来源快照及保存恢复合同。
2. 实现主动使用配置、统一请求 / 结果、能力校验和指定物品实例消费。
3. 接通四类效果、复合事务和无效使用规则，完成核心回归。
4. 加入首批消耗品配置、商人获得路径、图标、本地化与背包使用交互。
5. 验证状态 / 物品联动、生命周期和历史存档，更新模块说明后归档计划。

## 验收要求

| 合同 | 长期回归 |
| --- | --- |
| 使用能力 | 可消耗但不可主动使用；可使用但不消耗；不可堆叠消耗品；缺配置拒绝 |
| 消费与所有权 | 从选定堆扣一次；最后一件移除；不足、旧引用、商人 / 世界 / 其他角色物品拒绝；同一操作重复提交不重复消费 |
| 资源效果 | 部分缺血 / 蓝正确恢复；超额裁剪；百分比按正确上限计算；死亡目标拒绝 |
| 复合事务 | 多效果全部提交后再通知；模拟中途失败完全回退；所有效果无变化不扣；部分无变化但其他有效时正确消费 |
| 状态联动 | 药剂继承刷新 / 层数 / 抗性规则；末件消失不撤销状态；驱散范围准确；控制与用药许可不形成死锁 |
| UI / 生命周期 | 鼠标与手柄行为一致；最后一件焦点转移；暂停使用语义；Session 取消与重建无重复效果 |
| 存档 | 使用前后数量和状态往返；没有半笔事务；旧档物品仍保持原有能力；读取不再次即时回血 / 回蓝 |

优先扩展现有背包、资源、UI、状态和存档模块测试；独立使用事务可新增按模块命名的套件，不按版本新建重复测试。完成时运行项目 EditMode / PlayMode，清理临时脚本并保存当次证据。全部范围交付后再更新版本和“已实现”文档。
