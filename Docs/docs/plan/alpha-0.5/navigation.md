# Alpha 0.5：批量动态寻路

状态：计划，未实现。入口：[总计划](../alpha-0.5-plan.md)。目标为 500 活动怪物、1000 压力测试；保留现有战斗、属性、状态与 Rigidbody2D 集成。

## 系统边界

| 层 | 职责 |
| --- | --- |
| NavigationModel | 当前地图 generation、网格 / 障碍修订、Agent 注册与目标引用 |
| NavigationSystem | 管理请求、共享流场、缓存、Job 依赖和批量输出；Command / Query / Event 接入 QFramework |
| 纯数据算法 | 净空 / 代价、反向积分场、方向场、空间哈希、分离和边界约束；可独立测试并 Burst 编译 |
| 集中驱动 | 可取消的 UniTask 在明确 PlayerLoop 阶段采样 / 调度 / 应用，统一管理固定步；不为每只怪物再开导航循环 |
| Controller | 注册 / 注销自身、提供物理状态、应用本轮有效速度；攻击仍通过现有 Command |

Navigation 输出期望速度，不直接修改生命、状态、交易或场景。Jobs 只接收 blittable 数据和 Native 容器，不访问 GameObject、Transform、Rigidbody2D、SO、托管集合或 QFramework；主线程负责快照和最终应用。

## Grid Navigation

静态通行数据来自[地图编译](./map-data-terrain.md)，包括水域、边界、障碍 footprint、地形代价和区域规则。不同 AgentProfile 包含半径、可通行材质、代价倍率；按有限配置组合生成网格，禁止每个怪物创建一张独有网格。

- 八方向邻接，直 / 斜成本用固定整数比例（建议 10 / 14），阻挡独立表示，积分使用足够宽的整数和溢出保护。
- 斜走时两个相邻正交方向均须可走，禁止切角；更进一步检查带半径的移动线段，不能只验证终点。
- 水岸 / 障碍按 Agent 半径膨胀并检查边界净空，导航分辨率在 0.5.0 冻结。不同尺寸怪物不能共享错误的窄缝可达结论。
- 初始、传送、恢复和刷怪使用同一落点查询；位于阻挡中的目标在有限范围寻找合法候选，找不到返回 Unreachable，不无限搜索。
- 动态硬阻挡使用可增删的 footprint stamp / 引用计数，重叠障碍删除其一不能误清另一个。首期通过调试命令验证添加 / 移除，不额外引入完整建造玩法。
- 普通移动怪物不作为硬障碍反复触发重建，其相互影响交给 Spatial Hash 与 Separation。

## 共享 Flow Field

同地图、同目标格 / 目标集、同 AgentProfile、同导航修订共用一份 Cost / Integration / Flow 数据。目标是移动中的玩家；在目标格变化、目标失效或阻挡修订后请求更新，不按每只怪物计算完整 A*。

反向 Dijkstra 从合法目标集积分，代价方向必须和正向移动一致；方向选择合法邻居中 `边代价 + 邻居积分` 最小且能够前进者，等值按固定方向序。纯等代价格可使用对应简化，但不能把带代价的地图按普通 BFS 处理。共享场用于多起点同终点的依据见[Red Blob Games](https://www.redblobgames.com/pathfinding/tower-defense/)；地图分区和缓存扩展参考[Game AI Pro 第 23 章](https://www.gameaipro.com/GameAIPro/GameAIPro_Chapter23_Crowd_Pathfinding_and_Steering_Using_Flow_Field_Tiles.pdf)。

首期采用有界地图的完整积分场，缓存数量建议上限 8、LRU + 使用计数管理；暂不实现复杂层级 portal 路由。地图 chunk 用于数据与脏区定位，不代表改一个障碍只需更新该 chunk 的最短路：障碍可能改变全图连通，当前修订的受影响共享场必须失效并重新积分。

构建使用独立候选缓冲，完成后复核 MapGeneration / GridRevision / TargetRevision 再发布，不覆盖更新请求。持续移动时合并最新目标，建议最多每 100ms 发起一次有效目标重建；构建期保留上一份完整场，不读取半完成数组。

阻挡改变后旧方向必须经过最新局部通行 / swept segment 检查，新增墙立即禁止穿越；无安全旧结果则停车等待。移除墙后允许等新场再走，不用过期结果冒险穿墙。失效队列有上限，同 key 合并，超载表现为有界等待并记录原因。

目标在同格内的小幅移动不全图重建；靠近且视线与净空确认可直达时用局部目标位置平滑到达。隔墙或水域时不允许以“离玩家很近”绕开流场。无路、目标注销、冻结 / 死亡立即进入明确停止状态。

## Spatial Hash 与 Separation

每轮采样所有活动 Agent 的稳定身份、位置、半径、速度和行动许可。构建哈希格索引，格宽与局部查询半径关联；每个 Agent 遍历 `ceil(查询半径 / hash格宽)` 所需范围，不能永远只查九宫格而漏掉大型怪物。

建议采用按哈希格键 + 稳定 Agent ID 排序的连续 Native 数组和格范围表；复用 Collections 的排序 / 容器，避免每帧托管字典和临时 List。同一位置的退让方向使用一对稳定身份推导，彼此方向相反；不依赖随机遍历顺序。

疏散力由局部邻居距离 / 半径计算，并与流场方向、障碍避让、速度 / 加速度约束组合。到达停止圈后不再强行朝玩家中心挤压；拥堵时限制分离造成的逆向摆动，并按稳定优先级短暂让行。

哈希不自动保证最坏情况线性：全部单位落在同一桶仍可能退化。首期建议每 Agent 最多检查 96 个候选、从中取至多 24 个邻居；高密度桶采用稳定分段抽样与轮换覆盖，记录饱和计数。候选访问本身也必须有界，不能先扫描整桶再截取邻居。超过预算时允许局部重叠，但不允许穿硬障碍、NaN 或无限抖动；若持续拥堵，触发有冷却的重新选可达目标 / 等待策略，禁止每只 Agent 每帧请求新流场。

Separation 是软避让，不是 ORCA / 严格无碰撞多智能体规划。延续现有同阵营不产生实体碰撞的合同，不承诺窄口双向密集人群绝对无接触；以绕障安全、群体可疏通和可恢复为验收重点。

## Job / Burst 调度与生命周期

建议流水线：`主线程采样 → 网格 / 积分构建（按需）及空间索引 → 并行方向采样 / 分离 / 边界约束 → 主线程提交速度 → 物理步`。初期通过序列化依赖保证正确，再依据 Profiler 开放互不写同一缓冲的工作并行。

- 空间索引和转向使用批量 Job；Dijkstra 依赖前沿传播，不伪装成逐格独立 ParallelFor。使用可恢复的有界积分 Job，以节点处理配额分轮推进，预分配堆 / 队列，避免主线程为一张大图同步等待完整构建。
- Agent 数组采用 SoA / 连续数据布局，持久容器复用并按容量分档扩展。场缓存、前沿和双缓冲都有字节上限；超限返回有诊断的拒绝 / 等待，不无界分配。
- 存在明确完成屏障后才能访问输出或交换缓冲。允许使用上一轮完整速度时必须重新验证行动许可、地图版本、位移上限和最新障碍；停顿 / 暂停后不以旧 deltaTime 补跑。
- Application / Session 停止、切图、组件禁用时先停止调度并使 generation 失效，再完成已有 JobHandle、注销 Agent、释放容器。CancellationToken 不能中止已经运行的 Job，不得提前 Dispose 或让旧结果写入新地图。
- MonsterController 移除原全表分离遍历，保留必要表现 / 攻击入口；同一物理步只有一个速度写入者。提交前复核 CanMove / 死亡 / 禁用，眩晕及属性移速即时生效。
- 避免 `Schedule` 后立即无条件 `Complete` 抵消并行；同时不以无同步读取追求“零等待”。本机 Unity 包的安全句柄检查与实际 Profiler 决定调度窗口。

Unity 原生容器所有权和依赖同步以[NativeContainer](https://docs.unity3d.com/6000.0/Documentation/Manual/job-system-native-container.html)及[Job 依赖](https://docs.unity3d.com/6000.0/Documentation/Manual/job-system-job-dependencies.html)为准；容器选型核对本项目锁定的 [Collections 6.6](https://docs.unity3d.com/Packages/com.unity.collections@6.6/manual/collection-types.html)。

## 性能预算与测量

用户确定规模，以下时间 / 内存为首轮工程目标，不是已达到的性能结论。0.5.4 开始时固定 CPU、GPU、核心数、分辨率、构建后端、Unity / Burst、物理步和画质，再测量与调整实现；目标失守必须记录并处理，不能只降低单位数宣称通过。

| 场景 | 初始验收目标 |
| --- | --- |
| 500 个活动怪物，正式野外 128×128 逻辑格建议值 | 1920×1080 独立 Player，帧时间 P95 ≤ 16.7ms；导航主线程采样 / 调度 / 提交 P95 ≤ 2ms，导航关键路径 P95 ≤ 4ms |
| 1000 个怪物，瓶颈通道 / 密集出生 / 移动目标 | 帧时间 P95 ≤ 33.3ms，导航主线程 P95 ≤ 3ms，关键路径 P95 ≤ 8ms；无泄漏 / 失效写入 / 穿硬障碍 |
| 移动目标与动态障碍 | 新目标 / 拓扑可用场的 P95 延迟 ≤ 200ms（500）/ 400ms（1000）；新硬阻挡最迟下一物理步阻止穿越 |
| 内存 / 分配 | 预热后导航稳态 GC Alloc 为 0 B / tick；导航模块原生内存预算建议 ≤ 128 MiB，循环切图回到同容量基线 |

固定种子运行至少 60 秒、预热 10 秒、重复 3 轮，记录 P50 / P95 / P99、最大耗时和最长重建等待。Development Player + Profiler 用于归因，普通 Player 复核帧率；禁用 VSync / 帧率上限干扰，避免 Deep Profile 结果当性能基线。

分别测纯导航与带正式 Animator / Renderer / Rigidbody / HUD / 战斗的完整场景；500 的总帧率失败可能来自排序、物理或战斗，不允许只公布 Jobs 时间掩盖总成本。压力测试允许关闭无关视觉作诊断，但不能用诊断模式替代正式场景验收。

长期保留纯规则和生命周期正确性测试，性能跑分使用可重复场景 / 工具并归档当次证据，不在普通 CI 以易抖动的毫秒数作为固定单测断言。

## 行为矩阵与调试

回归覆盖最短代价、四 / 八邻接、拐角、不同半径、一格通道、水域、U 形障碍、完全断路、动态开闭、同格目标移动、目标传送、相向拥堵、同点出生、旧 Job 结果、缓存淘汰、暂停 / 眩晕 / 死亡 / Session 退出。接触攻击增加障碍遮挡检查，不能绕路移动但仍隔墙扣玩家生命。

Odin 调试面板与地图叠加显示 Cost / Integration / Flow、净空、哈希桶、邻居抽样、阻挡版本、待构建队列、缓存命中、Job 耗时、候选饱和、卡住数量及原生内存。日志记录状态变化和故障，不逐怪物逐帧刷日志。
