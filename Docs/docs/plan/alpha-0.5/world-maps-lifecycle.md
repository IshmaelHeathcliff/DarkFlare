# Alpha 0.5：世界排序、双地图与保存恢复

状态：计划，未实现。入口：[总计划](../alpha-0.5-plan.md)。用户已确认：各地图保留状态，离场期间暂停模拟。

## 世界层级与 Y 排序

复用 `WorldSortingSystem`、`WorldSortParticipant`、`SortingGroup`，仍以显式接地点 Y 为主键，较低 Y 显示在前；相同量化 Y 使用类别、稳定身份破同序，不以创建顺序或 Unity Instance ID 排序。

| 对象 | 处理 |
| --- | --- |
| 地表、水面、平面道路、贴地碎屑 | Ground 层，明确内部顺序；地表 Chunk 不与角色逐块争抢 Y 排序 |
| 玩家、怪物、商人、打造台、树木、岩石、建筑、掉落 | WorldObject，每个独立遮挡单元一个根 SortingGroup + 地面锚点；动态物体更新量化 Y |
| 阴影、轮廓、火焰、身上状态特效 | 归所属对象同一 Group 的局部顺序；不因子 Renderer 固定 Order 跨越别的对象 |
| 独立投射物、世界命中特效 | 按世界接地点注册 Y 排序，或附属命中对象的既有 Group；纠正现有全部 WorldEffect 总盖在世界之上的行为 |
| 伤害文字、世界提示、HUD | WorldInfo / UI 使用明确可读性例外，不以地表格号决定层级；例外必须登记 |

保留现有 1/64 单位 Y 量化作为初始配置，按新像素 / 世界尺度验证抖动。大型墙体、横跨道路的建筑不可全部只用一个中心点排序；按可独立遮挡的段拆成兄弟 Group，每段锚点和稳定 ID 来自对象定义，禁止嵌套 Group。首期不实现可进入的多层建筑和屋顶剖切系统。

静态对象身份为 `MapId/ObjectId/PartId`，动态对象使用真实 Actor / Item / WorldDrop 身份。同一地图卸载和再次加载不能产生重复注册； staging 内容未提交前不能进入活动排序。

排序系统性能与导航一起计入总帧预算：现有实现只要 Y 改变就全表排序，应先测量 500 / 1000 动态单位，再决定缓存静态序列并与动态序列合并、复用比较键及避免无变化写入。保持唯一稳定 Order 和无分配，检查 Sorting Order 可用范围，不在规划阶段无依据重写整套渲染。

Global Light 2D 的目标层、Sprite-Lit 材质、Shader 和所有生产 Prefab 同步校验。树后 / 树前、建筑两端、同 Y 交叉、掉落经过角色、投射物经过树干都要有可见验收；排序不得通过修改 Transform Z 或物理层修补。

## 场景与地图作用域

首期继续保留 `Bootstrap + Main` 场景拓扑，Main 改成可承载任意地图的玩法容器；城镇与野外是两份独立 MapDefinition / 数据资产，无需复制两套玩家、UI 和系统到两个 Unity Scene。

Session 拥有玩家、装备 / 背包、运行身份分配器及地图状态集合。新增 MapScope / MapGeneration 管理当前地图的地表、碰撞、静态对象、怪物、世界掉落、交互绑定、刷怪、导航容器及 Addressables lease。玩家继续留在 Session，不能切图重新执行 NewGame / 初始发放。

离场地图只保留冻结 DTO；活动 Unity 对象和专属资源释放，不把两张地图都隐藏着继续运行。玩家 / 通用内容资源由现有 Session owner 共享，地图独占内容按 MapScope 释放。现有 SessionObjectRegistry 增加按 map owner 清理能力，不能切图时 ReleaseAll 销毁玩家和 UI。

地图入口 / 出口由同一交互系统发出 ChangeMap 请求，由现有 Scene Flow 的单 active + latest pending 仲裁处理；Controller 不直接启停地图、调用 SceneManager 或访问存档存储。地图加载、保存和 Shell 共用 Busy / pause lease，错误仍使用现有本地化错误目录。

## 两张正式地图

| 地图 | 必须提供 | 完成条件 |
| --- | --- | --- |
| 城镇 `map_town`（计划 ID） | 玩家出生 / 返回入口、商人、打造台、去野外出口、明确无刷怪区域、道路与建筑 / 装饰 | 从出生点步行可达商人、打造台与出口；现有随机商店、消耗品、材料打造均可用；城镇不刷怪 |
| 野外 `map_wilderness`（计划 ID） | 安全返回入口、刷怪区域 / 禁刷区、水岸、绕行障碍、开阔空间与窄路 | 返回城镇可达；怪物只在合法区域与净空生成，绕障追逐、不在水中或墙内出生，死亡掉落可拾取 |

两图总体覆盖四种地表和变体；野外必须实际使用四种地表验证通行与过渡，城镇也保留水岸 / 草地样例。使用现有商人、打造台、怪物和内容定义；需要新增环境美术时先按资产合同生成样例再扩展，不以方块占位作为最终地图交付。

区域优先级解决禁刷与刷怪重叠；出生点至少留出对应半径净空。随机采样失败时跳过本次生成并记录原因，不沿用旧“夹到矩形边缘”回退把怪物塞进障碍。镜头跟随范围来自地图外包范围与可见安全边距，不随当前刷怪圈改变。

首期新游戏建议进入城镇；出口通过键鼠 E / 手柄现有交互动作触发，避免触碰边界自动往返。入场落点与出口触发区分离，并有一次交互释放门禁，防止同一次按键立即切回。复活位置采用当前地图明确 Respawn 入口并验证可达，不静默传送到坐标原点。

## 切图事务

1. 在当前状态允许时取得 pause / 输入门禁，关闭并结清拖放、交互与打造工作区状态。验证目标 MapId、EntryId、内容版本和数据，不以切图绕过未完成事务。
2. 排空待发布领域事务、状态时间积压、生成请求和导航 Job，捕获当前地图冻结快照及玩家回退状态。保存协调器不能在两图交错期间取快照。
3. 在未激活的 staging 下加载目标资源、地表 / 碰撞、通行网格、对象与目标地图 DTO；完成入口、资源、容量与内容校验。staging 不注册活动战斗 / 状态 / 排序，不运行刷怪，不发送正常进入事件。
4. 提交时一次替换活动 MapId / MapGeneration、作用域与模型归属，恢复目标地图 Actor / 状态、移动玩家到合法入口、绑定相机 / 交互 / 导航，再启用模拟并发布完成事件。只有一张图对玩家可见且可交互。
5. 提交前失败或取消，清理 staging 并恢复源图；提交中失败使用已捕获快照恢复源图，不能证明唯一性才进入已有 Fatal 恢复路径。旧物件在目标达到可提交条件前不提前销毁。
6. 成功后释放源 MapScope，留下冻结 DTO，标记存档 dirty 并调度正常保存；磁盘写失败保留当前正确 Session 并提供重试，不把新地图进度混写进旧活动图快照。

所有权 transfer、解绑与恢复要在 0.5.3 细化成可故障注入的小步骤。Save / ReturnFrontEnd / ChangeMap / 应用退出共用仲裁，不嵌套两个切图或保存半张图；加载取消后也等待可安全释放点再返回结果。

## 离场冻结规则

冻结范围包括：怪物身份 / 资源 / 词条 / 位置、状态层数与剩余时长 / 周期相位、掉落身份 / 数量 / 位置、对象开闭等状态、商店当前库存、地图随机通道、刷怪倒计时。返回地图不重生已死怪物、不补货、不补发掉落、不消耗离场期间随机数。

怪物离场不等于死亡；解除 CombatModel 和事件订阅时不能触发击杀、掉落或销毁来源的正常死亡副作用。冻结对象不参与目标搜索、导航、恢复、状态 Tick、攻击或动画。恢复采用专用导入路径，不调用普通 Spawn / ApplyStatus 重新掷值或首跳。

现有状态共用 Session 时钟，建议复用 StatusStore 的快照 / 专用导入合同并增加地图暂停边界：离场 Actor 从活动容器转出，快照记录冻结时钟；回图将该 Actor 所有 apply / expiry / nextTick 时间整体平移至当前时钟，保留层 ID、顺序和周期相位。不能仅暂停怪物 MonoBehaviour，也不能只移动过期时间却忘记周期索引。

玩家始终为活动 Session Actor，随玩家携带的限时状态在玩家所在活动地图正常计时；切图加载中的全局 pause 不推进。离场怪物先前施加到玩家的限时效果继续遵守现有脱离来源规则；SourceOwned 光环等依赖实时来源的效果在离开作用域时释放，不能保留一个假活跃来源。地图内相互引用与来源重映射在恢复时验证，跨地图瞬时寻敌不允许。

资源恢复、接触攻击 CD、复活 / 死亡待移除、刷怪与地图随机状态同样冻结；待销毁的纯表现对象可在快照边界收敛，但不得复制死亡奖励。跨进程继续也不补算离线时间。

## 存档与历史兼容

新增结构建议：Session 级玩家 / 背包 / 装备与全局实例序列，`activeMapId + mapStates[MapId]` 保存各图内容修订、怪物、掉落、刷怪、库存及对象状态。静态地表存正式内容引用；有运行时地图改动时只保存语义差量，Flow Field、哈希表和渲染缓存重建。

Save Schema 预期从 3 增至 4，core 内容目录在正式地图加入时独立升级；确切版本在该阶段实现确认。至少保留 Schema 0 → 1 → 2 → 3 的历史链，再添加映射，不把所有旧档统统当新游戏。

建议旧单 Main 快照映射到野外兼容区域：正式野外保留旧 `-16..16` 坐标区的合法落点语义，不在承接的旧角色 / 掉落范围新加阻挡；原商店库存绑定城镇同一商人身份，玩家物品与装备不变。迁移保留所有原有实例身份、词条、资源、状态、随机进度与数量；不能为了套用新地形而丢弃旧怪物或掉落。实施前用真实历史夹具验证坐标范围和交互状态，再冻结地图兼容布局；无法合法映射时明确拒绝并保留原档，不静默重开。

地图级随机流从运行根种子 + MapId 分离；玩家攻击等全局通道保持原进度，旧地图相关通道迁入野外，城镇初始流稳定派生且不消费野外序列。实例分配器检查所有活动 / 冻结地图，跨图不得重用 Monster / WorldDrop / Item ID。

现有 `MaximumMonsters = 512` 不满足多个地图累计和 1000 压力场景。阶段 0.5.3 明确每图、全存档、状态层、物品 / 掉落及字节上限，至少支持首期 1000 个怪物快照往返；依据实际 DTO 大小测量总预算，不仅放大一个常量。超限预检给出可读错误，不截断列表；保留容量保护和隔离数据测试。

## 验收

城镇买入 / 打造 → 野外战斗 / 掉落 → 回城 → 回野外；野外冻结前后等待一段城镇游戏时间，怪物生命、状态剩余时间 / 下一跳、掉落和刷怪倒计时一致。保存退出后继续同样一致，玩家状态则按玩家实际活动时间推进。

覆盖连续往返、快速重复请求、目标无效、缺资产、取消、准备 / 提交故障、保存失败、重进 Session、历史档、1000 怪物快照容量、跨图相同局部对象 ID、旧事件 / Job 写入防护。地图反复进入退出后活动注册数、Addressables lease 和原生内存回到基线。
