## 普通怪物状态

“玩家范围”解释为可配置的激活距离；“视野”由视距、朝向视角与障碍遮挡共同决定。两者不是相机可见范围，离屏仍可正确模拟。推荐层级：存活 → 休眠 / 活动 / 受控；活动 → 闲逛 / 战斗；战斗 → 追逐 / 攻击；死亡为最高优先级终态。

| 条件 / 状态 | 行为 | 退出条件 |
| --- | --- | --- |
| 玩家不在激活范围 / 休眠 | 零移动、无攻击，不提交寻路；保留身份、资源与状态效果 | 玩家进入激活范围 |
| 玩家在激活范围但未被发现 / 闲逛 | 围绕出生锚点选择小范围可达点，走停交替 | 发现玩家、离开激活范围或行动受限 |
| 发现玩家 / 追逐 | 向导航提交玩家目标，复用现有 Flow Field / A* | 进入攻击距离、记忆失效、离开激活范围或被打断 |
| 玩家处于攻击范围 / 攻击 | 前摇 → 一次命中判定 → 后摇 / 冷却；移动与攻击权限分别检查 | 动作完成、攻击禁止、目标无效、离场或死亡 |
| 控制状态 | Move 禁止只停车；Attack 禁止中断攻击；双禁止进入受控状态 | 解除后重新决策，不补发旧攻击 |
| 死亡 / 注销 | 中断树、撤销移动 / 攻击，停止新感知；由既有死亡管线结算 | 清理，不因动画回调重新进入存活 |

休眠只停止行为决策与移动，不等于离场冻结：活跃地图中的中毒、燃烧、恢复等仍沿用状态系统。离场则整个地图冻结，不补算行为计时。

以下为普通怪物阶段采用的规划依据，最终实现合同见模块文档：

- 激活退出采用迟滞避免反复唤醒；视距不大于激活距离。
- 丢失视线后短暂记住最后可见位置，导航到该位置；记忆到期回到出生附近闲逛。期间不读取不可见玩家的新位置作为追逐目标，不隔墙攻击。
- 受击警觉作为可选扩展；0.6.1 不因受击提供攻击者位置或突破激活距离唤醒，感知仍走同一视野规则，保持范围外静止。
- 闲逛目标必须位于锚点半径与同图可达区域内；采样有界，找不到则原地等待后重试。不可把 500 个闲逛目标同时降级为无限 A* 请求；受共享查询预算和错峰调度约束。
- 攻击命中时重新验证目标、距离、视线、阵营及行动许可。攻击启动、冷却消耗、命中 / 落空的具体规则必须统一，不能让旧接触攻击循环继续独立触发。
- 建议动作被正式接纳时开始冷却；前摇取消或挥空也消耗该次冷却，避免通过抖动距离 / 控制解除反复试击。命中时无效只落空，不产生伤害；是否消费伤害随机数需固定为明确合同并测试，不能由动画帧决定。

## 配置与接入

拟增加独立行为配置，由 MonsterDefinition 引用；配置包含激活 / 退出距离、视距 / 视角、感知频率、目标记忆、闲逛范围 / 等待、攻击前后摇及动作引用。使用中文 Odin 分组、单位与范围说明；所有浮点数拒绝 NaN / Infinity，攻击停止距离不得大于实际可攻击距离。

基础怪物继续复用现有属性、词条、掉落、伤害快照与随机管线。BehaviorSystem 负责决策和动作意图，NavigationSystem 负责路径 / 避让及安全速度，CombatSystem 负责伤害；MonsterController 只绑定生命周期。正式配置接入后从导航循环移除直接接触攻击，兼容工具 / 测试如需直接调用攻击仍走同一许可合同。

失活、死亡、切图、保存捕获与 Session 退出采用精确实例 / map generation 验证；同一个 Prefab 的两只怪物不能共享计时、目标或节点状态。行为随机使用实例独立种子 / 序列，不能让调试选择或感知批次改变掉落与攻击随机流。

## 守卫型 Boss

用户已确认近距离挥击、带预警冲锋及低血量强化方向。首版一个独立 Boss 原型、一个固定出生点；不扩展为完整 Boss 内容库。以 HFSM 管理生命阶段，阶段内行为树按明确优先级选择动作。

| 行为 | 拟定流程与约束 |
| --- | --- |
| 常规接敌 | 复用感知和导航；接近到挥击距离，不用持续接触伤害代替挥击 |
| 挥击 | 明确方向 / 范围预警，前摇锁定朝向；短命中窗口仅对玩家结算一次；后摇提供可见空档 |
| 冲锋 | 满足距离及冷却后锁定冲锋方向 / 终点；预警 → 直线冲锋 → 停止 / 撞墙 → 恢复；锁定后不追踪转弯，不穿水域、障碍或地图边界 |
| 低血量强化 | 建议阈值 50%，每个地图实例只进入一次；先结束或安全中断当前动作，再播放阶段转换，调整冷却 / 招式组合；不默认增加不可见伤害或隐式无敌 |
| 中断与死亡 | 死亡最高优先级，清除预警、攻击窗口及移动授权；首版不默认免疫现有控制，若需抗性通过现有状态配置显式表达 |

行为树候选结构：优先选择“阶段转换 → 满足条件的冲锋 → 近距离挥击 → 接敌 / 等待”；每种攻击是独立 Sequence，抢占必须完整 Abort。Phase 与动作 ID 稳定，调试图能指出当前停在前摇、冲锋、命中或恢复哪个节点。

数值（生命、伤害、预警时长、冲锋速度 / 距离、强化倍率）作为配置初值，正式阶段计划根据实测调整；不能把本表当作已验收平衡值。Boss 计入地图怪物容量，普通数量与 Boss 数量分别展示。

## 表现与内容

- 独立名字、本地化条目、Prefab、可辨识外观及动作映射。预警范围必须对应真实命中几何，并兼顾降低动态效果；不能仅依靠颜色识别。
- 若现有资源不满足 Boss 可辨识度，实施阶段用项目的美术生成 / Sprite 工作流制作正式资源；本轮不生成图片或改资产。
- 使用现有世界排序、状态显示、血条与死亡掉落管线；独立 Boss 血条只有在现有显示无法表达生命阶段时再纳入该阶段明确工作量。
- 冲锋运动与命中使用扫掠检测，低帧率不能跳过墙或玩家。AttackInstanceId 对同一次动作命中去重，动画桥不能成为第二伤害入口。

## 冻结、保存和恢复

0.6.1 就增加行为 DTO 与校验：出生锚点、朝向、当前高层状态、最后已知目标 / 剩余记忆、闲逛目标 / 剩余等待、随机序列；0.6.2 扩充 Boss 阶段、各技能冷却、动作阶段、锁定方向和已结算标记。保存语义数据，不序列化委托、运行节点对象、Animator Hash、路径或任务。

推荐保持精确冻结：前摇恢复剩余前摇，命中后的动作只能恢复后摇，冲锋保存当前位置 / 方向 / 剩余距离和已命中标记。恢复顺序是内容校验 → Actor / 状态 → 行为 → 安全移动意图 → 表现重建；动画可重播相位但不能再次结算伤害。不能通过加载存档跳过 Boss 已进入的强化阶段或复活已击杀 Boss。

旧 Schema 5 没有行为记录时，锚点取旧存档位置、动作设为空闲安全态，保留生命、词条、状态、身份及原有攻击冷却；不执行一次隐含攻击来“补齐”记录。未知状态 / 动作版本在预检明确拒绝或经显式迁移处理，不能静默丢数据。

## 验收

普通怪物必须实际演示“范围外静止 → 范围内墙后闲逛 → 看见后绕障追逐 → 攻击 → 丢失目标 → 恢复闲逛”，并覆盖边界迟滞、完全断路、玩家死亡、暂停与控制效果。核心规则用 EditMode，真实导航 / 战斗 / 冻结用现有 PlayMode 套件。

Boss 在当前 Windows Player 验收挥击可躲避、冲锋锁向 / 撞墙、低血量只转换一次、各阶段保存继续及中断清理。命中计数、伤害来源、技能冷却与可视化节点对应；死亡只掉落一次。实际键鼠与手柄至少走通遭遇、战斗、离场和返回，注入输入与实体设备验收分别记录。
