# 0.7.1-alpha.4 六键手动施法与棋盘效果实施计划

状态：2026-10-15，**已完成代码核对和工作包拆分，尚未实施**。阶段三已提交 `f896cc8`；当前运行版本仍为 `0.7.1-alpha.3`，Unity `6000.6.4f1`、core v12、Save / Settings Schema 11 / 1、地图 V4。已有项目回归 EditMode 949/949、PlayMode 102/102；本轮仅提交和规划，没有重跑 Unity 测试，也未提前推进版本。

入口：[活动总计划](../alpha-0.7.1-skill-board-plan.md) · [六键合同](manual-skills.md) · [阶段验收清单](acceptance.md) · [已交付成长模块](../../skill-board/growth.md) · [阶段三验收](../archive/0.7.1/acceptance/growth/README.md)。本计划只依据开发文档、代码和用户确认，不读取人工设计目录。

## 目标与本阶段边界

- 移除默认自动施放，提供独立普攻键与六个火焰槽、按下施法、瞄准和真实冷却。进入游戏、遇敌、冷却结束、复活、切图及读档都不产生自动攻击。
- 技能分为武器普通技能与火焰技能。普通技能由当前装备武器提供，无需火焰或柴薪点亮；火焰技能要求已点亮的合法柴薪。同一火焰最多分配一个槽，不同实例保持各自来源和效果。
- 普通天赋独立点亮；全局天赋、局部天赋、火焰自身词条与余烬进入同一攻击管线。局部效果按天赋连线路径到火焰计算，不作用于没有棋盘坐标的武器普通技能；角色全局效果仍正常生效。
- 普通技能与六槽状态接入保存 / 恢复、Application 输入与重绑定；交付六火焰槽及独立普通技能提示的最小 HUD，以及复用正式 Command / Query 的开发分配入口。新角色和旧档有明确的起始技能路径。
- 阶段五继续完成正式棋盘、玩家技能分配界面、充能 / 点亮界面及整体操作闭环。阶段四的六键、瞄准、重绑定和 HUD 必须当阶段可验证，不能把基础输入安全与迁移留到最后。

## 已确认规则

2026-10-15 用户确认：**范围走已点亮网络最短路径，每条连线统一算 1 步；同一火焰只允许一个槽；普通技能由当前武器提供且使用独立普攻键，六槽留给火焰**。每种武器有自己的普通技能。不采用此前赠送起始柴薪 / 火焰和零花费点亮的建议，成长账本继续保持阶段三合同。

两轮澄清均已收到用户答复，下列规则作为本阶段实施与验收依据。

| 规则组 | 确认合同 | 实际影响 |
| --- | --- | --- |
| 路径计长与通行（已确认） | 已点亮网络最短路，普通天赋从自身节点、余烬从所在裂缝节点到火焰中心；每条内部连线 / 跨柴薪裂缝连接均计 1 步，未点亮天赋不通行，包含边界。 | 跨空格长连线仍计 1 步；使用无权图最短路，不按几何长度加权。Radius = 0 仍表示全局天赋。 |

### 1. 技能状态与施法事务

- 技能来源区分当前武器普通技能与具体火焰实例，不以一个 SkillId 混用两者。普通技能使用独立入口、从武器配置解析；六槽只引用火焰实际变体，空槽无默认回退。
- 同一火焰最多一个槽；拖移 / 改分配采用原子移动，不复制引用，旧槽清空。不同火焰即使同定义仍独立。普通技能绑定当前武器能力入口，施法时再证明实际武器身份，换武器后的旧请求必须失效。
- 提供分配 / 清除槽位 Command 和六槽 Query；绑定预检与提交捕获玩家、Session、棋盘 / 成长 / 火焰修订。取回火焰原子清除相关绑定，失败保持绑定、棋盘与冷却原状。
- 冷却由技能系统按玩法时间维护，保存剩余值；火焰拟按实例持有冷却，普通技能拟按玩家普通技能入口持有冷却，换武器保留剩余等待。读 Query、换槽、取回再安装不能刷新冷却。背包中的同实例保留未结束冷却，交易 / 所有者转移纳入统一物品事务与保存合同，不产生两个冷却权威。
- 请求捕获槽位、武器 / 火焰身份、瞄准方向和 Session 世代，按序提交；生成前及最终提交前重新验证存活、Gameplay、挂起 / 暂停、动作许可、来源资格、冷却、法力和伤害来源。异步路径不能让另一枚火焰或另一把武器接管旧请求。
- 成功仅一次扣蓝、一次启动冷却、一次攻击通知。空槽、非法瞄准、过期来源、冷却中、法力不足、生成失败或取消均不扣蓝 / 启动冷却 / 补发。保留攻击种子的既有消费边界；生成失败不凭空承诺随机流回退。
- 复用已预热 Addressables 和 SpawnSystem；需要新增异步预热时绑定 Scene / Session 取消与资源 owner。并发请求不得在资源等待后各自通过同一份旧冷却 / 法力检查。

### 2. 棋盘效果与攻击快照

- 纯解析器消费不可变棋盘、成长激活与实际道具词条，输出全局来源和按 Flame InstanceId 分类的局部来源；范围走实际保存的天赋连线与裂缝配对图，不能用几何直线距离代替。查询与预览不得重新掷骰、点亮节点或改写 Model。
- 路径在已点亮网络上用 BFS 求最短步数，每条保存的连线或裂缝配对算 1 步，跨空格也不加权；未点亮天赋阻断，距离不超过范围时生效。覆盖无路径、环、多入口和跨根，中柴薪空白中心和棋盘中央保留区不得凭空接通路径。旋转 / 平移不改变同一连线身份。
- 全局普通天赋只在所属柴薪及该节点已点亮时进入 Actor 聚合，一来源应用一次。局部普通天赋遵守相同激活条件，按最终范围规则筛选火焰。
- 火焰自身隐式 / 显式词条只作用于自己；余烬仅在已点亮柴薪的合法未连接裂缝中生效，不额外创造点亮费用。目标火焰也须满足技能激活资格；既有裂缝连接互斥规则保持。武器普通技能接受全局天赋及现有合法装备效果，不冒充任意一枚火焰取得范围加成。
- 来源键包含玩家、柴薪 / 节点或嵌入物身份，目标键包含火焰实例。扩展 Origin 解释显示，不能仅靠同一个 SkillId 或 Scope.Skill 区分火焰，也不能把局部效果塞进角色全局修改器。
- 旋转、平移、重连、点亮、嵌入 / 取回和恢复只重建受影响投影；预检先准备最终态，提交后统一通知，不依赖多个 Event 回调按偶然顺序修补可用性 / 效果。
- 快照分别携带技能定义、火焰来源与现有武器伤害来源；发射后冻结本次词条与状态应用。飞行中换盘不改变已发出攻击，后续攻击读取新投影。
- 复用 `IStatusSourceRestoreProvider` 的所有权证明接口补齐 Talent 来源，验证节点 / 嵌入身份及激活资格；原生修改器仍从棋盘重建，没有维持状态配置时不额外制造状态层。派生效果不另存为第二份权威数据。

### 3. 武器配置、新游戏、存档与兼容

- 武器配置新增普通技能引用，非武器不得配置该能力；正式大剑、战斧等武器分别配置对应普通技能，使用已有技能定义 / 伤害管线。技能 Prefab、合法伤害来源、内容登记、Localization 和 Addressables 一并验证，避免给所有武器硬编码同一个场景技能。
- NewGame 先使用既有命令发放 / 装备起始武器，再建立独立普通技能入口；六个火焰槽初始为空。无须发放或激活任何棋盘道具，普通技能不消耗天赋点。
- Schema 11→12 拟加入类型明确的技能来源、六槽及冷却；旧 SkillContentId / AutoCastCooldownRemainingSeconds 仅用于历史迁移，转为当前装备武器的普通技能与剩余冷却，不伪造火焰实例。旧技能与武器新映射不同的情况提供明确兼容映射 / 诊断，不能静默丢弃旧等待时间。
- 历史迁移不新增物品或成长点数，已有棋盘 / 所有权 / 变体 / 属性 / 随机状态保持。没有装备武器的存档保留无普通技能状态，仍可从已有背包 / 商店装备武器获得；测试覆盖此路径，而不反复发起始武器。历史迁移链保留真实夹具，新 Schema 缺失字段不能误走旧档迁移。
- 六槽分配是玩家数据，按键覆盖是 Application 设置。Settings Schema 预计保持 1，只追加稳定的新 Action / Binding 身份，保留原覆盖；地图仍为 V4。core 拟升 v13，兼容映射与真实新增内容同时验证，最终版本以落地合同为准。
- Restore 先验证来源类型、武器装备关系、火焰所有者 / 唯一槽位、技能内容一致、冷却有限非负、成长和拓扑，再构造派生效果与技能运行态，最后恢复资源。失败不替换现有 Session；切图 / 复活 / 重绑 Controller 不清冷却或启动施法。

### 4. 输入、瞄准与最小 HUD

- Skill1–Skill6 采用 Button / 单次按下交互；沿用唯一 Application Action Asset，Session Adapter 对称订阅 / 释放。输入上下文切换继续走现有 onAfterUpdate 路径。
- Attack 驱动独立普通技能，保留鼠标左键 / 手柄西键；Skill1 使用手柄东键，Skill2 使用南键，其余四槽使用肩键 / 扳机。所有七个入口均可重绑定；一按不能同时施放普通技能和火焰，保留已有 Action / Binding GUID。
- Gameplay 中现有 HUD 按钮也使用鼠标左键；命中可交互 UI 的同次点击必须被消费，不得同时触发普攻。UI Context 切换、冲突 / 必填校验、恢复默认与设置提交回滚复用既有流程。
- 指针瞄准通过现有 Point 数据换算玩法平面，手柄读取 Look 右摇杆并处理死区；无有效方向沿用上次方向，按下时冻结请求方向。GlyphPreference 仅控制提示样式，不能被当作当前瞄准设备；有效瞄准不被移动朝向或自动寻敌覆盖。
- UI、重绑定捕获、Busy / Modal、失焦、平台挂起、死亡、设备断开与 Session 退出丢弃未提交请求。恢复后旧按住状态必须释放再按，不能因 Action 重新启用回放而补发。命令层复核这些条件。
- 最小 HUD 区分独立普通技能与六火焰槽，显示实际来源、图标 / 名称、绑定提示、剩余冷却 / 比例、耗蓝和不可用原因；空槽清晰可辨，换武器同步更新普通技能。复用已有武器 / 火焰 Sprite 与公共样式，未引入新美术需求时不额外生成贴图。
- 优先 UIToolkit，通过 Unity MCP 创建 / 调整 UI；沿用 PanelSettings、Localization、PrimeTween / Reduce Motion 和 HUD 的 Session 刷新作用域。只读刷新不推进技能时钟，禁用 / 重进不保留旧 Actor 或事件。
- 开发窗口支持明确火焰 ID 分配 / 清槽，显示六槽、冷却和局部来源清单，调用正式 Query / Command；不把 Odin 开发入口标为正式玩家分配 UI 已交付。
