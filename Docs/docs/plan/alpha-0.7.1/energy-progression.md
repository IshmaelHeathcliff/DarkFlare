# 0.7.1 能量瓶与天赋成长合同

状态：2026-10-06，**用户规则与三项澄清已确认，尚未实现**。主入口见[执行计划](../alpha-0.7.1-skill-board-plan.md)，验证入口见[阶段验收清单](acceptance.md)。

## 已确认规则

| 对象 | 规则 |
| --- | --- |
| 能量瓶 | 暂定小、中、大三种，容量不同；三种背包占位均为 **2×1**，不是按容量改变物理尺寸。具体容量尚未指定。 |
| 专属装备栏 | 增加能量瓶专用装备栏，装备后即可积蓄打怪获得的能量。背包内未装备瓶不能因持有而自动积蓄。 |
| 棋盘中心 | 能量瓶可放入中心充能；不要求满瓶。充入瓶内实际能量，同时消耗该瓶，不变成可重复使用的空瓶。 |
| 剩余能量 | 不足兑换下一点的能量保留在角色充能池，跨瓶累计；不能因消耗瓶子而丢失。 |
| 点数产出 | 每兑换 **1 天赋点，同时获得 1 基础属性分配点**。属性点用于力量、敏捷、智力；两类点数分别分配 / 消耗。 |
| 天赋点成本 | 每获得一个新天赋点，所需能量逐渐升高。具体曲线与数值未指定。 |
| 点亮 | **柴薪和普通天赋分别花天赋点点亮**。放置不等于点亮，点亮柴薪不自动激活其周围普通天赋。 |

智力使用现有稳定 ID `intelligence`，力量和敏捷使用 `strength`、`dexterity`；此前面板中的“智慧”统一对应智力，不新增第四种基础属性。

## 能量瓶与击杀积蓄

- 容量来自瓶型配置，已存能量属于瓶子实例数据，必须满足 `0 ≤ 已存能量 ≤ 容量`。物品移动、换装、保存恢复和允许的所有权转移都保留实际能量，不按瓶型重新填满或清空。
- 拟定每件瓶子具有稳定 `ItemInstanceId`，不堆叠；复用背包和装备的原子移动 / 交换规则。专用栏具有稳定身份，不借用腰带槽、不重编号既有十个战斗装备槽。
- 本版拟定以有效怪物死亡结算一次能量收益。复用 `ActorDiedEvent.Source` 的来源快照和稳定角色身份判断受益玩家；不能从当前 HUD 选择、附近玩家或某个 Controller 猜测归属。
- 获益只写入当时该玩家专栏中的瓶子；未装备不写背包其他瓶。满瓶与超出容量的收益处理尚待确定，先严格限制容量，不能静默生成第二瓶或转存角色充能池。
- 怪物 / Boss 能量收益通过配置表达，具体数量和瓶子获得渠道待确定。能量结算与普通掉落分开，不默认消耗掉落 / 攻击随机流，也不改变既有有限刷怪或重置规则。
- 正常攻击、持续伤害和有效来源的延迟死亡使用同一归属边界。无有效玩家来源、场景销毁 / 退图、重复死亡通知及读档重建不重复奖励；复用既有死亡 / 运行结算边界，必要去重状态归属对应 Run 生命周期。

现有 `ItemInstance` 没有瓶内能量字段，装备兼容当前只接受战斗装备类型；能量瓶需要专门的物品能力和持久化实例状态，不能伪装成饰品或把蓄能当成临时状态。现有[装备事务](../../equipment-system.md)与[统一物品](../../item-system.md)可复用。

## 中心充能与递增兑换

中心操作拟定为“放入 / 选择瓶子 → 查看本次充能结果 → 确认充能”。放置预览不提前消费；确认后整瓶一次性消费并转入实际能量。是否允许直接从装备栏提交、中心实际持有还是短暂引用，按统一所有权合同在阶段二确定。

角色持有：剩余充能池、累计已获得天赋点数、可用天赋点、可用基础属性点、三属性已分配点数，以及柴薪 / 天赋激活记录。这些数据属于玩家成长，不能绑在当前瓶子或某件柴薪上。

递增成本拟定按**累计已获得天赋点数**索引，不按剩余未花点数或当前瓶型计算。令已获得 n 点，下一点成本为 `Cost(n + 1)`，成本为正且逐点严格递增；消费 / 分配点数、换瓶、切图和读档不能降低该序号。曲线可通过配置表示，例如正基础值与正增量的递增公式；本计划不指定平衡数值。

一次充能的候选计算：

1. 将瓶内实际能量加入角色剩余充能池。
2. 按下一点成本依次兑换，扣除对应能量，并递增累计获得数。
3. 每兑换一次，增加 1 可用天赋点和 1 可用基础属性点。
4. 保存最后剩余能量，未达到下一阈值也允许完成充能并消费瓶子。

纯算例（不是正式数值）：前三点成本为 10、20、30，已有 0 点时充入 35 能量，得到 2 天赋点、2 属性点，保留 5 能量，下一点成本为 30。拆成 10 与 25 两瓶顺次充入，应获得相同点数和余量；花掉那 2 天赋点后，下一点仍需要 30。

零能量瓶能否充能尚未指定；建议拒绝无变化并保留瓶子。充能池 / 容量 / 成本 / 点数采用明确能量单位与上限，预检算术溢出、非法曲线与超额兑换，不能因大容量执行无界循环或静默裁掉玩家资产。

瓶子消费、装备 / 背包 / 中心槽清除、充能池、累计获得数和两类点数须作为同一事务提交。预览记录物品与成长 Revision、配置 / Session 身份，提交前复核；失败、取消和过期预览保持原状态，重复提交不能再消费或再加点。通知发布后异常不等于未成功，调用方须重新查询最终态。

现有[物品使用](../../item-use-system.md)仅支持背包所有权与生命 / 法力 / Timed 状态 / 驱散；本版复用其预检、提交与消费框架，但需要明确成长投影与专用插槽的协调入口，不能将永久成长伪装成一次性恢复或限时 Buff。

## 属性分配与天赋点亮

- 属性点通过 Command 分配到力量、敏捷或智力，预检余额并保存分配结果；成长基础值进入现有 `PrimaryAttributeResolver` 管线，不修改共享角色配置资产，也不重复累计上次聚合结果。
- 属性重建遵循现有主属性派生和生命 / 法力上限变动规则。全局天赋的加值与永久分配点分别证明来源，避免保存有效属性后又从分配记录重复应用。
- 柴薪激活使用道具实例身份；普通天赋激活使用该实例下的稳定局部节点身份。点亮须校验物品归属、节点角色、网络条件和可用点数，整次扣点与激活状态原子提交；重复点亮不能重复扣点或重复生效。
- 点亮柴薪后普通天赋仍分别等待点亮；未点亮的普通天赋不提供全局或局部词条。可放置的几何与可生效的激活网络分别查询，UI 不能以可放置状态推断已生效。
- 点亮柴薪是否同时解锁中心火焰、裂缝是否需要点数、每次点亮消耗几点，以及未点亮上游能否继续点亮下游，仍待确定。技能运行时须按最终激活合同校验火焰可用性，不通过六槽绑定绕过。
- 取回 / 转移已点亮柴薪时，点数与激活记录如何处理仍待确定；无论选保留、返还或重置方案，都不能复制成长收益、降低累计兑换成本或让未拥有的物品继续提供效果。洗点 / 退款费用不自动纳入本版。

## 持久化与阶段落点

- 阶段二交付三种瓶型、2×1 占位、专栏、积蓄和瓶内能量保存；阶段三交付中心充能、递增兑换、属性分配、柴薪 / 天赋独立点亮及对应成长保存。阶段四将激活资格接入六键技能与效果；阶段五完成正式操作、显示与综合验收。
- 新档保存瓶内能量、专栏所有权、成长余额 / 累计数、属性分配和激活身份；旧档迁移显式初始化成长状态，不重复兑换或重放死亡奖励。先前技能兼容方案必须与起始点亮规则一起核对，避免出现已分配但不可使用的软锁。
- Restore 预检覆盖负值 / 越容量、重复所有者、非法点数、未知节点、未拥有物品激活和错误成本合同；迁移或预检失败不污染当前 Session。读取只恢复权威状态与派生结果，不再次消费瓶子或发放点数。
- 容量、能量收益、兑换曲线和点亮成本以配置为准；发布后调整需明确内容 / 存档兼容策略，旧余额不能因配置热变更被静默重复兑换。
