# 0.7.1 能量瓶与天赋成长合同

状态：2026-10-15，**阶段三已按用户确认建议完成**。阶段三交付时为 `0.7.1-alpha.3`、core v12 / Schema 11；当前阶段四为 alpha.4 / core v13 / Schema 12；中心充能、成长和点亮见[模块](../../skill-board/growth.md)，[实施与证据](../archive/0.7.1/acceptance/growth/README.md)已归档。天赋 / 余烬效果与六键技能已由[阶段四模块](../../skill-board/manual-skills.md)接入。

## 已确认规则

| 对象 | 规则 |
| --- | --- |
| 能量瓶 | 小、中、大容量暂定 **1000 / 2000 / 4000**；三种背包占位均为 **2×1**。价格随容量档位类似增长，小瓶基价暂定 **100**，按容量倍率暂列中瓶 **200**、大瓶 **400**。 |
| 获得渠道 | 柴薪、火焰、余烬、能量瓶四类均可怪物掉落与商店购买，使用现有物品内容与货池。 |
| 专属装备栏 | 只有装备的能量瓶能积蓄打怪能量，超出容量的部分直接舍弃；满瓶停止收集，玩家必须手动更换装备瓶子。背包瓶不自动积蓄或自动装备。 |
| 怪物能量 | 每种怪物有基础能量值；词条数量、怪物整体稀有度与词条自身稀有度均提高收益。已实现首轮可配置整数公式，具体平衡见能量瓶模块，未视为最终值。 |
| 棋盘中心 | 能量瓶可放入中心充能；不要求满瓶。充入瓶内实际能量，同时消耗该瓶，不变成可重复使用的空瓶。 |
| 剩余能量 | 不足兑换下一点的能量保留在角色充能池，跨瓶累计；不能因消耗瓶子而丢失。 |
| 点数产出 | 每兑换 **1 天赋点，同时获得 1 基础属性分配点**。属性点用于力量、敏捷、智力；两类点数分别分配 / 消耗。 |
| 天赋点成本 | 每获得一个新天赋点，所需能量逐渐升高。首轮采用第 n 点消耗 100＋25×(n−1)；每次点亮柴薪 / 普通天赋各花 1 点，1 属性点增加 1 对应主属性。 |
| 点亮 | **柴薪和普通天赋分别花天赋点点亮**。放置不等于点亮，点亮柴薪不自动激活其周围普通天赋。 |

智力使用现有稳定 ID `intelligence`，力量和敏捷使用 `strength`、`dexterity`；此前面板中的“智慧”统一对应智力，不新增第四种基础属性。

## 能量瓶与击杀积蓄

- 容量来自瓶型配置，已存能量属于瓶子实例数据，必须满足 `0 ≤ 已存能量 ≤ 容量`。物品移动、换装、保存恢复和允许的所有权转移都保留实际能量，不按瓶型重新填满或清空。
- 每件瓶子具有稳定 `ItemInstanceId`，不堆叠；复用背包和装备的原子移动 / 交换规则。专用栏具有稳定身份，不借用腰带槽、不重编号既有十个战斗装备槽。
- 以有效怪物死亡结算一次能量收益。复用 `ActorDiedEvent.Source` 的来源快照和稳定角色身份判断受益玩家；不能从当前 HUD 选择、附近玩家或某个 Controller 猜测归属。
- 获益只写入当时该玩家专栏中的瓶子，收集量为 `min(本次收益, 容量 - 已存能量)`，超出部分直接舍弃。未装备 / 满瓶收集量为零，不转存背包瓶或角色充能池；满瓶后由玩家手动更换，不能自动换瓶或追补已经舍弃的收益。
- 每种怪物配置基础能量，结合该实例实际词条数量、怪物整体稀有度与各词条自身稀有度计算最终收益；固定其他条件，词条更多或任一种稀有度更高时能量收益提高。首轮采用普通 / 魔法 / 稀有 / 独特 0–3 级，基础能量乘 1＋怪物等级，再加数量与词条等级项；使用检查溢出的整数计算，实际参数见[模块](../../skill-board/energy-bottles.md)。不将生成权重等同于稀有度，不在死亡结算时重掷词条。
- 四类道具已接入怪物掉落与商店购买，八项正式内容与首轮权重见[安装模块](../../skill-board/items-installation.md)。能量结算与普通掉落分开，不消耗掉落 / 攻击随机流，也不改变既有有限刷怪或重置规则。
- 正常攻击、持续伤害和有效来源的延迟死亡使用同一归属边界。无有效玩家来源、场景销毁 / 退图、重复死亡通知及读档重建不重复奖励；复用既有死亡 / 运行结算边界，必要去重状态归属对应 Run 生命周期。

容量截取算例：小瓶已存 990 / 1000，怪物收益为 50，则瓶子收集 10 达到 1000，另外 40 舍弃；随后满瓶击杀不收集。玩家手动换上另一瓶后，只收集更换之后的有效击杀收益，先前舍弃的 40 不补发。

阶段二已为 `ItemInstance` 接入瓶内能量和独立专栏，见[当前模块](../../skill-board/energy-bottles.md)；[装备事务](../../equipment-system.md)与[统一物品](../../item-system.md)继续复用。阶段三已交付以下中心与成长合同，当前模块见[中心充能、属性与点亮](../../skill-board/growth.md)。

## 中心充能与递增兑换

中心开发入口采用“放入 / 选择瓶子 → 查看本次充能结果 → 确认充能”。放置预览不提前消费；确认后整瓶一次性消费并转入实际能量。中心短暂引用背包或专栏中的瓶子，原容器保留所有权，选择 / 取消不移动资产；阶段三确认时从原容器原子消费，不另存一份中心物品。选择失效或瓶子持续积蓄后重新预检，详见成长模块。

角色持有：剩余充能池、累计已获得天赋点数、可用天赋点、可用基础属性点、三属性已分配点数，以及柴薪 / 天赋激活记录。这些数据属于玩家成长，不能绑在当前瓶子或某件柴薪上。

递增成本按**累计已获得天赋点数**索引，不按剩余未花点数或当前瓶型计算。令已获得 n 点，下一点成本为 `Cost(n + 1)`，成本为正且逐点严格递增；消费 / 分配点数、换瓶、切图和读档不能降低该序号。首轮成本公式为 100＋25×n（n 为已经累计获得的点数），由正基础值与正增量配置。

一次充能的候选计算：

1. 将瓶内实际能量加入角色剩余充能池。
2. 按下一点成本依次兑换，扣除对应能量，并递增累计获得数。
3. 每兑换一次，增加 1 可用天赋点和 1 可用基础属性点。
4. 保存最后剩余能量，未达到下一阈值也允许完成充能并消费瓶子。

首轮算例：前三点成本为 100、125、150，已有 0 点时充入 425 能量，得到 3 天赋点、3 属性点，保留 50 能量，下一点成本为 175。拆成 100 与 325 两瓶顺次充入结果相同，花点后下一点仍需要 175。

零能量瓶已确认拒绝充能并保留。充能池 / 容量 / 成本 / 点数采用明确能量单位与上限，预检算术溢出、非法曲线与超额兑换，不能因大容量执行无界循环或静默裁掉玩家资产。

瓶子消费、装备 / 背包 / 中心槽清除、充能池、累计获得数和两类点数须作为同一事务提交。预览记录物品与成长 Revision、配置 / Session 身份，提交前复核；失败、取消和过期预览保持原状态，重复提交不能再消费或再加点。通知发布后异常不等于未成功，调用方须重新查询最终态。

现有[物品使用](../../item-use-system.md)仅支持背包所有权与生命 / 法力 / Timed 状态 / 驱散；本版复用其预检、提交与消费框架，但需要明确成长投影与专用插槽的协调入口，不能将永久成长伪装成一次性恢复或限时 Buff。

## 属性分配与天赋点亮

- 属性点通过 Command 分配到力量、敏捷或智力，预检余额并保存分配结果；成长基础值进入现有 `PrimaryAttributeResolver` 管线，不修改共享角色配置资产，也不重复累计上次聚合结果。
- 属性重建遵循现有主属性派生和生命 / 法力上限变动规则。全局天赋的加值与永久分配点分别证明来源，避免保存有效属性后又从分配记录重复应用。
- 柴薪激活使用道具实例身份；普通天赋激活使用该实例下的稳定局部节点身份。点亮须校验物品归属、节点角色、网络条件和可用点数，整次扣点与激活状态原子提交；重复点亮不能重复扣点或重复生效。
- 点亮柴薪后普通天赋仍分别等待点亮；未点亮的普通天赋不提供全局或局部词条。可放置的几何与可生效的激活网络分别查询，UI 不能以可放置状态推断已生效。
- 已确认柴薪点亮后开放裂缝，大柴薪点亮后开放中心火焰；裂缝不单独花点。中小柴薪须经已点亮柴薪连根；普通天赋沿显式连线从中心或有效接入裂缝逐点点亮。技能运行时在阶段四消费此资格，不通过六槽绑定绕过。
- 取回时清除当前柴薪及普通天赋激活并退还实花天赋点；累计兑换数和属性分配保持。其余激活失去路径时拒绝，背包不足也不能先退点，不自动连带退款；转移前仍须先取回。没有额外洗点 / 退款费用。

## 持久化与阶段落点

- 阶段二交付三种瓶型、2×1 占位、专栏、积蓄和瓶内能量保存；阶段三交付中心充能、递增兑换、属性分配、柴薪 / 天赋独立点亮及对应成长保存。阶段四已将激活资格接入六键技能与效果；阶段五完成正式操作、显示与综合验收。
- 新档保存瓶内能量、专栏所有权、成长余额 / 累计数、属性分配和激活身份；旧档迁移显式初始化成长状态，不重复兑换或重放死亡奖励。先前技能兼容方案必须与起始点亮规则一起核对，避免出现已分配但不可使用的软锁。
- Restore 预检覆盖负值 / 越容量、重复所有者、非法点数、未知节点、未拥有物品激活和错误成本合同；迁移或预检失败不污染当前 Session。读取只恢复权威状态与派生结果，不再次消费瓶子或发放点数。
- 容量、能量收益、兑换曲线和点亮成本以配置为准；发布后调整需明确内容 / 存档兼容策略，旧余额不能因配置热变更被静默重复兑换。
