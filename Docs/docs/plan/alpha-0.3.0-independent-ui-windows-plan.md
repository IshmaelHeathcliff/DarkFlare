## 阶段目标

将现有“共享背包列 + 互斥页签”改成独立背包、商店与打造窗口。每个窗口有独立标题、关闭、选择和内容区域；窗口组合时保持物品操作一致，关闭一个不影响其他窗口。

同时完成整轮 UI 的布局线框与一个代表组件视觉样例，供后续属性、HUD 和统一皮肤阶段沿用。本阶段不要求批量生成完整皮肤。

优先复现并修复用户反馈：打开设置 / 返回主菜单确认不关闭背包，手动关闭背包后上层界面无法交互。统一物品操作、唯一高亮和详情排版在本阶段完成，不延期到统一皮肤阶段。

## 窗口与上下文合同

- 背包入口只开关背包；商人 / 工作台交互分别打开对应功能窗口。已有背包窗口不因新功能窗口打开而关闭。
- 商店与打造各提供“打开背包”入口，但初次单独打开不强制显示完整背包；重复打开同一窗口只聚焦已有实例。
- 背包独立显示时保持整理、穿脱和物品详情；属性入口在后续阶段接入独立详情面板。
- 商店独立显示时可买卖：购买读取商人库存；出售使用本窗口的玩家物品选择视图，数据仍来自同一 InventoryModel。已有实例 ID 失效时不得对旧对象提交交易。
- 打造独立显示时，使用紧凑目标选择器读取背包中的可打造物品，确认后放入槽位；背包打开时也能拖入。选择器复用只读物品投影和详情组件，不复制玩法状态。
- 打造物品继续归属于背包并占原格。关闭背包不清空打造槽；关闭打造窗口释放槽的表现占用、取消待执行输入，物品仍在原背包位置，不额外发送取回或发放事务。
- 商店或打造目标失效时关闭 / 禁用对应功能并给出本地化原因；仅有窗口可见不能绕过世界交互授权。
- 商店和打造的同开权限由实际交互上下文决定。本阶段只保证现有有效组合，窗口容器不自行生成新的交易目标。

## 共享物品交互

- 每个窗口可记忆自己的选择与默认焦点，但全局只有一个可见物品高亮和一个详情来源；悬停、手柄焦点、固定选择、拖放由同一活动来源仲裁。只读物品投影按实例 ID 更新，不依赖另一个窗口可见。
- 同一时刻只有一个物品拖放会话。移动 / 穿脱复用已有领域 Command；指定格购买和丢弃补齐必要事务，所有路径都预检来源与目标，失败或取消不移动物品、不扣费。
- 物品拖放与窗口激活分开：单击固定选择；越过现有拖动阈值才拿起；非法目标、关闭来源 / 目标窗口、切换 Session 时统一取消。
- 支持背包与装备槽双向拖动、商品拖到背包指定格购买、背包物品拖到明确出售区卖出、背包与打造槽双向拖动，以及背包物品拖到明确丢弃区转为世界掉落。任意窗口背景不是出售 / 丢弃目标。
- 右键与手柄快捷操作按照可见且已授权的当前上下文路由；普通背包右键不得因后台隐藏商店而出售物品。多义操作显示明确动作名称，丢弃提供显式入口；完整矩阵见[交互合同](./alpha-0.3-item-interaction-contract.md)。
- 物品浮窗为窗口宿主拥有的共享展示实例，跟随来源窗口定位；不依赖固定大面板，不抢焦点，也不阻挡拖放落点或窗口关闭按钮。
- 来源窗口关闭、物品失效或拖放取消后隐藏旧浮窗；下一次主动预览再显示，保留已有防闪现合同。

## 暂停、焦点与输入

- 窗口显示状态与 Game Flow 状态分别管理，不直接用一个 UI Map 开关推断所有窗口应显示。
- 第一个玩法窗口打开时取得本组窗口的 UI Context / pause 所有权；最后一个关闭时释放。窗口间切换不反复暂停 / 恢复，不释放 Settings / Modal / Platform 的 lease。
- 进入 Settings 或确认 Modal 时，应用上层先接管输入和暂停，再隐藏底层玩法窗口、详情和拖动图标；保存可恢复的窗口组合与选择。Settings 返回 / Modal 取消后恢复仍有效的窗口及焦点；确认返回主菜单成功后清空旧状态。
- 顶层状态由唯一输入入口解析，不使用“关闭背包即 SwitchToGameplay”作为通用逻辑。现有 Input suspension 会禁用输入，不可把它当作可交互 UI Context；必要时扩展最小上下文所有权接口。
- 返回操作顺序：顶层应用 Modal / Settings → 当前拖放 / 目标选择器 → 当前功能窗口 → 无 UI 所有者时恢复 Gameplay；一次输入只消费一层。确认删除存档等应用流程不被玩法窗口截获。
- 鼠标操作激活命中的窗口；手柄提供明确的窗口循环导航，显示活动窗口和当前控件焦点，使用唯一 Input Actions 资产及 Glyph。
- 手柄四向导航以实际布局为准，包含同面板物品和边缘相邻窗口；背包 ↔ 商店、背包 ↔ 打造及装备栏 ↔ 背包均双向可达，不以循环切窗键替代自然方向移动。浏览与拿起状态规则见[空间导航合同](./alpha-0.3-item-interaction-contract.md#手柄空间导航)。
- 新增动作先检查现有绑定与冲突，支持键鼠 / 手柄和重绑定；不在 Controller 轮询设备或硬编码提示键名。
- 旧的保存 / 设置 / 返回前台入口迁入可独立访问的暂停菜单，不要求背包可见；保存失败保持现有 Session 和窗口状态。
- 关闭并重开窗口恢复有效选择，但新 Session 不复用旧物品、焦点、拖放或交互目标。所有异步定位与焦点恢复都校验当前窗口 / Session 代次。

## 布局与视觉预研

- 正式验收尺寸为 1920×1080；首轮采用固定停靠与确定性排列，窗口标题、动作区和物品浮窗必须位于安全区内。
- 共用标题、内容与操作栏的对齐基准；物品详情根据真实本地化文本换行和扩展，最高词条容量无超框、截字或互相覆盖。动态刷新和拖动图标不得造成面板跳位。
- 先做背包单窗、商店单窗、打造单窗、背包 + 商店、背包 + 打造、背包 + 属性位置预留的线框；保留 HUD 战斗仪表的底部空间。
- 背包保持 10×6 真实占格，本阶段运行四槽，同时验证收尾十槽的布局线框和导航空间。商人保留既有库存容量与稳定顺序，不能靠隐藏商品解决窗口尺寸问题；新增内容的展示容量由收尾阶段明确处理。
- 以暗石内底、旧铁外框和金铜强调做一个代表组件样例；再定义面板、按钮、槽位和 HUD 仪表的共同像素密度、边距、状态色及文字层级。
- 位图生产前按单图工作流冻结准确画布、可见范围、九宫格保护区和三档控件使用尺寸；代表组件通过后才在后续阶段扩展家族。
- 原型组合图仅作为不可导入的参考；实际 UXML / USS 布局通过 Unity MCP 创建 / 验证，打开的场景不直接改 YAML。

## 成功标准

- 背包、商店和打造分别单独可完成其已有核心操作，不依赖一个隐藏背包 Controller 执行 UI 工作。
- 背包 + 商店与背包 + 打造均通过打开、选择、操作、关闭其中一个、重开和继续操作的完整流程。
- 上下左右导航与实际视觉位置一致；不同尺寸物品、稀疏网格、空装备 / 打造槽、面板边缘及移动中重排均通过双向导航验证，一次方向输入只执行一步。
- 背包满、商品售空、金币不足、打造无候选、目标被装备 / 出售及拖放途中关闭窗口均安全失败或正确收敛；没有物品丢失、重复成交或重复扣费。
- 键鼠与手柄均能跨窗口导航；焦点不进入隐藏控件；Settings / Modal 往返后可继续操作；所有玩法窗口关闭后输入与时间状态正确。
- 打开设置 / 返回主菜单确认立即隐藏背包等玩法窗口；上层可以点击、导航、提交及返回。关闭底层窗口或同帧重复返回不会切断上层输入，也不会穿透到世界。
- 装备、丢弃、买入、卖出、打造放入 / 取出均通过[交互合同](./alpha-0.3-item-interaction-contract.md)的鼠标与手柄路径；丢弃保留物品实例及词缀，生成失败无损，重新拾取和存档恢复无重复。
- 跨窗口 / 跨设备切换、刷新及拖动期间最多一个物品高亮；目标区提示不把第二件物品画成选中。无长文本超框、面板错位或旧浮窗覆盖当前信息。
- 正式语言和 Pseudo Locale 下，最长物品名与高词条详情无关键内容遮挡；物品浮窗和拖放 ghost 不遮住必要操作。
- 三次 Session 往返后无窗口、事件订阅、异步任务或资源句柄累积；现有存档可继续，窗口状态不进入存档。
- 相关领域、窗口行为、输入与生命周期测试通过；正常路径 Console 零新增 Error / Warning；测试使用隔离用户数据根。
