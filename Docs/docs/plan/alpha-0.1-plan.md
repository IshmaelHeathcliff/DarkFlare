# alpha 0.1 开发计划

> 状态：开发中
> 建立日期：2026-08-09
> 最近更新：2026-08-12
> 当前阶段：`alpha 0.1.7` 阶段 A 已完成；下一步执行阶段 B（Pilot、逐帧生产与自动审计）
> 前置条件：首版单场景最小循环、初步体验优化与 `alpha 0.1.0` 物品 UI 工作台已完成

## 版本定位

`alpha 0.1` 的目标是在现有单场景循环上建立可扩展的战斗基础：统一标签语义，补齐命中、暴击、防御、伤害类型、资源消耗与恢复，建立可生成且可辨认的物品和怪物词条，以不可定向指定词条的随机打造形成装备迭代，并以多帧技能、命中反馈完成玩家可感知的闭环。

已完成的 `alpha 0.1.0` 保留为本版本的物品交互与信息展示基础。后续阶段不重做该 UI，而是在现有装备、背包、属性详情和浮动信息窗口上接入新增属性、词条与战斗结果。

此前暂缓的战斗标签改进已在 `alpha 0.1.1` 完成，实施记录归档于[战斗标签系统改进计划](./archive/combat-tag-system-improvement-plan.md)，当前契约见[战斗标签系统](../combat-tag-system.md)。

## 当前基线与剩余缺口

- 现有伤害计算已经支持物理、火焰、冰霜、闪电、混沌五类伤害，以及转换、额外伤害、增伤、更多伤害、承伤修正、护甲和抗性结算分解。
- `AttackSnapshot` 已冻结具名随机子流，命中 / 闪避与暴击在接触目标时正式判定，并通过结构化结果事件驱动表现。
- 当前武器技能只读取已装备武器的基础伤害；空手不再回退到技能配置或代码常量，新游戏由启动事务授予并装备初始大剑。
- 角色现已同时维护当前生命与当前法力；技能耗蓝、两类恢复、资源事件和 HUD 反馈已完成。
- 当前共有 23 个公开属性，新增生命恢复与法力恢复均有运行时消费者。
- 当前怪物只有基础定义和实例属性，没有可复现的怪物词条生成、显示与调试信息。
- 玩家、怪物与世界阻挡已完成 Layer 分层；角色之间不产生实体阻挡，怪物使用停止距离与稳定软分离，接触伤害仍由每只怪物按独立攻击间隔持续结算。
- 当前投射物命中特效复用投射物静态 Sprite 做缩放淡出，角色受击主要是闪白；尚无独立多帧技能和受击特效。
- 当前打造允许在 UI 中选择具体词条执行“移除并重随”和“提升数值”；该定向路径不符合后续随机打造定位，需要同时重构领域命令、随机选择与打造 UI。
- 配置中心可发现 `DarkFlare/Data` 下的配置类型，但缺少覆盖全部配置类型、序列化字段、校验和运行时消费者的统一参考文档。

## 范围解释

### 只有武器才会有基础伤害

- 物品基础伤害只允许配置在武器上；护甲、戒指和其他非武器物品不能携带基础伤害骰。
- 当前基础投射物技能使用武器伤害源；未装备有效武器时不能生成基础伤害包，也不能保留 `10–14` 或固定 `12` 的徒手回退。
- `Skill` 伤害源仍保留给未来真正具有技能基础伤害的法术，但不用于绕过当前武器技能的装备要求。
- 为避免新游戏无武器导致最小循环软锁，本阶段必须提供明确的初始武器配置、发放和自动装备路径。

### 所有属性词条

“所有”按公开 `StatId` 覆盖定义，不要求生成属性与层级的笛卡尔积：

- 每个公开属性必须至少有一条合法、可生成、可显示、运行时确实生效的物品词条路径。
- 增加生命恢复和法力恢复后，目标覆盖 23 个公开属性。
- 力量、敏捷、智力已在 `alpha 0.1.5` 阶段 A 冻结并接入集中派生规则；新增词条必须继续验证真实消费者，禁止交付只改面板数字的无效词条。
- 词条适用部位、数值区间、权重、互斥和层级由对应阶段计划冻结，不在总计划中提前假定最终平衡数值。

### 所有配置项文档

配置文档覆盖所有带 `DarkFlare/Data` 菜单入口的配置类型及其嵌套序列化结构。当前基线至少包括标签、属性、词条、物品、角色、投射物技能、怪物、怪物生成、掉落表、商人和打造配置。

每类配置至少记录：

- 资产用途、创建入口和示例资产。
- 全部序列化字段的类型、默认值、合法范围、是否必填和稳定 ID 规则。
- 运行时读取者、资源所有权、随机种子与可复现性要求。
- 编辑器校验、内容校验、常见错误和迁移注意事项。
- 新增字段对旧资产的默认兼容行为。

配置参考文档在 `alpha 0.1.1` 建立骨架，后续每个改变配置结构的阶段必须同步更新；最终通过自动覆盖检查，禁止新增配置类型或字段后无文档交付。

## alpha 0.1.1：标签契约重构

### 目标

消除不同语义域标签的任意并集，让物品生成、词条、角色、技能、攻击和伤害查询都有明确上下文；本阶段不主动改变伤害数值。

### 范围

- 先补充迁移前等价测试，冻结现有物品生成、词条匹配和伤害计算结果。
- 引入 `TagDomain`、作用域标签集合、结构化查询和 `CombatTagContext`。
- 由强类型字段派生物品类别、角色阵营和伤害类型，不再在多处资产中重复手填同一事实。
- 为伤害包区分当前伤害类型、缩放血统和自定义标签，支持转换后仍保留正确的缩放语义。
- 统一攻击上下文构建入口，清理运行时代码中的临时 `TagSet` 拼接。
- 增加配置验证、查询调试输出和标签配置参考文档。

### 成功标准

- 现有物品、词条和伤害结果在迁移前后保持等价。
- 生产路径不再把不同语义域标签无条件合并为一个平面集合。
- 标签查询失败时能输出域、必要条件、任一条件和阻止条件。
- 旧资产的重复标签被验证器识别，并有明确迁移结果。
- 详细实施按[归档的战斗标签系统改进计划](./archive/combat-tag-system-improvement-plan.md)完成。

### 完成记录

- 标签定义已具备 Domain 与使用状态，查询统一为作用域化的 `RequiredAll`、`RequiredAny`、`BlockedAny`。
- 攻击上下文已拆分来源角色、目标角色、技能、来源物品、攻击和伤害作用域；旧平面 `TagSet` 仅作为明确隔离的兼容层保留。
- 物品类别、怪物阵营、投射物技能和伤害类型改为从强类型事实自动派生；正式资产中的重复事实已清理。
- `DamagePacket` 已区分最终伤害类型、缩放血统和自定义标签，转换与额外获得伤害能保留来源类型且只应用一次修改器。
- 37 个相关配置资产经过精准预检，34 个资产完成迁移；二次预检为零待变更、零错误，一次性迁移入口已移除。
- 新增 10 项标签迁移特征测试；最终 EditMode 133/133 通过，PlayMode 12 项通过、2 项因 Input System 环境条件忽略、零失败。

## alpha 0.1.2：伤害判定与武器伤害源

### 目标

让一次攻击明确产生“未命中、闪避、暴击、普通命中或无伤害”等可解释结果，并让武器技能的基础伤害只来自有效武器。

### 范围

- 限制物品基础伤害只存在于武器配置；验证器拒绝非武器基础伤害。
- 移除当前武器技能的徒手与技能默认伤害回退；建立初始武器发放与自动装备。
- 冻结并实现命中率 / 闪避率公式、上下限和确定性随机通道。
- 命中后再进行暴击判定；暴击率与暴击伤害分别消费现有属性。
- 统一结算顺序：目标有效性与特殊阻止 → 命中 / 闪避 → 暴击 → 伤害转换与增益 → 承伤修正 → 护甲 / 抗性 → 生命扣减与事件。
- 完整验证物理、火焰、冰霜、闪电、混沌伤害，以及护甲、元素抗性和混沌抗性。
- `DamageResult` 提供命中结果、暴击结果、各伤害类型结算前后数值和减免来源，供调试、飘字与后续特效使用。
- 为基础伤害、命中和暴击使用独立确定性子随机流，避免调整某一步后改变其他判定序列。

### 成功标准

- 未装备武器时，当前基础投射物技能不造成基础伤害；新游戏仍能通过初始武器正常进入战斗循环。
- 固定配置和固定种子下，命中、闪避、暴击和最终伤害可复现。
- 护甲只减免物理伤害；各抗性只影响对应伤害类型。
- 未命中和闪避不扣生命、不触发受伤反馈，也不会错误显示零伤害。
- 伤害调试信息能够解释一次攻击从基础值到最终值的主要步骤。

### 完成记录

- 武器来源技能已移除空手、技能配置和固定常量回退；启动流程在刷怪前事务性装备初始大剑。
- 命中、闪避、暴击、五类伤害与防御分解均已进入正式属性和确定性随机链，未命中、闪避与零伤害不再触发实际受伤反馈。
- 玩家、三种怪物、基础投射物和相关内容约束已迁移；配置参考与受影响模块文档已同步。
- 全量 EditMode `141/141`、PlayMode `11/11` 通过，四个相关程序集均以零错误、零警告完成构建。

详细公式、配置迁移和验收记录见[已归档的 alpha 0.1.2 执行计划](./archive/alpha-0.1.2-damage-resolution-plan.md)。

## alpha 0.1.3：碰撞与怪群安全

### 目标

玩家可以穿出怪群而不会被实体碰撞卡死，同时保留每只怪物独立、可配置和可测试的接触攻击节奏。

### 范围

- 分离角色移动实体、世界阻挡和受击 / 接触检测职责。
- 玩家与怪物之间不使用会形成围堵的实体阻挡；玩家和世界边界、怪物和世界边界仍保持碰撞。
- 怪物之间不使用实体碰撞，改用停止距离和稳定软分离，避免物理挤压与完全重叠。
- 接触伤害继续按各怪物的伤害半径和独立攻击间隔结算，不增加玩家全局受伤冷却或伤害合并。
- 保留投射物、掉落拾取、商人 / 打造交互 Trigger 和世界边界阻挡。

### 成功标准

- 玩家被多只怪物包围时仍能沿任意可通行方向脱离。
- 改动不允许玩家或怪物穿过地表边界和世界阻挡。
- 怪物不会依靠物理解算挤压玩家，也不会长期完全重叠在同一中心点。
- 三种怪物持续接触时仍分别按 `0.75 / 0.55 / 1.0` 秒间隔独立尝试攻击。

### 完成记录

- 新增 `PlayerActor`、`MonsterActor`、`WorldObstacle` Layer，并精准冻结角色互相忽略、角色与世界及 `Default` 继续接触的 Physics2D Matrix。
- 四个 Actor Prefab 与 `Main.unity/WorldBounds` 已迁移；三种怪物显式保存 `0.6 / 0.8 / 0.65` 停止与软分离配置。
- `MonsterController` 通过 QFramework Query 读取同阵营 Actor，并使用实例种子处理完全重叠；接触伤害入口、独立冷却和命中结算未改。
- 精准迁移首次产生 17 项变更，复跑为 0 项，10 个目标文件复跑前后 SHA-256 完全一致；一次性迁移入口已移除。
- 定向测试 EditMode `6/6`、PlayMode `2/2` 通过；12 只怪物在四个主方向上的玩家位移均达到无阻挡基线的 90%，世界阻挡与 Default Trigger 回归通过。
- 全量 EditMode `148/148` 通过；PlayMode `17` 项中 `15` 项通过、`2` 项为 Input System 上游既有忽略、零失败。

详细合同、迁移与验收记录见[已归档的 alpha 0.1.3 执行计划](./archive/alpha-0.1.3-collision-safety-plan.md)。

## alpha 0.1.4：法力、耗蓝与恢复

详细实施边界、资源合同、迁移步骤和验收记录见[已归档的 alpha 0.1.4 法力、耗蓝与恢复执行计划](./archive/alpha-0.1.4-resource-system-plan.md)。

### 目标

建立生命和法力两种完整运行时资源，让技能消耗与恢复属性成为真实玩法约束。

### 范围

- 保留稳定 ID `mana`，将其明确为最大法力；为 `CombatActor` 增加当前法力。
- 新增 `health_regeneration` 与 `mana_regeneration` 属性定义，公开属性总数达到 23。
- 为投射物技能增加法力消耗配置。
- 在技能真正可以开始时原子校验并扣除法力；法力不足时不生成投射物，且不会进入无意义的高速重试。
- 增加生命、法力变化事件及统一调试信息；HUD 提供当前 / 最大法力的必要反馈。
- 使用可统一取消的系统级异步节拍处理恢复，不在每个 Controller 中建立无管理的 `Update`。
- 明确死亡时是否恢复、重生资源值、最大资源变化时的当前值保持策略。

### 成功标准

- 技能每次成功释放只扣除一次配置法力；失败释放不扣除资源。
- 固定时间窗内生命和法力恢复值可精确测试，且死亡、禁用后不会继续恢复。
- 装备变化导致最大生命 / 法力变化时，当前资源处理符合冻结规则且不越界。
- 玩家能从 HUD 和调试信息中理解技能未释放是因为法力不足。

### 完成记录

- 当前生命 / 法力、上限比例保持、出生与复活满值规则已统一进入 `CombatActor`。
- 基础投射物成功释放消耗 `8` 点法力；玩家以每秒 `1 / 5` 恢复生命 / 法力，暂停、死亡和禁用期间不推进。
- 23 份属性、玩家、三种怪物和技能配置完成精准迁移，复跑为零变更。
- 全量 EditMode `156/156` 通过；PlayMode `18` 项中 `16` 项通过、`2` 项为 Input System 上游既有忽略、零失败。

## alpha 0.1.5：全属性与怪物词条

详细领域合同、内容矩阵、执行切片和验收记录见[已归档的 alpha 0.1.5 全属性与怪物词条执行计划](./archive/alpha-0.1.5-affix-monster-plan.md)。

### 目标

让全部公开属性都能通过合法物品词条进入玩法，并让怪物获得可复现、可辨认且真实生效的属性变化。

### 范围

- 为 23 个公开属性建立词条覆盖矩阵，记录适用物品、修改方式、显示文本和运行时消费者。
- 只交付能够被运行时实际消费的词条；缺少派生规则的属性先补规则和测试。
- 怪物词条使用独立配置模型，不复用物品生成语义。
- `MonsterDefinition` 配置词条池、数量和权重；`MonsterInstanceData` 保存固定种子滚出的词条结果。

- 怪物通过名称、标记或其他统一 UI 反馈展示词条身份；调试信息可查看来源与最终值。
- 物品与怪物词条的配置中心文档、验证器和示例资产同步完成。

### 成功标准

- 23 个公开属性全部有合法的物品词条路径、运行时消费者和自动化验证，不存在只显示不生效的词条。
- 固定怪物定义和种子产生相同的词条、数值与攻击结果。
- 元素伤害、抗性、生命、护甲、闪避和移动速度词条分别能改变对应运行时行为。
- 玩家不依赖调试面板也能识别带词条怪物，详细数值可通过调试入口核对。

## alpha 0.1.6：基础随机打造重构

详细领域合同、随机子流、执行阶段和验收记录见[已归档的 alpha 0.1.6 基础随机打造执行计划](./archive/alpha-0.1.6-random-crafting-plan.md)。

### 目标

建立由四档稀有度容量、随机范围与金币成本共同驱动的基础打造：玩家只选择物品、操作和“任意 / 前缀 / 后缀”范围，系统随机决定具体词条和数值，UI 不再提供词条列表与具体目标选择。

### 范围

- 以唯一稀有度规则替换基底容量：普通 `0 / 0` 且零词缀；魔法前后缀各最多 1、总数 1–2；稀有各最多 3、总数 2–6；传奇各最多 3、总数 4–6。
- 随机移除可以让物品低于当前稀有度最低词条数，且不改变稀有度与容量；升阶、重随和新生成必须恢复对应正常范围。
- 增加单级稀有度提升和“清除全部显式词缀并还原普通”；普通依次升为魔法、稀有、传奇。
- 重随全部、随机增加一条、随机移除一条、随机重随一条数值都支持任意、前缀、后缀三种范围，但不允许指定具体词条。
- 移除打造 Command、System 与 UI 中由玩家传入目标词条索引、实例或稳定 ID 的正式入口；所有操作只接收目标物品、操作类型和范围。
- 候选词条选择、数值重掷与其他打造随机行为使用由稳定种子派生的独立随机通道；固定输入与种子必须可复现。
- 打造成本按职责分层：低阶升品最低、全随机重随居中、增加 / 移除与数值重随更高；指定前缀或后缀范围固定为任意范围的三倍。
- 打造 UI 移除全部词条列表、词条焦点和选择状态；改为升阶、还原、共享范围选择器、四项随机操作、动态价格与结果反馈。
- 同步更新物品生成、掉落数量、价值与容量快照、正式配置、验证器、领域测试和键鼠 / 手柄 UI 回归。

### 成功标准

- 四档稀有度容量与正常生成数量在物品生成、掉落、打造、UI 和验证器中完全一致，基底不再保存重复容量。
- 玩家无法通过 UI、Command 参数或其他正式运行时入口指定具体词条；14 个操作变体均能按合同执行或给出明确不可用原因。
- 固定物品、配置和种子产生相同的数量、分布、随机目标、随机结果与金币变化。
- 随机移除可以合法降到最低词条数以下且不降稀有度；其他操作不会超过容量，并在要求时保证正常数量下限。
- 正式价格满足冻结表，精准范围更贵，与当前商店和回收倍率不存在确定性套利。
- 打造页不再渲染可选择的词条列表，键鼠与手柄只需选择物品、范围和打造操作即可完成流程。
- 打造前后仍可通过统一物品信息浮窗查看完整词条，布局无空洞、遮挡、焦点丢失或按钮超框。

## alpha 0.1.7：多帧特效、稳定世界层级与综合验收

详细资产合同、世界排序键、配置文档覆盖基线、执行切片和提交门禁见[alpha 0.1.7 多帧特效、稳定世界层级与综合验收执行计划](./alpha-0.1.7-effects-sorting-acceptance-plan.md)。

### 目标

用独立多帧技能和受击特效替换临时缩放 / 闪白反馈，建立覆盖全部世界可见对象的稳定渲染层级，并完成 alpha 0.1 战斗、配置和内容的整体封板。

### 范围

- 将投射物飞行、命中爆发和角色受击拆为职责独立的特效族。
- 技能命中和受击特效使用多帧动画；暴击、未命中和闪避结果只触发与语义一致的反馈。
- 命中爆发不再复用当前投射物 Sprite；特效生命周期不反向驱动伤害逻辑。
- 每个动画帧为独立固定画布 PNG，遵守[美术资产生成规范](../visual-asset-generation.md)，不生成 SpriteSheet、不依赖人工切图、不在运行时缩放修补画面占比。
- 冻结每个特效家族的画布、PPU、Pivot、主体占比、视觉中心、帧数、帧率、方向和命名合同，并逐帧自动审计。
- 特效完成播放、目标销毁、场景退出和取消时均能释放；高频战斗下不产生持续增长的对象或 Addressables 句柄。
- 冻结正式 Sorting Layer 与 Order 分段合同，至少区分地表、世界对象、世界特效和世界信息；不再让角色、交互物和特效共同依赖 `Default` Layer 中零散的绝对 Order。
- 每个具有多个 Renderer 的逻辑世界对象使用单一 `SortingGroup` 作为整体排序边界，内部主体、描边、火焰、生命条和词条文字只使用冻结的相对顺序，禁止不同对象的子 Renderer 彼此穿插。
- 新增统一的世界对象排序入口，以对象接地点 / `SortAnchor` 的世界 Y 计算前后关系：屏幕下方对象稳定显示在前，上方对象显示在后；高大对象按接地点而不是 Sprite 中心或透明边界排序。
- Y 值相同或量化到同一档时使用显式类别优先级与稳定 Tie Breaker，结果不得依赖 Renderer 提交顺序、运行时 Instance ID、生成先后抖动或每帧浮点误差。
- 玩家、全部怪物、商人、工作台、掉落物和现有世界物件统一进入层级覆盖清单；新增带 SpriteRenderer / TilemapRenderer / ParticleSystemRenderer 的世界对象必须声明所属层级、排序锚点和内部偏移。
- 排序只驱动渲染表现，不修改 Transform Z、Collider、Rigidbody2D、寻路、交互距离或伤害判定；角色朝向翻转、死亡 / 复活、对象启用 / 禁用和对象池复用后必须保持原排序身份。
- 使用 Unity MCP / Editor API 精准迁移 Prefab、Sorting Layer 和场景引用，不直接修改已打开的场景或 Prefab YAML；同步更新视觉规范、视觉资产清单和内容校验。
- 补齐所有配置项文档，运行配置文档覆盖检查和全版本回归。

### 成功标准

- 投射物飞行、命中爆发和受击动画在连续帧中没有裁切、漂移、比例跳变或闪现。
- 每次攻击只执行一次玩法结算；视觉播放不会重复伤害或治疗事件。
- 伤害、治疗、暴击和闪避反馈在敌我双方上语义清晰。
- 玩家、怪物、商人和工作台在完全重叠、交叉移动与同 Y 停留时前后关系稳定，连续帧不闪烁，任一对象的主体、描边和附属表现不会被另一对象拆开穿插。
- 地表始终位于世界对象之后，投射物 / 命中特效与伤害数字按冻结层级显示；生命条、怪物词条和交互提示不会被对象主体错误遮挡。
- EditMode 覆盖全部正式世界 Prefab 的 Sorting Layer、唯一 `SortingGroup`、排序锚点和内部 Order 合同；PlayMode 覆盖上下交叉、同点重叠、翻转、死亡复活、生成销毁与固定帧序列回归。
- 世界可见对象覆盖扫描为零缺失；排序更新不产生逐帧 GC，不在多个 Controller 中复制 Y 到 Order 的计算公式。
- 所有生产栅格特效均为 `Sprite Mode: Single`，资源导入和绑定验证通过。
- 所有 `DarkFlare/Data` 配置类型和嵌套配置项都有可追踪文档，自动覆盖检查为零缺失。

## 跨阶段工程约束

- 遵守 QFramework 分层：Controller 只注册事件和转发意图，领域状态由 Model、System、Command 或 Query 管理。
- 异步循环使用 UniTask，并提供禁用、销毁和场景退出时的统一取消。
- 资源继续通过 Addressables 管理；运行时生成的特效必须有清晰所有权和释放路径。
- 不把标签类型、伤害类型、属性 ID 或词条效果复制成散落的字符串分支。
- 新增随机行为必须从稳定种子派生独立随机通道，并有固定种子测试。
- 配置结构变化必须同时更新示例资产、验证器、配置参考和迁移说明。
- 当前编辑器可提交基线要求 `EditorSettings.EnterPlayModeOptions = 0`，保留完整 Domain Reload 与 Scene Reload。专项测试期间可为加速验证临时调整，但测试完成、失败或中止后必须恢复为 `0` 并回归输入；提交前必须检查该值及 `ProjectSettings/EditorSettings.asset` 的 Git diff，禁止直接提交测试配置或无关自动序列化变动。持久改变此设置前必须完成静态状态、QFramework 架构和 Input System 生命周期专项审计。
- 每一阶段只修改该阶段依赖的基础契约；不得提前混入撤离、存档、Boss、远程怪物 AI、复杂法术体系或最终平衡数值。
- 开发、实现与测试期间继续禁止读取或修改 `Docs/design/`。
