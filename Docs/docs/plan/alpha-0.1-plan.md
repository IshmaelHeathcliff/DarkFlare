# alpha 0.1 开发计划

> 状态：规划准备
> 建立日期：2026-08-09
> 当前阶段：尚未启动 `alpha 0.1.0`
> 前置条件：首版单场景最小循环及初步体验优化已完成

## 版本定位

`alpha 0.1` 是项目进入 alpha 后的首个开发版本。版本计划需要在现有可玩闭环上选择一个明确的玩家体验目标，并以可独立验收的阶段逐步交付；在版本目标确定前，不预设具体玩法功能，也不启动代码实现。

## 当前基线

- `Main.unity` 已打通“战斗 → 掉落 → 拾取 → 整理 / 四槽装备 → 交易 / 打造 → 返回战斗”。
- 已有 3 种怪物、7 件装备、12 个可生效词条，以及可复现的战斗、生成和掉落随机通道。
- 键鼠与手柄均可完成场景交互、菜单操作、四槽换装、买卖、打造和暂停恢复。
- 地图、角色、怪物、装备图标、商人、打造台、战斗反馈和运行时 UI 已完成首批视觉接入；项目自有栅格资产已完成单图迁移。
- 初步体验优化收尾基线为 EditMode 98/98 通过；PlayMode 12 项中 10 项通过、2 项既有上游用例跳过、0 失败；五个项目程序集、Unity Console 与仓库检查均通过。
- 当前常规视觉与 UI 验收只保证 `1920×1080`。

## 版本规划前置准备

- alpha 阶段的新美术资产统一遵守[美术资产生成规范](../visual-asset-generation.md)。
- 一个生产 PNG 只包含一个 Sprite、动画帧、UI 状态或世界物件，不新增 SpriteSheet，也不依赖 Sprite Editor 人工切片。
- 生成前冻结家族画布、主体占比、视觉中心、锚点与 Unity 导入合同；生成后逐张自动审计和视觉复核。
- 2026-08-09 已完成并归档[美术资产单图迁移计划](./archive/alpha-0.1-art-asset-migration-plan.md)：92 张 PNG 均为独立单图，8 张旧 Sheet 已清理，`Sprite Mode: Multiple` 与旧引用均为 0。该工作属于版本目标确定前的生产准备，不占用 `alpha 0.1.0` 阶段编号。

## 已知边界

- 只有 `Main.unity` 单场景，没有撤离、场景切换、存档或局外成长闭环。
- 三种怪物仍共享追击和接触攻击 AI，没有远程、施法、精英或 Boss 行为。
- 背包没有拖拽换位、旋转、堆叠和重量；装备没有耐久、套装、纸娃娃或唯一特效。
- 交易仍是单商人库存，没有回购、刷新和价格波动；打造没有材料、配方、锁定词条和批量操作。
- 当前内容与数值用于验证闭环，不代表 alpha 版本的最终内容密度与节奏。

## 命名规则

- 版本名称使用 `alpha 0.1`。
- 版本内阶段使用三段式名称，从 `alpha 0.1.0` 开始，后续依次递增末位。
- 阶段计划文件使用 `alpha-0.1.0-<主题>-plan.md` 格式，主题使用小写短横线命名。
- 已归档的首版与初步体验优化阶段保留原名称，不追溯改名。
- 新增阶段前必须先在本计划登记目标、依赖、范围、成功标准和验收方式。

## 版本规划门槛

开始拆分 `alpha 0.1.0` 前，需要先确认：

1. `alpha 0.1` 要改善的核心玩家体验，以及玩家在一轮体验中应新增或明显改善的行为。
2. 本版本明确包含与不包含的范围，避免把现有全部缺口一次性并入。
3. 版本完成时可观察、可复现的验收路径和目标体验时长。
4. 对现有战斗、物品、经济、UI、场景和配置的影响面与前置依赖。
5. 需要新增或调整的自动化测试、Debug 信息、配置校验、文档和美术资源。

## 每阶段计划要求

每个阶段计划至少包含：

- 玩家可感知的目标与完成后的体验变化。
- 当前代码和配置基线，以及需要修改的模块边界。
- 明确的范围、非目标和兼容性约束。
- 按依赖排序的实施步骤，避免同一阶段并行改动过多基础契约。
- 键鼠与手柄路径、`1920×1080` UI、失败回滚、取消和资源释放要求。
- 纯逻辑测试、EditMode、PlayMode、程序集编译、Console 和实机验收清单。
- 对应模块文档的同步项，以及阶段完成后的计划归档要求。

## alpha 0.1 通用完成要求

- 不破坏现有单场景最小循环，旧流程回归保持通过。
- 新增流程遵守 QFramework 分层，Controller 不直接修改 Model，也不发送领域 Event。
- 异步流程使用 UniTask 并提供完整取消与统一清理；资源继续使用 Addressables 管理所有权和释放。
- 玩家操作同时覆盖键鼠与手柄，运行时 UI 默认以 `1920×1080` 验收。
- 版本目标对应的自动化、实机验证、Debug 信息和模块文档与实现同步完成。

## 下一步

确认 `alpha 0.1` 的核心体验目标和范围后，先补全本版本的成功标准，再建立 `alpha 0.1.0` 阶段计划；阶段计划通过复核后才进入实现。
