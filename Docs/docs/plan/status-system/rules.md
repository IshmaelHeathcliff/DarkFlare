# 状态系统规则草案

所属计划：[alpha 0.4 状态系统](../alpha-0.4-status-system-plan.md)。本文件保留完整规则目标；核心已经落地，实际 API 与工程边界见[状态模块](../../status-system.md)，角色效果、周期伤害与行动门禁已接入，正式异常、抗性、自动计时、存档及 UI 仍待后续阶段。明确标为“已确认”的内容来自用户，其余是工程实施建议。

## 定义、持有与生效

`StatusDefinition` 提供稳定 ContentId、本地化名称 / 说明、图标、分类、效果集合和规则。运行时状态记录目标、来源、实例 ID、施加次序、逐层数值快照及计时进度。状态可以没有数值效果，作为可查询、可消耗标记存在。

同一角色按状态定义形成显示组。多个来源保留各自身份，按定义决定是否共同竞争；默认在目标的同一状态组内执行择强和总层数上限。光环等持续提供方使用稳定来源键，重复注册同一来源必须幂等。

必须区分持有层数与生效层数：最强模式下可以持有多个候选，但只激活一个候选。未生效候选照常计时；强层结束或被移除后，剩余最强层立即接替，其剩余时间不重置。

## 层数模型

| 模型 | 数值语义 | 适用情况 |
| --- | --- | --- |
| 统一数值叠层 | 所有层使用同一组单层参数，汇总有效层数后产生效果 | 固定数值增益、减益和标记 |
| 独立数值层 | 每层保留自己的来源、幅度、持续时间和周期相位 | 流血、中毒及不同强度候选 |

统一数值模型不把不同来源的独立掷值悄悄平均。若重新施加需要不同参数，定义必须明确覆盖整组参数，或改用独立数值模型。最强候选比较使用独立实例记录；首期不叠加“每个候选又拥有多层”的第二套层数。

统一模型建议对 Flat / Increase / More 的单层幅度按层数线性累计，再向现有聚合器提供一个修改器；例如每层 More 10%、三层为 More 30%。独立层各自生效时仍保留逐项 More 乘算。Override、控制和标记不按层数乘值；配置校验阻止无意义的数值组合。

## 时长与到期

- 时长类型使用显式枚举：限时、来源维持、无限。不得使用 `0` 同时表示到期和永久；限时时长必须大于零。
- 共享计时：组内层使用一个到期点；重复施加按刷新策略处理，到期移除这一组剩余层。
- 逐层计时：每层有自己的到期点；到期只移除对应层，其他层保留原时间。流血 / 中毒采用此模型。
- 层被消耗、替换或驱散后，其未来周期和到期事件同时失效。
- 所有时长使用游戏时间；暂停和应用挂起不推进，不以现实时间补算离线伤害。

建议按“到期时间 / 周期时间 → 稳定实例次序”处理事件，确保相同输入可重放。周期首跳在一个完整间隔之后；恰好到期时先结算同一时刻应有的最后一跳，再到期；未满一个间隔的尾段不追加跳伤。刷新时间不重置尚未发生的周期相位，避免频繁刷新阻止伤害；替换为新实例则开始新相位。

## 重复施加与满层

三种重复施加行为及满层默认已确认；具体配置应提供中文说明和组合校验。

| 重复策略 | 未满层时 | 满层默认 | 可选覆盖策略 |
| --- | --- | --- | --- |
| 覆盖刷新 | 固定标记更新现有效果；统一叠层按请求增加至上限并刷新指定计时 | 刷新现有效果，不超过上限 | 拒绝刷新、仅刷新时长 |
| 共存、仅最强生效 | 保存新候选，重新选择最强者 | 比较新候选与已有候选，保留更强者 | 拒绝新增 |
| 共存、各层独立生效 | 添加独立层，原层保持原数值和时间 | 替换最早到期层 | 拒绝新增、刷新选定层时长 |

最强模式必须声明可比较的强度指标，不能默认相加不同属性。建议使用定义认可的非负强度 / 每秒伤害，抵抗后的效果强度参与排序；相同强度默认保留较早实例，结果不依赖字典顺序。复合效果整体选取同一获胜实例，不从不同候选拼接各自最高数值。

独立模式替换按“最早到期 → 最早施加 → 实例 ID”排序；无限层排在限时层之后。替换视为旧层移除与新层加入的一次事务，不能让 UI 或伤害循环看到中间状态。

共享计时仅用于统一数值组。独立数值候选和独立伤害层使用逐层计时，避免刷新一层时意外延长其他层。若未来需要更复杂组合，先增加规则与测试，再放开配置。

阶段 1 已提供 Uniform + PerLayer 的 RefreshExistingLayers 选项，默认开启；关闭后未满层新增保留旧层时间，满层仍遵循满层策略。来源维持还有身份约束：Uniform 满层的新提供方必须被拒绝，不能只改写其他提供方的效果而不登记自身层；需要多来源候选竞争的光环使用 Strongest。

## 检测、消耗与驱散

- 查询同时提供 `HasStatus`、持有层数、生效层数、逐层快照；也支持按分类 / 标签过滤。
- 标记不是数值修改器；状态组仍存在时才能被查询命中。状态标签按真实拥有关系动态派生，移除一个来源不能清除另一个来源仍提供的标签。
- `TryConsumeStatusStacks` 默认要求足额，数量不足、目标失效、版本过期时整次失败。成功返回被消耗层的数值与来源，供技能等后续机制计算效果。
- 默认消费持有层，按最早到期优先；允许调用者限定生效层或指定实例，以免机制依赖隐含选择顺序。
- 消耗和后续技能效果由同一 Command 编排。先校验资源、状态及目标，再准备效果；提交失败必须恢复原层、时间及资源，不用“再施加一次”模拟回退。
- `DispelStatuses` 可按异常类别 / 标签 / 指定定义筛选，支持移除全部或指定层数；是否可驱散与是否可消耗分别配置。
- 驱散、层数消费、到期、来源失效、替换使用不同移除原因；普通到期不被当作消费触发。
- 事件在事务完成后发送；事件回调产生的新操作排队处理，避免迭代时修改集合和同一层重复消费。

## 效果表达

状态复用 `StatModifierDefinition` / `ModifierInstance` 的属性表达，生命周期由状态系统管理。计算作用域继续明确为 `GlobalActor`、`Skill` 或 `TargetTaken`；`Temporary` 不作为隐式“全都生效”的通道。

另外提供周期伤害、行动限制与纯标记三类效果。属性降低用既有 Reduced / Less 数值语义表达。周期效果经战斗系统提交生命变化；控制效果经统一行动限制 Query 和命令校验生效。首期不为每个异常编写单独的循环或独立 MonoBehaviour。

## 七种异常的首期建议

下表是对用户列出异常的实现映射建议；具体平衡参数仍待配置。

| 异常 | 建议效果 | 建议重复模型 | 抗性作用 |
| --- | --- | --- | --- |
| 虚弱 | 降低造成伤害的幅度 | 候选共存、仅最强生效 | 降低减伤幅度 |
| 眩晕 | 禁止主动移动、攻击和施法 | 覆盖刷新 | 缩短持续时间 |
| 流血 | 物理周期伤害 | 每层独立数值、逐层计时并生效 | 降低该层伤害 |
| 燃烧 | 火焰周期伤害 | 候选共存、仅最强生效 | 降低该层伤害 |
| 冰缓 | 降低移动速度 | 候选共存、仅最强生效 | 降低减速幅度 |
| 感电 | `TargetTaken` 增加承受伤害 | 候选共存、仅最强生效 | 降低承伤增加幅度 |
| 中毒 | 混沌周期伤害 | 每层独立数值、逐层计时并生效 | 降低该层伤害 |

眩晕不暂停其他状态倒计时或被动恢复，也不禁止菜单、状态查看和系统操作。冰缓首期只接入现有移动速度消费者；攻击 / 施法速度不是当前已有属性，不在本阶段悄悄引入。

异常与伤害类型相关，但不会因为一次伤害含有某元素就自动施加异常。具体技能、装备或其他来源显式配置施加规则；通用接口也允许没有伤害事件的直接施加。周期伤害默认不会再次自动施加异常，避免递归触发。

## 异常抗性

按效果类型分别减弱已确认。建议注册七个独立稳定属性：`weakness_resistance`、`stun_resistance`、`bleeding_resistance`、`burning_resistance`、`chill_resistance`、`shock_resistance`、`poison_resistance`；使用同一抗性解析器，并同步 StatIds、正式资产、说明及配置校验。

建议初期有效范围为 0–100%，系数 `1 - clamp(R, 0, 100) / 100`。这一范围是待落实建议，不沿用元素抗性的 -100–75% 边界。属性异常向“无效果”缩放，伤害异常缩放伤害，眩晕只缩放时长；同一抗性不再同时减幅度、时长和施加概率。

建议在施加时冻结异常抗性结果，记录抵抗前后参数；后续抗性变化影响新施加。100% 抵抗时拒绝对应异常的新施加，不产生零效果层；已有状态按其快照继续，驱散负责清除。该快照政策应在正式配置前落实。

伤害类型抗性与异常抗性不同：燃烧抗性降低异常伤害快照，火焰抗性仍在每次承伤时参与防御。物理护甲只用于命中伤害，流血不重复走护甲；周期伤害是否受到额外机制影响必须由其 DamageForm 条件明确声明。
