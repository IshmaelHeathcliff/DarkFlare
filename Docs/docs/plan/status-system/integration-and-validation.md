# 状态系统工程接入与验收

所属计划：[alpha 0.4 状态系统](../alpha-0.4-status-system-plan.md)。下列类型名为计划名，实施时按最少改动落地，不代表已有 API。

## 分层与通用入口

| 层 | 计划职责 |
| --- | --- |
| 配置 | `StatusDefinition` 保存效果及规则；Odin 中文分组、图标预览、合法组合校验；加入 ContentCatalog 与 Addressables |
| Model | `StatusModel` 保存按目标运行时身份索引的状态组、层和版本；不处理 UI 或资源加载 |
| 纯规则 | 处理候选择强、计时、满层替换、消耗选择及抵抗计算，可显式传入时间测试 |
| System | `StatusSystem` 编排施加、到期、效果生效 / 移除、来源释放；统一时间推进与事件发布 |
| Command / Query | Controller 通过命令变更、查询快照；技能 / 装备 / 后续天赋和物品调用同一 System 合同 |
| Controller | HUD、图标详情和调试面板只呈现快照、执行命令、注册事件 |

建议接口合同：

- `ApplyStatus(request)`：目标、定义、来源、请求层数、数值快照及可配置时长；返回接受 / 刷新 / 替换 / 拒绝结果和实例身份。
- `GetStatusSnapshot(target)` / `HasStatus` / `GetStatusStacks`：区分持有与生效，提供来源及时间，无副作用。
- `TryConsumeStatusStacks(request)`：指定目标、状态、数量、选择范围、可选期望版本；返回确切消费记录及失败原因。
- `DispelStatuses(request)`：筛选范围及最大移除数量，返回实际移除结果。
- `ReleaseStatusSource(ownerKey)`：只移除指定持续来源所提供的状态；释放与重复释放均安全。

SourceRef 区分技能、装备实例、天赋节点、消耗物品及其他机制。目标和来源角色使用玩家 / 怪物运行时身份与 Session generation，不能使用怪物基底 `ActorId` 充当唯一实例 ID；两个相同基底怪物的状态必须隔离。来源数据使用稳定 ID 和值对象，状态不长期抓住已销毁的 Unity 对象。

本期接入样例应至少验证：技能直接施加、伤害后显式施加、装备持续提供、按条件消费标记触发效果，以及技能 / 物品调用同一驱散入口。未建设的天赋树和药水效果通过适配合同测试验证，不能把调试按钮宣称为完整玩法。

用户已安排[统一物品使用阶段](../alpha-0.4-usable-items-plan.md)紧随状态验收。Apply / Dispel 应支持无副作用的预检及准备结果，并在宿主 Command 完整提交后通知，以便与回血 / 回蓝和物品数量组成一次事务。药剂限时状态保存来源快照，不依赖原物品仍存在；行动限制为后续 CanUseItem 保留独立语义，不直接复用 CanCast。

## 属性与标签

为角色建立按来源键管理的修改器集合，提供整组替换和来源移除；EquipmentSystem、怪物词条及状态分别只操作自己的来源。汇总后调用现有 CombatStatResolver，事务内批量重建一次，避免逐层反复改变生命上限。移除全部状态不等于 `SetModifiers(null)`。

状态强弱切换、层数变化和结束时标记有效属性版本变化。ModifierOrigin 增加来源种类与状态身份，属性详情能解释“来自何种状态、多少生效层”。基础属性不吸收临时增益；最终属性也不能再次作为重建输入。

状态标记查询独立可用；需要参与词条条件时，将仍持有状态派生到角色标签上下文，保持来源和目标域隔离。攻击快照冻结攻击者侧状态，结算时读取目标侧当前状态；不修改已经发出的攻击快照。

## 周期伤害与行动限制

扩展 `DamageForm`（命中 / 周期伤害）及 DamageContext、DamageResult。持续伤害复用承伤、防御、生命提交及死亡事件，不调用命中 / 闪避 / 暴击判定，也不冒充 `IsHit`；审查 CombatEffectPalette、ActorAnimatorController、ActorVisualFeedbackController、伤害文字及其他事件消费者。

建议施加时冻结来源伤害参数和异常抗性结果；每跳读取目标当前元素 / 混沌抗性及承伤修改器。快照必须标明数值处于管线哪一阶段，避免既把已增伤的 DPS 存下来，又在每跳重新应用来源增伤 / 转换。由命中衍生的异常不直接取已经过目标防御和暴击的最终生命损失作为通用基底。

死亡由 CombatSystem 唯一提交，一次致死只产生一次死亡 / 掉落。限时伤害的来源死亡或离场后，已施加快照可继续，归属使用记录的稳定来源；来源维持的光环随来源失效而释放。目标死亡后建议清除限时状态并停止周期结算，复活后由有效持续提供方重新绑定，不恢复残留眩晕。

`CanMove` / `CanAttack` / `CanCast` 统一查询行动限制。玩家、怪物移动入口读取限制并及时清零速度；FireProjectileCommand 等最终提交入口再次检查。眩晕期间失败施法不扣法力、不产生投射物、不消费状态层。已发出的投射物保留原有攻击快照和生命周期。

## 时间、生命周期与存档

- 使用一个 Session 作用域内的可取消 UniTask 推进状态，不为每个状态启动独立循环。内部显式推进实际游戏时间，测试可注入时间。
- GameTimeService 暂停租约、平台挂起和 Session 非 Running 阶段都不推进；禁用 / 注销目标后取消待执行事件并移除目标记录，防止对象池复用串状态。
- 处理大时间步时按计划事件时间顺序逐次结算，并在每步检查目标死亡、取消和版本变化；为单次预算分批处理积压，不能静默丢跳或把同一时间算两次。
- UI 倒计时只读取快照；暂停、打开菜单和切换语言不会重置状态时间。
- 保存状态定义 ID、实例 / 来源身份、数值快照、持有层、剩余时长、距下一跳时间和确定性次序；不写 Unity 对象、图标地址或现实世界到期时间。
- Schema 计划从 2 升至 3，旧档迁移为空状态集合，保留已有 Schema 0→1→2 及 core v1→v2→v3 路径。新增正式定义时审查 core 内容版本变更及显式兼容路径。
- Restore 先恢复来源与状态，再统一重建有效属性，最后校验和恢复生命 / 法力；防止旧的临时最大生命导致资源验证失败。
- 来源维持状态由有效提供方重建或凭稳定来源记录去重恢复，只能选择一个权威路径。限时状态按保存剩余时间恢复，不补算离线时间，不重复执行首跳。
- 未知状态 ID、非法数量 / 时长、重复身份、错误所有权及未来 Schema 按现有存档预检规则拒绝，不能部分恢复进 Session。

## 图标、详情与输入

优先在玩家 HUD 上方预留状态区域，复用现有 PanelRenderer 和共享皮肤；鼠标悬停、键盘 / 手柄焦点均显示同一份详情。怪物复用快照与图标组件，在明确选中目标的详情位置接入；不要求所有怪物头顶同时展开完整状态列表。

- 按状态定义聚合一个图标，角标显示持有层数。最强模式的浮窗另列“持有 / 生效”，说明候选接替规则。
- 单一共享时钟显示整组剩余时间；逐层时钟显示最近一层到期时间，浮窗标注“下一层到期”，并可查看各层来源、幅度和剩余时间。
- 无限 / 来源维持状态不显示伪造的剩余秒数；可展示来源有效提示。周期倒计时与持续倒计时分别解释。
- 更新层数或倒计时时复用图标节点；焦点所在状态消失时转移到相邻图标或状态区入口，及时关闭失效浮窗。
- Gameplay 模式不直接启用 UI Navigate 抢占移动；经现有菜单 / 查看入口进入可导航状态列表，再按返回键恢复原输入上下文。状态信息在暂停时仍可查看。
- 图标为一状态一 PNG，固定画布和家族统一 Pivot / PPU，Sprite Mode Single，Addressables 由 Session 资源作用域持有。正式图标生成 / 导入遵循 unity-2d-sprite-workflow；布局使用 Unity MCP。
- 名称、效果、来源、层数、时间与驱散说明全部本地化；支持中英、伪本地化、Reduce Motion 及设备切换。装饰性倒计时不遮挡图标命中区。

## 长期验收矩阵

| 合同 | 核心验证 |
| --- | --- |
| 层数与时间 | 共享 / 独立到期；一次推进与分段推进一致；边界最后一跳；刷新不重复首跳；暂停不推进 |
| 重复与上限 | 覆盖刷新；强层压制弱层、强层消失后弱层以原剩余时间接替；独立层各自数值；达到上限时确定性替换 |
| 消耗与驱散 | 足额成功、不足不变；仅删指定层 / 来源；驱散过滤；失败回退保留原时间；失效版本拒绝；回调重入不重复消费 |
| 数值共存 | 装备与状态互不覆盖；叠层后正确累计；强弱切换属性立即重建；来源解释正确；资源比例无重复缩放 |
| 异常与抗性 | 七种异常行为；零 / 中间 / 完全抗性；负向幅度向无效果缩放；眩晕仅缩时；异常抗性与类型防御不重复计算 |
| 伤害与控制 | 周期不命中、不暴击、不触发命中反馈；施加不依赖伤害类型自动推导；眩晕拦截玩家 / 怪物和直接命令；致死一次提交 |
| 来源 | 两个同基底怪物隔离；来源重复绑定幂等；装备解绑只释放自己；来源死亡后的限时伤害与光环分别遵循策略 |
| 保存恢复 | 异构逐层数值 / 时间 / 周期相位往返；旧档空集合迁移；上限属性先恢复；持续来源无重复；无离线补跳 |
| 生命周期 | 死亡复活、禁用重启、Session 重建、初始化取消、无 Domain Reload 不留任务或订阅 |
| UI 与资源 | 实际鼠标 / 手柄焦点与浮窗、消失后焦点转移、多状态滚动、中英 / Pseudo、图标异步失败 / 取消 / 卸载 |

纯状态规则新增按模块命名的 `StatusSystemTests`；伤害、装备、资源、标签、存档和输入优先扩展现有对应测试。阶段验收使用项目两个测试程序集，截图工具完成后清理，仅将证据归档到 `Docs/docs/assets/acceptance/`。
