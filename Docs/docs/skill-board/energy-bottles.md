# 能量瓶装备与击杀收集

三种能量瓶均占背包 2×1、不堆叠，可怪物掉落和商店购买。专栏独立于十个战斗装备槽；只有专栏装备瓶收集能量。新瓶为零能量，取回、买卖、切图和恢复保留实际值。安装入口见[道具安装](items-installation.md)。

| 档位 | 容量 | 基础价格 |
| --- | ---: | ---: |
| 小 | 1000 | 100 |
| 中 | 2000 | 200 |
| 大 | 4000 | 400 |

容量与小瓶价格由用户暂定，中大价格按容量 1∶2∶4 推导；实际买卖继续叠加既有商人倍率。换瓶把旧瓶放到新瓶原背包 2×1 位置，最终背包空间不足整次失败；空专栏卸下使用背包合法空位。预检期间积蓄推进物品 Revision，旧换装预览须重做。

## 收益与归属

`EnergyBottleSystem` 消费 CombatSystem 的 ActorDiedEvent，要求怪物已死亡、仍登记在当前 CombatModel、实例 RunId 属于当前 Run，来源阵营为 Player 且 ActorKey 属于当前唯一玩家。普通命中与持续伤害共用此入口；空来源、敌方、其他 Run、未登记或存活对象均不收集。

死亡先按 MonsterInstanceId 去重，再判断瓶子和归属。空栏 / 满瓶本次死亡同样已结算，之后装备瓶不能追溯领取；当前 Run 的集合在 Run 变化与 System 销毁时清除。恢复不会重放死亡事件，已死亡实例不重新生成收益。

首轮整数收益：`基础能量 × (1 + 怪物稀有度等级) + 词条数 × 每词条加成 + 词条稀有度等级之和 × 每稀有度级加成`。Normal / Magic / Rare / Unique 为 0 / 1 / 2 / 3，整体等级和词条自身等级分别配置，与 Weight 无关。普通怪物基础 10，守卫基础 100 / Unique；两项加成各 5。storm_touched / armored 为 Rare，其余词条 Magic。具体数值为首轮暂定，正整数与枚举配置接受校验，计算溢出拒绝并记录 Warning，不调用攻击 / 掉落随机流。

收集量 = `min(收益, 容量 - 已存能量)`，超出部分直接舍弃，满瓶必须手动更换。正收集才推进实例 Revision 并发 EnergyCollectedEvent；事件含完整收益、实收、舍弃、瓶与怪物身份，SaveCoordinator 标脏。空栏 / 满瓶不发伪成功事件，没有自动换瓶或角色池转存。

## 保存与后续

瓶能量随 ItemInstanceDto.SkillBoard.Energy 保存，Profile.SkillBoard.EnergyBottleInstanceId 指定唯一装备所有者。Restore 拒绝负值、越容量和错误角色；不会填瓶、补领或更换实例。

本阶段可通过开发窗口装备 / 卸下和查看积蓄。中心充能消耗瓶、角色余额跨瓶累计、1 天赋点＋1 属性点兑换、递增成本与点亮属于下一阶段，依据[成长合同](../plan/alpha-0.7.1/energy-progression.md)。长期 `EnergyBottleTests` 保护四个收益因素、归属、去重、容量舍弃、手动换瓶和 Session 隔离；真实死亡、保存继续和切图由现有 PlayMode 保存套件覆盖。
