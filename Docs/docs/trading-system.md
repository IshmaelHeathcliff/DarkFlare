# 商店与随机库存

## 玩家行为

正式商人每批提供 16 件独立商品。候选池包含二十件装备和四种药水，有放回按权重抽取；装备各 100，药水各 300。允许同基底重复出现，但每件拥有独立身份、品质与数值。购买成功只减少对应一件，不自动补货；药水每件数量为 1，进入背包后按既有规则合堆。

装备稀有度权重为普通 40、魔法 40、稀有 18、传奇 2。普通无显式词条；其他品质复用 `CraftingOperations` 的候选、组互斥、容量、最低条数与数值随机规则。候选池、批次数量、品质权重和词条池均由 `TraderDefinition` 配置，见[配置参考](./config-reference/trade-and-crafting.md)。怪物掉落权重与打造成本不受影响。

商店提供“刷新商品（免费）”，可用鼠标、键盘或手柄操作。整批替换未售商品，已购商品、金币与玩家物品不变；刷新失败保留原库存并显示反馈。关窗再打开不会刷新。

## 架构与事务

`RefreshMerchantCommand` → `TradingSystem.RefreshMerchant`：拒绝已销毁 Session、场景切换 / 输入挂起及重入；先生成完整候选数组，成功后通过 `EconomyModel.RestoreState` 一次替换，再发送 `MerchantStockRefreshedEvent`。旧商品引用失去库存资格，不能重复购买。生成异常记录警告并返回失败。

`ShopPanelController` 监听事件，取消旧拖放和动作菜单，清除浮窗，重建列表并保留刷新按钮焦点。`SaveCoordinator` 监听同一事件标记脏数据。Controller 不直接操作库存或发送事件。

新建与主动刷新各使用独立随机种子；刷新日志记录种子，不消耗战斗 / 掉落 / 打造随机序列。给定同一生成种子和配置，可重现商品基底、品质和词条数值，实例 ID 仍独立生成。

## 保存与兼容

当前商品身份、顺序、品质、词条与数值沿既有物品 DTO 保存，不增加存档字段。旧档原样恢复剩余库存，主动刷新后使用新候选规则；未来刷新结果不承诺跨读档重放。未启用 `RandomStock` 的历史或测试配置保留固定库存生成。当前运行版本仍为 `0.4.2-alpha`，core v5、Schema 3。

## 回归覆盖

在既有交易基础测试中覆盖四种品质的合法词条、固定种子重现、刷新失败回退、重入与过期商品拒绝。既有 UI 测试覆盖键盘 / 手柄刷新、焦点与关窗重开不补货；保存恢复测试覆盖刷新标脏、库存身份 / 品质 / 词条数值往返。需要完整商品池的装备和消耗品交互测试使用独立测试库存，避免依赖随机抽样。
