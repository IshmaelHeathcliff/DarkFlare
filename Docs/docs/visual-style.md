# 视觉规范

## 验收分辨率

- 当前及后续视觉与 UI 验收以 1920×1080 为唯一保证分辨率。
- 1280×720 与 2560×1440 的既有截图只作为历史记录，不再进入常规回归和正式截图流程。
- 如果未来需要支持新的分辨率或宽高比，应单独立项并补充对应布局规则与自动化覆盖。

## 适用范围

本文定义初版体验优化阶段 0、0.5 与阶段 5 的视觉基线，服务于 `Main.unity` 的完整首版循环。阶段 5 首次验收暴露了主体尺寸、非等比切图和场景摆放问题；后续返工进一步确认，生成式动画与场景图必须保留整张源图并在 Unity Sprite Editor 内切片，不能再由外部工具拆成逐帧 PNG。

风格参考图见 [阶段 0 风格板](./assets/visual-style/phase-0-style-board.png)，具体资源规格见 [视觉资产清单](./visual-assets.md)。

## 视觉方向

- 视角：2D 俯视 3/4，世界物件保持统一的左上方冷光与右下方暗部。
- 风格：暗色奇幻、低分辨率手绘、像素化硬边；强调轮廓和材质块面，不追求细碎写实纹理。
- 氛围：冷灰、低饱和、压暗背景；角色、敌人、交互物和技能效果通过有限高亮建立层级。
- 可读性：玩家、怪物、交互物必须同时依靠轮廓、明度和局部色彩区分，不能只依靠色相。

## 世界 Sprite 规格

| 类型 | 画布 | PPU | Pivot | Filter | 压缩 |
| --- | --- | --- | --- | --- | --- |
| 地表切片 | 512×512 | 64 | Center | Point | None |
| 角色动画 Sheet | 保留生成源尺寸 | 按可见尺寸标定 | Sprite Editor 自定义 | Point | None |
| 生成式世界物件 Sheet | 保留生成源尺寸 | 按网格世界尺寸标定 | Sprite Editor 自定义 | Point | None |
| 投射物 | 64×64 | 64 | Center | Point | None |
| 物品图标 | 96×96 | 64 | Center | Point | None |

- 角色动画默认 10 FPS；Idle 允许 4 帧，Move 使用 4 帧。
- 玩家先验证四方向共用轮廓与水平翻转；怪物阶段 0 使用左右翻转。
- 角色脚底、武器握点和主要体块在相邻帧中不得漂移。
- 世界排序先沿用 Default Sorting Layer，通过 Sorting Order 保证地表 < 掉落 < 角色 < 特效；批量生产前再评估是否拆分 Sorting Layer。

## 可见尺寸与源图合同

### 通用导入

- 玩家、荒原游魂、新怪物和 NPC 的多帧资源全部保留透明整图，直接导入 `Assets/Art/SpriteSheets/`，使用 `Sprite Mode: Multiple` 和 Unity Sprite Editor 保存 Rect、名称与 Pivot。禁止把整图拆成正式逐帧 PNG。
- 七件正式装备图标继续使用 **96×96 RGBA 独立 Sprite**，因为运行时图标缓存以 Addressable GUID 为键；旧大剑不再保留 64×64 正式例外。
- Filter Mode 为 Point，Compression 为 None，关闭 Mipmap，透明边缘不得带色键残边。装备图标维持 64 PPU；整图 Sheet 按目标可见尺寸单独记录 PPU。
- 角色 Sheet 子 Sprite 在 Sprite Editor 中分别校准角色中心与共享脚底线；装备图标 Pivot 固定为 `(0.5, 0.5)`。
- Prefab 和切图过程只允许等比缩放，必须满足 `scaleX == scaleY`。禁止把长方形源单元直接拉伸到 96×96，也禁止靠非等比 Transform 修正变形。
- 96×96 对逐帧资产和装备仍是画布规格；整图 Sheet 使用等效可见尺寸验收，通过 PPU、Pivot 和已记录的等比 Prefab Scale 对齐世界体量。

### 角色主体尺寸

主体包围盒以 Alpha 大于 8 的像素计算；Idle 为正式尺寸基准：

| 类型 | Alpha 主体目标 | 底部透明边距 | Prefab 等比缩放 | 最终可见尺寸目标 |
| --- | --- | ---: | ---: | --- |
| 玩家 / 人形 NPC | 宽 52–66、高 86–90 px | 3–6 px | 0.80 | 高 1.05–1.15 世界单位 |
| 普通怪物 | 宽 76–84、高 86–90 px | 3–6 px | 0.75 | 最大边 0.95–1.10 世界单位 |
| 迅捷四足怪物 | 宽 68–78、高 48–56 px | 4–8 px | 0.90 | 宽 0.95–1.10 世界单位 |
| 重装怪物 | 宽 70–80、高 82–88 px | 3–6 px | 0.75 | 高 0.95–1.05 世界单位 |

- 体型差异通过轮廓和主体包围盒表达，不通过临场随意修改 Prefab Scale 表达；只允许使用表中按角色体型明确记录的等比缩放。
- 同一角色的 Idle / Move 帧使用同一个缩放因子和地面锚点；躯干高度波动不超过 4 px，四肢动作造成的总包围盒宽度波动不超过 12 px，落脚点横向漂移不超过 2 px。
- Attack、Hit、Death 可因动作改变包围盒，但角色本体不得重新缩放；超出安全区时增加透明留白，不得压缩主体。
- 画面底部可见像素必须稳定落在底边上方 3–8 px，中心轴保持在 `x = 48 ± 2 px`。低姿态四足怪物仍需达到目标宽度，不能因高度较低而整体缩小。

### 装备图标主体尺寸

- 七件正式装备全部重新规范为 96×96；Alpha 主体最长边为 72–80 px，中心与画布中心偏差不超过 3 px，任一侧透明安全边距不得小于 6 px。
- 武器、护甲和戒指允许轮廓不同，但不得通过让某一类别占满画布来制造“更强”感。两件同类物品的最长边差异不得超过 6 px。
- 图标使用相同的 1–2 px 硬边轮廓、左上冷光、右下暗部和受控金属高光；不加入 UI 框、投影、文字或独立背景。
- 世界掉落和全部 UI 直接使用同一 Sprite。不得为世界与 UI 分别维护不同尺寸或二次缩放版本。

### 生成与切图流程

1. 旧玩家、旧荒原游魂和旧大剑是强制风格参考；生成时必须作为图像参考输入，不能只在提示词中描述“相似风格”。
2. 每个新角色先只生成一张 Idle 基准帧。基准帧通过轮廓、主体尺寸、颜色、光向和像素密度验收后，才允许派生 Move、Attack、Hit 与 Death。
3. 动画帧优先从已通过的 Idle 基准做图像编辑，保持角色身份和比例；不分别生成互不关联的动作图。
4. 生成输出完成透明化后，整张图原尺寸进入 Unity；不得在外部裁帧、压缩到方形或重排为新的运行时小图。
5. 在 Sprite Editor 中按原始网格建立命名 Rect，并逐帧调整 Pivot 对齐角色中心与共享脚底线；非方形单元保持原比例。
6. 通过 Sheet 的 PPU 与已记录的等比 Prefab Scale 对齐目标世界体量；不得使用非等比 Transform 补偿。
7. 全套角色和物品接入前先输出尺寸审计表与并排预览；只有数值与视觉同时通过才进入 Animator、Addressables 和 Prefab。

## 动画状态

| 状态 | 阶段 0 接入 | 验收重点 |
| --- | --- | --- |
| Idle | 运行时 | 呼吸幅度小、脚底稳定 |
| Move | 运行时 | 步幅可读、移动方向一致 |
| Attack / Cast | 预览 | 武器或施法方向稳定 |
| Hit | 预览 | 轮廓收缩且不依赖纯红闪 |
| Death | 预览 | 明确失去战斗姿态，避免与 Idle 混淆 |

## 阶段 0.5 运动、边界与掉落基线

- 玩家移动使用 `Rigidbody2D.Interpolate` 衔接物理帧与渲染帧；相机保留 `LateUpdate + SmoothDamp`，切换目标时必须清空旧平滑速度。
- 当前不挂 Pixel Perfect Camera，也不引入 Cinemachine。只有原生输出再次出现非整数采样问题时才重新评估。
- `Main.unity` 的 `WorldBounds` 是物理边界、相机范围和怪物生成范围的共同来源；视觉地表必须继续覆盖镜头边界之外。
- 世界掉落排序为地表 < 投影 / 稀有度框 < 图标 < 标签。悬浮和呼吸只修改视觉子节点，不移动根碰撞体。
- 掉落至少同时使用图标轮廓、框体形状、稀有度颜色和中文名称；稀有度不得只依赖颜色。

## 阶段 5 世界与反馈基线

- 地图继续使用现有 5×5 分层地表与 `WorldBounds`，通过少量营地、路径、破损地表、岩石、枯树、旗帜、箱具和火盆建立层次，不迁移 Tilemap。
- 地表变化只作为视觉层，不增加 Collider，不改变刷怪采样、寻路、交互范围或安全区规则。
- 荒原游魂、裂爪猎犬和铁壳尸傀必须同时依靠轮廓、体量和局部材质辨识；三者共享 Animator 参数契约，但使用独立 Sprite、Clip、Controller 与 Prefab。
- 商人与打造台使用金铜与暖色照明从战斗单位中分离；获得交互焦点时仅显示轮廓、提示与名称牌，不对商人、工作台、火盆或火光做缩放呼吸。
- 命中反馈为约 0.08 秒闪白与单个总伤害数字；怪物血条受伤后显示，满血或死亡时隐藏；投射物命中使用约 0.25 秒青色冲击。
- 死亡和淡出只属于表现层。掉落仍在既有死亡事件上即时结算，临时表现不得重复发送攻击、死亡或掉落事件。
- 所有临时表现必须在禁用、销毁、复活和场景退出时停止并清理。

### 地表物件布局规则

- 先划分功能区再摆放物件：营地核心为 `x = -6..6, y = 1..7`；主路径沿场景中轴由营地向南延伸；其余区域为战斗区与边界缓冲。
- 营地必须形成可解释关系：帐篷位于北侧并朝向营地中心；商人与货箱组成东侧交易组；打造台、火盆与旗帜组成西侧制造组；玩家出生点和交互通道保持净空。
- 商人和打造台周围至少保留 2 世界单位的可读净空；出生点周围至少保留 2 世界单位；主路径中心两侧各 1.5 世界单位内不放大型装饰。
- 战斗区装饰按“一个主物件 + 0–2 个陪衬”的小簇布置。枯树、大岩石是主物件，小石块和碎石只能作为陪衬；禁止把单件资源均匀或随机撒满地图。
- 边界装饰用于解释 `WorldBounds`，优先集中在四角、转折和缺口，不按等距点阵重复；视觉阻挡必须位于碰撞边界外侧或与其一致。
- 地表变化贴图对齐 8×8 地表网格，不使用无语义的小偏移。营地地表、路径和破损地表分别只出现在对应功能区。
- 每个场景物件必须归入 `Camp`、`Path`、`CombatClusters` 或 `BoundaryDecorations` 层级；坐标表必须同时记录“用途”和“避让对象”，不能只记录位置。

## UI 规格

- `Theme.uss` 是运行时 UI 的共享主题入口，统一背景、边框、间距、字号、稀有度和交互状态；各面板 USS 只保留自身布局和少量局部规则。
- 背包面板使用深石板底、铁质边框和克制的金铜角件。
- 基础间距按 4 px 倍数；格子基线维持 48 px，不改变现有 10×6 布局逻辑。
- 普通、悬停、焦点、选中、禁用至少具有边框粗细、亮度或角标差异。
- 键鼠悬停与手柄焦点可以共用强调色，但焦点必须在没有鼠标时持续可见。
- 稀有度除颜色外增加边框或角标；阶段 0 的大剑使用金铜角标验证该规则。
- UI 位图只承担纹理和装饰，文字、布局、交互状态仍由 UXML / USS 管理。
- 动态装备图标由 Addressables 加载；固定 HUD、页签、槽位和关闭图标由 USS 静态引用。
- HUD 使用生命、金币和当前武器的“图标 + 文本”结构；空武器与空装备槽使用明确剪影。
- 背包、商店、打造、详情、HUD 和世界掉落必须从同一物品基底解析图标与稀有度，不允许按页面维护独立图标映射。
- Default、Hover、Pressed、Selected、Focused、Disabled 均需可辨识；键鼠悬停可与手柄焦点共用强调色，但手柄焦点必须持续可见。
- 稀有度继续同时使用颜色、边框形状和文字，不以单一颜色传达。

### UI 切图与九宫格合同

- 固定功能图标保留为一张 1448×1086 RGBA Sheet，源图按 4×3 排列，但 Sprite Editor 使用图形透明边界建立 12 个紧边界子 Sprite；USS 必须引用具体子 Sprite，不再维护派生 64×64 散图。
- UI 图集切片必须先验证单元边界，再检查 Alpha 主体是否完整落在单元内。不能仅按“行列数”平均切分后直接接受结果。
- 面板、边框和槽位保留为一张 1254×1254 RGBA Sheet，源图按 2×2 排列，当前四个紧边界 Rect 分别为 `(79,648,534,527)`、`(693,679,436,465)`、`(105,110,479,469)`、`(693,110,436,469)`；它们不与普通图标共用 Slice 规则。
- 九宫格 Slice 线只能穿过可重复的纯边框或纯底纹，禁止穿过金属角件、斜切缺口、铆钉、徽记和其他非重复图形。
- `ui_frames_sheet_0`（面板）使用四向 98 px 保护区；`ui_frames_sheet_1`（普通槽）使用四向 78 px Slice。
- `ui_frames_sheet_2`（焦点槽）与 `ui_frames_sheet_3`（禁用槽）含角件 / 斜切结构，使用四向 157 px Slice。
- 固定图标当前按 `ui_icons_sheet_0..11` 依次映射生命、金币、武器、护甲、戒指、背包、商店、打造、关闭、取消、空槽和缺失图标；重新切片后必须同步更新 USS 与 Prefab 的 fileID。
- 如果某个装饰无法在九宫格规则下完整保留，应拆成“可拉伸底板 + 独立角件”两个 UI 元素，而不是继续移动切线碰运气。
- 每张 UI 资产接入前必须保存三种尺寸预览：原始尺寸、最小实际控件尺寸、最大实际控件尺寸；任一预览出现断线、重复角件、半个徽记或非整数模糊即失败。
- UI 图标和九宫格 Sheet 继续使用 Point 与无压缩导入；拉伸只发生在九宫格中心 / 边段，角件保持原始像素比例。

## 生成基线

- 生成模式：内置 imagegen。
- 风格板用途：统一地图、玩家、怪物、投射物、大剑和背包面板的材质、轮廓与色彩。
- 透明 Sprite：先生成均匀色键背景，再在本地移除背景并验证 Alpha。
- 生成提示词与最终文件路径记录在 [视觉资产清单](./visual-assets.md)。
