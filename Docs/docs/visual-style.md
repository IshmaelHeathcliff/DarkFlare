# 视觉规范

## 验收分辨率

- 当前及后续视觉与 UI 验收以 1920×1080 为唯一保证分辨率。
- 1280×720 与 2560×1440 的既有截图只作为历史记录，不再进入常规回归和正式截图流程。
- 如果未来需要支持新的分辨率或宽高比，应单独立项并补充对应布局规则与自动化覆盖。

## 适用范围

本文保留初版体验优化阶段 0、0.5 与阶段 5 的视觉基线，并定义 `Main.unity` 当前视觉方向。alpha 阶段的项目自有运行时栅格资产统一遵守[美术资产生成规范](./visual-asset-generation.md)：一张 PNG 只包含一个生产 Sprite 或动画帧，不生成 SpriteSheet，不依赖 Sprite Editor 人工切片；初版 Sheet 已由 alpha 单图迁移退役。

风格参考图见 [阶段 0 风格板](./assets/visual-style/phase-0-style-board.png)，具体资源规格见 [视觉资产清单](./visual-assets.md)。

## 视觉方向

- 视角：2D 俯视 3/4，世界物件保持统一的左上方冷光与右下方暗部。
- 风格：暗色奇幻、低分辨率手绘、像素化硬边；强调轮廓和材质块面，不追求细碎写实纹理。
- 氛围：冷灰、低饱和、压暗背景；角色、敌人、交互物和技能效果通过有限高亮建立层级。
- 可读性：玩家、怪物、交互物必须同时依靠轮廓、明度和局部色彩区分，不能只依靠色相。

- 角色动画默认 10 FPS；Idle 允许 4 帧，Move 使用 4 帧。
- 玩家先验证四方向共用轮廓与水平翻转；怪物阶段 0 使用左右翻转。
- 角色脚底、武器握点和主要体块在相邻帧中不得漂移。
- 世界排序先沿用 Default Sorting Layer，通过 Sorting Order 保证地表 < 掉落 < 角色 < 特效；批量生产前再评估是否拆分 Sorting Layer。

## 可见尺寸与源图合同

### 通用导入

- alpha 阶段的新资产以一个 PNG 对应一个 `Sprite Mode: Single` 资产；角色每个动画帧、UI 每个状态、世界每个物件均独立保存。
- 禁止新增 SpriteSheet、`Sprite Mode: Multiple`、人工 Sprite Editor Rect、人工 Pivot 微调和 sub-sprite fileID 依赖。
- Filter Mode 为 Point，Compression 为 None，关闭 Mipmap，透明边缘不得带色键残边；PPU 与 Pivot 按家族合同通过 Preset、Editor 工具或 Unity MCP 自动设置。
- 角色中心、共享脚底线、图标光学中心和世界物件接地点必须在生成前进入合同，并由单图审计验证，不能在导入后人工修正。
- 新家族 Prefab 默认使用 `(1, 1, 1)`；禁止非等比 Transform、逐资产 scale-to-fit 或运行时缩放动画掩盖资源尺寸问题。玩家、三类怪物、商人和投射物的既有根 Scale 因同时承载 Collider / 子节点，本轮明确保留为历史运行时例外。
- 如果生成工具不能直接输出交付画布，只允许使用生成前声明的家族共用全画布等比导出；不得按每张图的主体包围盒单独缩放。
- 生产资产全部使用 Full Rect 单 Sprite；初版 Sheet、人工 Rect 和 sub-sprite fileID 已退出运行时合同。

### 角色主体尺寸

主体包围盒以 Alpha 大于 8 的像素计算；Idle 为正式尺寸基准：

| 类型 | Alpha 主体目标 | 底部透明边距 | 初版既有 Prefab 等比缩放 | 最终可见尺寸目标 |
| --- | --- | ---: | ---: | --- |
| 玩家 / 人形 NPC | 宽 52–66、高 86–90 px | 3–6 px | 0.80 | 高 1.05–1.15 世界单位 |
| 普通怪物 | 宽 76–84、高 86–90 px | 3–6 px | 0.75 | 最大边 0.95–1.10 世界单位 |
| 迅捷四足怪物 | 宽 68–78、高 48–56 px | 4–8 px | 0.90 | 宽 0.95–1.10 世界单位 |
| 重装怪物 | 宽 70–80、高 82–88 px | 3–6 px | 0.75 | 高 0.95–1.05 世界单位 |

- 表中的 Prefab Scale 是本轮为保持 Collider、交互范围与既有世界尺寸而保留的运行时例外。后续若要归一到 `(1, 1, 1)`，必须单独迁移 Collider 和全部子节点，不能混入单图生成。
- 同一角色的 Idle / Move 帧使用同一个缩放因子和地面锚点；躯干高度波动不超过 4 px，四肢动作造成的总包围盒宽度波动不超过 12 px，落脚点横向漂移不超过 2 px。
- Attack、Hit、Death 可因动作改变包围盒，但角色本体不得重新缩放；超出安全区时增加透明留白，不得压缩主体。
- 当前 128×128 角色画布的底部可见像素必须稳定落在底边上方 3–8 px，稳定帧几何中心保持在 `x = 64 ± 2 px`。低姿态四足怪物仍需达到目标宽度，不能因高度较低而整体缩小。

### 装备图标主体尺寸

- 七件正式装备全部重新规范为 96×96；Alpha 主体最长边为 72–80 px，中心与画布中心偏差不超过 3 px，任一侧透明安全边距不得小于 6 px。
- 武器、护甲和戒指允许轮廓不同，但不得通过让某一类别占满画布来制造“更强”感。两件同类物品的最长边差异不得超过 6 px。
- 图标使用相同的 1–2 px 硬边轮廓、左上冷光、右下暗部和受控金属高光；不加入 UI 框、投影、文字或独立背景。
- 世界掉落和全部 UI 直接使用同一 Sprite。不得为世界与 UI 分别维护不同尺寸或二次缩放版本。

### 单图生成与检查流程

1. 旧玩家、旧荒原游魂和旧大剑是强制风格参考；生成时必须作为图像参考输入，不能只在提示词中描述“相似风格”。
2. 生成前先冻结家族的生成画布、交付画布、主体宽高、覆盖率、视觉中心、安全边距、接地线、PPU 和 Pivot；没有合同不得开始。
3. 每个新角色先只生成一张 Idle 0 Pilot。Pilot 通过轮廓、主体尺寸、视觉中心、颜色、光向、身份和像素密度验收后，才允许派生其他帧。
4. 每个动画帧都以不可变 Pilot 为身份参考；可额外引用上一张已通过帧保证动作连续，但不能只链式引用上一帧。
5. 一次只生成一个 Sprite 或动画帧，输出后立即运行单图审计并进行原生像素视觉检查；未通过时停止并重新生成或编辑当前图。
6. 通过的单图直接使用最终文件名保存，不合并 SpriteSheet，不紧边界裁切，不按单张 Alpha 包围盒缩放。
7. Unity 以 `Sprite Mode: Single` 自动导入并按合同设置 PPU、Pivot 与其他 Importer 选项，不使用 Sprite Editor 作为生产步骤。
8. 全套资产接入前再次执行家族差值审计与并排预览；只有数值与视觉同时通过才进入 Animator、Addressables 和 Prefab。

完整合同、Manifest、自动审计命令和失败条件见[美术资产生成规范](./visual-asset-generation.md)。

alpha 单图迁移的量化基线：

| 家族 | 数量 | 画布 | 关键审计结果 |
| --- | ---: | --- | --- |
| 玩家、三类怪物、商人 | 52 | 128×128 | 底部边距 3–5 px；Idle / Move 稳定组差异通过 |
| 固定 UI 图标 | 12 | 96×96 | Alpha 加权中心 x=48.116–48.283、y=48.110–48.397 |
| 投射物 | 1 | 96×96 | 主体 56×22，四边留白 20 / 37 / 20 / 37 px |
| 世界物件 | 12 | 384×384 | 最小边缘留白 12 px；主体未按单件缩放 |
| 装备图标 | 7 | 96×96 | 最长边 72–80 px；中心与安全边距通过 |

完整静态合同与机器报告位于 `Docs/docs/assets/visual-assets/alpha-0.1/`。初版 Sheet 的返工记录只保存在归档计划中，不再作为当前生产合同。

## 动画状态

| 状态 | 阶段 0 接入 | 验收重点 |
| --- | --- | --- |
| Idle | 运行时 | 呼吸幅度小、脚底稳定 |
| Move | 运行时 | 步幅可读、移动方向一致 |
| Attack / Cast | 预览 | 武器或施法方向稳定 |
| Hit | 预览 | 轮廓收缩且不依赖纯红闪 |
| Death | 预览 | 明确失去战斗姿态，避免与 Idle 混淆 |

## 阶段 0.5 运动、边界与掉落基线

- 玩家移动使用 `Rigidbody2D.Interpolate` 衔接物理帧与渲染帧；相机保留 `LateUpdate + SmoothDamp`，切换目标时必须清空旧平滑速度。
- 当前不挂 Pixel Perfect Camera，也不引入 Cinemachine。只有原生输出再次出现非整数采样问题时才重新评估。
- `Main.unity` 的 `WorldBounds` 是物理边界、相机范围和怪物生成范围的共同来源；视觉地表必须继续覆盖镜头边界之外。
- 世界掉落排序为地表 < 投影 / 稀有度环 < 图标 < 标签。图标与标签允许轻微悬浮；稀有度环持续匀速旋转，禁止再使用 UI 方框或缩放呼吸。所有运动只修改视觉子节点，不移动根碰撞体。
- 掉落至少同时使用图标轮廓、圆环形状、稀有度颜色和中文名称；普通 / 魔法 / 稀有 / 独特分别使用银灰 / 蓝 / 金 / 橙，且稀有度不得只依赖颜色。

## 阶段 5 世界与反馈基线

- 地图使用 `GroundBaseTilemap` 与 `GroundDetailTilemap` 组成双层地表；基础层 5×5 全覆盖，细节层稀疏叠加裂纹、碎石和灰烬。两层继续与既有 `WorldBounds`、营地、路径和边界装饰共同建立层次。
- 地表变化只作为视觉层，不增加 Collider，不改变刷怪采样、寻路、交互范围或安全区规则。
- 荒原游魂、裂爪猎犬和铁壳尸傀必须同时依靠轮廓、体量和局部材质辨识；三者共享 Animator 参数契约，但使用独立 Sprite、Clip、Controller 与 Prefab。
- 商人与打造台使用金铜与暖色照明从战斗单位中分离；获得交互焦点时仅显示轮廓、提示与名称牌，不对商人、工作台、火盆或火光做缩放呼吸。
- 命中反馈为约 0.08 秒闪白与单个总伤害数字；战斗飘字同时使用正负号与四套颜色区分玩家受伤、敌人受伤、玩家治疗和敌人治疗，不能只靠单一颜色表达伤害与恢复。怪物血条受伤或治疗后刷新，满血或死亡时隐藏；投射物命中使用约 0.25 秒青色冲击。
- 死亡和淡出只属于表现层。掉落仍在既有死亡事件上即时结算，临时表现不得重复发送攻击、死亡或掉落事件。
- 所有临时表现必须在禁用、销毁、复活和场景退出时停止并清理。

### 地表物件布局规则

- 先划分功能区再摆放物件：营地核心为 `x = -6..6, y = 1..7`；主路径沿场景中轴由营地向南延伸；其余区域为战斗区与边界缓冲。
- 营地必须形成可解释关系：帐篷位于北侧并朝向营地中心；商人与货箱组成东侧交易组；打造台、火盆与旗帜组成西侧制造组；玩家出生点和交互通道保持净空。
- 商人和打造台周围至少保留 2 世界单位的可读净空；出生点周围至少保留 2 世界单位；主路径中心两侧各 1.5 世界单位内不放大型装饰。
- 战斗区装饰按“一个主物件 + 0–2 个陪衬”的小簇布置。枯树、大岩石是主物件，小石块和碎石只能作为陪衬；禁止把单件资源均匀或随机撒满地图。
- 边界装饰用于解释 `WorldBounds`，优先集中在四角、转折和缺口，不按等距点阵重复；视觉阻挡必须位于碰撞边界外侧或与其一致。
- 双层 Tilemap 使用 8×8 世界单位网格；基础层覆盖 `-20..20`，细节层只使用整格位置、90 度旋转和受控透明度，不使用无语义的小偏移。
- 基础 Tile 必须全画布不透明、任意对边可连接并共享家族边缘；细节 Tile 必须保留透明安全边，不得形成新的碰撞或遮挡营地交互物。
- 每个场景物件必须归入 `Camp`、`Path`、`CombatClusters` 或 `BoundaryDecorations` 层级；坐标表必须同时记录“用途”和“避让对象”，不能只记录位置。

## UI 规格

- `Theme.uss` 是运行时 UI 的共享主题入口，统一背景、边框、间距、字号、稀有度和交互状态；各面板 USS 只保留自身布局和少量局部规则。
- 背包面板使用深石板底、铁质边框和克制的金铜角件。
- 基础间距按 4 px 倍数；格子基线维持 48 px，不改变现有 10×6 布局逻辑。
- 普通、悬停、焦点、选中、禁用至少具有边框粗细、亮度或角标差异。
- 键鼠悬停与手柄焦点可以共用强调色，但焦点必须在没有鼠标时持续可见。
- 稀有度除颜色外增加边框或角标；阶段 0 的大剑使用金铜角标验证该规则。
- UI 位图只承担纹理和装饰，文字、布局、交互状态仍由 UXML / USS 管理。
- 动态装备图标由 Addressables 加载；固定 HUD、页签、槽位和关闭图标由 USS 静态引用。
- HUD 只保留生命、金币和交互提示；装备图标只在共享玩家装备区展示。当前有效属性移动到背包页
  右侧，采用固定双列短行结构，避免长文本、图标或装备名称挤压 HUD。
- 物品信息栏固定展开且不使用滚动容器，顶部与主菜单对齐；玩家与打造物品位于左侧，商人物品位于右侧。
- 背包、商店、打造、详情、HUD 和世界掉落必须从同一物品基底解析图标与稀有度，不允许按页面维护独立图标映射。
- Default、Hover、Pressed、Selected、Focused、Disabled 均需可辨识；键鼠悬停可与手柄焦点共用强调色，但手柄焦点必须持续可见。
- 稀有度继续同时使用颜色、边框形状和文字，不以单一颜色传达。

### UI 单图与九宫格合同

- Game UI Kit 组件板只作为风格、材质、边框、层级和焦点语言参考，不直接切割为生产资产。
- 固定功能图标、面板、边框、槽位和交互状态分别使用独立 PNG；禁止把多个组件或 Default / Hover / Focused / Pressed / Disabled 状态生成到同一张生产图中。
- UI 生产图不烘焙文字、数量、示例装备和相邻组件；这些内容继续由 UXML / USS 和独立图标组合。
- 九宫格 Border 在生成前写入组件合同，并通过 Importer 自动设置；不得在 Sprite Editor 中移动 Rect 或 Slice 线试错。
- 九宫格线只能穿过可重复的纯边框或纯底纹，禁止穿过金属角件、斜切缺口、铆钉、徽记和其他非重复图形。
- 如果某个装饰无法在九宫格规则下完整保留，应拆成“可拉伸底板 + 独立装饰”两个 UI 元素，每个元素仍是一图一资产。
- 每张 UI 资产接入前必须保存原生像素、最小实际控件尺寸和最大实际控件尺寸三种预览；出现断线、重复角件、半个徽记或非整数模糊即失败。
- UI 图标和九宫格图片继续使用 Point 与无压缩导入；拉伸只发生在九宫格中心 / 边段，角件保持原始像素比例。
- 固定 UI 图标和四个面板 / 槽位状态均为独立 PNG；USS 只引用单图主 Sprite，不再引用 Sheet 子资源。

## 生成基线

- 生成模式：内置 imagegen。
- 风格板用途：统一地图、玩家、怪物、投射物、大剑和背包面板的材质、轮廓与色彩。
- 生产输出：每次只生成一个固定画布 Sprite 或动画帧；Game UI Kit 组件板等组合图只作为不可导入的视觉参考。
- 透明 Sprite：优先直接生成透明背景；需要色键移除时，色键与移除参数必须在家族合同中统一，并在移除后重新审计 Alpha、边缘、中心和主体占比。
- 生成失败时重新生成或编辑当前单图，不依靠人工裁切、逐图缩放或 Sprite Editor 修正。
- 新提示词、家族合同、Manifest、审计报告与最终文件路径记录在 [视觉资产清单](./visual-assets.md)；初版历史提示见[阶段 0 视觉生成提示词](./assets/visual-style/generation-prompts.md)。
