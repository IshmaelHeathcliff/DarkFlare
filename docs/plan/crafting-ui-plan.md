# 打造交互执行计划

## 目标

让玩家在现有营地菜单内选择背包物品和词缀，通过 `CraftItemCommand` 完成四种打造操作，并立即看到金币、词缀和物品价值变化。

## 范围

- 在共享菜单增加“打造”页签，不新增 `UIDocument` 或 `EventSystem`。
- 提供背包物品、现有词缀、物品详情、金币、四种操作与失败反馈。
- 键鼠点击和 UI Action Map 的导航 / 提交共用同一选择状态。
- Controller 只通过 Query、Command 和领域事件工作，不直接修改 Model。
- 打造对象必须位于玩家背包；所有失败分支保持物品、金币和事件不变。

本步不加入配方、材料物品、打造台场景实体、装备中物品打造，也不扩展物品价值公式。

## 执行顺序

1. 修复 `CraftingOperations` 的事务语义：重随失败恢复原词缀；移除重随保持词缀类型；提升数值只有严格变大才成功。
2. 在 `CraftingSystem` 增加背包归属检查和配置状态，保证未持有物品不能打造。
3. 新增 `GetCraftingSnapshotQuery`，集中返回金币、成本、背包物品、词缀详情、价值与出售价。
4. 使用 Unity-MCP 创建 `Crafting.uxml` / `Crafting.uss`，并把第三个页签和模板接入 `GameRoot.uxml`。
5. 新增 `CraftingPanelController`，发送 `CraftItemCommand`，订阅金币、背包和打造完成事件刷新。
6. 把 Controller 挂到 `Main.unity/UIRoot`，检查 visual tree、自动化测试、真实按钮链路和 1920×1080 渲染。

## 完成标准

- 添加、重随全部、移除重随、提升数值四个按钮都能通过键鼠或 Submit 动作触发。
- 成功操作只扣对应成本一次；失败、无改进或非法目标不扣金币、不发成功事件。
- 重随全部保持原前后缀数量；移除重随保持目标词缀类型；任一替换失败都恢复原状态。
- 打造后列表、选择、金币、词缀数值、物品价值和出售价同步刷新。
- 共享菜单三页互斥显示，打开期间 Gameplay Action Map 保持禁用。
- Unity 编译、全量 EditMode、Play 控制台、visual tree 与 1920×1080 渲染检查通过。

## 验证结果

- Unity 脚本编译和静态脚本校验均为 0 错误。
- EditMode 全量 42/42 通过，其中打造与 UI 定向测试 20/20 通过。
- Play Mode 通过真实 `NavigationSubmitEvent` 触发四个按钮：添加词缀使金币 85→65、词缀 0→1、价值 10→12；重随全部扣 40；移除重随扣 30；提升数值在 10 次随机尝试中仅成功一次并只扣 25，数值 27.21→28.72。
- 1920×1080 前后渲染无重叠或截断，Play 控制台 0 错误。
