# 初版体验优化：内容与随机化

## 目标

在现有伤害、物品生成、掉落表和刷怪池上填充首批有效内容，并让生命、伤害和掉落具备可复现的变化。主执行顺序与总验收见 [初版体验优化计划](./README.md)。

## 一、随机化规则

### 怪物随机血量

- 在 `MonsterDefinition` 中配置基础生命和实例随机倍率范围，建议默认从 `0.85–1.15` 起步。
- 生成怪物时创建带种子的实例数据，得到本次最大生命；`MonsterController` 不直接修改共享配置资产。
- HUD / 敌人生命条读取实例最大生命，死亡、复活和测试使用同一结果。
- 开发日志记录怪物 ID、种子和最终生命，便于复现。

### 随机伤害

- 为玩家技能和每种怪物填充非空 `DamageRollDefinition`，移除正式配置对固定 12 / 8 回退值的依赖。
- 每次命中使用命中种子随机基础伤害；同一命中内所有阶段复用同一快照，不重复随机。
- 物品隐式与词条数值继续由物品种子决定，装备生成后保持稳定。
- 接入武器基础伤害后重新校准技能倍率，避免当前大剑 20–40 基础伤害与技能固定伤害重复相加导致数值突增。

### 物品掉落概率

- `LootTableDefinition` 增加 `0–1` 表级掉落概率；失败时合法返回无掉落。
- 只有掉落判定成功后才按现有条目权重选择物品。
- 首版每次死亡最多 1 次掉落判定；多次掉落、保底和稀有度独立抽取留给后续。
- 使用固定种子做大量模拟，验证 0%、100% 和中间概率，不编写依赖真实波动的测试。

## 二、标签与词条

首批至少建立 12 个稳定标签：

- 装备类别：weapon、armor、ring。
- 武器子类：sword、axe。
- 伤害 / 技能：physical、fire、cold、lightning、projectile、melee。
- 角色类别：monster。

稳定 ID 统一使用小写 `snake_case`，中文名用于 Inspector 和 UI。现有 `Damage` 标签迁移前先核对全部引用。

首批至少建立 12 个实际可生效词条，覆盖：

- 武器：基础物理伤害、全局伤害、元素额外伤害、暴击相关。
- 护甲：最大生命、护甲、元素抗性。
- 戒指：通用伤害、生命和单项 / 复合抗性。

每个词条必须配置非空组 ID、允许标签、禁止标签、权重和中文修改器说明。填充前先确认对应 Operation、Scope 和 Stat 已被当前伤害管线支持。

## 三、装备池

首批目标为 7 个装备基底：

- 2 把武器：不同基础伤害范围、格子尺寸和速度 / 伤害取向。
- 2 件护甲：生命取向与护甲取向。
- 3 枚戒指：伤害、生命和抗性取向。

每个基底都必须配置稳定 ID、中文名、装备槽、标签、图标、格子尺寸、基础价值、前后缀容量和至少一个有意义的基础属性或隐式修改器。

首版继续使用 `LootTableDefinition` 条目和 `TraderDefinition` 库存组织装备，不急于新增全局 `EquipmentPoolDefinition`。只有多个系统开始重复同一池配置时再抽取共用类型。

## 四、怪物池

首批目标为 3 种共享追击 / 接触攻击逻辑的怪物：

- 均衡型：标准生命、移动和伤害。
- 迅捷型：低生命、高移动、较低单次伤害。
- 重装型：高生命、低移动、较高单次伤害和掉落机会。

每种怪物使用独立 `MonsterDefinition`、Prefab、动画和掉落表，在 `MonsterSpawnDefinition` 中配置权重。首版不通过同一 Prefab 运行时换色伪装成不同怪物。

## 五、内容平衡目标

- 普通怪物未装备时击杀时间约 2–4 秒，重装怪物约 4–7 秒；装备改善后能明显缩短，但不能一次命中清空全部怪物。
- 玩家应能承受数次接触伤害并有机会脱离，不因一次高随机伤害直接死亡。
- 掉落节奏允许玩家在一次 3–5 分钟战斗段后回营整理，而不是几十秒内塞满背包。
- 各装备类别在掉落、商店和打造池中都能出现；任一类别至少有 4 个兼容词条候选。

## 六、配置校验

在 Odin 配置中心或配置资产上增加只读诊断 / 校验入口，检查：

- 重复或空稳定 ID、非小写 ID。
- 随机范围最小值大于最大值。
- 掉落概率越界、池为空、所有权重为 0。
- 物品槽位与标签冲突、缺少图标或基础属性。
- 词条组为空、没有兼容物品、引用未支持 Operation / Scope。
- 怪物缺少 Prefab、动画、伤害配置或掉落表。
- Addressable key / 引用缺失。

## 七、调试、测试与资源保障

- 为怪物生成、掉落和物品生成保留种子，并在开发日志中输出关键结果。
- 增加可固定全局测试种子的入口，方便 Play Mode 重放同一轮怪物和掉落。
- 随机逻辑保持纯 C# 可测试，不直接散落调用 `UnityEngine.Random`；场景层只负责提供种子。
- 覆盖生命范围、伤害范围、掉落 0% / 100%、加权条目、标签筛选、词条组互斥和空池边界。
- 图标、动画和 Prefab 通过 Addressables 统一预热 / 缓存 / 释放。
- UI 列表继续由事件驱动刷新，不增加每帧 Query 或重复异步加载。
- 所有 UniTask 视觉加载绑定面板 / 场景取消令牌，关闭或销毁后不回写失效元素。

## 完成标准

- 固定种子能够复现怪物生命、命中伤害、掉落结果和装备词条。
- 三种怪物和七个装备基底都能通过真实场景流程出现。
- 掉落概率和条目权重职责分离，合法无掉落不会报错。
- 所有首批词条至少兼容一个装备基底，并能在当前管线产生可观察效果。
- 交易、打造和装备系统共享同一批物品与词条配置，没有孤立内容。
