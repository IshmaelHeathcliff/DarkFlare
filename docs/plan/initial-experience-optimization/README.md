# 初版体验优化计划

## 状态

- 状态：阶段 1 UX 快速改进已完成，下一步规划阶段 2
- 建立日期：2026-07-20
- 前置条件：首版单场景最小循环已完成
- 目标场景：`Assets/Scenes/Main.unity`
- 关联文档：[首版玩法循环](../../gameplay-loop.md)、[输入与运行时 UI](../../input-ui-system.md)、[伤害系统与词条系统设计](../../damage-affix-system.md)、[打造系统](../../crafting-system.md)

## 目标

在不扩张到新场景、存档、复杂 AI 或新玩法循环的前提下，把当前“功能可通”的原型优化成一版具有基本辨识度、操作连续性、装备选择和内容变化的可玩版本。

本计划完成后，玩家应能在 10–15 分钟体验中：

1. 从地图、角色、怪物、掉落、商人、打造台和 UI 上清楚识别各对象与交互状态。
2. 连续进行购买、出售、查看词条、换装和打造，不因刷新丢失列表位置、选择或手柄焦点。
3. 使用武器、护甲和两个戒指槽形成可观察的属性与伤害差异。
4. 遇到至少三种数值和外观可区分的怪物，并获得多种带有效标签与词条的装备。
5. 感受到怪物生命、单次伤害和掉落结果的变化，同时能够通过固定随机种子复现问题。

## 当前基线

| 领域 | 当前实现 | 主要缺口 |
| --- | --- | --- |
| 世界视觉 | 阶段 0.5 已启用玩家 Rigidbody 插值，地表扩展为 5×5，并建立相机、玩家和刷怪器共用的 `WorldBounds`；掉落已接入图标、投影、稀有度框、标签和悬浮表现 | 商人与打造台仍为原型表现，完整地图和其余对象仍待批量填充 |
| UI 视觉 | 阶段 0 已接入背包面板、格子和焦点视觉；HUD、商店和打造仍主要由纯色 USS 组成 | 其余面板缺少统一图标与纹理，手柄焦点和稀有度表达仍需统一 |
| 商店状态 | 刷新时仅在同一物品仍存在时保留选择 | 重建列表会丢失滚动位置和焦点；买卖后容易跳回列表开头或其他物品 |
| 物品详情 | 背包与商店只提供词条数量；打造页能显示前后缀明细，但格式逻辑独立且部分显示原始属性 ID | 无统一装备详情、隐式词条、装备对比和跨面板一致格式 |
| 装备 | `ItemType` 已有 Weapon、Armor、Accessory，但 `EquipmentModel` 仅保存单武器；`CombatSystem.EquipWeapon` 会用武器修改器覆盖 Actor 修改器 | 无护甲与戒指槽，也不能聚合多件装备或卸装 |
| 怪物内容 | 只有 1 个怪物定义和 1 个刷怪池条目，最大生命固定为 24 | 无同类个体差异，也没有多怪物组合 |
| 伤害内容 | 玩家技能和怪物碰撞伤害配置均为空，分别回退固定 12 和 8；伤害范围结构本身已支持按命中种子随机 | 配置没有启用随机伤害；武器资产的 20–40 基础伤害范围尚未接入玩家攻击来源 |
| 掉落内容 | 每次怪物死亡都会从 1 个条目的掉落表生成 1 件大剑；权重只负责条目间选择 | 没有“不掉落”概率、掉落节奏或多装备池 |
| 标签与词条 | 当前只有 1 个伤害标签和 1 个无限制的伤害增加前缀 | 标签筛选、词条组、装备类别差异和构筑选择尚未形成 |

## 阶段 0 验收后补充问题

| 优先级 | 问题 | 影响 | 处理方向 |
| --- | --- | --- | --- |
| P0 | 相机跟随时人物移动模糊 | 运动中无法稳定观察角色轮廓和动画，也会干扰后续动画质量判断 | 先区分纹理过滤、亚像素移动、相机阻尼和渲染缩放的影响，再统一像素密度、采样与跟随策略 |
| P0 | 地图边界明显 | 玩家能直接看见切片矩形或硬边，破坏场景连续性 | 使用过渡地块、边缘装饰和镜头安全外扩弱化视觉硬边，同时保留明确且可靠的碰撞边界 |
| P0 | 掉落物不够清晰 | 战斗和地表信息会淹没掉落，玩家难以及时判断是否产生物品 | 强化图标尺寸、明暗对比、光圈 / 投影、悬浮反馈、名称与稀有度冗余表达，并校准世界排序 |

## 范围决策

- 装备槽首版按 **1 武器 + 1 护甲 + 2 戒指** 实现。两个戒指槽从一开始显式区分，避免以后再修改交换和 UI 契约。
- 怪物首版只扩充数值、外观和权重，不新增远程、施法、精英词缀等新 AI 行为。
- 装备视觉优先完成图标、槽位剪影、稀有度框和世界掉落表现；不做完整纸娃娃换装。角色身上的武器叠加表现作为可选增强。
- 随机数区分两类：物品生成种子决定物品的永久属性；命中 / 怪物生成种子决定每次攻击或每只怪物的临时随机结果。
- 掉落首版保持“每只怪物最多生成 1 件装备”，新增表级掉落概率；条目权重继续只负责成功掉落后的物品选择。
- 词条首版不加入等级段、触发词条或复杂条件，只填充当前伤害管线已经支持且可测试的属性与运算。
- 暂定视觉方向为俯视 3/4、低分辨率暗色奇幻风格。批量生产前先完成一组垂直切片并确认风格。

## 执行顺序

### 阶段 0：视觉规范与技术切片

阶段 0 已完成并归档：[阶段 0：视觉垂直切片执行计划](../archive/phase-0-visual-slice-plan.md)。

1. 建立视觉资产清单、命名、PPU、Pivot、Sorting Layer、色板和 UI 状态规范。
2. 完成地图小块、玩家、1 种怪物、1 件装备、掉落和 1 个 UI 面板的垂直切片。
3. 验证 Sprite 导入、Animator、Addressables、UIToolkit 图片和不同分辨率。

完成门槛：风格切片可在 `Main.unity` 独立预览，资源链无加载泄漏或引用丢失，再开始批量生产。

### 阶段 0.5：视觉体验修正

阶段 0.5 已完成并归档：[阶段 0.5：视觉体验修正执行计划](../archive/phase-0.5-visual-experience-fix-plan.md)。

1. 在键鼠与手柄移动下复现人物模糊，记录 1280×720、1920×1080、2560×1440 三档画面，并定位纹理过滤、亚像素移动、相机阻尼或渲染缩放中的实际原因。
2. 调整相机跟随与像素采样，使静止、水平、垂直和斜向移动时角色轮廓保持清晰，且不引入明显抖动或跟随迟滞。
3. 扩展镜头安全区内的地表覆盖，加入边缘过渡和有限装饰，隐藏切片硬边；碰撞边界、生成区域和营地入口保持正确。
4. 强化世界掉落的图标、光圈 / 投影、悬浮反馈、文本标签和稀有度表达，保证战斗中能快速发现且不只依赖颜色。
5. 使用固定场景位置分别留存三档分辨率的移动、地图边缘和掉落截图，并完成一轮真实击杀、掉落、自动拾取验证。

完成门槛：三档分辨率下人物运动清晰且无明显抖动，正常可达区域看不到突兀地图硬边，掉落物在地表和战斗效果中均可立即辨识；修正不改变移动、边界碰撞、掉落与拾取事务。

完成结果：玩家实机确认 `Rigidbody2D.Interpolate` 明显缓解移动模糊，因此未引入 Pixel Perfect Camera 或 Cinemachine；地表覆盖扩展到约 40×40 世界单位，可玩边界为约 32×32 世界单位；三档原生分辨率与边界机位截图通过，专项和全量自动化回归通过。

## 主要风险

- **美术范围膨胀**：先确认一组风格切片；首版不做完整纸娃娃、复杂特效和大量方向帧。
- **UI 快照重复**：先抽取共用详情模型，再改三个面板。
- **多装备修改器错误**：集中重建装备聚合，不在每个槽位写独立加减逻辑。
- **随机问题难复现**：所有运行时随机结果保留种子，测试使用注入的 `System.Random`。
- **概率和权重混淆**：掉落概率只决定“是否掉落”，权重只决定“掉什么”。
- **LocalItem 语义未完整**：内容填充前先验证伤害管线支持范围，未支持词条不进入首批配置。
- **死亡动画破坏掉落**：死亡 Event 仍即时触发掉落；表现层延迟销毁不能重复发送死亡或掉落。
- **Addressables 泄漏**：批量图标和动画接入时同步记录 handle 所有权、取消和释放路径。

## 本阶段不做

- 新场景、撤离、存档和局外成长。
- 新怪物 AI 类型、Boss、精英词缀和复杂技能。
- 背包拖拽、旋转、堆叠和重量规则。
- 装备耐久、套装、唯一装备特效和完整纸娃娃换装。
- 词条等级段、异常状态、Trigger / Chance / Limit 等未支持机制。
- 多商人独立经济、回购、商店刷新计时和价格波动。
- 打造材料、配方、锁定词条和批量打造。
- 正式音乐、过场、剧情和任务系统。
