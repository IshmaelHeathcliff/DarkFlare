# 阶段 5：美术资产规范收缩与返工

状态：实现与自动化回归完成，等待最终视觉复验

> 当前规则以“角色与固定 UI 均保留整图并在 Unity Sprite Editor 内人工校正紧边界切片”为准；任何 Rect 调整后必须同步重绑 USS、Prefab 与场景 fileID。96×96 只继续用于 Addressable 装备图标与等效可见尺寸基线。

## 背景

阶段 5 首轮技术验收证明 Addressables、Animator、战斗反馈和统一 UI 链路可用，但最终美术复验未通过：

1. 裂爪猎犬、铁壳尸傀和商人的 96×96 输出主体尺寸不一致。
2. 非方形源单元被直接缩放到 96×96，造成横纵比例失真。
3. 大剑为 64×64，其余六件装备为 96×96，且主体占画布比例差异过大。
4. 地表物件只有坐标清单，没有功能分区、视觉动线、净空和聚类规则。
5. 部分 UI 面板和槽位沿错误的九宫格切线拉伸，切线穿过角件、斜切缺口等完整图形。

本返工不改变玩法、数值、AI、Prefab 地址、Animator 参数、事件或 UI 事务。

## 审计基线

| 对象 | 画布 | Alpha 主体 | Prefab 缩放 | 结论 |
| --- | --- | --- | --- | --- |
| 玩家 Idle | 96×96 | 61×90 | 0.80 | 人形风格与尺寸参考 |
| 荒原游魂 Idle | 96×96 | 81×90 | 0.75 | 怪物风格与尺寸参考 |
| 裂爪猎犬 Idle | 96×96 | 56×42 | 0.75 | 主体过小 |
| 铁壳尸傀 Idle | 96×96 | 75×65 | 0.75 | 高度不足、非等比压缩 |
| 商人 Idle | 96×96 | 67×69 | 1.00 | 高度不足、非等比压缩、Prefab 缩放不统一 |
| 大剑 | 64×64 | 43×56 | — | 正式画布规格不一致 |
| 六件新装备 | 96×96 | 最长边 81–84 | — | 相对大剑过大 |

导入规格均为 64 PPU、Point、无压缩；问题集中在生成、切帧、主体包围盒和 Prefab 显示约束，而非 TextureImporter。

## 批次 A：冻结资产合同

- 以 [视觉规范](../../visual-style.md) 的“96×96 硬性资产合同”为唯一验收来源。
- 角色、怪物、NPC 和装备统一 96×96；删除正式资产中的 64×64 例外。
- 增加编辑器校验：画布、PPU、Pivot、Filter、Compression、Alpha 包围盒、底部锚点、同动画帧尺寸波动和 Prefab 等比缩放。
- 切图工具只能等比缩放并透明补边；非方形单元直接缩放到方形视为错误。

完成门槛：当前问题资产会被校验明确拒绝，旧玩家与荒原游魂参考资产保持通过。

## 批次 B：角色与商人返工

1. 使用旧玩家、荒原游魂及当前获批色板作为图像参考，只生成裂爪猎犬、铁壳尸傀和商人的 Idle 基准帧。
2. 对 Idle 基准先验收轮廓、比例、光向、像素密度、主体包围盒和世界尺寸。
3. 基于已通过 Idle 做图像编辑，派生 Move、Attack、Hit、Death；同一角色使用共享等比缩放和地面锚点。
4. 原路径覆盖 Sprite，保留 Clip、Animator Controller、Prefab、Addressables 与业务组件引用。
5. 商人 Prefab 等比缩放收敛到 0.80；普通与重装怪物保持 0.75，低姿态裂爪猎犬使用已记录的 0.90 等比缩放。碰撞与交互范围不因视觉返工改变。

完成门槛：三种怪物和商人无拉伸压缩，世界可见尺寸落入规范区间；动画切换时不发生大小跳变或脚底漂移。

## 批次 C：七件装备统一

1. 旧大剑作为风格参考，但七件装备共同按 96×96 重新规范，不能只给 64×64 大剑补透明边。
2. 七件装备主体最长边统一到 72–80 px；同类物品差异不超过 6 px。
3. 保留现有文件路径和 `ItemBaseDefinition.Icon` GUID，避免修改运行时数据和 Addressables 引用。
4. 对比世界掉落、背包、装备槽、商店、打造、详情和 HUD，确认同一 Sprite 在所有入口的视觉重量一致。

完成门槛：七件装备画布和主体尺度一致，不再出现大剑明显偏小或新图标明显偏大的情况。

## 批次 D：UI 切图与九宫格返工

1. 固定功能图标保持 64×64，逐个核对源图单元、Alpha 主体边界、命名映射和实际 USS 使用位置；任何裁切主体的图标重新提取或重制。
2. 面板和槽位不再按图集平均网格处理，建立显式切图清单：源矩形、目标文件、四向 Slice、不可切割装饰区。
3. `ui_inventory_panel.png` 的四向 Slice 从 28 px 收敛为 40 px，完整保护金属角件。
4. 普通槽使用 8 px Slice；焦点槽和禁用槽分别使用 16 px Slice，避免角件和右下斜切结构被分割。
5. 无法通过九宫格完整保留的装饰拆成独立角件 VisualElement；不通过扩大背景图或继续试切解决。
6. 使用 unityMCP 在最小、标准和最大控件尺寸下渲染背包、商店、打造和详情，检查边线连续性与角件完整性。

完成门槛：所有面板边线连续，角件、铆钉、斜切缺口和功能图标完整；不同分辨率和控件尺寸下不出现半个图形、重复角件或拉伸变形。

## 批次 E：地图重新布局

- 营地核心限定在 `x = -6..6, y = 1..7`，按“帐篷北侧、商人与货箱东侧、打造台与火盆西侧”的关系组织。
- 主路径沿中轴向南延伸，中心两侧各 1.5 世界单位保持净空；地表路径贴图对齐 8×8 网格。
- 战斗区改为少量物件簇：每簇一个枯树或大岩石，最多两个小型陪衬；不再单件随机散布。
- 边界装饰集中在四角、转折和缺口，取消等距点阵式重复。
- 通过 unityMCP 修改和保存 Main，不直接编辑场景 YAML。

完成门槛：仅看画面即可解释营地功能、出入口、战斗区与边界；大型物件不遮挡出生点、交互点、主路径或战斗反馈。

## 验证

- 自动化扫描全部正式角色 Sheet 和装备，验证切片数量、PPU、Pivot、导入设置和等效 Alpha 主体阈值。
- 自动化扫描固定 UI 图标与面板 Sheet；检查九宫格子 Sprite 使用各自允许的源图 Slice 值，不允许不同结构复用错误切线。
- 对每套动画检查 Sheet 子 Sprite、共享脚底线和等比处理；姿态与攻击特效允许改变 Alpha 包围盒，但角色躯干不能因适配画布而逐帧缩放。
- 检查所有 SpriteRenderer 与父节点均为等比缩放；禁止 `scaleX != scaleY`。
- 在 Unity 中并排生成玩家、三种怪物与商人，记录实际 Renderer Alpha 可见尺寸和 Collider 对比。
- 分别生成七件世界掉落，并在 HUD、背包、商店、打造和详情检查视觉重量。
- 在 1280×720、1920×1080、2560×1440 下重新检查营地、路径、战斗簇、世界边界和三个菜单。
- 对面板和槽位额外保存原始、最小和最大控件尺寸的九宫格预览，检查切线不穿过不可重复图形。
- 最终重新运行全量 EditMode、PlayMode、程序集编译、Addressables 预热、Console 与 `git diff --check`。
