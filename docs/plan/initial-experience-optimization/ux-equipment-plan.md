# 初版体验优化：UX 与装备系统

## 目标

让连续买卖、词条查看和多槽换装保持稳定、可解释，并保证键鼠与手柄使用同一套选择状态。主执行顺序与总验收见 [初版体验优化计划](./README.md)。

## 分阶段实施

- 阶段 1 已完成共用物品详情、中文词条格式和商店选择 / 滚动 / 焦点恢复，记录见 [阶段 1：UX 快速改进](../archive/phase-1-ux-quick-improvement-plan.md)。
- 下一步进入阶段 2：扩展武器、护甲和双戒指槽，并接入装备聚合、对应槽位比较和武器伤害来源。
- 当前仍保留单武器装备语义；阶段 2 实施前先核定槽位事务与伤害快照边界。

## 一、商店操作保留状态

新增仅属于表现层的 `ShopViewState`，至少保存：

- 当前来源列（商人 / 玩家）。
- 两列各自的选中物品 `InstanceId`、后备索引和滚动偏移。
- 当前手柄 / 键盘焦点。
- 最近一次交易反馈，直到下一次选择或交易覆盖。

刷新规则：

1. 刷新前记录选择、索引、滚动和焦点。
2. 重建列表后优先恢复同一 `InstanceId`。
3. 物品因买入或卖出消失时，留在原来源列并选择原索引上的下一件；没有下一件时选择上一件。
4. 布局完成后再恢复滚动偏移和焦点，避免 UIToolkit 重建期间强制回到顶部。
5. 背包、商店、打造页签切换后保留状态；关闭并重新与同一商人交互时保留本次运行期状态。
6. 后续出现多商人时按稳定 ID 分开保存；本阶段不把 ViewState 写入游戏存档或 Model。

验收：连续购买、出售 5 次以及页签往返后，列表不跳回顶部，焦点仍在原列的合理相邻物品上，反馈不会被刷新立即覆盖。

## 二、UI 查看装备词条

- 抽取共用 `ItemDetailSnapshot`、`AffixDetailSnapshot` 和格式化工具，替代背包、商店、打造各自拼接文本。
- 统一展示图标、名称、类别 / 槽位、稀有度、物品等级、基础属性、隐式修改器、前缀、后缀、价值和交易价格。
- 属性名使用 `StatDefinition` 中文名，不在玩家 UI 中直接显示 `damage` 等内部 ID。
- 背包和商店增加固定详情区；鼠标 Hover 可临时预览，点击 / Submit 固定选择。不能只依赖鼠标 Tooltip。
- 对可装备物品显示“选中物品 vs 对应槽位装备”的并排比较；正负变化同时使用符号、文字和颜色。
- 打造页复用相同基础详情，在其上额外保留词条选择、成本和操作结果。
- 当前没有词条等级段，首版详情不伪造 Tier；后续加入等级段再扩展快照。

验收：任意背包、商店和打造物品都能看到完整且一致的词条明细；使用手柄可进入详情、切换物品并返回操作按钮。

## 三、扩展装备栏

### 数据与运行时模型

- 新增明确的 `EquipmentSlot`：Weapon、Armor、RingLeft、RingRight。
- `ItemBaseDefinition` 增加允许装备槽信息，不再只通过 `ItemType` 推断。`Accessory` 首版只允许进入戒指槽。
- `EquipmentModel` 改为每个 Actor 持有完整 `EquipmentLoadout`，提供按槽查询和只读枚举。
- `EquipItemCommand` 接收目标槽；戒指由 UI 明确选择左 / 右槽，不能隐式覆盖未知戒指。
- 增加卸装入口。卸装和换装都先验证背包空间，再原子提交；失败时装备、背包和 Event 全部不变。

### 属性与伤害接入

- 每次装备变化后统一重建装备修改器集合，不能继续用新武器的修改器覆盖所有来源。
- 武器基础伤害只来自 Weapon 槽；护甲和戒指提供全局角色修改器。
- 首版护甲 / 戒指优先使用已支持的 `GlobalActor` 修改器；`LocalItem` 只在已验证的武器本地伤害路径使用。
- 把武器 `DamageRollDefinition` 接入玩家攻击来源，并在投射物生成时建立攻击快照，避免飞行途中换装改变已发出投射物。
- `EquipmentChangedEvent` 增加槽位、旧物品和新物品信息，HUD、背包和详情比较按槽刷新。

### UI

- 背包页新增四个槽位、空槽剪影、装备 / 替换 / 卸下按钮和属性摘要。
- 选择戒指时先选择 RingLeft 或 RingRight；键鼠和手柄使用同一状态机。
- HUD 保留紧凑摘要，不把四件装备的完整词条堆在常驻界面。

## 四、核心测试

- 四槽首次装备、同槽替换和卸装。
- 两个戒指槽独立保存，替换一个槽不影响另一个槽。
- 背包空间不足时原子回滚，不丢失旧装备或新物品。
- 多件装备修改器正确聚合；移除任意一件后只移除它提供的效果。
- 武器基础伤害进入攻击，护甲 / 戒指不会错误地成为基础伤害来源。
- 在途投射物使用发射时快照，不受命中前换装影响。
- 事件只在成功提交后发送，快照、详情比较和 UI 选择同步更新。
- 商店刷新覆盖同物品保留、交易后邻近选择、滚动恢复和对象失效降级。

## 完成标准

- 商店连续操作、页签切换和重新打开不丢失合理状态。
- 三个面板使用同一详情模型和中文格式，不存在相互矛盾的词条显示。
- 武器、护甲、左戒指和右戒指均可独立装备、替换和卸下。
- 所有失败路径保持背包、装备、属性和事件不变。
- 键鼠与手柄能够完成查看、比较、选槽、装备和卸装完整链路。
