# 初版体验优化：视觉填充

> 当前状态：阶段 0、0.5 与阶段 5 视觉实现、美术返工及阶段 6 的 1920×1080 完整终验均已完成并归档。记录见[阶段 5：批量视觉接入与表现反馈](../phase-5-batch-visual-integration-plan.md)与[阶段 5 美术资产规范收缩与返工](./phase-5-visual-asset-correction-plan.md)，当前规格见[视觉规范](../../../visual-style.md)与[视觉资产清单](../../../visual-assets.md)。

## 目标

用统一且可批量扩展的视觉语言替换当前主要对象共用 `PrototypeSquare.png` 的状态，同时保持战斗、掉落和交互信息清楚。主执行顺序与总验收见 [初版体验优化计划](./README.md)。

## 阶段 0.5 已完成的优先修正

以下问题来自阶段 0 实机验收，已在阶段 0.5 先于 UX 和批量视觉工作完成处理：

完成记录与验收见 [阶段 0.5：视觉体验修正执行计划](../phase-0.5-visual-experience-fix-plan.md)。

### 相机跟随与人物运动清晰度

- 分别检查 Sprite Filter Mode、PPU、Pixel Perfect / Render Scale、角色与相机的亚像素位置、相机阻尼，先确定实际模糊来源。
- 在不改变移动速度和输入语义的前提下统一角色、地表与相机采样；如保留平滑跟随，必须同时避免像素抖动、拖影和明显迟滞。
- 覆盖键鼠与手柄的水平、垂直、斜向移动，以及 Idle、Move、Attack 状态切换；不以关闭角色动画规避问题。

完成：玩家 `Rigidbody2D` 使用 `Interpolate`，相机继续在 `LateUpdate` 跟随，并在目标变更时清理平滑速度；实机确认移动模糊明显改善，未额外引入 Pixel Perfect Camera 或 Cinemachine。

验收：1280×720、1920×1080、2560×1440 下，静止与运动中的角色轮廓均清晰，动画帧可辨识，无明显抖动、拖影、突跳或镜头落后。

### 地图边界弱化

- 地表覆盖范围向镜头安全区外扩，避免相机直接看到切片矩形边缘或空白背景。
- 用过渡地块、阴影、岩石 / 植被等有限装饰打散直线边缘；不可达边界仍由稳定碰撞控制，不依赖装饰物碰撞临时拼接。
- 核对出生点、营地入口、商人、打造台和刷怪区域，不因外扩或遮挡改变可达性与生成逻辑。

完成：地表从 3×3 扩展到 5×5；闭合 `EdgeCollider2D` 同时作为物理、相机和刷怪范围来源，相机按当前正交尺寸和宽高比扣除半屏范围。

验收：三档分辨率下巡查正常可达区域看不到突兀地图硬边，视觉阻挡与碰撞边界一致，玩家和怪物不会离开有效区域。

### 掉落物清晰度

- 提高图标在地表上的尺寸、轮廓和明暗对比，并通过光圈 / 投影、轻量悬浮或呼吸动画与静态装饰区分。
- 校准 Sorting Order，保证掉落不会被地表覆盖，也不会长期压住角色和关键战斗反馈。
- 同时提供图标、名称标签和稀有度边框 / 角标等冗余信息，不能只靠颜色；多个掉落靠近时仍需可分辨。
- 拾取成功与背包已满继续使用不同反馈，视觉增强不得改变当前自动拾取事务。

完成：`LootPickup` 根节点只保留碰撞与拾取事务，表现层增加投影、金属稀有度框、图标、中文标签和 PrimeTween 悬浮 / 呼吸动画；背包满保留和拾取销毁逻辑未改变。

验收：真实击杀后，玩家无需贴近即可在战斗背景中发现掉落并判断其类别 / 稀有度；自动拾取、背包满保留和世界对象销毁行为保持正确。

## 1. 战斗地图

- 使用 Tilemap 或等价的 2D 分层方案建立地表、边界、遮挡和装饰层。
- 在同一场景中形成可辨识的营地区与战斗区：商人、打造台位于营地，刷怪范围位于战斗区。
- 配置实际碰撞边界，避免玩家和怪物离开画面或生成在不可达位置。
- 地表和边缘装饰覆盖到镜头安全区外，避免正常移动时暴露切片矩形或空白背景。
- 保持出生点、商人、打造台和怪物生成范围互不遮挡；本阶段不实现安全区规则。
- 加入地面变化、路径、营地标记和有限装饰，控制视觉噪声，保证掉落和提示清楚。

验收：1280×720、1920×1080 和 2560×1440 下没有大片空白背景或突兀硬边，营地与战斗区可一眼区分，视觉阻挡、碰撞边界和生成点工作正常。

## 2. 玩家、怪物、投射物与动画

- 玩家至少提供 Idle、Move、Attack/Cast、Hit、Death 五种状态；移动与施法方向覆盖键鼠和手柄产生的朝向。
- 三种首版怪物至少提供 Idle、Move、Hit、Death；可通过左右翻转减少方向资源量。
- 投射物提供独立飞行形象和命中特效，不再使用纯色方块。
- 使用 Animator Controller 或等价状态机，不在 Controller 内硬编码逐帧切图。
- 当前怪物死亡后立即 `Destroy`，接入死亡动画时先停用碰撞、移动和攻击，再由表现完成事件或可取消延迟销毁。
- 增加命中闪白、死亡淡出或简短粒子，避免只靠日志表达命中与死亡。

验收：移动方向、攻击、受击、死亡和复活不会卡死；暂停菜单时表现符合暂停约定；销毁后无残留任务或回调。

## 3. 装备视觉

- 为每个 `ItemBaseDefinition` 增加可由 Addressables 管理的图标引用或统一视觉目录引用。
- 背包、商店、打造和装备栏复用同一物品图标、稀有度框与类别角标。
- 为武器、护甲、左戒指、右戒指提供空槽剪影和已装备状态。
- 可选增强：玩家身上显示当前武器轮廓；护甲和戒指首版不要求改变角色外观。

验收：不读文字也能区分武器、护甲和戒指；同一物品在所有 UI 与世界掉落中的图标一致。

## 4. 掉落物

- `LootPickupController` 根据物品基底显示对应图标，不再只改变方块颜色。
- 同时使用图标、稀有度边框 / 光圈和文本标签表达掉落，不能只靠颜色。
- 强化图标尺寸、轮廓、明暗对比和世界排序，确保掉落在地表、角色和战斗效果之间保持清晰。
- 增加轻量落地、悬浮或呼吸动画，以及拾取成功反馈。
- 背包满时显示明确提示并保留掉落物。

验收：常用镜头缩放和三档分辨率下，类别和稀有度可立即辨识；拾取成功、背包已满和未拾取三种状态没有歧义。

## 5. 商人

- 替换绿色方块为独立角色形象，至少有 Idle 动画、名称牌和可交互高亮。
- 进入范围时同时强化角色轮廓和 HUD 提示；离开、打开菜单或目标切换时正确恢复。
- 商人造型与战斗怪物在轮廓、色彩和站姿上明显不同。

## 6. 打造台

- 替换橙色方块为独立工作台 / 熔炉形象，加入持续但克制的火光、火星或能量效果。
- 交互高亮与商人共用统一规则，但图标和提示语义不同。
- 粒子和动画在菜单暂停时不推动玩法逻辑；纯 UI 反馈可使用不受 `timeScale` 影响的时间源。

## 7. UI 视觉元素

- 建立统一的颜色、间距、字号、边框、稀有度和交互状态变量，减少各 USS 重复硬编码。
- 加入面板底图、九宫格边框、页签 / 操作图标、物品图标、金币图标和装备槽图标。
- 明确 Default、Hover、Pressed、Selected、Focused、Disabled 六种状态；手柄焦点必须持续可见。
- 稀有度同时使用颜色、边框形状或文字，避免只靠颜色区分。
- 继续复用单个 `UIDocument` 和 `EventSystem`，不为视觉改造新增重复根节点。

验收：键鼠与手柄都能明确识别焦点、选择与禁用状态；1280×720、1920×1080、2560×1440 下无关键遮挡。

## 8. 同步补充的表现反馈

- 敌人生命条、伤害数字、命中闪白、死亡反馈和轻量 Tween / 镜头反馈。
- 掉落名称、拾取提示、背包已满提示、金币变化和交易 / 打造结果提示。
- 基础音效作为非阻塞增强：攻击、命中、死亡、拾取、买卖、打造、UI 确认和取消；正式音乐不在本阶段范围内。

## 视觉资源流程

1. 先制作“地图小块 + 玩家 + 1 种怪物 + 1 件装备 + 掉落 + 1 个 UI 面板”的风格切片。
2. 确认色板、光照方向、轮廓粗细、像素密度 / PPU、动画帧率和 UI 图标规范。
3. 核对引用后，将空的 `Assets/Art/Animaitons` 修正为 `Assets/Art/Animations`，再导入正式动画资源。
4. 按 Environment、Characters、Items、Props、Effects、UI 分类保存源资源和导入资源，不覆盖现有 Prototype 占位图。
5. 对运行时加载的 Sprite 使用 Addressables 预热、缓存和释放；异步 UI 图标请求使用 UniTask 并带取消逻辑。
6. 场景和 UIRoot 的实际修改使用 unityMCP 完成，不直接编辑已打开场景的 YAML。

## 视觉完成标准

- 主循环中的地图、玩家、三种怪物、投射物、装备、掉落、商人、打造台和 UI 均有一致的首版资源。
- PrototypeSquare 只保留为调试占位，不再表达主要可玩对象。
- 视觉反馈不会改变领域事务，也不会因动画延迟重复触发伤害、掉落或交互。
- Addressables、Animator、粒子和异步加载在重复进入场景与对象销毁后无泄漏或报错。
