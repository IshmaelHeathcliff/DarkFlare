# 标签

标签用于限制词条的生成对象与生效上下文，也可描述基础伤害包。本文以当前项目已实现行为为准；旧案中的层级标签目录保留为候选方向，不代表当前可用内容。

## 当前已实现规则

- 标签由稳定 ID、中文名和说明组成。
- 标签匹配采用区分大小写的完整 ID 精确匹配。
- `.` 当前只是普通字符，不具有层级继承语义。例如 `Damage.Type.Fire` 不会自动满足 `Damage`。
- 空 ID 会被忽略，重复 ID 会被合并。
- 当前词条没有“自身标签”或 `AnyTags` 字段。

标签目前出现在以下位置：

| 位置 | 规则 |
| --- | --- |
| 物品标签 | 描述基础物品，供词条生成筛选 |
| 基础伤害标签 | 随伤害包进入伤害上下文 |
| 词条允许物品标签 | 非空时，物品至少精确拥有其中一个标签才可生成该词条 |
| 词条禁止物品标签 | 物品精确拥有任意一个时，不可生成该词条 |
| 修改器必须标签 | 生效上下文必须精确拥有全部标签 |
| 修改器禁止标签 | 生效上下文拥有任意一个时，修改器不生效 |

## 当前配置

| 内容 | 当前状态 |
| --- | --- |
| 已创建标签 | 仅有 `Damage`（伤害） |
| 基础伤害 | 大剑的物理基础伤害带有 `Damage` |
| 三件基础物品的物品标签 | 均为空 |
| 两个已配置词条的允许与禁止物品标签 | 均为空，因此可出现在所有当前物品上 |
| 两个已配置词条修改器的必须与禁止标签 | 均为空，因此不受上下文筛选 |

因此，标签系统的筛选能力已经存在，但当前内容尚未形成实际的物品分类或伤害分类。旧案中“火焰标签只提高火焰伤害”等组合目前没有对应标签资产与词条配置。

## 候选标签方向

以下分类可作为后续内容扩充方向，但在创建标签资产并逐项绑定之前均属于“未实现”：

- 物品：武器、护甲、饰品，以及更具体的装备类型。
- 伤害类型：物理、火焰、冰霜、闪电、混沌。
- 伤害来源：攻击、法术、持续伤害、次要伤害。
- 伤害形式：近战、投射物、范围、单体。
- 武器形式：利刃、钝器、穿刺。
- 触发条件：命中、暴击、击杀、受伤、低生命。
- 异常状态：虚弱、骨折、流血、眩晕、燃烧、冰缓、感电。

候选 ID 可以继续使用点号组织可读性，但必须将每个需要匹配的 ID 显式加入对象与条件。当前实现已经包含混沌伤害与混沌抗性，因此后续伤害类型标签不应遗漏混沌。

## 已决定

- 在标签层级能力实现前，所有筛选均按精确 ID 设计。
- 当前只有 `Damage` 可以作为已配置标签使用。
- 状态与触发标签在对应玩法系统完成前不得加入正式词条池。

## 待验证

- 是否需要让子标签自动满足父标签；若需要，应先明确层级匹配规则再批量建立标签目录。
- 物品类型应使用标签还是直接使用现有物品类型与装备槽筛选。
- 伤害类型应主要依赖伤害类型字段，还是同时维护对应标签。

## 开放问题

- 标签 ID 最终采用当前 `Damage` 风格，还是统一为小写路径。
- 是否需要词条自身标签以支持制作检索、权重调整和标签化词条池。
